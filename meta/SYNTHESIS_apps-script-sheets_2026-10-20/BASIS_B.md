## Случаи без адреса

Эти случаи в старом тексте Skill названы без адреса вне Skill (или с адресом только внутри Skill); поиск по клону адреса не дал. Этот отчёт становится их адресом.

- **Б-1 (правило ASS.4.2.зона).** Книга WB_Аналитика: весь аналитический слой держался на трёх управляющих ячейках листа `dashboard` — `K3` (начало периода), `K4` (конец периода), `I4` (числовой параметр). На `K3` и `K4` ссылались девять формул `FILTER` в строке 2 листа `sales_unit_economics`. Лист `dashboard` выглядел пустым, потому что был прочитан диапазоном `A1:J24` (колонка K — одиннадцатая, в чтение не попала). Стирание `dashboard` обнулило границы периода → `FILTER` перестал отдавать строки → `sales_unit_economics` опустел → обнулились `cost_monitor` целиком и часть `weekly_history`. Дата в тексте Skill не записана. Сам рассказ живёт в старом references/book-traps.md, §3.1 (группа C); период `dashboard!K3`/`K4` книги назван в `projects/wb-ue/PLAN.md`, строка 30, но сам случай стирания там не описан.
- **Б-2 (правило ASS.4.2.ключ).** По опыту книг «Цена», «Деньги», «Товары» 2026-09-28 (строка шапки старого SKILL.md «Редакция 2026-09-28 … ручной ввод по ключу (§4.2)»): ручной ввод на перестраиваемых листах (параметры, ячейки что-если, цена для проверки) возвращается после пересборки по подписи, имени диапазона или артикулу; несовпавший ключ даёт значение по умолчанию. Случая сбоя (чужое число в слоте) текст не называет — правило конструкции, а не урок отказа.
- **Б-3 (правило ASS.4.5.живость).** Проверка «нет `#ERROR!`/`#REF!`/`#NAME?`» отрапортовала «всё хорошо» на полностью мёртвой книге: формулы синтаксически корректны, источник пуст.
