# Синтез знания в Skills — правило вместо истории, перезапись вместо дописывания

Заведён 2026-10-18 по слову Андрея в чате SYS: «Нам обязательно нужен механизм синтеза знаний, а не их переноса». Работа и её контракт — задача `projects/knowledge-synthesis/HISTORY_2026-10-18_to_2026-10-21.md`; там же замер роста Skills, ревизия замысла и отвергнутые варианты. Пилот на разделе Р15 Skill `second-brain-engineer` — `meta/SYNTHESIS_pilot_2026-10-18.md`.

Кто читает и когда:
- сессия стадии Б процедуры отбора уроков (`meta/PROTOCOL_lesson-triage.md`) — перед подготовкой любой правки Skill: правка готовится по этому файлу;
- харвест — шаг 5 `meta/PROTOCOL_harvest.md`, через ту же стадию Б;
- полный проход по каталогу Skills — по слову Андрея «синтез каталога» (раздел «Полный проход по каталогу»); по слову «синтез <имя Skill>» — проход по одному Skill.
Расписания, монитора и счётчика у процедуры нет.

## Как запустить — слова Андрея

Писать в чате проекта SYS (Claude Project «15.02_Поддержка Проекта Второй мозг»), каждое слово — в начале нового чата или после !save прошлого:
- «**карта каталога**» — только шаг К1: сессия запускает картографа и записывает `meta/SKILLS_MAP.md`. Отдельное слово, потому что карта полезна и без синтеза (раздел «Кто читает карту»).
- «**синтез каталога**» — полный проход. Нет карты — сначала К1. Есть карта — следующий Skill со статусом «не начат» из её раздела «Ход прохода»; один Skill за сессию.
- «**синтез <имя Skill>**» — проход по одному Skill вне очереди карты.
Сессия, получившая слово, работает автопилотом (Skill `avtopilot`): сама составляет контракт по этому файлу, после одного «да» Андрея сама запускает исполнителей ролей, принимает их ответы и пишет в канон. Андрей не переключает роли. От него — три вещи: «да» на контракт; ответы по спискам «предлагаю снять», «расширено» и «противоречия» в итоговом отчёте; внесение готового Skill в Customize → Skills.

## Кто читает карту

`meta/SKILLS_MAP.md` — первая в системе запись о том, где живёт каждый механизм. Её читают:
- синтез — шаг С1 (где копии механизма) и шаг К2 (какой Skill следующий, какие кластеры);
- процедура отбора уроков — пункт А6 «назначить целевой Skill»: урок идёт в дом своего механизма по карте, а не в тот Skill, что первым пришёл в голову; механизм, которого в карте нет, — новый, и ему назначается дом;
- любая сессия, которая правит Skill или заводит новый Skill, — проверка, не живёт ли механизм уже в другом Skill, и не пересекается ли описание нового Skill с описанием существующего (`second-brain-engineer`, «Гигиена каталога Skill»);
- харвест — шаг 2: уроки сверяются с домом механизма по карте.
Без карты каждая из этих сессий ищет по всему каталогу поиском по словам, и копия механизма в чужом Skill остаётся незамеченной — так и возникали дубли.

## Зачем

Каждый урок до сих пор входил в Skill новым абзацем или новым предложением в старом абзаце: случай, его дата, номер исполнения, что подумали и как оказалось на деле. Шаг «бюджет правки» процедуры отбора требовал назвать, что та же правка снимает, — и почти всегда получал «снимать нечего». Итог по зеркалу `skills/`: семь основных Skills — 783 КБ после харвеста 2026-10-09, 910 КБ после Архивариуса 2026-10-13; пакет харвеста 2026-10-18 добавил бы ещё около 89 КБ, причём 5 из 16 его правок Skill `second-brain-engineer` — строки истории правок в шапках. Skill читается моделью целиком при каждом срабатывании, поэтому каждая строка истории оплачивается в каждой сессии, а правило тонет среди рассказов о том, как оно добывалось.

## Закон

**Skill хранит знание в форме правила. История случая хранится по адресу. Новый урок не дописывается к Skill — кластер, в который он входит, переписывается заново как правило.**

Синтез ничего не удаляет, если выполнены два условия, и без них не выполняется:
1. Каждая единица прежнего текста учтена: она есть в новом тексте или лежит по адресу, который проверен существующим. Это проверяет не тот, кто писал новый текст (шаг С5).
2. Единица снимается из знания совсем (устарела, опровергнута, относится к снятому объекту) только решением Андрея по списку «предлагаю снять». Сессия о важности не судит.

Второе условие — ответ на причину, по которой умер план «Слот + Дата + Сон» (запись Р-28 журнала `projects/git-migration/LOG_ARCHIVE.md`): там судьбу данных решал агент по суждению о важности. Здесь агент переписывает форму, а убирает содержание только Андрей.

## Что такое правило

У правила в Skill четыре обязательных элемента. Порядок и оформление — стилем самого Skill (у каждого Skill свой стиль — предпочтение Андрея 2026-09-17), но ни один элемент не пропускается:
- **что делать или чего не делать, и когда** — условие применения и действие;
- **почему** — механизм одной-двумя фразами. Модель обобщает причину на случаи, которых в правиле нет (`second-brain-engineer`, `references/prompt-craft.md`);
- **признак** — как узнать ситуацию или отказ, если это неочевидно (симптом);
- **основание** — число независимых случаев, дата последнего и адрес каждого случая. Адрес называет сам случай — запись журнала, урок карты, файл задачи, — а не сводку, которая о нём упоминает: пилот 2026-10-18 сослался на находку пакета харвеста вместо записей журналов, и три случая стали недоступны (`meta/SYNTHESIS_pilot_2026-10-18.md`). Адрес перед записью проверяется существующим: в пилоте две ссылки старого текста вели не в тот файл. Например: «причина — 4, последний 2026-10-17: запись Р-21 журнала `projects/deklaration-wb/LOG.md`, …». Несколько оснований одного раздела собираются списком в его конце.
  Где основание лежит (внесено 2026-10-22, решение Андрея по контракту `projects/kontext-reduktion/PLAN.md`, раздел «Контракт автопилота — чтение Skills по видам сессий»): не в теле правила, а в файле `references/basis.md` того же Skill — одна строка на основание, с ярлыком; в тексте правила остаётся только ярлык вида `[основание: <ярлык>]`. Основание нужно тому, кто правило правит или оспаривает (синтез, харвест, спор с правилом), и не нужно тому, кто его исполняет; исполнитель читает Skill в каждой сессии, редактор — раз в проход. Четвёртый элемент правила при этом выполнен: ярлык разрешается в `basis.md` однозначно, а адрес случая остаётся проверяемым. Строки «Почему» и «Не путать» остаются в теле правила — они нужны исполнителю. Замер 2026-10-22: строки основания — 6–9 % постоянного слоя каждого Skill (`meta/COST_skill-reading_2026-10-22.md`).

## Чего в Skill не бывает

- **Рассказа случая**: кто, когда, номер исполнения, сколько байт, что подумали сначала, как оказалось на деле. Случай сокращается до счёта в строке основания; сам рассказ — по адресу.
- **Истории редакций в шапке.** Шапка Skill — одна строка «Редакция <дата>». Что и почему менялось, отвечают история коммитов зеркала `skills/<имя>/` и журналы, на которые ссылаются строки основания.
- **Объяснения устройства Skill в шапке** (внесено 2026-10-22, тот же контракт). Шапка для исполнителя — не больше трёх строк сверх строки редакции: что остальное лежит в `references/` и читается перед своим действием целиком по таблице «Что читать дальше»; что номера пунктов сквозные и не перенумеровываются; что действие без прочитанного файла — нарушение. Почему устройство такое (правило раскладки по триггеру, откуда взялись слои, кто решил и когда) — в `references/basis.md`, раздел «Устройство Skill»: это текст для редактора, а исполнитель платит за него в каждой сессии.
- **Блока ИСТОРИЯ ДИАГНОЗА.** Опровергнутый диагноз хранится в журнале или в отчёте синтеза, на которые ссылается строка основания; в Skill остаётся одна строка «не путать: X — на деле Y», если ложная версия правдоподобна и сессия к ней вернётся сама. Это исключение для Skills записано в пункте 0.4.1 `core/R-06a.md` решением Андрея 2026-10-18; в остальных файлах, которые правятся на месте, блок ИСТОРИЯ ДИАГНОЗА по-прежнему обязателен.

- **Состояния и особенностей конкретного объекта** — проекта, таблицы, книги, воркфлоу, сервера, кабинета маркетплейса: «воркфлоу такой-то опубликован», «у книги такой-то разделитель», «адаптер пишет в такой-то лист», «ключ шифрования на нашем сервере не в бэкапе». Skill — инструкции, нужные любой сессии любого проекта; особенность объекта меняют или отменяют в любую минуту, и Skill, который её держит, врёт молча (решение Андрея 2026-10-20, `projects/knowledge-synthesis/HISTORY_2026-10-18_to_2026-10-21.md`, раздел «Решение Андрея 2026-10-20: Skill — инструкции для всех»). Носитель такой единицы — канон своего проекта или лаборатории, паспорт воркфлоу, реестр `registry/` или файл кейсов `meta/CASES_*.md`. В синтезе единица старого текста этого рода не переписывается, а получает вердикт ПО АДРЕСУ: синтез проверяет, что факт есть в носителе, и только тогда снимает его из Skill; факта в носителе нет — переносит его туда тем же проходом (файл репозитория — по правилам `second-brain-git`; документ Google Docs — захватом с тегом проекта-носителя). Новый урок этого рода в таблицу шага С3 не входит. Свойство платформы или внешнего инструмента, верное для любого его экземпляра (движок n8n, Google Sheets, Telegram, git), особенностью не является.

## Где живёт история

Адрес случая — запись журнала проекта, находка пакета харвеста (`meta/HARVEST_<дата>.md`), урок карты `projects/archivarius/TRIAGE.md` или списка `meta/LESSONS_waiting.md`, файл задачи лаборатории. Если у случая нет адреса вне Skill, синтез сначала записывает его в отчёт прохода (шаг С7), и адресом становится отчёт. Прежний текст Skill целиком остаётся в истории зеркала `skills/`: отчёт называет коммит зеркала, на котором стоит текст до синтеза.

## Единица — кластер

Синтез работает не с уроком и не со всем Skill, а с кластером: всеми местами одного Skill, которые говорят об одном механизме, плюс копиями той же мысли в других Skills. Урок — слишком мелко: дописывание по уроку и дало рост. Весь Skill — слишком крупно: полное переписывание контекста моделью ведёт к его схлопыванию, детали теряются (исследование ACE, Agentic Context Engineering, ICLR 2026; `meta/PROTOCOL_lesson-triage.md`, раздел «Зачем»). Кластер достаточно мал, чтобы проверить сохранение по единицам, и достаточно велик, чтобы найти общий закон.

## Шаги

С0. **Собрать вход до контракта** (внесено 2026-10-22: сессия по слову «синтез n8n-engineering-manual» составила контракт без находок харвеста, лежавших в позиции очереди). Слово Андрея — не единственный вход. До составления контракта прочитать в `registry/maintenance-queue.md` все открытые позиции этого Skill (статусы «ОТКРЫТА», «ЖДЁТ синтеза <имя Skill>») и находки, которые они перечисляют: пакет `meta/HARVEST_<дата>.md` и карты его папки `_reports/`. Эти находки входят в С3 наравне с уроками. Контракт, не называющий позиции очереди и их находки поимённо, не составлен. Задача лаборатории с остатками харвеста находок не несёт — они в позициях очереди.

С1. **Собрать кластер.** Прочитать живой Skill целиком (`/mnt/skills/plugins/<имя>/` — главный файл и все `references/`). Собрать все абзацы о механизме урока. Копии той же мысли в других Skills взять из карты каталога `meta/SKILLS_MAP.md`, если она есть, и дополнительно найти поиском старой фразы командой по каталогу Skills и по репозиторию — копии переписываются тем же действием или заменяются ссылкой на основное место.

С2. **Разложить старый текст на единицы.** Делает проверяющий шага С5 — исполнитель, который новый текст писать не будет, — и делает это до того, как увидит новый текст: первым заданием он раскладывает старый текст, вторым (продолжение того же исполнителя) проверяет новый. В пилоте разложение и проверку делали два разных исполнителя; это вдвое дороже по стартам, а главную защиту дала не таблица, а повторное чтение старого текста проверяющим. Единица — одно атомарное утверждение с классом и дословной цитатой до 80 знаков: ПРАВИЛО (что делать и когда), ИСКЛЮЧЕНИЕ, ПОРОГ (число, формат, имя инструмента или поля), ПРИЧИНА, СЛУЧАЙ (дата, номер исполнения, счёт случаев, адрес строки как доказательство), АДРЕС (ссылка на место знания), ПРОВЕРКА. Каждое предложение кластера покрыто хотя бы одной единицей. Таблица сохраняется файлом. Образец задания — отчёт пилота.

С3. **Добавить новое.** Единицы новых уроков дописываются в ту же таблицу. Совпадающие по механизму сливаются (встречаемость — по независимым случаям, процедура отбора, пункт А1). Противоречие между единицами — вопрос Андрею с обоими текстами, не выбор сессии.

С4. **Синтезировать.** Сначала вопрос в превосходной степени: какое одно утверждение делает правила кластера своими частными случаями? Если такой закон есть — он ставится наверх с причиной, частные правила идут под ним короткими уточнениями или таблицей «вид случая — что делать». Если закона нет — правила стоят рядом, но каждое в форме правила (четыре элемента). Все единицы класса СЛУЧАЙ сворачиваются в строки основания. Текст пишется заново, а не правится по месту.

С4а. **Назначить триггер и файл** (внесено 2026-10-20, решение Андрея; план `meta/PLAN_skill-layers_2026-10-20_v3.md`, раздел 2). Каждому правилу нового текста назначается строка ТРИГГЕР — когда оно применяется. Триггер определяет файл Skill, где правило живёт: конкретное событие или действие (старт сессии, команда, изменение воркфлоу, работа вне Claude Project, чтение тяжёлого объекта, поиск документа) — файл `references/<действие>.md` и строка в таблице «Что читать дальше» основного файла; «любое действие», «любое утверждение», «любая запись» — основной файл `SKILL.md`. Правило, у которого триггер сузился с «любое действие» до конкретного события, переезжает в файл по действию тем же проходом; правило без триггера в Skill не входит. Так постоянный слой — то, что модель читает при каждой загрузке Skill, — не растёт от правил одного вида действия. Потолка размера и вытеснения нет: снятие правила совсем решает только Андрей (условие 2 закона); сессия о важности не судит, она назначает триггер по тексту правила. У Skills, устроенных не разделами с ТРИГГЕРом, а нумерованными пунктами (`second-brain-git`), роль триггера играет таблица «Что читать дальше» в шапке — правило назначается её строке.
Зерно файла `references/` — момент действия, а не тема (внесено 2026-10-22, тот же контракт). Файл по действию дробится до тех пор, пока строка таблицы не ведёт на текст, который сессия этого действия использует целиком: файл «всё о проектировании» в 39 КБ, из которого проектирование берёт 6 КБ, — та же ошибка, что правило по действию в постоянном слое, только этажом ниже. Правила, действующие на всём протяжении одного вида работы, остаются в файле этого действия; правила, срабатывающие на отдельном событии внутри него (приёмка, замер, правка Skill, массовый перенос), получают свой файл и свою строку таблицы. Строка таблицы стоит около 150 байт, файл — от 5 до 40 КБ, поэтому лишняя строка дешевле лишнего файла. Замер 2026-10-22 — `meta/COST_skill-reading_2026-10-22.md`.

С5. **Проверить сохранение.** Делает независимый проверяющий старшего класса, который не писал новый текст. Он получает старый текст кластера, новый текст и таблицу единиц и выносит по каждой единице один вердикт:
- В ТЕКСТЕ — с цитатой из нового текста;
- ПО АДРЕСУ — адрес назван в новом тексте и проверен существующим;
- ОСЛАБЛЕНО — смысл изменён: условие сужено или расширено, «запрещено» стало «желательно», число изменилось;
- ПОТЕРЯНО.
Правила допуска: ПРАВИЛО, ИСКЛЮЧЕНИЕ, ПОРОГ и ПРОВЕРКА принимаются только В ТЕКСТЕ; ПРИЧИНА — в тексте, допустимо в обобщённой форме; СЛУЧАЙ и АДРЕС — в тексте или ПО АДРЕСУ. Отдельно проверяющий ищет в старом тексте знание, которого нет в таблице единиц: таблица составлена моделью и сама может терять. И третье — выписывает, что новый текст утверждает сверх старого: обобщение, которое расширяет область правила, допустимо только как осознанное решение, поэтому оно выносится Андрею списком «расширено».

С6. **Исправить.** Новый текст правится, пока ни одной единицы не останется ПОТЕРЯНО или ОСЛАБЛЕНО. Два круга правок без сходимости — стоп, выбор выносится Андрею (стоп-линия Skill `denken`). Единица, которую сессия считает нужным снять совсем, в счёт сохранения не идёт и попадает в список «предлагаю снять» с причиной; решение по каждой — Андрея. Второй круг проверяет тот же проверяющий по исправленным единицам и по разности первой и второй редакции: исправление само может потерять то, что первая редакция сохранила.

С7. **Выдать.** Одна правка «было → стало» на весь кластер — якорь, полный старый текст, полный новый текст. Отчёт прохода — файл в репозитории (в харвест — в папке `meta/HARVEST_<дата>_edits/`): таблица единиц с вердиктами, список «предлагаю снять», список «расширено», случаи без прежнего адреса, коммит зеркала с текстом до синтеза, размер кластера до и после. Размер — сведение, а не цель: сокращение ради сокращения не цель (предпочтение Андрея 2026-09-26), цель — правило без истории и без потерь.

## Когда синтез обязателен

- **Любая правка Skill по стадии Б процедуры отбора.** Урок не дописывается: находится его кластер и переписывается по шагам С1–С7. Дописать новое предложение без синтеза можно, только если кластера нет (механизм в Skill новый) — тогда новое правило сразу пишется в форме с четырьмя элементами.
- **Повтор после внесения** (урок с вердиктом «есть, но произошло», шаг 2 харвеста). Первый вопрос — нельзя ли исполнить правило кодом (`second-brain-engineer`, `references/catalog-hygiene.md`, пункт 16). Если нельзя — пересинтез кластера: правило, которое не сработало, переформулируется и переносится туда, где его читают в момент действия; новый случай увеличивает счёт в строке основания, а не добавляет абзац.
- **Уже написанные правила** (решение Андрея 2026-10-18: синтез касается и их, а не только новых уроков) — полным проходом по каталогу, раздел ниже.
- **Пакеты правок харвеста** — все правки до внесения проходят синтез; правки, которые только добавляют строки истории в шапки Skills, не вносятся вовсе (решение Андрея 2026-10-18).
- **Оценка ценности правок харвеста** до синтеза — по пяти вопросам раздела 4 файла `meta/PLAN_skill-layers_2026-10-20_v3.md` (история → не вносится; текст не удерживает → в код; есть кластер → синтез кластера; новый механизм с основанием → вносится в файл по триггеру; остальное → вопрос Андрею); результат — файл вердиктов `meta/HARVEST_<дата>_verdicts.md` и статусы позиций Очереди. Вердикты выносятся по признакам текста и объекта, не по суждению о важности (внесено 2026-10-20).

## Полный проход по каталогу

Синтез отдельных кластеров не видит, что один и тот же механизм описан в двух Skills, и не может развести их зоны ответственности. Поэтому полный проход начинается с карты каталога.

К1. **Карта каталога.** Исполнитель высшего класса (таблица ниже) читает все собственные Skills Андрея целиком, только чтение, и пишет файл `meta/SKILLS_MAP.md`:
- по каждому Skill — зона ответственности одной фразой, его слова-триггеры и подпись стиля (как устроен текст: например, «ТРИГГЕР — ДЕЙСТВИЕ — ПРОВЕРКА», «нумерованные пункты и инварианты», «ворота по порядку», «протокол с превосходной степенью»);
- по каждому механизму — дом (Skill, файл, раздел) и копии в других Skills с вердиктом по каждой копии: заменить ссылкой на дом, оставить с причиной, противоречие (оба текста — вопрос Андрею);
- пересечения описаний (description) Skills, которые путают срабатывание (`second-brain-engineer`, `references/design.md`, раздел «Гигиена каталога Skill»), — число и список;
- список кластеров на синтез по каждому Skill, в порядке: сначала механизмы с копиями и противоречиями, затем остальные;
- раздел «Ход прохода» — таблица Skills в порядке синтеза со статусом «не начат», «идёт», «внесён <дата>»; её правит диспетчер синтеза тем же коммитом, что результат прохода по Skill. По ней слово «синтез каталога» находит, с какого Skill продолжать.
Как сессия выбирает, какую часть Skill брать: часть — это кластер из списка карты для этого Skill; порядок — по списку; Skill — первый со статусом «не начат» в «Ходе прохода». Порядок Skills по умолчанию — ниже.
Сам исполнитель карты Skills не правит и новый текст не пишет: карта — вход для шагов С1–С7.

К2. **Синтез по одному Skill.** Для каждого Skill по карте — шаги С1–С7: исполнитель высокого класса пишет, другой исполнитель высокого класса раскладывает и проверяет. Копии механизма в чужих Skills заменяются ссылкой на дом тем же проходом. Стиль Skill сохраняется по подписи из карты (у каждого Skill свой стиль — предпочтение Андрея 2026-09-17): стиль — одно из средств, которым модель различает Skills, поэтому писатель не приводит Skills к одному языку.

К3. **Ведение карты.** Карта правится тем же коммитом, которым синтез переносит механизм в другой дом или снимает копию. Карта, разошедшаяся с Skills, хуже отсутствия карты, поэтому новая карта по слову «синтез каталога» пишется заново, а не досматривается.

Порядок Skills на первый проход — по росту и по числу копий из карты; первыми, по замеру 2026-10-18, `second-brain-git` и `second-brain-engineer` (каждый прибавил бы около 17 КБ по пакету харвеста), затем `n8n-engineering-manual` и `apps-script-sheets`. Проход делается частями — по Skill за сессию — и не должен укладываться в одну неделю.

Оценка цены первого прохода — оценка, не замер: карта — одно чтение всего каталога, около 1 МБ текста; синтез и проверка — по два исполнителя на Skill, одиннадцать собственных Skills. По пилоту (проверка раздела в 15 КБ за два круга — около 164 тысяч токенов) порядок величины всего прохода — несколько миллионов токенов.
