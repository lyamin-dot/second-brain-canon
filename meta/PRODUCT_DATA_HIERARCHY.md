# Иерархия таблиц товарных данных (Liqui Moly, Ozon, Wildberries)

Читатель: любая сессия любого проекта, которой нужен список товаров, их ключи или номера деклараций. Мастер-промпт проекта для этого не нужен: файл самодостаточен. Решение Андрея от 2026-10-02, подтверждено 2026-10-06. Обоснование — Google Doc DESIGN_единая_модель_данных_товара (1hhO6Vd5WNNmxzPfIEvvcfWeaehf0ns0FdI6imSrpNVM, 2026-10-02). Состояние описано на 2026-10-06. Ведёт лаборатория ozon-ue, задача labs/ozon-ue/t-product-data-model.md. Если файл расходится с живой таблицей, прав таблица, а расхождение записывается в эту задачу.

## 1. Главное правило

Список товаров и связь «наш артикул → номера Liqui Moly → SKU Ozon → nmID Wildberries → номер декларации» читается из ОДНОЙ таблицы: Price Master (1mntwAaplJSn3bHczqGDrzmBjotrsHe3MZ78ChViCDVk), лист Artikel. Ключ товара — наш артикул (число из 4 и более цифр). Другие копии этой связи источником не являются.

4а. СВОЙСТВА АРТИКУЛА (введено 2026-10-08 по решению Андрея): лист ARTIKEL_PROPS в Price Master, ключ sku, одна строка на артикул. Ручные колонки, робот их не трогает: okpd2, okpd2_src (откуда взято значение), note. Роботные колонки пишет воркфлоу «ARTIKEL_PROPS — Build (manuell)» jEYQtwSxCEF0Swiv (вручную, прогон 77063, 459 строк, дублей нет). Состав kiz_* — наблюдение 2026-10-08 по листу «Проблемы карточек WB 2026-10-08» (только карточки с проблемами; у остальных пусто); 37 артикулов из наблюдения в Artikel нет (1937–1939, 3000-е, 3100-е, 3200-е, 3 не-LM) — в лист не вошли. Okpd2 реальных значений пока нет: нужна таблица поставщика или ключ Нацкаталога ЧЗ.

## 3. Колонки Artikel

A sku (наш артикул, ключ), B wb_nm_id, C wb_barcode, D ozon_product_id, E ozon_sku, F LM_ID_1, G LM_ID_2, H product_name, I wb_last_seen, J offer_id, K name, L wb_card (nmID из WB_Cards_Staging), M wb_decl_no (номер декларации в карточке WB), N status («продаётся», если есть SKU Ozon или карточка WB). Колонки A–N читают роботы: посреди них колонки не вставлять и не переставлять. O:S — ручная вставка старого снимка Ozon, не трогать. Чтение из n8n: узел Google Sheets читать с диапазоном A:N. В O:S те же заголовки sku, ozon_sku, name, offer_id, ozon_product_id, и по записи задачи от 2026-10-03 они подменяют колонки A–E, J, K. Список в O другой: 387 строк против 459 в A, порядок иной, 74 артикула из A в нём нет (чтение 2026-10-07). Строка 2 — описания колонок, а не данные: брать строки, где sku — число из 4 и более цифр. Названия колонок отличаются от MASTER_MAP: our_sku → sku, lm_id_1 → LM_ID_1, lm_id_2 → LM_ID_2; wb_nm_id и ozon_sku называются так же. X lm_decl_no (декларация по номеру Liqui Moly из LM_DECL) и Y wb_decl_check (совпадает ли номер в карточке WB) добавил Андрей.
## 4. Правила чтения

- Склеивать данные по ключу «наш артикул», не по номеру строки. 2026-10-06 прогон 76252 показал артикул 1000 с LM_ID_1 = 1015 вместо 1340, а причину не удалось доказать; позиционная склейка двух цепочек IMPORTRANGE допускает такой сдвиг. Колонки F:G Artikel с 2026-10-06 (правка Андрея) берутся по ключу.
- Ошибка и пустая ячейка не данные. #N/A в wb_nm_id не значит «карточки нет» (см. раздел 5).
- Изменять таблицы можно только с явного «да» Андрея. Действующую декларацию в карточке не заменять: заполняются только пустые и просроченные. Даты в карточках WB — ММ-ДД-ГГ (01-27-27 = 27.01.2027).

## 5. Известные ограничения на 2026-10-06

1. wb_nm_id (B) с 2026-10-07 берётся из колонки L, а при пустом L — по продажам WB (sku_cost); формулу правил Андрей, она прочитана 2026-10-07. До правки в B было 106 ошибок #N/A, после — ноль, у всех 422 строк с L значение B равно L (чтение 2026-10-07). Пример: 1404 — 1244813140 (магазин Кипарис), раньше в B стоял старый 564242876. Пустой B у 36 строк: у них нет карточки WB (среди них 1180, только кабинет ИП). Слабое звено запасного пути: у артикула 1744 из продаж пришёл nmID 504368536 при пустом L. Гипотеза (не проверена): номер мёртвый. Проверить: есть ли такая карточка в кабинете WB. Решение Андрея 2026-10-07: запасной путь оставить; вернуться к вопросу перед переводом первого читателя на Artikel и после проверки карточки 504368536.
2. Кабинеты ИП вне накопителей. Товар, который есть только в кабинете ИП (пример: 1180, внесён 2026-10-06), получает от Справочника номера Liqui Moly и название, но SKU Ozon, nmID и карточка у него пусты, а статус (N) «не продаётся» неверен. Отдельный воркфлоу только на чтение для кабинетов ИП не сделан.
3. Номера Liqui Moly без строки в LM_DECL (сверка 2026-10-06, посредник): 5 значений LM_ID_1 нет в article_1 (3 из них есть в article_2) и 13 значений LM_ID_2 нет ни там, ни там. Список брать свежим чтением.

## 7. Как появляется новый артикул

Андрей вносит строку в Справочник. За минуты номера Liqui Moly и название приходят в Акт.цена, sku_cost и Artikel (2026-10-06 проверено на 1180: F = 2326, G = 8064). SKU Ozon и nmID WB появляются, когда на площадке есть карточка и отработал ночной или утренний робот (только кабинеты без ИП, см. 5.2). Новые номера Liqui Moly дописывает в LM_DECL робот LM_DECL Intake (qKgc8hhOLwehejYp, 05:30 по Москве, по индексу лаборатории ozon-ue).
