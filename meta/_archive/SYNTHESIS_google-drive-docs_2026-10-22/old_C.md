### 2.2 ПРАВИЛА ЧТЕНИЯ ЧЕРЕЗ MCP

ЗАКОН РАЗДЕЛА (он же дом правил пунктов 3, 5, 6 и полноты обхода в §2.3). Ответ инструмента чтения или поиска доказывает только то, что вернул этот вызов. «Пусто», «не найдено», «найдено N» и число из метаданных не доказывают ни что объекта нет, ни что он пуст, ни что список полон, ни каков размер: тихий отказ инструмента выглядит так же, как настоящий ответ. Утверждение об отсутствии, пустоте, полноте или размере делается только по признаку, который его действительно проверяет (пункты ниже), иначе — «неизвестно». Общий стандарт утверждения об отсутствии для любого носителя — second-brain-engineer, «Утверждение об отсутствии».

1. **Старые имена инструментов.** google_drive_fetch — прежний инструмент чтения; он давал пустой ответ без ошибки на крупных и растущих файлах. В нынешнем коннекторе его нет; его место занял read_file_content, и на него действует запрет §0 п.2 с единственным исключением для отчётов вики. Основание: 2 случая, последний 2026-07-23 — отчёт синтеза, правило D.2.2.1.

2. **РАЗМЕР НЕ ОПРЕДЕЛЯТЬ ПО fileSize из get_file_metadata.** Для нативных Google Docs fileSize отражает внутреннее представление, а не размер экспортируемого текста. Соотношение на кириллице зависит от единицы: в байтах UTF-8 экспорт ≈ 3× fileSize (замеры 2,81–3,20), в символах ≈ 2× (замеры 1,84–2,03). Число без единицы ошибается вдвое.
   Не путать: «экспорт ≈ 3× fileSize» без единицы — верно только для байтов; для символов ≈ 2×.
   contentSnippet и fileSize из метаданных — кеш, для проверки содержимого непригодны. Рабочий способ узнать размер — gdocs-read с `fromLine:1, toLine:1` (§3.5): он возвращает `byteLength` и `totalLines` всего документа при одной строке текста в ответе (цена такого вызова — полный документ в контексте, §3.5).
   Основание: 2 случая, последний 2026-10-12 — отчёт синтеза, правило D.2.2.2.

3. **ПУСТОЙ РЕЗУЛЬТАТ ЧТЕНИЯ = СТОП.** Явно сообщить «чтение вернуло пусто» и остановиться. ЗАПРЕЩЕНО отвечать реконструкцией по памяти. Почему: тихий отказ инструмента плюс правдоподобный ответ модели поверх него неотличимы от лжи.
   Одно исключение, и оно проверяемо числом: `gdocs-read` с `fromLine` больше `totalLines` возвращает `success:true`, `text:""`, `returnedChars:0` и заполненный `totalLines`. Документ при этом прочитан целиком и корректно — пуст только запрошенный срез. Различать по паре `fromLine` против `totalLines`, а не по одному `text` (E19). Всё прочее пустое чтение остаётся стопом.
   Основание: 2 случая, последний 2026-07-23 — отчёт синтеза, правило D.2.2.3.

4. **Байтовый релей через контекст сессии портит символы.** Передача байтов через контекст (base64 из одного инструмента → декодирование в другом) портит символы начиная примерно с 20–25 КБ. Для сверок и обратного чтения брать второй независимый путь чтения (gdocs-read), а хеши и контрольные суммы считать на стороне (Apps Script, сервер), не через контекст. Основание: случай не записан — отчёт синтеза, правило D.2.2.4.

5. **Пустое чтение файла, в который в этой же сессии идёт активная запись**, может быть гонкой чтения и записи и неотличимо от прочих тихих пустых ответов. Не читать файл во время активной записи в него; при подозрении на гонку — подождать и перечитать. Основание: случай не записан — отчёт синтеза, правило D.2.2.5.

6. **Файл в Корзине Drive (Trash)** на всех путях чтения — get_file_metadata, search_files, gdocs-read — отвечает «not found» или пусто, одинаково с «не существует» и с «не расшарен на сервисный аккаунт»; программно эти случаи не различить. Если объект должен существовать, но не находится нигде, — проверить Корзину вручную в интерфейсе Drive.
   Граница правила: оно действует, только когда файл ДОЛЖЕН существовать. Если цель действия — отсутствие файла (перенос в Корзину, удаление, снятие доступа), «not found» после действия — достигнутый результат, а не отказ: Корзину не проверять и владельца не спрашивать, достаточно назвать в отчёте, какой ответ получен и каким инструментом.
   Основание: 2 случая, последний 2026-10-11 — отчёт синтеза, правило D.2.2.6.

7. **ЦЕНА ПОЛНОГО ТЕКСТА PDF.** `read_file_content` по PDF приносит в контекст весь текст файла: статья среднего размера (PDF около 1,5 МБ) заняла около 25 000 токенов — почти весь допустимый объём одного результата инструмента. Поэтому полный текст PDF читается только прицельно — когда нужно содержание именно этой статьи. Для обхода и описи многих файлов (тип, тема, годится ли) хватает имени, размера и метаданных (get_file_metadata, search_files с `excludeContentSnippets: true`); массовую механическую работу — опись папок, нарезку текста — делает скрипт в среде с bash, а не модель вызовами коннектора по одному файлу. Основание: 1 случай, последний 2026-09-25 — отчёт синтеза, правило D.2.2.7.

### 2.3 search_files

**Синтаксис запроса.** `title contains 'x'`, `title = 'x'`, `fullText contains 'x'`, `parentId = 'ID'`, `mimeType = '…'`, `modifiedTime > '2026-09-01T00:00:00Z'`, `owner = 'me'`; строки — в одинарных кавычках; условия соединяются `and`, `or`, `not`.
Не путать: прежнее имя инструмента — google_drive_search, и его синтаксис (`name contains`, `'ID' in parents`) в нынешнем коннекторе не действует.
Основание: 1 случай, последний 2026-09-26 — отчёт синтеза, правило D.2.3.1.

**Объём ответа.** По умолчанию каждая найденная запись несёт отрывок текста до примерно 5 000 знаков. Когда нужен только ID или список файлов — `excludeContentSnippets: true`; когда отрывок нужен — `snippetVerbosity: "BRIEF"` (около 1 000 знаков). Отрывок — кеш индекса, для проверки содержимого не годится (§2.2 п.2). Основание: 1 случай, последний 2026-09-26 — отчёт синтеза, правило D.2.3.2.

**Свежий не-native файл не находится сразу.** Свежесозданные PDF и бинарные файлы появляются в поиске с задержкой индексации — искать их get_file_metadata по ID или search_files по parentId. Пустой ответ search_files ≠ «файла нет» (§7). Основание: случай не записан — отчёт синтеза, правило D.2.3.3.

**ПОЛНОТА ОБХОДА.** Обход папки или список файлов считается полным, только если части, которые не открылись (подпапки, страницы ответа, файлы с ошибкой), перечислены явно и этот перечень пуст. Отсутствие перечня — не «ничего не пропущено», а «неизвестно, что пропущено».
Почему: неполный список, записанный как полный, дальше выглядит полным для всех читателей. Признак: опись меньше, чем видно в интерфейсе Drive, а отчёт обхода не называет ни одной неоткрывшейся части.
Для своих скриптов и воркфлоу обхода отсюда два требования: неоткрывшиеся части выводятся отдельным списком; оборванная на середине пагинация (ответ с признаком следующей страницы, которую не прочитали) роняет прогон, а не превращается в предупреждение в тексте отчёта. Ответ `search_files` сам по себе перечня неоткрывшегося не несёт, поэтому «пусто» и «нашлось N» от него — не доказательство полноты (§7). То же правило для пагинации внешних API в воркфлоу — n8n-engineering-manual, references/engine.md §4.9.
Основание: 1 случай, последний 2026-09-27 — отчёт синтеза, правило D.2.3.4.

## 5. RCLONE — бэкапы

Где, чем и по какому расписанию бэкапится база n8n этого инстанса и в каком состоянии бэкап сейчас — не в Skill: это факт сервера, его носитель — канон сервера; пока он не записан, — задачи `labs/sys/t-server-knowledge.md` и `labs/sys/t-n8n-backup-stopped.md`. Правила ниже верны для любого бэкапа в Google Drive.

- **Бэкап в том же Google-аккаунте, что и оригиналы, потерю аккаунта не переживёт.** Успешное учение восстановления этого не меняет: оно проверяет копию, а не её независимость от аккаунта. Шаг 0 любого восстановления — убедиться, что свежий бэкап есть (файл моложе суток, проверенный по дате создания и размеру), и знать, кто и где его делает.
- **apt-пакет rclone может быть собран без backend Mega** — ставить официальным install-скриптом и фиксировать версию.
- **Общий client_id rclone Google планово выводит из обращения** — для remote Google Drive использовать собственный client_id, иначе бэкапы молча остановятся. Признак: `rclone config show <remote>:` — пустые client_id и client_secret значат, что используется общий client_id (под угрозой); заполненные значения или сервисный аккаунт — не касается.

Основание:
- бэкап в одном аккаунте — 1 случай, последний 2026-07 (день в источнике не записан) — отчёт синтеза, правило C.5.1;
- Mega и client_id — без адреса вне Skill, отчёт синтеза, правило C.5.2.
