## Р15. Провенанс и верификация — единый стандарт

**ЗАКОН.** Утверждение верно только для того чтения объекта, из которого оно взято. Всё, чего сессия не прочитала в самом объекте, — память, пересказ или старая запись, и решение на этом не принимается: объект читается до решения, либо утверждение пишется словами «Гипотеза (не проверена):». 3. Три уточнения закона для чисел:
- Число в критерии приёмки, в контракте работы и в ожидаемом результате проверки — тоже число в канон: его выводят чтением объекта до того, как критерий записан, и рядом называют чтение, из которого оно взято.
- Число о живом файле или документе, в который пишут и другие (размер, число строк, число записей), пишется вместе с отметкой версии чтения — blob sha для файла репозитория, checkSum ответа gdocs-read для документа Google. Критерий приёмки по такой величине — соотношение, проверяемое на свежем чтении в момент приёмки («зона не выросла», «добавилась ровно одна запись»); абсолютное число — только база для сравнения.
- Дата записи — в журнале, в имени файла, в поле «создан» — берётся из инструмента текущего времени, из даты, которую харнесс сообщил в контексте сессии, или из ответа инструмента (время старта исполнения n8n, createdTime ответа Drive), а не из памяти модели.
4. Конкретика (ID, пороги, версии) берётся из реестра в момент использования, а не из текста задания; в задания пишутся правила поведения при неизвестном, а не факты. Перед пакетной операцией — манифест реальных объектов, полученных чтением в этой сессии.
5. Запись верифицируется только независимым перечитыванием, один стандарт для обоих носителей: Docs — gdocs-read, счёт вхождений якоря или совпадение текста; repo — `second-brain-git` 8.1 (в среде с клоном `git fetch` и `git hash-object`, без клона — один вызов Git Read Lines с pattern по первой строке записанного); blob sha записанного равен sha намеренного. `success: true`, `occurrencesChanged`, номер исполнения, ответ инструмента — сигналы, не доказательства.
6. Расхождение факта с ожиданием — стоп и вопрос, не тихая правка. Опровергнутая причина не стирается, а сохраняется рядом с исправлением блоком ИСТОРИЯ ДИАГНОЗА (`core/R-06a.md`, пункт 0.4.1).
