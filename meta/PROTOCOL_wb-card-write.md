# Как исправлять карточки WB через API — порядок работы

Версия для человека. Копия для агента на английском — `meta/PROTOCOL_wb-card-write.en.md`; содержание одно и то же, при правке менять оба файла. Введено 2026-10-09 по задаче Андрея; решения — журнал `projects/deklaration-wb/LOG.md`, записи Р-7, Р-11, Р-12.

## 1. Что считается правильным значением (источники истины)

| Поле карточки WB | Номер характеристики WB | Откуда брать правильное значение |
|---|---|---|
| Номер декларации соответствия | 15001135 | Сайт Liqui Moly: лист LM_DECL книги LM_DECL_MASTER. В книге Price Master это колонка X листа Artikel и колонка E (ref_decl) листа WB_Compare. |
| Дата регистрации декларации | 15001137 | Лист «Декларации» книги LM_DECL_MASTER, колонка date_from. |
| Дата окончания декларации | 15001138 | Тот же лист, колонка date_to. Просроченную декларацию в карточку не писать. |
| ТН ВЭД | 15000001 | Выписка декларации. Эталон по артикулу — лист ARTIKEL_PROPS книги Price Master, колонка N tnved_decl; колонка O tnved_decl_src говорит, откуда взят код или почему пусто (журнал `projects/deklaration-wb/LOG.md`, запись Р-13). Пусто — эталона нет, поле карточки не трогать. Колонка C tnved того же листа — НЕ эталон, это ТН ВЭД из карточки основного кабинета. |
| ОКПД 2 | 15004292 | Только документ: выписка декларации, Национальный каталог «Честного знака», импортёр. Подбор по аналогии запрещён; 2026-10-09 Андрей временно снял запрет только для 11 карточек автохимии кабинета ИП (запись Р-12). Для любых других карточек — спросить Андрея. |
| Галка «Подтверждаю, что на товар нанесена маркировка» (kizMarked) | поле карточки, не характеристика | Это заявление продавца по закону о маркировке. Ставить только по прямому слову Андрея на названные им карточки. |
| Признак «Нужна маркировка КИЗ» (needKiz) | поле карточки, только чтение | Через API его записать нельзя: WB выводит его сам из предмета, ТН ВЭД и ОКПД 2. Без ОКПД 2 WB через API признак не включает; ручная галка сотрудника в личном кабинете — включает. Правильное значение на этом этапе берётся из основного кабинета («Кипарис»), потому что там его недавно проверили руками. |

То, что сейчас стоит в карточках любого из двух кабинетов, правильным значением НЕ считается. Копировать значения из основного кабинета в кабинет ИП нельзя: в основном кабинете есть ошибки, а галка kizMarked — заявление конкретного юридического лица.

## 2. Где смотреть, что сейчас в карточках

- Лист WB_Cards_Staging книги Price Master — карточки основного кабинета; заполняет робот fGHfVrI58Ws1wfTw каждую ночь в 04:10 по Москве.
- Лист WB_Cards_Staging_IP — карточки кабинета ИП; робот vIteQxGrqI7kLkb0, 04:25 по Москве.
- Лист WB_Compare — сравнение «эталон / основной кабинет / кабинет ИП» по декларации, ТН ВЭД, ОКПД 2 и маркировке; только формулы, обновляется сам.
- Правила чтения этих листов — `meta/PRODUCT_DATA_HIERARCHY.md`, разделы 4б и 4в.

| Инструмент n8n | Когда | Как устроен |
|---|---|---|

## 4. Порядок работы

1. Составить список карточек и правильных значений по разделу 1. Значения считать по листам (WB_Compare, ARTIKEL_PROPS, лист «Декларации»), а не по памяти.
2. Отдельно выписать спорные случаи: эталона нет; эталонная декларация просрочена; два источника расходятся (например номера Liqui Moly нет в перечне декларации на листе «Декларации», хотя LM_DECL указывает эту декларацию); на карточке стоит другая действующая декларация.
3. Вписать строки в 01_Params, режим «проверка», запустить. Проверить ответ узла 03_Build: сколько карточек найдено, пуст ли список problems, что именно уйдёт в каждую карточку (поле report: «было → станет»).
4. Показать сводку Андрею вместе со спорными случаями. Писать — только после его согласия.
5. Перевести в режим «запись», запустить. Посмотреть узел 06_Report: статус каждой пачки. Ответ WB 200 с пустой ошибкой — принято в обработку. Ответ 400 или 500 «Internal server error» бывает случайно — повторить только упавшие пачки через ONLY.
6. Вернуть mode в «проверка» и очистить ONLY. В 01_Params дописать номера исполнений.
7. Проверить результат на СЛЕДУЮЩИЙ день по листам WB_Cards_Staging_IP и WB_Compare после ночного робота. WB применяет правки кабинета ИП с задержкой в часы: чтение через 45 секунд и даже через 4 минуты ещё показывает старую карточку — это не отказ.
8. Записать решение и итог в журнал проекта (`projects/deklaration-wb/LOG.md`), следующий шаг — в `STATE.md`.

## 5. Ловушки

- Полная перезапись карточки стирает ОКПД 2, введённый сотрудником в личном кабинете: API такой ОКПД 2 не показывает, значит инструмент его не передаст, и вместе с ним у карточки может слететь «нужен КИЗ». Так 07.10 потеряли КИЗ 29 карточек основного кабинета. Карточки основного кабинета из предметов «Автохимия» и «Смазки автомобильные» без ОКПД 2 из документа не перезаписывать.
- Запись ОКПД 2 из перечня обязательной маркировки может включить needKiz. Если продавец не зарегистрирован в «Честном знаке» по этой товарной группе, WB заблокирует карточку. Так были заблокированы моторные масла кабинета ИП 08.10.
- WB при каждой записи декларации создаёт документ заново (новый id). Промежуточный вердикт документа, например supplier_not_registered, может смениться на ok через несколько часов.
- Значения характеристик передаются массивом строк: например ["3403990000"], ["01.06.2026"].
- В карточке, где характеристик мало (у 1053 их две), инструмент передаёт только то, что есть: недостающие характеристики он не придумывает.
