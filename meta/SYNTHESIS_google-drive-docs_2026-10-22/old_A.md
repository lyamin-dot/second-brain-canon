## 3. N8N — ЗАПИСЬ И ЧТЕНИЕ GOOGLE DOCS

Закон раздела: инструменты gdocs-* и gsheets-* — воркфлоу n8n, и сессия видит их только через MCP-сервер n8n; всё, что этот путь не показывает, считается неизвестным, а не успешным. Общая механика вызова живёт в n8n-engineering-manual, §1.1; здесь — то, что нужно для вызова инструментов Google без открытия того Skill.

**Вызов — только `n8n:execute_workflow`, никогда curl или bash.** Почему: egress-прокси облачной сессии блокирует домен инстанса. Основание — n8n-engineering-manual, §1.1, правило §1.1.0.

**Форма вызова:** параметр `triggerNodeName` — точное имя узла-триггера этого воркфлоу, плюс `inputs: {webhookData: {method: "POST", body: {…поля инструмента…}}}`; для воркфлоу с формой — `inputs: {formData: {…}}`; поля `type` внутри `inputs` нет. Имя триггера у каждого воркфлоу своё — его не угадывают, а берут из `get_workflow_details` или из сигнатуры в `registry/tools.md`; вызов с неверным именем безвреден: сервер отвечает ошибкой со списком доступных триггеров. Тексты ошибок старой формы и правило «верить ответу сервера, а не описанию инструмента в клиенте» — n8n-engineering-manual, §1.1. Поля `body` каждого инструмента — его контракт в §3.1–3.6, §4.0, §4.0а.
Основание: 2 случая, последний 2026-10-09 — отчёт синтеза, правило A.3.3.

**Метод POST указывается явно, поле называется `inputs`, а не `data`.** Почему: по умолчанию инструмент ставит метод GET; с полем `data` тело не доезжает до воркфлоу. Признак: разбор входа в воркфлоу падает на отсутствии обязательного поля («Missing fileId»), а MCP при этом отвечает `{"status":"started"}` — тихий отказ, который выглядит как ошибка параметров, а не формы вызова.
Основание: 1 случай, последний 2026-09-08 — отчёт синтеза, правило A.3.4.

**`executionMode` — обязательный параметр; ответ инструмента виден только в `manual`.** Запуск в `production` исполняет опубликованную версию асинхронно: тело ответа не возвращается, исполнение не видно в `get_execution` и `search_executions`, поля `success`, `reason`, `context` наблюдаемы только в ручном режиме и в запуске с закреплёнными данными (pinData) — то есть при отладке. Поэтому в бою запись проверяется только обратным чтением целевого файла через gdocs-read (§7). Какую версию воркфлоу исполняет ручной запуск — n8n-engineering-manual, references/roots.md, правило R2.3.
Основание — n8n-engineering-manual, §1.1, правило §1.1.2.

**Имена полей `body` — не косметика: каждый инструмент получает поля точно по своему контракту.** Почему: инструмент, не проверяющий вход, получив текст в поле с другим именем, отправляет в Google запрос с пустым телом — файл молча затирается пустотой. Признак: `modifiedTime` обновлён, файл пуст. Инструменты v2 от этого защищены — при отсутствии нужного поля они отказывают с ошибкой; старая версия overwrite ждала поле `newContent` и на поле `text` затирала файл.
Основание: 1 случай, дата в источнике не записана — отчёт синтеза, правило A.3.2.

**Текст крупнее примерно 1–2 КБ через тело вызова gdocs-append, gdocs-replace или gdocs-overwrite v2 не передавать** — причина, порядок путей и сверка стыков порций: §3.0 (`references/docs-write.md`).
