Этот этап предшествует этапу триажа (Ш3 ниже) и обязателен до его начала.

Три шага:

1. **Перечислить.** Составить сплошной перечень всех разделов документа-источника по номерам — без выборки и без пропуска. Список должен покрывать источник целиком от первого раздела до последнего.
2. **Классифицировать.** Каждому разделу из перечня присвоить ровно одну метку:
   - «переезжает» — раздел переносится в целевой файл (полностью или в виде смысла, извлечённого по правилам Ш3);
   - «архив/невзятое» — раздел заведомо не переезжает, попадает в раздел невзятого (Ш3-список);
   - «неприменимо» — раздел не подпадает ни под одну из двух меток выше (например, служебный, пустой или технический раздел источника).
3. **Подтвердить счётом.** Явно подтвердить закрытие списка равенством: N разделов найдено = N разделов классифицировано, 0 разделов без метки. Это равенство — обязательное предусловие: перенос содержимого (Ш3) не начинается, пока счёт не сошёлся.

## Алгоритм триажа [источник: раздел 3, утверждён Андреем 2026-09-01]

Единица — блок (правило, Р-запись, наряд, секция), не строка.
Шаг 0. Инвентаризация: каждому блоку ID, источник, байты; сумма байтов каталога сходится с byteLength источника — блок вне каталога есть дефект инвентаризации, не мусор.
Шаг 1. Классовый фильтр: НЕРУШИМОЕ → ЗОЛОТО автоматически; СЛЕД → АРХИВ автоматически (ссылка едет с правилом, тело следа в архиве); ДОГОВОРЁННОСТЬ → шаг 2.
Шаг 2. Тест читателя и триггера, оба по объекту: Q1 ЧИТАТЕЛЬ — какая сессия по какому протоколу доходит до блока (назвать протокол); Q2 СЛЕД ПРИМЕНЕНИЯ — применялся ли блок с 19.07 (CHANGELOG, наряд, аудит, детектор). Q1да+Q2да → ЗОЛОТО. Q1да+Q2нет → КАНДИДАТ (решает Андрей). Q1нет → АРХИВ.
Шаг 3. Дедупликация: блок, покрытый другим золотым блоком или Skill → ШУМ с пометкой «дубль T-NNN».
Шаг 4. Выходной артефакт: каталог ID | источник | байты | класс | Q1 | Q2 | вердикт | основание. Контроль: сумма байтов по вердиктам = байты источников. Андрей утверждает каталог целиком и решает КАНДИДАТОВ.
Слабое место алгоритма: Q2 зависит от полноты CHANGELOG (12 ложных самоотчётов августа) — поэтому Q2 в одиночку ничего не хоронит, только понижает до КАНДИДАТА.

## Перенято из PLAN_slotdatesleep [источник: раздел 10, v0.2 2026-09-01]

10.1 Экзамен Контролёра: до триажа документа read-only Контролёр (отдельная сессия) составляет из оригинала 7 вопросов (5 «что сессия обязана знать на старте» + 2 намеренно по материалу-кандидату на отсев), запечатывает в файл. Триажёр вопросов не видит. Приёмка переноса: чистая сессия отвечает только по новому канону, порог 6/7 и не хуже оригинала более чем на 1. Оговорка по находке 14.1(г) (см. `projects/git-migration/STATE.md`, уточнение 14.1(г)): гейт непригоден, когда вопросы опираются на материал, чей живой носитель — Skill, а сам экзамен даётся сессии без доступа к Skills.
10.2 Дата смерти: каждая фаза получает календарную дату вердикта при выдаче наряда. Нет вердикта к дате = провал фазы, запись Т-NN, не продление.
10.3 Квитанция машиной: перенос по-файлово; квитанция файла = независимый git-read + сверка SHA (не самоотчёт сессии). Байтовая сверка по каталогу как доказательство целостности из этого пункта исключена запретом Б-1 (`projects/git-migration/PLAN.md` §7) — держится только проверка по SHA. Нет квитанции — следующий файл не стартует.
10.4 Адрес восстановления: каждый блок с вердиктом АРХИВ/ШУМ несёт в каталоге адрес восстановления (замороженный Docs + позиция). Ноль «неизвестно» — условие утверждения каталога.
10.5 Лимит вне агента: потолок размера канона — параметр git-write гейта в n8n, недоступный сессии. Сессии запрещено предлагать поднятие потолка; каждое предложение считается (метрика дрейфа).
10.6 Правило золотого файла: одна формулировка на факт, актуальная формулировка последней в блоке, атомарные строки.
Не перенято: слоты/TTL/ночной компактор/resurfacing (механика суждения агента о судьбе данных — причина смерти исходного плана); ревизии Docs как приёмник (заменены git-историей).
