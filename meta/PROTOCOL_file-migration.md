## Алгоритм триажа [источник: раздел 3, утверждён Андреем 2026-09-01]

Единица — блок (правило, Р-запись, наряд, секция), не строка.
Шаг 0. Инвентаризация: каждому блоку ID, источник, байты; сумма байтов каталога сходится с byteLength источника — блок вне каталога есть дефект инвентаризации, не мусор.
Шаг 1. Классовый фильтр: НЕРУШИМОЕ → ЗОЛОТО автоматически; СЛЕД → АРХИВ автоматически (ссылка едет с правилом, тело следа в архиве); ДОГОВОРЁННОСТЬ → шаг 2.
Шаг 2. Тест читателя и триггера, оба по объекту: Q1 ЧИТАТЕЛЬ — какая сессия по какому протоколу доходит до блока (назвать протокол); Q2 СЛЕД ПРИМЕНЕНИЯ — применялся ли блок с 19.07 (CHANGELOG, наряд, аудит, детектор). Q1да+Q2да → ЗОЛОТО. Q1да+Q2нет → КАНДИДАТ (решает Андрей). Q1нет → АРХИВ.
Шаг 3. Дедупликация: блок, покрытый другим золотым блоком или Skill → ШУМ с пометкой «дубль T-NNN».
Шаг 4. Выходной артефакт: каталог ID | источник | байты | класс | Q1 | Q2 | вердикт | основание. Контроль: сумма байтов по вердиктам = байты источников. Андрей утверждает каталог целиком и решает КАНДИДАТОВ.
Слабое место алгоритма: Q2 зависит от полноты CHANGELOG (12 ложных самоотчётов августа) — поэтому Q2 в одиночку ничего не хоронит, только понижает до КАНДИДАТА.

10.5 Лимит вне агента: потолок размера канона — параметр git-write гейта в n8n, недоступный сессии. Сессии запрещено предлагать поднятие потолка; каждое предложение считается (метрика дрейфа).
10.6 Правило золотого файла: одна формулировка на факт, актуальная формулировка последней в блоке, атомарные строки.

## Этап 0в: правила переноса задач Зоны А

1. Поля задачи «условие готовности» («Готово = …»), «метка приоритета», «дата», «идентификаторы» переносятся дословно из источника. Поля в источнике нет — прочерк; вывод даты из номера наряда или из соседних строк ЗАПРЕЩЁН. Дословность доказывается, а не заявляется: поле помечается в файле задачи как цитата, и приёмка сверяет его подстрокой в тексте источника после нормализации пробелов и кавычек. Помечено цитатой и подстрокой не совпало — искажение; не помечено — пересказ, и тоже искажение. Абзац источника переносится до своего конца: если блок продолжается за строкой, названной в наряде, продолжение либо едет в цель, либо получает строку в NOT_TAKEN.md с адресом. Формула «перенесена строка N» хвост блока не покрывает. (П-1 Контролёра, Р-75)
2. Основание снятия обязано содержать цитату той строки источника, из которой снятие следует. Основание из другой строки или из решения владельца называется адресом: номер строки либо «решение владельца, дата».
3. Строка, заканчивающаяся не терминальным знаком и не маркером, продолжается следующей строкой: gdocs-read разрывает длинные строки. Вердикт «строка оборвана, содержания нет» ЗАПРЕЩЁН, пока не прочитана следующая строка.
4. Право 13.2 Skill чинить ссылки, заголовки и разрывы фраз на поля п. 1 не распространяется.
5. Две задачи об одном предмете снимаются только по собственному тексту каждой; снятие одной «как дубля» другой при одновременном снятии второй ЗАПРЕЩЕНО (прецедент: строки 315 и 354). Объединение двух задач источника в один файл ДОПУСКАЕТСЯ; тогда строка INDEX.md несёт метку и дату каждой из них через запятую, а файл задачи называет обе строки источника. Одна метка на объединённый файл — потеря метки второй задачи. (П-3 Р-75)
6. Идентификатор источника — Drive fileId, ID воркфлоу n8n, номер Р/Т/Н, ссылка вида «CORE Р.N» — переносится в файл задачи как есть. Замена идентификатора указателем на файл репозитория («инструменты Канала — registry/tools.md») ДОПУСКАЕТСЯ только вместе со строкой в NOT_TAKEN.md, называющей сам идентификатор и его адрес в источнике. Без такой строки замена есть потеря: 13.4(а) Skill требует найти идентификатор либо в цели, либо в NOT_TAKEN.md и третьего места не знает. (П-2 Р-75)
7. Метка приоритета в INDEX.md берётся только из источника. Маркер, не являющийся меткой приоритета (ЗАХВАЧЕНО, ДЕФЕКТ и прочие), в метку не переводится: метки нет — прочерк по пункту 1. Присвоение метки по оценке исполнителя ЗАПРЕЩЕНО, в том числе когда прочерк в таблице выглядит незаполненным полем. (П-4 Р-75)
