## 1. Skill naryad — заменить целиком

Новый текст: `meta/EDITS_skills_2026-11-10/naryad/SKILL.md`. Заливка — архив через Customize → Skills. Названия разделов, на которые ссылаются другие Skill и протокол харвеста, сохранены: «Роли», «Стоп-правила» (подразделы «Роли и шина», «Выдача (Руководитель)»), «Форма наряда», «Поле ГДЕ», «Поле МОДЕЛЬ», «Приём наряда», «Проверка перед выдачей», «Паспорт стоимости», «Пересмотр Skill».

Что изменилось и что убрано — решение по каждому пункту за Андреем:
1. Убрано правило «Андрей — шина»: Андрей переносит только наряд, возврат через канон.
2. Убрано «Руководитель не вызывает инструменты» и роль Прораба с дочерними нарядами .1 .2: раздачу внутри наряда ведёт диспетчер пакетами К1, К2.
3. Убрано дерево поля ГДЕ по контексту Claude Project и ОСНОВАНИЕ ГДЕ: умолчание — Claude Code на компьютере, другое значение — по признаку.
4. Убрано поле ТРЕБУЕТ: на его месте проба среды при приёме, поля РАЗРЕШЕНО и МЕХАНИКА. Это закрывает вопрос позиции AJ-78 (с 22.10 ни одного отказа по ТРЕБУЕТ): поле не работало.
5. Поле МОДЕЛЬ больше не адресовано Андрею: оно называет класс диспетчера, модели помощников выбирает диспетчер.
6. Маршрут шага сокращён с пяти вопросов до четырёх: вопрос о стоимости шага против накладных наряда заменён признаком 4 точки перехода («пакетов не меньше трёх»).
7. Сняты потолки «не больше пяти открытых корневых нарядов» и «глубина раздачи 1»: при одном наряде на точку перехода они не работают; глубина помощников ограничена в avtopilot.
8. Журнал хода и остановка по перерасходу перенесены в avtopilot — это исполнение, а не выдача.
9. Добавлены: точка перехода с четырьмя признаками; поля ПАКЕТЫ, ОКНО, РАЗРЕШЕНО, РУЧНОЕ, СТОП, МЕХАНИКА; паспорт с новыми слагаемыми (запись по каждому объекту, круг исправлений текста) — по факту конвейера Н-09.11-07 (31 запись при прогнозе 19); раздел «Возврат и приёмка».
10. Вопросы пересмотра для харвеста заменены: прежние про ТРЕБУЕТ, push и маршрут Б по стоимости потеряли предмет; новые — про ручные действия вне списка, шину, раннюю точку перехода, столкновение параллельных пакетов.
11. Сохранено без изменения смысла: мандат на отказ, паспорт и замысел для деструктивных правок, строка позиции AJ-83 (пакет разрешения не заменяет паспорт и замысел), правила выдачи проверяющему, приёмка по объекту.

## 2. Skill avtopilot — заменить целиком

Новый текст: `meta/EDITS_skills_2026-11-10/avtopilot/SKILL.md`. Сохранены названия «Ворота 2. Ревизия», «Ворота 3. Контракт запуска», «Ворота 4. Исполнение — Андрея нет», «Ворота 5. Приёмка и отчёт».

Что изменилось — решение за Андреем:
1. Два входа: наряд из чата (начинается с ворот 4) и прямое слово «автопилот» (ворота 1–3 здесь).
2. Правило «помощник своих помощников не запускает» заменено проверкой среды на старте: в Claude Code на компьютере вложенность работает (проба 10.11), в чате Claude Project — нет; потолок — два уровня под диспетчером.
3. Признак параллельности — общий ресурс (воркфлоу, книга, функция, файл); по отчёту исполнителя конвейера пакеты книг показа могли идти параллельно.
4. Пишущий помощник — в своей отдельной копии репозитория; оговорка: копия не отнимает право отправки в main, поэтому три способа для читающих заданий и сверка `git ls-remote` сохранены.
5. Один писатель эстафеты во время исполнения — по находке приёмщика конвейера (STATE.md распух от двух писателей).
6. Добавлено ограничение приёмщика той же модели: деньги — сверка с отчётом площадки; текст — второй круг.
7. Строка PASSPORT в новом воркфлоу — сессия сама (решение Андрея 10.11); существующий — поле РУЧНОЕ.
8. Динамический workflow — только по слову Андрея в наряде; публикация — только если наряд разрешает.
9. Ожидание: фоновые помощники сообщают о конце сами; будильники и запланированные задачи — только для ожидания на часы.
10. В итоговый отчёт добавлена строка замера: сколько раз понадобился Андрей и сколько длилась работа.
11. Не включено: правка позиции AJ-62 (перевод репозитория в приватный) — обусловлена событием, которое не наступило; в новом тексте упоминаний публичного клона нет, поэтому после перевода репозитория к avtopilot эта позиция, вероятно, не относится — проверить при переводе.

## 3. Skill n8n-workflow-passport — две точечные правки

Файл `SKILL.md`. После заливки Андрей вычёркивает строку 1 в `meta/PENDING_RULES.md`.

**Правка 1.** Раздел «Стоп-правила», подраздел «Рождение и строка PASSPORT», первая строка подраздела.

Было:
```
- Строку `PASSPORT:` в `description` существующего воркфлоу сессия через MCP не вписывает — вписывает Андрей руками в настройках воркфлоу.
```
Стало:
```
- Строку `PASSPORT:` в `description` существующего воркфлоу (созданного не этой сессией) сессия через MCP не вписывает — вписывает Андрей руками в настройках воркфлоу. В `description` нового воркфлоу, созданного этой сессией, строку вписывает сама сессия (стадия 3, пункт 5).
```

**Правка 2.** Раздел «Стадия 3. Родить паспорт», пункт 5, второй подпункт.

Было:
```
   - Воркфлоу создаётся в этой же сессии: описание держать коротким, чтобы вместе со строкой PASSPORT оно уложилось в 255 знаков, и передать его параметром `description` вызова `create_workflow_from_code`. Паспорта к этому моменту ещё нет — строку позже вписывает Андрей.
```
Стало:
```
   - Воркфлоу создан в этой же сессии: описание держать коротким, чтобы вместе со строкой PASSPORT оно уложилось в 255 знаков. Паспорта при создании воркфлоу ещё нет, поэтому строку сессия вписывает сама после создания паспорта — операцией `setWorkflowMetadata` вызова `update_workflow` (предел 255 знаков — раздел «Адреса и ловушки»); отдельного «да» Андрея это не требует: воркфлоу новый и создан этой сессией.
```
