# Перенос Skill в короткую форму — критерии и конвейер

Согласовано Андреем 2026-11-03 (критерии — в чате, решение Р-39 журнала `projects/kontext-reduktion/LOG.md`; текст этого документа — после его прочтения Андреем).

Кто читает: каждая сессия, которая переносит Skill или проверяет перенос. Читается целиком до начала работы.

## Главное

1. Ты **забираешь** из старого текста то, что подходит под критерии ниже. Ты ничего не режешь и не удаляешь.
2. Старый текст остаётся в репозитории целиком (`skills/_v1/<имя>/`). Всё незабранное там и лежит — **за незабранное ты не отвечаешь**.
3. Ты не решаешь, что ценно. Ты определяешь **тип** фразы по признаку из таблицы. Признак не подошёл — фраза идёт в список «?», и дальше её судьбу решает Андрей, не ты.
4. Потолка размера нет. Новый Skill такой длины, какой получился из забранного.

## Типы фраз

Каждая фраза или пункт старого текста получает ровно один тип.

| Тип | Признак | Что делать |
|---|---|---|
| **М. Маршрут** | «при X читай Y», «команда Z ведёт в W»; триггеры описания Skill | Забрать |
| **С. Стоп** | Запрет или обязательная проверка перед необратимым действием: запись во внешнюю систему, удаление, push, перезапись рабочего воркфлоу, деньги | Забрать одной строкой, без «почему» |
| **П. Процедура** | Шаги операции, которая есть только в нашей системе (маршрут Канала, Git Append, заливка Skill) | Забрать шагами |
| **Ф-адрес** | ID, имя книги, URL, путь — без него нельзя выполнить действие, и в реестре (`registry/*`, Skill `n8n-workflow-registry`) его нет | Забрать одной строкой. Если адрес есть в реестре — забрать только «адреса — в реестре <имя>» |
| **Ф-ловушка** | Поведение внешней системы, у которого выполнены **все три** условия: (1) операция завершилась без ошибки; (2) результат неверен — данные испорчены, потеряны или записаны не туда; (3) это противоречит документации или очевидному ожиданию | Забрать одной строкой: «X молча делает Y — проверяй Z». Если система возвращает ошибку — это не ловушка, не забирать |
| **И. История** | «почему», прецедент, номер записи журнала (Р-…, Т-…), «так было до…», «основание: …», даты решений | Не забирать |
| **О. Общее знание** | Как устроены платформа, язык, API — то, что модель знает или выяснит сама | Не забирать |
| **?** | Ни один признак не подошёл | В список «?» (ниже). Не забирать и не удалять |

Решения Андрея отдельным типом не являются. Решение, задающее, **как мы действуем** во всех проектах, переписывается в инструкцию типа М, С или П — без «Андрей решил», без даты. Решение об одном проекте — тип И.

Абзац, где смешаны несколько типов, разбирается по фразам: забирается только фраза нужного типа, остальное остаётся в архиве.

## Шаблон нового Skill

```
---
name: <как было>
description: <триггеры из старого описания; без истории>
---
# <имя>
Что это — до трёх строк.
## Что читать
| Ситуация | Файл |
## Стоп-правила
- одна строка на правило
## Как делать
<процедуры П, шагами>
## Адреса и ловушки
- Ф-адрес и Ф-ловушка, по строке
## Куда писать результат
```

Разделы без содержания опускаются. Файлы `references/` — только для процедур П, которые не помещаются в «Как делать» без потери шагов.

**Ссылки на другие Skills** — по имени Skill и заголовку раздела («`second-brain-git`, раздел „Дозапись в журнал“»), не по номеру пункта. Старые номерные ссылки других Skills продолжают разрешаться по архиву `skills/_v1/`.

## Конвейер

| # | Кто | Что | Наблюдаемый результат |
|---|---|---|---|
| 1 | Сессия | Копирует `skills/<имя>/` в `skills/_v1/<имя>/`; в начало каждого файла копии — строка «Архив до переноса <дата>. Справочник: правила здесь не действуют, действует только `skills/<имя>/`.» | Копия отличается от оригинала только этой строкой |
| 2 | Сессия высшего класса, одна на Skill | Читает старый текст целиком, размечает по типам, собирает новый `skills/<имя>/` по шаблону. Читает строку позиции очереди этого Skill, снятой по Р-39 (AJ-71, AJ-73, AJ-75, AJ-76), и забирает из неё только тип П | Новый Skill; файл разметки `skills/_v1/<имя>/TRANSFER.md` |
| 3 | Андрей | Смотрит в списке «?» только красные пункты | Ответ по каждому красному |
| 4 | Независимый агент | Ищет в архиве фразы типов С и Ф-ловушка, которые не забраны. Другие типы не проверяет | Список пропусков пуст или исправлен |
| 5 | Сессия | Две реальные задачи из недавних проектов с новым Skill — одна на Sonnet, одна на Opus | По каждой: сделана или нет; понадобился ли архив и где |
| 6 | Андрей | Заливка в Customize | Живой Skill совпадает с `skills/<имя>/` |
| 7 | Сессия, по слову Андрея | Удаление списка «?»: всё, на что Андрей не ответил «оставить», остаётся только в архиве | Строка в `TRANSFER.md`: «список „?“ закрыт <дата>» |

Пилот — `apps-script-sheets`. Следующие Skills — после итогов пилота.

## Файл разметки TRANSFER.md

```
# Разметка переноса <имя>, <дата>
## Покрытие
| Раздел старого текста (заголовок) | Типы | Куда забрано |
## Список «?»
| # | Фраза (адрес: файл и заголовок) | Что это и на что влияет — мнение агента | Красный |
## Числа
разделов: N; забрано по типам: М _, С _, П _, Ф-адрес _, Ф-ловушка _; «?» _ (красных _)
```

Покрытие — каждый заголовок старого текста стоит в таблице. Красный — пункт, в котором упомянута запись наружу, удаление или деньги.

Итоги пилота смотрятся по трём числам: доля «?» (больше 10 % — правятся критерии, а не агент), размер нового Skill, сколько раз задачам шага 5 понадобился архив.
