Источник: решение Андрея 2026-10-30 (чат SYS): проверка содержания STATE.md при записи — скриптом, без отдельного воркфлоу-монитора; контракт — `meta/CONTRACT_state-content.md`, скрипт — `meta/scripts/state_split.py` (режим `check`), перенос — `meta/scripts/state_apply.py`. Якорь-строка (после неё вставить): строка, начинающаяся словами «3. Проект в repo — `second-brain-git` 10».

Было: пункта нет.

Стало (новый пункт 3а):

```
3а. STATE.md проекта в repo после записи проверяется на содержание тем же !save: в среде с клоном — `python3 meta/scripts/state_split.py check projects/<имя>/STATE.md`; раздел, который скрипт отнёс к истории или к правилам, переносится той же сессией скриптом `meta/scripts/state_apply.py` (решения — файл JSON, приёмка по строкам внутри скрипта) — отработавшее блоком хроники в LOG.md, правила и реестры в PLAN.md. Что остаётся в STATE.md — `meta/CONTRACT_state-content.md`. Клон для проверки есть почти в любой среде: репозиторий публичный, клон анонимный, командная строка есть и в сессиях Claude Project (проверено 2026-10-27, `meta/CASES_sys-lab-closed-2026-10-27.md`, раздел t-repo-search-unknown-path); сессия без командной строки сравнивает byteLength STATE.md из ответа Канала с бюджетом 8 192 Б и при превышении пишет в отчёт о !save строку «STATE.md выше бюджета, разбор — следующей сессией с командной строкой» — это сигнал, а не проверка содержания (размер критерием не является, 5.5 пункт 3). Почему: правило разбора по ролям (`second-brain-git` 5.1, 5.5) стояло в Skill с 2026-09-10, а дописывающая сессия его не исполняла — STATE.md wb-ue дорос до 79 403 Б, после разбора 2026-10-26 за четыре дня снова вышел за бюджет; проверка держится, когда стоит в точке записи, а не там, где ей «правильно» жить (ретроспектива `meta/RETRO_skill-rework_2026-10-23.md`). Превышение бюджета после разбора — не дефект (5.5, пункт 3): вопрос к каждой строке один — изменит ли она действие следующей сессии.
```

Стало (новый абзац):

```
**STATE.md после прогона.** Перед итоговым отчётом диспетчер запускает `python3 meta/scripts/state_split.py check` на STATE.md каждого проекта, в который прогон писал, и переносит отработавшее скриптом `meta/scripts/state_apply.py` (контракт `meta/CONTRACT_state-content.md`) — тем же прогоном, не отдельной задачей. ```
```
