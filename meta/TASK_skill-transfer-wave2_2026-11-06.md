# Задание: перенос оставшихся Skills в короткую форму — вторая волна, параллельно

Выдано 2026-11-06 сессией Claude Code (чат «Тест эффективности skills»), ревизия Р3 по Skill denken. Копия для агента на английском — `meta/TASK_skill-transfer-wave2_2026-11-06.en.md`; при расхождении действует этот файл.

## Цель

Восемь Skills переведены в короткую форму по `meta/CRITERIA_skill-transfer.md`, каждое правило, которое повторяется в нескольких Skills, имеет ровно один дом, и ни одно правило типа «Стоп» или «Ловушка» не потеряно между Skills. Итог — восемь zip-архивов для заливки и одна запись в журнал проекта.

Не переносятся: apps-script-sheets, n8n-engineering-manual, google-drive-docs — уже перенесены и заморожены (Р-42, Р-43); triz и triz-skill — чужие методики, не система Андрея; clasp-apps-script — в аккаунте не залит, в зеркале лежит один (вопрос Андрею в отчёте, не переносить).

Почему две волны: Skills первой волны — центр, на них ссылаются все остальные (second-brain-engineer упоминается в остальных Skills больше 20 раз). Если менять центр и края одновременно, края будут ссылаться на заголовки, которых уже нет. Вторая волна стартует, когда в первой волне закрыта Книга переноса (ниже) и заголовки новых Skills зафиксированы.

## Как устроена работа

Ведущая сессия (лидер) и по одному агенту на строку таблицы, до трёх агентов одновременно.

Режим. Если в этой среде Claude Code доступна команда агентов (agent teams, агенты пишут друг другу напрямую) — использовать её. Если нет — лидер запускает субагентов, а общение идёт только через Книгу переноса. Результат в обоих режимах одинаковый, потому что решение «куда идёт правило» существует, только когда записано в Книгу: сообщение между агентами решением не считается.

### Книга переноса — единственное место договорённостей

Файл `meta/TRANSFER_wave2/LEDGER.md`. Строка на каждое правило, которое агент встретил в своём Skill и которое, по его мнению, живёт или должно жить в другом Skill:

`| адрес в архиве (Skill, файл, заголовок) | тип по CRITERIA | короткая формулировка | дом (Skill, раздел) | кто предложил | статус |`

Статусы: «предложено» → «забрано домом» (ставит только агент Skill-дома, после того как правило стоит в его новом тексте) или «спор» → решение лидера или вопрос Андрею.

Правило выбора дома: дом — тот Skill, который загружается в момент действия, к которому относится правило. Пример: правило про запись в файл репозитория — дом second-brain-git; правило «когда и с чьего согласия» — дом second-brain-engineer; правило про наряд — naryad. Остальные Skills получают одну строку ссылки «Skill X, раздел „Y“».

Запрет: агент не выбрасывает правило из своего Skill с мыслью «его заберёт другой», пока в Книге против этого правила не стоит «забрано домом».

### Шаги для каждого Skill (конвейер CRITERIA с изменениями этой волны)

1. Перед началом лидер сверяет зеркало `skills/<имя>/` с живым Skill (`/mnt/skills/plugins/<имя>/`), `diff -rq`. Известное расхождение: зеркало avtopilot новее живого — в нём правка Р-44, Андрей её ещё не залил. Переносится версия из зеркала, в отчёте это называется.
2. Шаг 1 CRITERIA — архив `skills/_v1/<имя>/` со строкой «Архив до переноса 2026-11-06…».
3. Шаг 2 CRITERIA — разметка и новый Skill, файл `skills/_v1/<имя>/TRANSFER.md`. Дополнительно: строки в Книгу переноса для правил с чужим домом.
4. В описание (description) каждого нового Skill — фраза о загрузке (Р-46): «Загружать сразу, до первого вызова инструмента, и тогда, когда задача — только план, разбор или вопрос без правки: пункт плана «загрузить Skill» загрузку не заменяет.» Длина description — не больше 1024 знаков, проверка скриптом из `second-brain-git`, references/skill-edit.md, шаг 4.
5. Шаг 3 CRITERIA — красные пункты списка «?» всех Skills волны лидер собирает в один список Андрею, не больше трёх вопросов за раз, простыми словами с последствиями «да» и «нет».
6. Шаг 4 CRITERIA, расширенный: независимый агент, не участвовавший в переносе, берёт архивы всех Skills волны вместе и ищет фразы типов «Стоп» и «Ф-ловушка», которых нет ни в одном новом Skill (не только в своём). Плюс проверка ссылок скриптом: каждая ссылка вида «Skill X, раздел „Y“» во всех новых Skills, включая уже перенесённые три, находит заголовок Y в новом X.
7. Шаг 5 CRITERIA не выполняется — решение Р-47.
8. Шаг 6 CRITERIA — один zip на Skill, сборка и сверка по `second-brain-git`, references/skill-edit.md, шаг 4. Отдельно назвать: zip avtopilot заменяет и незалитый архив Р-44.

### Запись и push

- Агенты пишут только в свои папки `skills/<имя>/`, `skills/_v1/<имя>/` и строками в Книгу. Чужие папки не трогают.
- Коммиты и push в main делает только лидер; после каждого пакета — `git ls-remote origin main` и `git status`. Если агент сделал коммит или push сам — стоп и откат (Skill avtopilot, Ворота 4, «Задание субагенту»).
- Перенос по-прежнему только забирает: старый текст лежит в архиве целиком (CRITERIA, «Главное»).

## Наблюдаемый результат

- восемь новых `skills/<имя>/` и восемь `TRANSFER.md`;
- Книга переноса: ни одной строки в статусе «предложено» или «спор» без решения;
- шаг 6: пустой список пропусков «Стоп»/«Ф-ловушка» по всем архивам волны и ноль битых ссылок;
- восемь zip, выданных Андрею, с перечнем, какие прежние архивы теперь не заливать;
- запись в `projects/kontext-reduktion/LOG.md` по форме `second-brain-git` (references/log-form.md): что перенесено, числа по каждому Skill, расход токенов по отчётам агентов.

## Стоп-правила

- Заливку в Customize делает только Андрей; zip до прохождения шага 6 не выдаётся.
- Уже перенесённые apps-script-sheets, n8n-engineering-manual, google-drive-docs не правятся. Если правилу вне их место только там — строка в список «?» Андрею.
- Длина нового Skill не ограничена (CRITERIA, «Главное», пункт 4) — сокращение не цель.
- Расход: пилот одного Skill стоил около 1,3 млн токенов (Р-43). Волна из восьми Skills с командой агентов ожидаемо 8–15 млн. Лидер сообщает Андрею расход после первой волны, до запуска второй.
