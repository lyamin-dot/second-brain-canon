## Шаги

1. Снять дату последнего изменения (get_file_metadata) со всех документов опыта в Google Docs: это каждый документ `registry/documents.md`, в имени которого есть INDEX, JOURNAL или LOG, — INDEX проектов, журнальные корпуса (SYS_JOURNAL_2026, SYS_JOURNAL_2026_02, N8N_JOURNAL_2026), журналы инцидентов (JOURNAL_INCIDENTS, N8N_INCIDENT_LOG) и журнал решений PROJECT_LOG_SYS. Отбор идёт по имени, а не по списку блоков, поэтому новый журнал попадает в харвест сам, без правки этого файла. Пропускаются папки и таблицы Google Sheets с такими именами и машинные журналы, которые пишет воркфлоу (LOG_gap-monitor-findings): опыта они не несут. Полностью прочитать через gdocs-read только те, что изменены позже строки «последний харвест», — и в INDEX не только секции опыта: опыт там часто лежит датированными блоками Зоны Б. Документ, замороженный после переноса проекта в репозиторий (пометка «заморожен» в `registry/documents.md` или в колонке статуса `registry/projects.md`), читается один раз — первым харвестом после даты заморозки — и по шагу 6 вносится в строку «прочитаны после заморозки» в начале этого файла; документ из этой строки шаг 1 больше не читает, даже если дата его изменения новее: изменения замороженного документа — это сама заморозка и служебные пометки, а не новый опыт. В ответ — список прочитанных и список пропущенных с датами.
1б. Проекты и лаборатории в репозитории. Список — `registry/projects.md`, все строки обеих таблиц (проекты и лаборатории) с носителем repo. Для каждого проекта — записи Р и Т журнала `projects/<папка>/LOG.md` с датой не раньше строки «последний харвест»; если журнал ротировался после этой даты — то же по `LOG_ARCHIVE.md`. Сначала оглавление журнала, затем целиком только записи нужных дат (`second-brain-git` 7.6, строки «оглавление журнала» и «запись журнала по номеру»; в среде с клоном — `grep` по клону после `git fetch`). Для каждой лаборатории — файлы задач `labs/<папка>/t-*.md`, изменённые или удалённые коммитами после этой даты (`git log --since=<дата> --name-status -- labs/<папка>/`; текст удалённой задачи — по ref родителя коммита удаления, `second-brain-git` 4б.6). Для каждого проекта, кроме журнала, — `STATE.md` и `PLAN.md`, если они менялись коммитами после этой даты (`git log --since=<дата> -- projects/<папка>/`), целиком: в них живут ловушки, разделы «Предложения Клода», правила и допущения проекта, которых в журнале нет (харвест 2026-10-08 нашёл там около 35 уроков, не попавших в журналы). Плюс файлы `meta/`, изменённые после этой даты, кроме `meta/prompts/`, `meta/PENDING_RULES.md` и этого файла, — тоже целиком; правило из `meta/`, которое Skill обязан называть и не называет, — находка шага 2. Каждый файл этого шага, включая крупные файлы задач, читается целиком: просмотр поиском по словам чтением не считается. В ответ — список журналов, файлов и лабораторий с числом просмотренных записей и файлов по каждому.
Если объём больше, чем одна сессия прочитает с запасом (ориентир 2026-10-08: около 390 записей журналов, 62 файла задач и около 550 КБ файлов STATE.md, PLAN.md и meta/; первый харвест на Git раздал это одиннадцати посредникам), журналы раздаются посредникам группами (Skill `second-brain-engineer`, Р21). Каждому — вопрос: «какие уроки из записей с датой не раньше <дата> в файлах <список> повторяются в двух и более проектах или отсутствуют в тексте Skills; для каждого — номер записи, одна строка урока и результат поиска формулировки в Skills». Посредник возвращает ответ, а не текст записей. Запись, на которую сессия опирается в шаге 5, сессия перечитывает сама.
2. В прочитанных документах шага 1 — в INDEX секции НАКОПЛЕННЫЙ ОПЫТ и РЕШЕНИЯ и датированные блоки Зоны Б, в журнальных корпусах и журналах — записи; в журналах, задачах, файлах STATE.md, PLAN.md и meta/ (шаг 1б) — записи Р и Т, тела задач, ловушки и правила; везде только новее строки «последний харвест». Отобрать уроки по процедуре `meta/PROTOCOL_lesson-triage.md`: каждый урок, которого нет в действующих Skills, оценивается тремя осями (тяжесть, встречаемость по независимым случаям, скрытность) и получает уровень размещения — код инструмента, главный файл Skill, файл references/, таблица симптомов или отказ; урок, повторяющийся в двух и более проектах, — это встречаемость по оси, а не отдельный критерий. До оценки каждый урок сверяется со списком ожидающих уроков `meta/LESSONS_waiting.md`: поиск по словам из колонки «слова для поиска» строк списка и их синонимам, найденная строка читается целиком. Совпадение по механизму — новый независимый случай: отдельной строкой урок не заводится, строка списка возвращается в отбор со встречаемостью на единицу больше и пересчитанной оценкой. Урок, отказанный по оценке, ложится в этот список (процедура отбора, уровень 4). В ответ шага — число уроков, сверенных со списком, и число совпадений. Прежний критерий «повторяются в двух и более проектах или отсутствуют в действующих Skills» снят 2026-10-11 (запись Р-16 журнала `projects/archivarius/LOG.md`): союз «или» пропускал в Skill однократный факт. Проверка отсутствия — поиск формулировки в тексте ЖИВОГО Skill, а не память: живой — тот, что загружен в эту сессию (в среде, где Skills лежат файлами, — каталог Skills среды, например `/mnt/skills/plugins/<имя>/`). Зеркало `skills/` репозитория годится как основа поиска, только если живого текста в среде нет. Если доступны оба — до поиска сравнить их (`diff -rq`), и каждое расхождение — само находка пакета: харвест 2026-10-08 нашёл, что зеркала `second-brain-engineer`, `second-brain-git` (references/migration.md) и `n8n-workflow-registry` отстали от живых, и одна находка, сделанная по зеркалу, оказалась ложной.
3. Очередь правок `registry/maintenance-queue.md`: найти позиции, чей статус не означает внесение, снятие, закрытие или дубль, а дата смерти наступила или наступит до ближайшего понедельника. Искать по строкам таблиц (Git Read Lines с pattern по номеру позиции и по дате; в среде с клоном — grep. Git Grep для этого шага ЗАПРЕЩЁН: он несёт в contextData base64 всего файла, nodeNames его не режет, поэтому поиск по очереди стоит дороже, чем чтение очереди целиком — Р-2 `meta/CONTRACT_file-limits.md`, exec 63960), а не по разделам «Счёт» — счёты в файле не сходятся (`labs/sys/t-queue-count.md`). Ответ «да» на вопрос — правка текста naryad в пакет шага 5; ответ «не помню» — вопрос снимается до следующего харвеста, без пометки. Прежний шаг 4 — перепроверка правил с меткой `[verified]` старше 90 суток — снят решением владельца 2026-09-27 (Р-113 журнала `projects/git-migration/LOG.md`): меток в Skills не было, и шаг всегда давал ноль.

## Архивное чтение — режим Архивариуса

Разовое чтение корпуса, у которого не было читателя. Родился в проекте `projects/archivarius/` (2026-10-10…2026-10-13, закрыт): 12 корпусов Google Docs, записи весны и лета 2026, 165 уроков, 115 правок в восьми Skills, около трёх с половиной дней работы. Проекта и мастер-промпта у режима нет: его исполняет сессия SYS по этому разделу.

Когда: только по слову владельца — «архивное чтение» или «харвест, режим Архивариуса». Повод — в систему входит корпус, который никто не читал: найденный старый документ, проект, переносимый из Google Docs, журнал закрытого проекта, записи старше окна обычного харвеста. Расписания нет.

Граница окна. Любой читатель, чьё окно задано датой («записи новее …»), при заведении или сдвиге окна записывает, кто читает записи старше окна, либо прямо пишет «никто». Прецедент: харвест открыл окно с 2026-08-31, не назвав читателя прошлого, — записи весны и лета 2026 никто не читал до Архивариуса.

Шаги:
А1. Показание — записать до чтения: какой корпус; наблюдаемый факт, что у него нет читателя (кто читал и до какой даты); окно (с какой по какую дату); выход — уроки, а не задачи; адресат каждого урока. Корпус, чьё окно уже кто-то прочитал, не читается.
А2. Пробное чтение: из каждого корпуса 20 записей окна, по каждой вердикт — новый урок, уже есть (с адресом абзаца), хроника, устарел. Условие отказа называется до пробы (у Архивариуса: во всех трёх корпусах меньше трёх новых уроков из двадцати — закрыть). Проба отвечает «стоит ли читать», а не «что там есть»: поздние записи — плохая выборка (N8N_JOURNAL_2026: 5 новых из 20 поздних против 25 при полном чтении).
А3. Полное чтение окна без отсечки. Документ Google Docs — один вызов gdocs-read в режиме full в среде с командной строкой, byteLength и checkSum пересчитываются по тексту. Крупный корпус — подагентам по диапазонам строк с общим заданием; каждый вердикт «новый урок» основная сессия перепроверяет сама. Сверка — с живыми Skills среды (не с зеркалом `skills/`), `meta/`, `core/`, `registry/`, уже собранным пакетом и `meta/LESSONS_waiting.md`.
А4. Противоречие между записью корпуса и текстом Skill решается пробой на объекте — воркфлоу-инструментом без внешней записи, чтением кода воркфлоу, документацией, — а не правилом «что новее, то и верно». Так Архивариус нашёл пять ошибок в живых Skills (executeOnce в середине цепочки, причина ошибки E16, порог обрезки чтения, затирание формул автосопоставлением колонок, несуществующий статус заказа Wildberries).
А5. Отбор и правки — `meta/PROTOCOL_lesson-triage.md`, стадии А и Б. Стадию А лучше исполняет отдельная сессия с правом возразить процедуре; проверяющему не сообщается ожидаемый ответ.
А6. Выдача и приёмка: один пакет, у каждой правки полный текст «было → стало»; каждая правка применена скриптом к копии живого Skill с проверкой «текст Было найден ровно один раз». После заливки владельцем — сравнение живых Skills с выданными (diff -rq), затем запись зеркала `skills/` из живых Skills.

Конец: окно разобрано — документ вносится в строку «прочитаны после заморозки» (если заморожен) или в журнале проекта пишется «прошлое окно корпуса просмотрено» с датой. Новой сущности режим не оставляет.
