# BORDER_core-index-skill — граница CORE / INDEX / SKILL [источник: раздел 14.3, читать до переноса любого INDEX]

Выведена 2026-09-02 из объекта (диск, Skill second-brain-engineer), не из рассуждения.
SKILL — кристаллизованные законы. Основания: SBE §8 «обслуживание: опыт → Skills»; §5.13 период полураспада знаний, метка `[verified: дата]`, порог 90 дней; §9 «все актуальные ID — только из CORE Раздел 2, не хранить копию в Skill».
INDEX — сбор и ростки. Основание: SBE §5.9 правило второго раза — класс ошибки фиксируется в НАКОПЛЕННЫЙ ОПЫТ того INDEX (симптом, причина, превентив, момент-триггер), откуда обслуживание поднимает его в Skill. Трёхступенчатость: наблюдение → накопленный опыт → закон.
CORE — три роли и только они: реестр (Р.1 проекты и веса, Р.2 ID файлов), состояние инстанса (Р.12 повестка, LAST_HARVEST), контракты команд (Р.6, Р.7, Р.13), на которые прямо ссылается замороженный мастер-промпт. CORE читается не на старте, а при командах и обслуживании; на старте читается Зона А INDEX.
Пересказ содержания Skill внутри CORE или INDEX — ШУМ. Короткий указатель носителя («эталон — в SBE §N, не дублировать здесь») — не мусор, а разделитель границы, предотвращающий третью копию.
Следствие для переноса INDEX: шаблон INDEX уже разделяет слои (Зона А / Зона Б / НАКОПЛЕННЫЙ ОПЫТ) — триаж INDEX кратно дешевле триажа CORE. CORE был худшим случаем: в нём смешаны все три роли плюс исторические дубли, накопленные до появления Skills.
