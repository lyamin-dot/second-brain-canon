## Алгоритм анализа каждого файла

### Шаг 1 — Прочитай файл
Используй Google Drive MCP: read_file_content

### Шаг 2 — Проверь на устаревание
Перед извлечением любого факта спроси себя:
- Это описывает старую архитектуру? (Daily_Context, 00_System,
  TECH_INDEX единый, OZON_INDEX единый) → пропустить
- Это противоречит тому что уже есть в Core или INDEX файлах? → 
  использовать более новую версию, старую пропустить
- Это задача которая уже выполнена или закрыта? → пропустить
  (признаки: [x], «выполнено», «закрыто», «решено», дата в прошлом)
- Это актуальный факт, задача или идея? → извлечь

### Шаг 3 — Классифицируй каждый элемент

ТИПЫ:
  Задача   → конкретное действие, можно выполнить
  Идея     → требует развития, нет конкретного шага
  Решение  → принятое решение, фиксируется с датой
  Справка  → технический факт, параметр, ссылка
  Мусор    → дублирует существующее / устарело / нерелевантно

ПРИОРИТЕТ (только для Задач):
  БЛОКЕР   → без этого что-то стоит прямо сейчас
  РЫЧАГ    → небольшое усилие, большой эффект
  РУТИНА   → нужно, не срочно
  ЗОМБИ    → висит давно, неясна судьба

ПРОЕКТ — один из:
  [OZON_UE]  [OZON_CV]  [WB_UE]  [WB_CV]
  [N8N]      [SERVER]   [RENO]   [TRADE]
  [SYS]      [USER]     [REF]    [?]

  [USER] → идёт в USER_PROFILE
  [REF]  → идёт в REFERENCE_DOC (технические факты)
  [?]    → не удалось классифицировать, спросить у пользователя

### Шаг 4 — Проверь на дубли
Перед записью прочитай целевой INDEX файл.
Если похожая задача/идея уже есть — не дублировать.
Если новая информация дополняет существующую — обновить через
v2-replace, а не добавлять новую строку.

### Шаг 5 — Запиши
Используй v2-воркфлоу записи (верификация read-back встроена в код инструмента):

Добавить новый элемент в конец файла:
  n8n:execute_workflow | workflowId: YfzWwu1VmIUCbUu0
  body: { "fileId": "...", "text": "..." }
  Верификация: success: true
  success:true = инструмент сам перечитал документ и подтвердил,
  что текст записан. При success:false — читай поле reason, не повторяй вслепую.

Обновить существующую строку:
  n8n:execute_workflow | workflowId: nvNYvvmuOqGyHXfL
  body: { "fileId": "...", "search": "...", "replace": "..." }
  Верификация: success: true
  v2 сам перечитывает документ после замены и сверяет indexOf.
  При success:false — в ответе reason + context ±150 символов.
  НЕ полагайся только на occurrencesChanged: success учитывает read-back, occurrencesChanged — нет.

После каждой записи — верифицировать по полю success.
success:true доверять можно (read-back зашит в код инструмента);
success:false — не повторять вслепую, сначала прочитать reason.

1. Никогда не записывать без проверки на дубль

   сообщить: «Файл пуст / всё устарело, можно архивировать»
5. Не спрашивать разрешения на каждую запись — работать
   автономно, отчитываться после каждого файла
6. Максимум один вопрос за раз если нужно уточнение
