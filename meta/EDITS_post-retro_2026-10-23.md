## Правка 1. avtopilot — SKILL.md, блок «Задание субагенту» (строки 63–66), шаг 4а дорожной карты

Якорь: строка 64 `- по умолчанию только чтение, и это написано в задании словами «READ-ONLY, ничего не менять»;`

Было:
```
- по умолчанию только чтение, и это написано в задании словами «READ-ONLY, ничего не менять»;
- у вопроса закрытый набор вердиктов (например, ЖИВ / ИСПРАВЛЕН / ИЗМЕНЁН);
```

Стало:
```
- по умолчанию только чтение, и это написано в задании словами «READ-ONLY, ничего не менять»;
- читающее или тестовое задание не выдаётся субагенту в сессии, где `git push --dry-run` прошёл (`second-brain-git` 9.1): запрет записи в задании держится только словами, а право отправки в main субагент наследует от сессии. Такое задание — в сессии без открытого push: клон публичного репозитория читается анонимно, записать из него нельзя. Почему: 2026-10-22 два тестовых субагента отправили коммиты в main (64ccf73, 9815579; откаты 273a0dc, fd1aca5) и два правили зеркало Skill в рабочей копии — при тексте «READ-ONLY» в каждом задании (`meta/TEST_skill-layers_2026-10-22_report.md`, таблица, задания 1, 8, 11; `labs/sys/t-session-behavior-tests.md`, раздел 3);
- у вопроса закрытый набор вердиктов (например, ЖИВ / ИСПРАВЛЕН / ИЗМЕНЁН);
```

Что меняется в поведении: диспетчер, у которого открыт push, не запускает тестовых и читающих субагентов — либо закрывает задачу сам, либо отдаёт её в сессию без push. Фраза для поиска копий старой формулировки: «по умолчанию только чтение, и это написано».

## Правка 2. second-brain-engineer — references/design-acceptance.md, пункт 14г (строка 30), шаг 6 дорожной карты

Якорь: строка 30 начинается словами `- **г. Вопросы приёмки составляет не исполнитель работы**`; правка — дописка в конец этого абзаца, перед строкой `  Почему: исполнитель, выбирающий вопросы, …`.

Было (конец абзаца строки 30):
```
… Для промежуточной приёмки внутри фазы отдельный приёмщик не обязателен, кроме режима автопилота, где Skill `avtopilot` требует его всегда.
  Почему: исполнитель, выбирающий вопросы, выбирает те, на которые его работа уже отвечает; приёмщик, не видевший построения, находит то, чего исполнитель не видит. Отдельный приёмщик сильного класса дорог, поэтому обязателен только там, где закрывается фаза или проект.
```

Стало:
```
… Для промежуточной приёмки внутри фазы отдельный приёмщик не обязателен, кроме режима автопилота, где Skill `avtopilot` требует его всегда. Файл с вопросами или критериями поведенческого теста лежит там, куда тестируемая сессия не дотянется поиском: не в репозитории и не в папке Skills — у Андрея или в документе Drive, не названном тестируемой сессии; сам тест поведения идёт в живом чате проекта, доказательство — лента вызовов (снимок экрана), история версий воркфлоу и история коммитов, а не отчёт сессии о себе и не вопрос «перечисли свои вызовы».
  Почему: исполнитель, выбирающий вопросы, выбирает те, на которые его работа уже отвечает; приёмщик, не видевший построения, находит то, чего исполнитель не видит. Отдельный приёмщик сильного класса дорог, поэтому обязателен только там, где закрывается фаза или проект. Носитель критериев назван отдельно, потому что правило об авторе критериев, стоя в этом пункте, 2026-10-22 нарушила сессия, которая сама его исполняла: задания теста слоёв написал автор переложения (коммиты b068320, f339311), файл заданий лежал в репозитории, и семь прогонов нашли его поиском до ответа (`meta/TEST_skill-layers_2026-10-22_report.md`, раздел «Отступления от наряда», пункт 4); субагент с мастер-промптом в тексте запроса сессией проекта не становится — из 13 прогонов Skill загрузили три (там же, раздел «Итог»).
```

Что меняется в поведении: сессия, готовящая тест, не кладёт файл критериев в репозиторий и не прогоняет тест субагентами; задача `labs/sys/t-session-behavior-tests.md`, раздел 2, после внесения закрывается как перенесённая в Skill. Фраза для поиска копий: «кроме режима автопилота, где Skill».

## Правка 3. second-brain-engineer — references/permissions.md, раздел Р13 (после строки 32), шаг 7 дорожной карты

Якорь: строка 32 `**Андрей не должен:** менять структуру INDEX напрямую; …` — новый абзац вставляется после неё, перед пустой строкой и `**ПРОВЕРКА.**`.

Было:
```
**Андрей не должен:** менять структуру INDEX напрямую; переименовывать/удалять воркфлоу без согласования; менять колонки Sheets; править середину функций Apps Script (только полная замена).

**ПРОВЕРКА.** Перед действием из строки «после да» в чате видно «да» Андрея или названо исключение Р10: пакет — с адресом записи, «реши сам» — со словами поручения.
```

Стало:
```
**Андрей не должен:** менять структуру INDEX напрямую; переименовывать/удалять воркфлоу без согласования; менять колонки Sheets; править середину функций Apps Script (только полная замена).

**Форма вопроса, требующего «да» Андрея.** Три строки, простыми словами, коды и номера пунктов — в скобках после слов: `ВОПРОС:` что меняется; `ЕСЛИ «ДА»:` ближайшее наблюдаемое последствие для работы Андрея; `ЕСЛИ «НЕТ»:` что останется как есть и чем это грозит. В одном сообщении не больше трёх таких вопросов; больше — делятся на части, следующая часть после ответа на предыдущую. Ответ «согласен со всем» на пакет из нескольких вопросов решением по каждому не является: вопросы, на которые нет отдельного ответа, остаются открытыми, и в запись решения они не идут. Почему: 2026-10-22 пакет из 26 находок и 74 вердиктов принят одной фразой (`meta/HARVEST_2026-10-22_answers.md`, строка 3), а решения, принятые сессией «по поручению», в правках Skill записаны как решения Андрея (`meta/SYNTHESIS_second-brain-engineer_2026-10-20/ACCEPTANCE_opus.md`, строка 92; `meta/HARVEST_2026-10-18_verdicts.md`, строка 33); слова Андрея 2026-10-23: он не понимает ни вопросов с кодами, ни их последствий для системы. Гипотеза (не проверена): форма из трёх строк увеличит долю решений, принятых по одному; проверка — следующий харвест.

**ПРОВЕРКА.** Перед действием из строки «после да» в чате видно «да» Андрея или названо исключение Р10: пакет — с адресом записи, «реши сам» — со словами поручения; вопрос Андрею в чате стоит в форме трёх строк, и в одном сообщении их не больше трёх.
```

Что меняется в поведении: любой вопрос, требующий «да», сессия пишет тремя строками и не больше трёх за раз; пакетное «согласен со всем» больше не закрывает вопросы. Фраза для поиска копий: «Перед действием из строки «после да» в чате видно».
