# RES-006 — где хранить данные учёта четырёх кабинетов Ozon и Wildberries (исследование И-1 проекта marketplace-rebuild)

Разбор исполнителем наряда Н-24.10-01, 2026-10-24, по первоисточникам в интернете (сырого отчёта нет; адреса ниже), инстансу n8n Андрея только на чтение и файлам канона. Читатель — этап 2 «модель данных» файла projects/marketplace-rebuild/PLAN.md, исследование И-1 раздела 5 (этап 1а) и строка «Исследование И-1» раздела 9. Коды доверия — wiki/DESIGN.md, пункт 2: буква — надёжность источника (A — документация владельца продукта; B — запись нашего канона, снятая с объекта прежней сессией; D — форум), цифра — подтверждённость (1 — прочитано на нашем объекте в этой сессии или вторым независимым источником; 2 — первоисточник прочитан, предложение в нём есть). Все внешние страницы прочитаны 2026-10-24.

## Ответ

Хранилище — база данных PostgreSQL на сервере Андрея: отдельная база в уже работающем контейнере PostgreSQL 16, где уже лежат база знаний liquimoly_kb и таблица sku_mapping. Предел объёма для этой задачи не достижим: 32 ТБ на таблицу, строк — сколько поместится в 4 294 967 295 страниц (утверждение 7). Дополнительная цена — 0: сервер и PostgreSQL уже работают и оплачиваются (утверждения 8, 9); цена самого сервера по прайсу Hetzner первоисточником не читалась.
Агент читает без дополнительного инструмента: НЕТ — нужен один новый воркфлоу n8n «чтение SQL» с пользователем базы только на чтение (утверждение 13). Андрей читает глазами без дополнительного инструмента: НЕТ — свод (не сырые строки) выводится в его книги Google Sheets, либо на сервер ставится веб-просмотрщик базы (решение этапа 2).
Почему не Google Sheets и не таблицы данных n8n, хотя оба читаются без дополнительного инструмента, — раздел «Отвергнуто».

## Отвергнуто

- Google Sheets как хранилище сырых данных. Четыре кабинета (утверждение 3) за год превышают предел книги 20 млн (4); раздельные книги по кабинету проходят по ячейкам около 3,7 года, но расчёт в Apps Script уже упирается в 6 минут на одном кабинете (5, 6) — четыре кабинета этот путь закрывают. Sheets остаётся местом, где Андрей видит свод.
- Таблицы данных n8n. По умолчанию 200 МиБ на весь инстанс (10); оценка сырых данных четырёх кабинетов за год — 200–300 МБ, Гипотеза (не проверена): около 500 байт на строку не замерялось. Предел поднимается, но тогда это та же PostgreSQL (11) без SQL: агрегаций нет ни у MCP (12), ни из узла Code (10), и свод для юнит-экономики пришлось бы считать опять в Sheets или в n8n по строкам — та же болезнь, что в утверждении 6. Годятся для служебного состояния и справочников (курсоры, сопоставления, список кабинетов).
- Четвёртый кандидат не назван: набор полон для задачи — внешние сервисы баз данных добавили бы цену и ключи без выигрыша перед уже работающей PostgreSQL (8, 9).

## Что это требует от этапа 2 (не решено здесь)

- Отдельный пользователь базы только на чтение и воркфлоу «чтение SQL» для агента; DDL делает владелец (в PostgreSQL 15 и новее у пользователей нет права CREATE в схеме public — projects/wb-reviews/PLAN.md, строка 58, B2).
- Свод в книги Андрея пишет воркфлоу n8n (сотни строк, не десятки тысяч) — тогда Apps Script не считает по сырым строкам.
- Включить новую базу в бэкап и проверить по объекту (14).
