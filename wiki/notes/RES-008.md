# RES-008 — что в пилоте кабинетов ИП делает агент, а что детерминированный воркфлоу n8n (исследование И-3 проекта marketplace-rebuild)

Разбор исполнителем пакета 4 контракта подготовки пилота (projects/marketplace-rebuild/PLAN.md, раздел 12), 2026-10-25, только чтение. Читатель — этап 3 «пилот» и строки контрактов сборщиков ИП в разделе 9 PLAN.md; критерий ответа — раздел 5 PLAN.md, этап 1а: «таблица агент делает / воркфлоу делает по каждой операции, одна причина в строке». Источники: документация Anthropic (code.claude.com, support.claude.com) и n8n (docs.n8n.io), все страницы прочитаны 2026-10-25; канон — wiki/notes/RES-006.md, wiki/notes/RES-007.md, STATE.md (таблица проб этапа 0), LOG.md (записи Р-10, Р-13), снимок registry/n8n-map.md. Коды доверия — wiki/DESIGN.md, пункт 2 (A — документация владельца продукта; B — запись канона, снятая с объекта прежней сессией; цифра 1 — прочитано на нашем объекте или вторым источником, 2 — первоисточник прочитан, нужное предложение в нём есть). В n8n, книгах, на сервере и в площадках ничего не менялось.

## Ответ

Всё, что повторяется каждый день по заранее известным шагам (сбор продаж, остатков, карточек обоих кабинетов ИП, запись в базу mkt2, повтор при сбое, честное падение), делает воркфлоу n8n по расписанию. Агент делает то, что требует суждения и случается редко: строит и правит воркфлоу, разбирает неоднозначные сопоставления артикулов, принимает части по объекту, сверяет с первоисточником, разбирает упавшие исполнения — по вызову Андрея или по наряду, не по расписанию. Агента по расписанию (облачная или локальная запланированная задача Claude) в пилоте нет ни на одной операции: «зелёный» запуск не означает выполненную задачу (утверждение 3), запуски расходуют лимит подписки и ограничены дневным числом (4), локальная задача пропускается, пока компьютер спит (5).

## Утверждения

1. Агент из чата строит воркфлоу n8n, привязывает существующий ключ площадки по ID и получает живой ответ Ozon кабинета ИП. — B1. STATE.md, таблица «Этап 0 — пробы», строка 1+2 (исполнение 85542); LOG.md, запись Р-10.
2. Агент правит скрипт копии книги мостом gas-bridge без рук Андрея; ID скрипта копии находится только через браузер. — B1. STATE.md, таблица проб, строка 3 (исполнения моста 85547, 85550, 85555).
3. Облачная запланированная задача Claude Code: зелёный статус запуска означает только, что сессия стартовала и закончилась без ошибки инфраструктуры, а не что задача выполнена; заблокированные сетевые запросы и отсутствующие инструменты коннектора видны только в тексте запуска. — A2. code.claude.com/docs/en/web-scheduled-tasks, раздел «View and interact with runs».
4. Облачные задачи расходуют лимит подписки так же, как обычные сессии, и сверх него ограничены дневным числом запусков на аккаунт; минимальный интервал — один час; функция в статусе предварительного исследования, поведение и лимиты могут меняться. — A2. Там же, разделы «Usage and limits», «Add a schedule trigger» и пометка в начале страницы.
5. Локальная запланированная задача Claude Code Desktop запускается только при открытом приложении и не спящем компьютере; пропущенный запуск догоняется одним запуском при пробуждении; в ручном режиме разрешений запуск стоит до одобрения. — A2. code.claude.com/docs/en/desktop-scheduled-tasks, разделы «How scheduled tasks run», «Missed runs», «Permissions for scheduled tasks».
6. Облачная задача в окружении по умолчанию ходит в сеть только по списку разрешённых доменов, остальное — отказ 403; коннекторы MCP идут через серверы Anthropic. Значит, к API площадок и к базе на сервере она дотянулась бы только через коннектор n8n или с открытием сети и ключами в окружении. — A2. Там же (web-scheduled-tasks), раздел «Environments and network access»; вывод о площадках и сервере — расчёт из этого предложения.
7. Узел Postgres n8n имеет операцию «Insert or Update». — A2. docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.postgres/
8. Настройка узла «Retry On Fail»: при сбое узел перезапускается до успеха; «On Error» — остановить воркфлоу, продолжить или продолжить с выходом ошибки. — A2. docs.n8n.io/workflows/components/nodes/
9. Узел Stop and Error заставляет исполнение упасть при заданном условии и передаёт данные ошибки в воркфлоу ошибок; воркфлоу ошибок начинается с Error Trigger и назначается в настройках воркфлоу. — A2. docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.stopanderror/; docs.n8n.io/flow-logic/error-handling/
10. Воркфлоу ошибок инстанса уже есть: «Error Notifier» M5BLqclKBjGTpz33, активен, назначен воркфлоу ошибок у действующих воркфлоу (например, WB_WF_sku-mapping-loader). — B1. registry/n8n-map.md, строки M5BLqclKBjGTpz33 и qrZw8bxIEpRAUwEe (снимок на 2026-10-24).
11. Узел Schedule Trigger поддерживает интервалы от секунд до месяцев и выражение cron; расписание действует только у сохранённого и опубликованного воркфлоу; часовой пояс — воркфлоу, иначе инстанса. — A2. docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.scheduletrigger/
12. Сервер и PostgreSQL уже работают и оплачены; лишней цены у ежедневного запуска воркфлоу нет. — B2. wiki/notes/RES-006.md, утверждения 8 и 9.

## Отвергнуто

- Ежедневный сбор агентом по расписанию (облачная задача, читающая площадки через коннектор n8n): тратит лимит подписки и дневное число запусков (4) на работу без суждения, а «зелёный» запуск не доказывает, что данные легли (3) — пришлось бы ставить проверку поверх, то есть монитор.
- Локальная запланированная задача на компьютере Андрея: пропуск, пока компьютер спит (5); Андрей работает сменами, в том числе в выездах.
- Агент по расписанию, который каждое утро читает исполнения и сообщает о сбоях: дублирует действующий Error Notifier (10), второй сигнал без нового действия — монитор (правило Андрея 2026-09-03, инвариант 6 PLAN.md).
- Поиск деловых отклонений (падение продаж, выбросы цен) в пилоте: юнит-экономики ИП в пилоте нет (PLAN.md, этап 3), действия у такого сигнала нет.
- Узел ИИ-агента внутри воркфлоу сборщика: управление потоком в сборщике фиксировано; модель в нём добавила бы недетерминированность к повторяемой записи (7).

## Пробелы

1. Число дневных запусков облачных задач на тарифе Андрея на странице не названо — видно только в claude.ai/code/routines. Проверить: эта страница при входе Андрея. На ответ не влияет: агента по расписанию в таблице нет.
2. Гипотеза (не проверена): роль-владелец базы mkt2 может создавать таблицы в схемах raw и ref, и воркфлоу MKT2 под её ключом исполнит DDL. Проверить: после скрипта Андрея (запись Р-13) — разовый воркфлоу MKT2 с CREATE TABLE в пустой схеме, номер исполнения.
3. Гипотеза (не проверена): Error Notifier сам доставляет сообщение Андрею (Telegram или почта) — канал доставки не читался. Проверить: get_workflow_details M5BLqclKBjGTpz33, узлы после Error Trigger.
4. Не проверено исполнением: пустой ответ какого именно метода для кабинета ИП невозможен (карточек и остатков у ИП 170 товаров Ozon по исполнению 85542; у WB не читалось). Правило «пусто — падение» ставить только на такие методы; продажи за сутки могут быть законно пусты.
