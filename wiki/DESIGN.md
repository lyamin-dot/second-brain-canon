# Вики внешних исследований — замысел

Составлен 2026-09-25 сессией проекта kontext-reduktion по трём отчётам Perplexity — RES-001, RES-002, RES-003 в wiki/INDEX.md. Утверждён владельцем в тот же день целиком, вместе с дополнениями по полному тексту RES-003 (Р-30 журнала projects/kontext-reduktion/LOG.md): вики живёт в отдельной папке репозитория и не смешивается с проектами; всё ниже — действующее устройство, а не предложения.

## Проблема

Внешний отчёт весит 10–30 КБ, это 3–8 тысяч токенов при чтении целиком, а через ссылку на Google Doc — вдвое больше: gdocs-read приносит текст дважды. В одном отчёте рядом стоят проверенное и выдуманное: в RES-002 утверждение, которое подтвердила наша проба, соседствует с таблицей тестов, противоречащей самой себе, и с цифрами расхода лимита, пересказанными с Reddit. Без хранилища отчёт живёт только в чате, где его разобрали, и отвергнутая идея возвращается заново.

## Устройство

1. Три уровня чтения; следующий открывается, только если не хватило предыдущего.
   - Строка в wiki/INDEX.md: вывод, доверие, адрес, связанные решения, дата «проверить после».
   - Заметка wiki/notes/RES-NNN.md, 1–3 КБ: утверждения отчёта по одному в строке, у каждого код доверия и адрес источника; отвергнутое — с причиной.
   - Сырой отчёт. В repo кладётся только маршрутом, где текст не проходит через модель (правило происхождения текста, second-brain-git 4.5); иначе в строке индекса — адрес: вложение, Google Doc, ветка Perplexity.
2. Доверие по двум осям, как в шкале Адмиралтейства. Буква — надёжность источника: справка Anthropic ≈ A или B, пересказ Perplexity ≈ C, сообщение на Reddit ≈ D, F — нельзя судить. Цифра — подтверждённость утверждения: 1 — подтверждено нашей пробой или вторым независимым источником, 2 — вероятно, 3 — возможно, 4 — сомнительно, 5 — неправдоподобно, 6 — нельзя судить. Отчёт целиком оценивается только в строке индекса; в заметке оценивается каждое утверждение. Основание — RES-002: одна оценка на весь отчёт скрыла бы и лучшее, и худшее в нём.
3. Правило входа в канон: утверждение из вики становится правилом Skill или CORE только с цифрой 1 (подтверждено нашей пробой или вторым независимым источником) либо с кодом A2 или B2 (первоисточник найден и прочитан, нужное предложение в нём есть). Всё прочее — кандидат, и так и называется. Почему буква важна: почти всё из Perplexity по происхождению — пересказ, буква C; при правиле «цифра 1 или 2» правдоподобный пересказ с кодом C2 уходил бы в Skill без единой проверки, а правило Skill агенты исполняют как закон. Практически: утверждение Perplexity попадает в правило только после пробы или после чтения первоисточника.
4. Связь с решениями в обе стороны. Строка индекса называет записи журналов, которые на отчёте стоят; запись журнала называет ID отчёта. Когда отчёт получает статус «заменён» или «устарел», поиск по его ID находит все решения, которые надо перепроверить.
5. Срок годности по типу утверждения. Цены, лимиты, поведение продуктов и моделей — пересмотр через три месяца или при смене модели. Принципы — без срока. Статусы строки: действует, заменён RES-NNN, устарел, неполный. Готовая дата пересмотра стоит полем в строке индекса, чтобы читающая сессия сверяла одно число, а не выводила срок из типа утверждения. Отдельного механизма напоминаний не заводится: срок проверяет та сессия, которая строку читает.
6. Вики не входит в обязательное чтение на старте. RES-003 называет расточительным подход Cline Memory Bank, где все файлы памяти читаются каждую сессию. Индекс читает только сессия, которой нужен внешний факт.
7. Разбор нового отчёта — отдельная сессия, один проход: отчёт в чат → заметка с оценкой утверждений → строка индекса → ссылка на ID отчёта в затронутых решениях. Сомнительное утверждение проверяется пробой в системе или вторым источником, и только тогда получает цифру 1.
   - Отчёт передаётся вложением или ссылкой на Google Doc там, где подключён Google Drive: чтение коннектором приносит текст один раз. Удваивает текст только n8n-воркфлоу gdocs-read — для чтения отчётов его не использовать (Р-30 уточняет пункт 6 Р-29).
   - Субагент для разбора не нужен. Отчёт разбирается целиком, срезом по шаблону его не сузить; изоляцию контекста даёт сама отдельная сессия, которая после разбора закрывается, — без обмена расхода на контекст около 55 к 1, измеренного у посредника (Р-25).
   - Проверка независимости: несколько статей, пересказывающих один источник, — один источник, а не несколько. У отчётов Perplexity это типичный случай.
   - Собственные пометки отчёта о статусе («measured», «documented», «подтверждено») кодом доверия не считаются: код ставит сессия разбора. В RES-003 пометка «measured» стоит у числа из одного обсуждения на GitHub.
8. Поиск без векторной базы: строки индекса начинаются с `RES-`, темы — метки через `#`. Один вызов Git Read Lines с pattern по метке находит все отчёты темы; в среде с клоном — один grep.

## Что нужно от владельца

- Утвердить или поправить формат строки индекса и шкалу доверия.
- Внести папку wiki/ в карту репозитория: Skill second-brain-git, раздел 3.
- Решить, где хранить сырые RES-001 и RES-003: сейчас они есть только во вложениях чата 2026-09-25. Дешёвый путь — сохранить ответ файлом на Google Drive или оставить ветку Perplexity и записать её адрес.
- Если нужны разделы 2–9 RES-003 и часть B о схеме взаимодействия Андрей — Система, прислать остаток ответа: получено 8,7 КБ, только раздел 1.

## Отвергнуто

- llms.txt как формат индекса: это стандарт для веб-сайтов; по RES-003, публичные файлы llms.txt почти не запрашиваются ботами; репозиторию с файлом-списком он ничего не добавляет.
- Обязательное чтение всей вики на старте, по образцу Cline Memory Bank: платит каждая сессия, а нужен вики редкой.
- Векторный поиск: для правил пропуск недопустим (Р-13 журнала projects/kontext-reduktion/LOG.md); для вики он допустим, но при нынешнем объёме не нужен.
