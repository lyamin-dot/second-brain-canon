# PLAN_family-docs — реестр личных документов семьи

Летопись без Claude Project. Состояние — `STATE.md`, решения и тупики — `LOG.md`.

## Цель

Андрей в любой момент видит в Google Sheets, какие документы по видам и типам есть у каждого члена семьи, у каких истёк срок и каких не хватает; Claude в любой сессии отвечает на вопрос о номере документа по этой книге. Новый скан в папке семьи попадает в книгу без участия Андрея.

Фаза 1 — немецкие документы (папка сканов в OneDrive). Фаза 3 — то же для российских документов (запись Р-1 журнала).

## Инварианты

1. Номера документов, имена членов семьи кроме владельца, даты рождения, пути и имена личных папок и файлов в этот репозиторий не пишутся (И-7 `second-brain-git`). Они живут в книге и в локальном `config.json` на компьютере Андрея.
2. Скан не копируется ни на какой носитель. Для распознавания страница уходит на сервер потоком (картинка на stdin одноразового контейнера без сети) и на диске сервера не остаётся.
3. Ключ сервисного аккаунта не покидает сервер: локальный скрипт получает по SSH токен на один час.
4. Лист «Правки» пишет только человек; робот его читает и создаёт один раз (шапку). Все остальные листы книги — робота, он пересобирает их целиком (`google-drive-docs` §4, «лист — единица владения»).
5. Статус документа — формула от СЕГОДНЯ(), а не значение, записанное роботом: срок истекает в книге вовремя, даже когда компьютер выключен.
6. Номер недействующего документа (просрочен, неактуален после гражданства, договор расторгнут) не показывается ни на одном видимом листе, а при следующей синхронизации стирается и со служебного листа (запись Р-4 журнала).
7. Файл или папка со словом «Alt» — старый недействительный документ, пропускается (слово Андрея, запись Р-3 журнала).
8. Неуверенное распознавание не выдаётся за верное: такая запись получает уверенность «проверить», а срок, который не прочитан, — статус «❓ срок не прочитан», а не «бессрочно».

## Устройство

| Часть | Где живёт | Что делает |
|---|---|---|
| код (`extract_text.py`, `mrz.py`, `classify.py`, `catalog.py`, `sheets.py`, `sync.py`) | `C:\Users\lyami\family-docs\tools` на компьютере Андрея, без GitHub — запись Р-2 журнала | весь конвейер |
| `config.json`, кэш текстов, журнал прогонов | `%LOCALAPPDATA%\family-docs` | люди, роли, возраст, гражданство, ID книги; кэш распознанного по sha1 файла |
| распознавание | сервер n8n, образ архивного воркера (Tesseract 5.3, deu, eng, rus, osd) | `docker run -i --rm --network none` на каждую страницу |
| выдача токена | скрипт в папке проекта в домашнем каталоге на сервере | токен Sheets API на час под сервисным аккаунтом сервера |
| книга «Документы семьи DE» | Google Drive Андрея, ID — `STATE.md` | листы ниже |
| запуск | Планировщик Windows, задача «FamilyDocs Sync»: при входе (через 3 мин) и каждые 30 минут | `run_sync.cmd` → `sync.py` |
| ответы на вопросы | инструмент gsheets-read (воркфлоу «Claude → Google Sheets Read»), книга расшарена его сервисному аккаунту на чтение | Claude из любой сессии |

Конвейер одного прогона: обход папки (размер и время изменения; облачные файлы OneDrive не скачиваются, пока не изменились) → текст новых файлов (текстовый слой PDF, docx, иначе распознавание первых двух страниц серым JPEG 300 dpi) → тип по имени файла, поля по тексту → для удостоверений второй проход распознавания по алфавиту MRZ и разбор MRZ с контрольными цифрами → «Правки» → листы книги. Если ничего не изменилось, книга не переписывается.

Листы книги: «Матрица» (виды и типы × люди), «Не хватает» (нет обязательного или рекомендуемого, просрочен, истекает в 90 дней, срок не прочитан), «Документы» (по записи на документ), «Файлы» (каждый файл папки и что с ним сделано, включая пропущенные), «Правки», «Справочник», «Лог», служебные «_данные» и «_проверка» (скрыты).

Справочник видов и типов (`catalog.py`): удостоверения личности, право на пребывание, гражданство и персональные данные, налоги и соцстрахование, транспорт, профессиональные, здоровье, страховые полисы, семья — 38 типов. У типа: есть ли номер, вид срока (на документе / бессрочно / до расторжения / по возрасту для паспорта РФ) и нужность по ролям (обязательный, рекомендуемый, по ситуации). Роли и возраст — из `config.json`.

Лист «Правки»: действие «добавить» — запись без файла (так внесены внутренние паспорта РФ из присланного PDF); «исправить» — заменяет все автоматические записи этого человека и типа; «скрыть» — убирает их.

Не дефект, не расследовать: строка «Детское пособие» у детей и «Свидетельство о браке» у взрослых — «🟡 нет», пока в папке нет скана: тип рекомендуемый, номер Kindergeld и запись о браке в папке отсутствуют. Записи журнала прогонов на листе «Лог» от 2026-10-22 15:51 и 15:52 — сквозная проверка тестовым файлом, а не изменения документов.

## Риски

- Распознавание фотографий карт с голограммами ненадёжно (права, карта больничной кассы): поле получает «проверить», правка — листом «Правки».
- Компьютер включается редко: новый файл попадает в книгу при следующем включении. Сроки при этом считаются вовремя (инвариант 5).
- Связь с сервером медленная на отправку (около 65 КБ/с): поэтому серый JPEG, а не PNG (тупик Т-1).
- Тип определяется прежде всего по имени файла: скан с безликим именем («scan_001.pdf») попадёт в «Файлы» как «прочее», пока его не переименуют или не внесут в «Правки».
