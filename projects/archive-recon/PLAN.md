## Цель

Действующая цель (решение Р-17 LOG.md, 2026-10-10; заменяет цель «каталог тестовой папки — достигнутая цель» из Р-14): система, которой владелец пользуется как врач — находит статьи и руководства по теме без опоры на свои папки, видит, какая версия руководства свежая, что лежит дважды и что ещё не проработано. Путь к ней — четыре ступени проработки архива (раздел «Ступени и приёмка» ниже); ступень берётся только приёмочным тестом, а не фактом сбора данных. Сначала ступени 3 и 4 принимаются на тестовой папке «AA Beruf», затем тот же конвейер идёт на главный архив, затем — на новые файлы.

Предыдущая цель (Р-14 LOG.md, 2026-09-27): каталог тестовой папки (см. STATE.md, «Где смотреть результат каталогизации») вместо проверки метода на главном архиве. Проверка Р-17 показала, что этим каталогом пользоваться для поиска по теме нельзя, поэтому цель заменена.

Текст ниже — ИСХОДНАЯ цель проекта, историческая, сохранена для контекста фаз Ф1–Ф3 (Ф1 завершена и использована напрямую в качестве метода каталогизации, фазы Ф2 и Ф3 в исходном виде закрыты).

Научиться разбирать личный архив PDF-статей по специальности (анестезиология, интенсивная терапия, неотложная медицина), не зная заранее, как он организован. Результат этого проекта — не каталог статей, а перечень подтверждённых способов организации архива (схем вложенности папок, маркеров статуса в именах файлов, состава типов файлов) плюс замер эффективности инструментов и подходов, которыми этот перечень собирается. Каталогизация содержимого статей — отдельная задача, к ней не переходят, пока метод разбора не подтверждён хотя бы на части архива.

Главный архив лежит на отдельном диске и сейчас недоступен. Тестовая база — папка Google Drive (ID 100K6ANAOStQ19kQfT2RLt0Hw0wtn0o1r), предложенная владельцем как тренировочная. По факту она не тренировочная в смысле «маленькая»: около 24 тематических подпапок плюс отдельные Google Docs и Google Sheets в корне, плюс минимум один PDF без всякой подпапки. При первом же взгляде внутрь (папка Sepsis) обнаружилась одна конкретная схема: подпапка на статью, часто с датой в названии; флаг «OHNE MM» в имени подпапки или файла означает «конспект (mind map) ещё не сделан»; пара файлов «‹Тема› MM.pdf» + «‹Тема›.mom» означает «статья переварена, есть конспект». Эта схема не принимается за схему всего архива — см. И-1.

## Инварианты

И-1. По одной просмотренной подпапке правило для всего архива не пишется. Схема, увиденная один раз, — гипотеза; она подтверждается или опровергается следующими просмотренными подпапками, с учётом их числа.

И-2. (Действовал для фаз Ф1–Ф3 при исходной цели. С решения Р-17 LOG.md, 2026-10-10, НЕ действует: ступень 4 — это именно содержание первых страниц, темы и метаданные конкретных статей.) Предмет этого проекта — способы организации, а не содержание статей. Резюме, теги, метаданные конкретных статей в рамки не входят, если не требуются для распознавания самой схемы (пример: разбор CME-статьи Thieme понадобился, чтобы понять, что у таких статей есть встроенный блок Kernaussagen и вопросы CME — это факт о типе файла, не резюме конкретной статьи).

И-3. Каждый обнаруженный паттерн организации фиксируется вместе с адресом (путём папки), где он найден, и числом подпапок из просмотренных, которые ему соответствуют. Паттерн без примера — не паттерн.

И-4. Случай, не подошедший ни под один известный паттерн, не отбрасывается и не подгоняется под существующий силой — фиксируется отдельно как нераспознанный, с путём.

И-5. Ведётся замер применённых инструментов: что использовано на каждом шаге, что получилось, и где есть измеримая стоимость (токены, число вызовов, время) — она фиксируется в LOG.md как часть записи о попытке или решении, а не отдельным счётчиком.

И-6. Организация тестовой папки не считается отражением структуры архивов, которые будут даны позже. То, что тестовая папка организована удачно, — недоказанный тезис, не допущение по умолчанию. Файлы в её корне (Google Docs, Google Sheets с прошлыми заметками и попытками каталогизации) не являются ни инструкцией, ни образцом схемы для этого проекта — они фиксируются как найденные факты, не как правило для подражания.

## Метод

(Метод фазы Ф1 — обход агентом через Google Drive MCP. С решения Р-15 LOG.md, 2026-09-27, опись любого архива ведёт локальный скрипт archive_scan.py, а не агент; метод ниже сохранён как описание Ф1.)

## Параметры обхода (решено 2026-09-25, Р-3 LOG.md)

- Глубина: не более 2 уровней вложенности на тематическую подпапку — пока не станет ясен тип вложенности этой подпапки, глубже не идти.
- Выборка: 5 элементов на тематическую подпапку, не всё содержимое. Общее число элементов в папке берётся бесплатно из ответа search_files (длина списка), без открытия остальных. В таблице правил число подтверждений пишется как «N из выборки 5 при общем размере папки K».
- Запись: результат обхода накапливается за один проход по всем оставшимся тематическим подпапкам корня; запись в STATE.md и LOG.md — одна сводная в конце прохода, не по одной на подпапку.
- Граница нераспознанного случая (И-4) — на усмотрение исполнителя по ситуации: при сомнении фиксируется отдельная строка, не подгонка под существующий паттерн.

## Ступени и приёмка (решение Р-17 LOG.md, 2026-10-10)

Ступень 1 — структура: какие папки есть и как они устроены.
Ступень 2 — опись файлов: имена, типы, размеры.
Ступень 3 — библиографические данные: год, DOI, тип документа, номер реестра AWMF, дубли, статус проработки (есть ли рядом мемокарта).
Ступень 4 — содержание: текст первых страниц, по нему темы, и из всего этого база для поиска.

Ступень считается взятой, когда владелец задаёт системе вопросы приёмочного набора и получает ответы, которым верит. Ступени 3 и 4 принимаются вместе: главный вопрос (а) требует текста первых страниц.

Приёмочный набор:
(а) Что почитать по теме. Проверочные темы: сепсис, массивное кровотечение и гемостаз, реанимация, политравма, делир, вентиляция и ARDS. Ответ — список статей, собранный без опоры на папки владельца, без ложных находок, упорядоченный по году.
(б) Какие руководства у меня есть, какая версия каждого самая свежая и какие версии устарели.
(в) Какие файлы лежат дважды.
(г) Что прочитано, но не проработано (нет мемокарты) — статус, которому можно верить.
(д) Найти документ, имя файла которого ничего не говорит о содержании («02.pdf», «5.1.pdf», имя файла издательства Springer вида «s40140-021-00511-z.pdf»), — по названию или по тексту.
(е) Где у меня написано про конкретный клинический вопрос (пример: дозировка транексамовой кислоты) — в пределах сохранённого текста первых страниц.

## Метод: как книга, разрезанная на файлы, собирается по главам (решение Р-31 LOG.md, 2026-10-13)

Это правило проекта для любого будущего разбора, в том числе главного архива. Код — tools/build_data.py, раздел «книги из файлов-глав». Английская копия — PLAN_fixes.en.md, раздел «Book assembly algorithm».

Главная мысль. Файл относится к главе не по имени и не по заголовку внутри, а по номерам страниц книги, напечатанным в самом файле. Имя файла не используется вообще: оно часто врёт (файл «5.1» содержит главу 7, «24.5» — главу 23, «KursbuchECHO0XX» — главу 6).

Шаги.
1. Найти книгу. В тексте первых страниц каждого файла искать колонтитул издательства вида «Фамилия, Название (ISBN 978-…)». Файлы с одним ISBN — одна книга. Так нашлись Kursbuch Notfallsonografie (Blank), Kursbuch Echokardiografie (Flachskampf), Basiswissen POCUS (Bailer) и не собранная «Checkliste Sonographie». Thieme печатает этот колонтитул на каждой странице; у других издательств признак другой — для них шаг проверяется заново.
2. Найти оглавление. Обычно это первый файл книги (титул, выходные данные, Inhaltsverzeichnis): «01 Anhang», «KursbuchECHO001», «001 POCUS». Прочитать его целиком: коннектором Диска read_file_content по PDF или скриптом на компьютере. Сохранить список глав: номер, название, первая страница главы в книге; последнюю страницу текста книги взять по строке «Sachverzeichnis» или «Literatur».
3. Найти страницы файла. В тексте файла рядом с колонтитулом стоят печатные номера страниц книги: «… All rights reserved. 23 Dieses Dokument …» или «23 Blank, Kursbuch …». Собрать все такие номера (регулярное выражение PAGE в скрипте). Начало файла — самый маленький номер, конец — начало плюс число страниц PDF минус один. Пример: в «5.1.pdf» номера 44, 45, 46, в PDF 10 страниц, значит файл — страницы 44–53 книги.
4. Отнести к главе. Глава файла — последняя глава оглавления, чья первая страница не больше начала файла. Пример: глава 7 начинается со страницы 44, глава 8 — с 80, значит «5.1.pdf» (44–53) — глава 7. Если конец файла заходит за начало следующей главы, файл задевает несколько глав, и в названии пишется «Kap. 7–8».
5. Особые случаи.
   - Номеров страниц нет или начало файла раньше первой главы — это титул и оглавление, отдельная строка книги.
   - У двух файлов одинаковые страницы — вероятно, копия (KursbuchECHO008 и KursbuchECHO008_Print).
   - Страницы файла целиком лежат внутри другого, более длинного файла — пометка «эти страницы целиком есть в файле …» (12.2 внутри 11, ECHO015 внутри ECHO0XX).
6. Посчитать полноту. Для каждой главы: сколько её страниц покрыто файлами из всех, сколько страниц в главе (от её начала до начала следующей). Глава без своих файлов, начало которой лежит в конце файла предыдущей главы, помечается «начало главы есть в конце файла …».
7. Проверить. При первом применении к новой книге или новому издательству сверить результат с заголовками в тексте файлов: первый заголовок из оглавления, найденный в тексте файла, должен принадлежать той же главе. Для Kursbuch Notfallsonografie глава по номерам страниц совпала с раскладкой по заголовкам (запись Р-28) у всех 73 файлов.

Запасной путь, если номеров страниц в тексте нет: искать в тексте первых страниц файла заголовки разделов из оглавления (например «7.2 …»); самый ранний найденный заголовок даёт главу, найденные заголовки той же главы — диапазон разделов. Он слабее: видит только первые страницы файла и путается на стыках (запись Р-28).

Чего метод не делает. Не склеивает PDF и не переименовывает файлы. Не вносит в repo оглавления и названия глав — это текст издательства, он живёт только в данных страницы (запись Р-28). Не работает с целыми книгами одним файлом — для них оглавление берётся из закладок PDF (отложено, раздел «План исправлений по критике 2026-10-13»).

## Работа с книгами через сервер (решение Р-32 LOG.md, 2026-10-13)

Зачем сервер. Полный текст всех страниц и оглавления нужны, чтобы поиск отвечал на клинические вопросы и чтобы целые книги разбирались по главам. Через чат это не делается: шесть книг весят 200–786 МБ и в окно чата не грузятся, а полный текст (десятки и сотни мегабайт) не помещается в страницу поиска (её предел 16 МБ). Поэтому текст и поиск живут на сервере, а облачная сессия и страница обращаются к ним через n8n. Схема «одна книга — один чат» отвергнута: она не масштабируется на главный архив.

Как устроено.
1. Зеркало. rclone на сервере держит копию папки «AA Beruf» (только PDF) на диске сервера, доступ к Диску только на чтение — через сервисный аккаунт n8n-liamin@decent-surf-488714-u4.iam.gserviceaccount.com, которому владелец открывает папку правом «Читатель».
2. Индекс. Скрипт tools/pdf_index.py проходит зеркало и для каждого PDF сохраняет: md5 (тот же ключ, что у страницы и отметок), закладки PDF как оглавление, печатные номера страниц (page labels), текст каждой страницы в базу SQLite с полнотекстовым поиском, список страниц без текста для распознавания. Немецкие умлауты складываются: «Tranexamsaure» находит «Tranexamsäure». Точные копии в базу второй раз не пишутся. Проверено на тестовом PDF в облачной сессии 2026-10-13.
3. Доступ. Сервис распознавания на сервере получает четыре адреса только для чтения: поиск, текст одной страницы, оглавления, сводка. n8n получает три воркфлоу-инструмента: «ArchiveRecon Fulltext Search», «ArchiveRecon Page Text», «ArchiveRecon Outlines Read».
4. Облачная сессия по оглавлениям собирает 39 целых книг по главам (глава = файл плюс диапазон страниц), добавляет их на вкладку «Книги»; отметка «Прочитано» на главе целой книги получает ключ «md5 файла плюс диапазон страниц». На вопросы по содержанию отвечает поиском по полному тексту через n8n со ссылкой на файл и страницу. Можно ли звать поиск сервера прямо со страницы (через коннектор n8n), проверяется отдельной пробой; без неё полнотекстовый поиск идёт через чат.

Кто что делает.
- Владелец, один раз: открыть папку «AA Beruf» сервисному аккаунту правом «Читатель»; положить на сервер JSON-ключ этого аккаунта, если сессия сервера его не найдёт (она даст точные шаги); запустить сессию Claude Code на сервере словами «Прочитай projects/archive-recon/SERVER_TASKS.en.md в репозитории lyamin-dot/second-brain-canon и выполни задачу S0»; вернуть отчёт сессии сервера в облачную сессию, если та не может писать в repo.
- Поправка 2026-10-13 (Р-33 LOG.md): Claude Code на сервере исполняет только разрешённые команды ops-* (ops-status, ops-ocr-fetch) без прав root; установку пакетов, rclone, прогон индекса и правку сервиса делает владелец по SSH командами агента, обслуживающего сервер (Claude Project «01_Развитие сервера»). Агент сервера решает, КАК делать на сервере; SERVER_TASKS.en.md говорит, ЧТО нужно и как принимается результат.
- Исполнители задач S0–S3 файла SERVER_TASKS.en.md (дополнительная роль по 4.6: доска заданий для сессии сервера на английском, задания пишет облачная сессия, отчёты дописывает сессия сервера в раздел Report; читатель — сессия сервера при каждом старте; бюджет чтения не задан).
- Облачная сессия: принять отчёты по объекту (вызовом воркфлоу n8n, а не по словам отчёта), собрать книги по оглавлениям, перестроить страницу, провести повторный тест моделью Opus.

Порядок: S0 проверка сервера → S1 зеркало → S2 индекс → S3 доступ через n8n → облачная сессия: книги и поиск → тест Opus → распознавание страниц без текста, ночная синхронизация (фаза Ф6) → главный архив тем же конвейером со своим зеркалом и индексом (фаза Ф5; нужно около 80 ГБ диска).

Риски: места на диске сервера может не хватить для главного архива — проверка S0; самые большие PDF могут потребовать много памяти — скрипт обрабатывает файл постранично и помечает упавший файл, не останавливая обход; закладки есть не у всех книг — без закладок книга разбирается методом печатных номеров страниц (раздел «Метод: как книга, разрезанная на файлы, собирается по главам») или остаётся целой.
