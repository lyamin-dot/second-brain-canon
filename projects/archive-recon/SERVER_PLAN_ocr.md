# План: распознавание книг архива на сервере без участия Андрея — версия для человека, 2026-10-21

Статус: ПРИНЯТ Андреем 2026-10-21 в 12:09. Он согласился на рабочий контейнер вместо запуска на хосте (это меняет его решение 16 октября «на этом этапе запускать на хосте») и на то, что код на сервере меняется только его командой, а роль сервисного аккаунта drive-reader на папке «AA Beruf» остаётся «редактор». Коллега из проекта archive-recon (распознавание и каталогизация) принял устройство с дополнениями, они внесены ниже.
Автор: агент сервера (Claude Project «01_Развитие сервера»). Канон проекта сервера — документ SERVER_INDEX в Google Docs; этот файл лежит здесь, потому что план относится к конвейеру проекта archive-recon. Английская копия для агента: SERVER_PLAN_ocr.en.md; если версии расходятся, верна английская. Пути на сервере, адреса и номера в этот файл не пишутся (репозиторий публичный) — они в снимке сервера в файлах проекта сервера.
Основание: ревизия denken третьего уровня 2026-10-21 над первым вариантом плана агента сервера; встречный план сессии archive-recon от того же дня.

## Задача
Распознать 40 файлов из папки «Telegram» на Диске (около 5,3 ГБ: сканы без текстового слоя, сканы с частичным слоем, PDF с настоящим слоем и рисунками), положить текст в поисковый индекс и дать сессиям Claude читать результат без ручной пересылки команд.

## Устройство
Новый сервис в compose — рабочий контейнер archive:
- Внутри: Python, PyMuPDF (закладки PDF для оглавления, печатные номера страниц; на ней написан tools/pdf_index.py), Tesseract с английским, немецким, русским и определением поворота страницы, инструменты PDF poppler, rclone, SQLite.
- Без root, без доступа к docker и к хосту. Подключены только папка архива (запись) и папка ключа drive-reader (только чтение). Ограничения: 1,5 ядра, 1,5 ГБ памяти — у сервера 8 ГБ без файла подкачки, и раздувшееся распознавание на хосте могло бы стоить базе бизнеса принудительной остановки ядром.
- Своя сеть, в которой кроме него только n8n; n8n вписан в эту сеть и в compose, чтобы следующее пересоздание n8n её не потеряло. До Postgres и Vaultwarden контейнер не дотягивается. Новых открытых портов нет.
- Работает постоянно и продолжает с места остановки: следующая книга по очерёдности → скачать и сверить контрольную сумму с Диском → язык: первые три страницы распознаются сразу английским, немецким и русским, дальше книга идёт с сочетанием, давшим лучшую уверенность → распознать КАЖДУЮ страницу (по умолчанию 200 точек на дюйм) → снять текстовый слой, если он есть → записать в индекс → удалить скачанный файл → отметить книгу в очереди.
- На каждую страницу три текста: слой как есть, распознанный текст как есть, поисковый текст распознавания со склейкой переносов на месте. Каждое совпадение поиска несёт источник: слой, распознавание или оба. Поисковый текст пересобирается из сырого без повторного распознавания.
- Правило склейки: дефис сохраняется, если вторая часть начинается с заглавной буквы (немецкие составные слова), по умолчанию да; минимум две буквы с каждой стороны переноса.
- Разрешение 300 точек для книг с рисунками решает сессия archive-recon по своему замеру на первой книге (около 20 страниц, в том числе 103, 104, 141–155, число слов из словаря при 200 и при 300 точках).
- Почему распознаются все страницы: слой бывает мусорным (в первой книге 1202 управляющих символа и скрытый русский текст) и теряет подписи в рисунках (первая книга, страницы 103 и 104). Правило «распознавать, если слоя нет» молча выбросило бы такие страницы из поиска. Цена — около полутора суток машинного времени (предположение).
- Почему свой Tesseract, а не общий сервис распознавания: новый код очереди общего сервиса ни разу не проверен в работе, и суточный прогон стал бы его первым испытанием; постраничная отправка гоняла бы файл целиком на каждую страницу (скан на 300 страниц по 200 МБ — около 60 ГБ записи временных файлов на книгу).

## Каналы
- Внутренние адреса, только в сети archive: состояние, поиск, страница, управление (http://archive:8080/status, /search, /page, /control/...).
- Воркфлоу-инструменты n8n: «поиск», «статус и страница», «управление». «Управление»: по книге — поставить заново, пропустить, поставить в очередь, очерёдность, язык, разрешение; разрешение по умолчанию; пересборка поискового текста всех книг; параметры склейки; пауза и продолжение. Язык принимается только из английского, немецкого, русского и их сочетаний через «+», разрешение — только целое от 150 до 400, остальное отклоняется: эти значения попадают в команду распознавания. Произвольный код через «управление» не исполняется. Воркфлоу создаёт агент сервера после «да» Андрея по правилу для воркфлоу.
- Код меняется только командой Андрея: скачать по коммиту, сверить контрольную сумму, перезапустить сервис archive. На массовом прогоне код заморожен.
- Уведомления: личный чат Андрея в Telegram, которым уже пользуются действующие воркфлоу («WB Monitor Telegram Reader», «OZON Money Telegram»). Предложено: воркфлоу n8n раз в час читает состояние контейнера и пишет только при остановке или завершении — без новой точки входа, потому что адреса n8n открыты в интернет через Caddy. Если сессия archive-recon настаивает на вызове из скрипта — только с проверкой секрета в заголовке, секрет лежит только на сервере. Ждёт ответа сессии archive-recon.
- Запуск приёмки: сессия archive-recon сама ставит отложенное сообщение в свою сессию на расчётный конец прогона.

## Шаги
1. Андрей по команде агента сервера, только чтение: устройство compose, сети, сети n8n, диск, номер пользователя, файлы ключа. СДЕЛАНО 2026-10-21, вывод совпал со снимком сервера.
2. Агент сервера: код в tools/ этого проекта; прогон у себя в рабочей среде на скане и на PDF со слоем и рисунками.
3. Андрей по командам агента сервера: копия compose, сервис и сеть, n8n вписан в сеть, код по коммиту со сверкой суммы, сборка, запуск только archive, подключение n8n к сети без перезапуска. Проверка: запрос состояния из контейнера n8n отвечает пустой очередью.
4. Агент сервера после «да»: воркфлоу-инструменты.
5. Тестовая фаза: первая книга («contralateral» находит страницу 251, сниппеты без хвоста склеенных слов) и одна книга-скан без слоя.
6. Массовый прогон 40 файлов.
7. Независимый приёмщик Opus, не делавший работу: вопросы по оглавлениям трёх случайных книг, попадание подтверждается заголовком главы; запасной путь для номеров — печатные номера страниц из PDF, иначе сдвиг по одной главе (в первой книге сдвиг 19). Порог: 4 из 5 по каждой книге среди пяти лучших.
8. Агент сервера: отчёт, правка снимка сервера, записи в журналы.

## Стопы
Свободно меньше 20 ГиБ — пауза. Три книги подряд с ошибкой. Пять версий кода без успеха на тестовой фазе. Приёмка ниже порога. Нужна правка существующих воркфлоу, других сервисов compose или запись на Диск.

## Отклонено
- Автоматическая подтяжка кода из репозитория раз в сутки: пока у drive-reader права редактора, подтянутый код мог бы обратиться к Диску с правом записи; к тому же в репозиторий пишут многие сессии, и подтяжка сделала бы его каналом исполнения кода на боевом сервере. На тестовой фазе она медленнее команды Андрея, на массовом прогоне код заморожен — экономии нет.
- Отдельный пользователь на хосте с cron и виртуальным окружением Python: шире доступ (хост достаёт до всей сети контейнеров), больше движущихся частей.
- Общий сервис распознавания — см. «Устройство».
- Классификатор «какие страницы распознавать» — теряет страницы с мусорным слоем.

## Вердикт ревизии
Решение есть, частично вырожденное: прогон идёт без Андрея, а правка кода требует его одной команды на версию. Барьер Андрея «drive-reader остаётся редактором» не снят — это и есть цена.
