## Почему извлечение метаданных из PDF — нетривиальная задача

PDF ориентирован исключительно на визуальное представление (координаты глифов) и почти не содержит семантической структуры — в отличие от HTML/XML нет тегов, указывающих, что блок текста — заголовок или имя автора. Надёжное извлечение требует ML-моделей или эвристик.

## Сравнение инструментов

GROBID — отраслевой стандарт для парсинга научных PDF. Каскад CRF/Deep Learning, 55+ внутренних меток (заголовок, авторы, аффилиации, аннотация, список литературы). На бенчмарке PubMed Central (1943 документа) макро-F1 0.80–0.89 для заголовков и списков литературы; лучший среди open-source (против CERMINE, Science Parse, ParsCit). На немецком точность ниже: сноски вместо списка литературы, сокращения типа «Hrsg.» сбивают базовые модели (проект EXCITE); для максимальной точности нужно дообучение. Работает и без него, просто хуже. Разворачивается локально через Docker, бесплатно, без лимитов запросов, нужно ≥ 4 ГБ ОЗУ на контейнер; python-клиент grobid_client_python; вывод — TEI XML с тегами title/author/date/title[@level=j] (журнал), парсится grobid_tei_xml или BeautifulSoup.

Docling (IBM Research) — парсер нового поколения на анализе макета (layout analysis), модели (включая TableFormer) обучены на DocLayNet. Восстанавливает правильный порядок чтения в многоколоночных статьях, точность извлечения таблиц — 97.9%. Конвертирует сложный PDF (клинические руководства AWMF, немецкие CME-статьи с врезками/инфографикой) в чистый Markdown или JSON — это можно передать дальше regex или локальной LLM для нестандартных метаданных.

Zotero — гибрид: pdftotext сканирует первые страницы на DOI → запрос в CrossRef/PubMed; без DOI — вероятностный поиск по заголовку в CrossRef (fuzzy search). Эффективно для современных англоязычных статей; для немецких guideline без DOI или старых сканов часто даёт сбой, пустые поля или ложные совпадения из-за ошибок OCR. Web API (библиотека Pyzotero) позволяет интегрировать библиотеку во внешние скрипты.

CrossRef API — не парсер PDF, а узел валидации: REST API по DOI или текстовому запросу (библиотеки habanero, crossref-commons). Ограничение: только документы, зарегистрированные издателем — исключает большинство внутренних протоколов клиник, госдокументы и серую литературу. Требуется указать email для доступа в «Polite Pool», иначе жёсткие лимиты запросов.

Mendeley (Elsevier) — закрыла локальную базу (шифрованное облачное хранение) — не годится для open-source пайплайна.

Paperpile — браузерный, глубокая интеграция с Google Workspace, но массовое автоизвлечение ограничено ручным экспортом RIS/CSV.

pdf2doi — лёгкая Python-библиотека, ищет DOI/arXiv ID в сыром тексте через regex (напр. 10.\d{4,9}/[-._;()/:A-Z0-9]+), затем валидирует через API. Легко встраивается в пайплайны.

Embedded-метаданные PDF (exiftool, PyPDF2, XMP/Document Information Dictionary) — НЕНАДЁЖНО: поле Author часто содержит имя ПО (напр. Microsoft Word), Title — техническое имя файла при сохранении. Полагаться на эти поля не рекомендуется.

## Опыт сообщества (r/datacuration, r/zotero) по организации архивов

«Папочная парадигма» (Folder Fallacy) признана неэффективной для архивов из сотен/тысяч файлов: папки взаимоисключающие, а статья часто принадлежит нескольким категориям сразу. Дублирование файла для помещения в несколько папок ведёт к рассинхронизации аннотаций; неконтролируемое разрастание вложенных коллекций (collection bloat) трудно исправить постфактум.

Рекомендуемая схема: единая плоская папка (напр. Medical_Library_PDFs на Google Drive) + жёсткая машиночитаемая номенклатура файлов ([Первый Автор]_[Год]_[первые 3–4 слова заголовка].pdf) + уникальные citekeys (напр. Muller2023a) + фасетные теги с префиксами вместо папок-категорий: status/unread|in_progress|annotated, type/RCT|review|guideline|CME, topic/airway|sepsis|neuroanesthesia — взаимоисключающие типы тегов важны, чтобы не накопились сотни одноразовых ключевых слов. Для Zotero 7 — плагины Attanger и ZotMoov (пришли на смену устаревшему ZotFile) автоматически переименовывают и перемещают файлы по шаблону.

## Архитектура пайплайна «папка PDF → Google Sheets»

Подход 1 (серверный Python-скрипт, полная автоматизация). Шаг 1: google-api-python-client + service account (credentials.json) — обход Google Drive, список PDF, сверка с уже обработанными, загрузка новых во временную папку. Шаг 2, каскад: сначала pdf2doi (эвристический поиск DOI) → если найден — CrossRef через habanero/crossref-commons (чистый JSON: авторы, год, название, журнал) — покрывает большинство стандартных и CME-статей; если DOI нет — фолбэк в GROBID (локальный Docker-контейнер через grobid_client_python), разбор TEI XML через grobid_tei_xml/BeautifulSoup. Шаг 3: запись в Google Sheets через gspread + pandas — все данные в один DataFrame и одним пакетным вызовом (worksheet.update(...)); построчная запись (один вызов API на строку) ведёт к блокировке по квотам.

Подход 2 (Zotero как движок синхронизации, API Sync). Файлы импортируются в Zotero, встроенный движок ищет метаданные; параллельно Python-скрипт через Pyzotero тянет всю библиотеку через Zotero Web API v3 (API-ключ) в JSON → pandas DataFrame → синхронизация с Google Sheets. Преимущество: статус чтения, заметки и аннотации из PDF-ридера Zotero автоматически попадают в колонки таблицы.

## Дедупликация

Хэширование файлов (MD5/SHA-256) НЕ работает для научных PDF: издатели (Springer, Thieme, Elsevier) внедряют водяные знаки, IP, timestamp скачивания — один и тот же документ даёт разные хэши. Надёжная дедупликация — только по извлечённым метаданным.

RapidFuzz (C++-перепись FuzzyWuzzy, в 20–40 раз быстрее) — стандарт для nечёткого сравнения заголовков. Метод token_sort_ratio или token_set_ratio (токенизация, алфавитная сортировка, удаление дублей) устойчив к разному порядку слов в заголовке. Порог совпадения обычно 90–95%. Для десятков тысяч файлов — библиотека Dedupe (активное обучение для правил блокировки); для сотен файлов достаточно RapidFuzz.

## AWMF и серая немецкая литература (без DOI)

Клинические рекомендации AWMF — серая литература, часто без DOI и без строгих библиографических блоков, на которых обучен GROBID. У AWMF есть своя жёсткая нумерация реестра — Registernummer (напр. «006-120»). Regex для извлечения из сырого текста (Docling или pdfplumber):
re.search(r'Registernummer\s*[:\-]?\s*(\d{3}\s*-\s*\d{3})', text, re.IGNORECASE)
При находке паттерна документ классифицируется как «AWMF Guideline»; по номеру можно обратиться к сайту реестра AWMF за актуальным статусом (действует/пересматривается) и точным официальным названием, игнорируя визуальный мусор титульного листа.

Медицинские CME-статьи (журналы типа «Die Anästhesiologie» Springer, журналы Thieme), как правило, аккуратно индексируются в CrossRef и содержат явный/скрытый DOI на первой странице — для этого пула связка pdf2doi + CrossRef работает надёжно (по данным исследования).

## Три ранжированные рекомендации исследования (по растущим трудозатратам программирования)

1. Гибридный workflow на базе Zotero: Zotero 7 + ZotMoov (переименование/перемещение в папку на Google Drive) → встроенное извлечение + автообнаружение дублей (Duplicate Items) → Python-утилита на Pyzotero + gspread для синхронизации с Sheets. Преимущество: нулевой риск потери данных, удобный интерфейс для чтения, встроенное цитирование.
2. Полностью автоматический Python-пайплайн: Docker + GROBID (docker run --rm -p 8070:8070 grobid/grobid:0.8.0) → скрипт обходит Google Drive, к каждому файлу — pdf2doi → CrossRef при находке DOI, иначе GROBID (дополнительно — поиск Registernummer регуляркой) → RapidFuzz против уже записанных заголовков (порог >92% — дубликат, удаляется лишняя копия с Drive) → уникальные записи пакетом в Sheets через gspread. Преимущество: полная автоматизация без закрытых экосистем.
3. Docling + LLM для сложной немецкоязычной вёрстки: PDF → Docling → структурированный Markdown (колонки, заголовки, таблицы сохранены) → передаётся в LLM со строгим системным промптом (schema-first: извлечь Автор, Название, Год, Организация (AWMF/DGAI), Номер протокола — в формате JSON) → JSON напрямую в колонки Sheets. Преимущество: преодолевает ограничения GROBID/CrossRef на серой неиндексируемой немецкоязычной литературе, не зависит от визуального макета.
