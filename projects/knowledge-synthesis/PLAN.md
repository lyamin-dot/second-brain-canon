# PLAN_knowledge-synthesis — цель, финиш, закон, порядок работ

Проект заведён 2026-10-21 по слову Андрея в чате SYS («Оформи данный проект по синтезу знаний как отдельный проект с инструкциями, результатами и прочим, все по схеме … Название я принял»); основание и отвергнутое — запись Р-1 `LOG.md`. До этого работа шла задачей лаборатории `projects/knowledge-synthesis/HISTORY_2026-10-18_to_2026-10-21.md` (с 2026-10-18); у задачи появились фазы, общий следующий шаг и названный финиш, и по пункту 4б.7 Skill `second-brain-git` она задачей быть перестала. Текущее положение дел — `STATE.md`; решения с датами — `LOG.md`.

## Цель

Каждый Skill каталога держит знание в форме правила, а не истории: один кластер — одно правило, переписанное целиком, а не дописанное; у каждого факта один носитель; особенностей отдельных проектов, книг, воркфлоу и кабинетов в Skills нет — только указатели на их носителей.

Размер Skills — не цель, а сведение. Синтез может и увеличить Skill (синтез `n8n-engineering-manual`: с 211 926 до 251 468 байт), и это правильный исход, если ничего не потеряно и правила стали проверяемыми. Уменьшением обязательного чтения занимается соседний проект `projects/kontext-reduktion/`; общий у двух проектов один рычаг — раскладка Skill на слои по поводу чтения (`meta/PLAN_skill-layers_2026-10-20_v3.md`, раздел 2).

## Финиш

1. Все Skills каталога имеют статус «готов» в разделе 6 `meta/SKILLS_MAP.md`: синтез (или разбор по носителям) выполнен, независимая приёмка пройдена, живой Skill совпал с зеркалом `skills/<имя>/` по снимку.
2. Открытые вопросы владельцу в отчётах синтеза закрыты: решены или переданы в задачу или проект с адресом.
3. Шаги 6–8 плана версии 3 (`meta/PLAN_skill-layers_2026-10-20_v3.md`, раздел 5) исполнены или отвергнуты Андреем с записью в `LOG.md`.

## Закон

Правила синтеза живут в одном файле — `meta/PROTOCOL_knowledge-synthesis.md` (закон, шаги С1–С5, «Чего в Skill не бывает», роли и классы исполнителей). Здесь они не повторяются: копия стала бы вторым носителем.

Решения Андрея, которые действуют для каждого прохода (адреса — в истории задачи лаборатории, файл `projects/knowledge-synthesis/HISTORY_2026-10-18_to_2026-10-21.md` на коммите 421cb72):
1. Синтез, а не перенос: правило вместо истории, перезапись кластера вместо дописывания (2026-10-18; раздел «Проблема и замер»).
2. Опровергнутый диагноз хранится в журнале, в Skill — одна строка «не путать» (2026-10-18, пункт 0.4.1 CORE, `core/R-06a.md`; раздел «Решения Андрея 2026-10-18»).
3. Синтез касается и уже написанных правил, а не только новых уроков: полный проход по каталогу (2026-10-18, там же).
4. Skill — инструкции для всех; состояние и особенности конкретного проекта, таблицы, книги, воркфлоу, сервера или кабинета в Skill не пишутся (2026-10-20; раздел «Решение Андрея 2026-10-20: Skill — инструкции для всех»). Skill, целиком состоящий из особенностей, не синтезируется, а разбирается по носителям — так сделано с `n8n-workflow-registry` 2026-10-21.
5. Каждый проход заканчивается независимой приёмкой исполнителем, который работу не делал и отчётов исполнителей не читал (протокол, раздел «Шаги», шаг С5 «Проверить сохранение»; Skill `avtopilot`).
