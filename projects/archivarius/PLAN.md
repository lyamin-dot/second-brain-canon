# Архивариус — читатель корпусов знания

Проект заведён 2026-10-10 сессией SYS (Аргус) по слову Андрея в чате SYS того же дня. Это глубокая переработка прежнего Claude Project «Архивариус», а не новая сущность: функция та же (читать старые корпуса, извлекать ценное, не плодить дубли и мусор), сменились носитель, вход и выход. Обоснование выбора — запись Р-1 журнала этого проекта. Не путать с проектом `projects/archive-recon/` — тот каталогизирует личный архив PDF-статей по медицине, у него другой предмет.

Текст прежнего мастер-промпта сохранён в `meta/prompts/archivarius.md` (резерв, не действует).

## Цель

Закрыть дыру Главной задачи SYS «цикл знания» (`labs/sys/t-knowledge-loop.md`): ни один корпус знания не остаётся без читателя, ни один читатель без выхода, ни один выход без следа применения. Архивариус — кандидат в первые читатели.

Признак достижения цели: хотя бы один урок, извлечённый Архивариусом из корпуса без читателя, виден в живом Skill или в файле `meta/` репозитория, и это доказано обратным чтением объекта.

## Почему корпуса без читателя (показание к операции)

1. По `core/R-06b.md` (пункт 0.5.4) Зона Б документа INDEX в Google Docs — холодное хранилище записей типов Урок, Событие, Результат; назначенный читатель — «обслуживание», то есть раздел 12 ядра системы (CORE).
2. По `core/MANIFEST.md` раздел 12 снят решением владельца 2026-09-07.
3. Следствие: у Зон Б всех замороженных документов читатель есть только на бумаге.

4. Уточнение после Ф1 (запись Р-4 журнала): функцию обслуживания по уроку взял харвест (`meta/PROTOCOL_harvest.md`). Он читает только записи новее строки «последний харвест», окно открылось с даты 2026-08-31, а журнальные корпуса и датированные блоки Зоны Б вошли в его чтение только 2026-10-08. Значит без читателя осталось не всё содержимое корпусов, а их прошлое окно — записи старше 2026-08-31. Единственное известное чтение этого окна — читатель R2 по SYS_JOURNAL_2026 2026-08-13 (`registry/documents.md`, блок T-010).

ИСТОРИЯ ДИАГНОЗА: при заведении проекта 2026-10-10 считалось, что у Зон Б нет никакого живого читателя (пункты 1–3 выше). Опровергнуто в тот же день на Ф1: живой читатель есть — харвест, — но он не смотрит назад дальше 2026-08-31. Отсюда смена роли: Архивариус не постоянный второй читатель, а разовый читатель прошлого окна.

Если появится другой читатель прошлого окна, показание пересматривается.

## Что Архивариус читает и что выдаёт

Вход — прошлое окно корпусов: записи старше 2026-08-31. Новее этой даты корпуса читает харвест, Архивариус их не трогает. Корпуса (ID — `registry/documents.md`; носитель — Google Docs, все только читаются):
- журнальные корпуса SYS_JOURNAL_2026, SYS_JOURNAL_2026_02, N8N_JOURNAL_2026;
- журналы инцидентов JOURNAL_INCIDENTS, N8N_INCIDENT_LOG;
- датированные блоки Зоны Б и секции НАКОПЛЕННЫЙ ОПЫТ и РЕШЕНИЯ замороженных INDEX (SYS, N8N, OZON_UE, WB_UE, WB_LOGISTICS, WB_REVIEWS) — записи старше 2026-08-31.

По Зоне Б OZON_UE: незакрытые записи уже взяты при переносе 2026-09-30 (`labs/ozon-ue/INDEX.md`, шапка); для Архивариуса там остаются только уроки.

Работа конечна: когда прошлое окно всех корпусов разобрано, проект закрывается сменой статуса в `registry/projects.md`. Дальше корпуса читает только харвест.

Выход — уроки, а не задачи. Задачи из Зон Б уже подняты переносами в репозиторий; искать их повторно — вырожденная работа (запись Р-2 журнала).

Урок применяется по адресату:
- адресат — файл репозитория (`meta/*.md`, `STATE.md` или `PLAN.md` проекта, `core/`) — Архивариус применяет сам, коммитом с обратным чтением;
- адресат — Skill — позиция в `registry/maintenance-queue.md`; уроки для Skills копятся до конца разбора и выходят одним пакетом вместе с отложенной позицией AI-4 очереди — Андрей разбирает их все разом (запись Р-5 журнала);
- урок, который уже есть в живом Skill, — не выдаётся, корпус помечается «просмотрено».

Сверка «есть ли урок в Skill» — только с живыми Skills, загруженными в сессию (в облачной сессии Claude Code они лежат в `/mnt/skills/plugins/<имя>/`), а не с зеркалом `skills/`: зеркало отстаёт (`labs/sys/t-skills-mirror-drift.md`). Не дефект, не расследовать: расхождение зеркала с живым Skill на этом проекте ожидаемо до закрытия той задачи.

## Инварианты проекта

1. Замороженные документы Google Docs только читаются. Ни одной записи в них.
2. Корпус читается диапазонами строк (gdocs-read, `fromLine`/`toLine`); обрезанный вывод значит «не прочитано» (second-brain-git 7.7).
3. Ни одной новой роли Архивариуса (вход Inbox, ночной смотритель, компилятор сводных страниц), пока у первой нет применённого выхода. Основание — правило порядка Главной задачи: второй читатель не запускается, пока первый не имеет применённого выхода.
4. Своего хранилища скомпилированного знания у проекта нет: скомпилированный слой системы — Skills и файлы `meta/`. Вторая вики рядом с ними — второй источник истины (запись Р-2 журнала, отвергнуто).

## Фазы

Ф0. Стоп прежнего промпта. Исполнитель — Андрей. Первой строкой в поле Project instructions прежнего проекта «Архивариус» вставить: «Проект выведен из работы 2026-10-10, ничего не записывать». Результат — строка видна в проекте. Текст промпта уже сохранён (`meta/prompts/archivarius.md`).

Ф1. Есть ли уже первый читатель. ЗАКРЫТА 2026-10-10 записью Р-4 журнала: первый читатель с применённым выходом был (R2 по SYS_JOURNAL_2026, гейт 2026-08-13, 6 из 17 находок дошли до решений), живой читатель новых записей есть (харвест); правило порядка Главной задачи второго читателя не запрещает, но место Архивариуса — только прошлое окно.

Ф2. Зонд трёх корпусов. Исполнитель — сессия SYS или сессия Архивариуса; модель — высокого уровня (решение «урок новый или уже в Skill» — суждение, а не извлечение). Корпуса: N8N_JOURNAL_2026 (читателя в реестре нет вовсе), SYS_JOURNAL_2026 (читался один раз, 2026-08-13), Зона Б N8N_INDEX. В каждом взять 20 записей старше 2026-08-31, самых поздних в этом окне, и по каждой вынести один вердикт:
- «новый урок» — правила нет ни в одном живом Skill и ни в одном файле `meta/` и `core/`;
- «уже есть» — назвать Skill или файл и якорь-строку;
- «хроника» — запись о событии без правила на будущее;
- «устарел» — правило относится к механике, которой больше нет (Google Docs как носитель канона, пароли-канарейки, снятый раздел 12).
Перед зондом прочитать паспорт READER_R2_passport (ID — `registry/documents.md`, блок T-010): формат выхода и гейт R2 переиспользуются, а не изобретаются заново.
Результат — запись в журнале с таблицей вердиктов по каждому корпусу (по каждой записи — адрес строки в документе).
Опровергающий факт: во всех трёх меньше трёх «новых уроков» из двадцати — замысел не спасается, прошлое окно помечается просмотренным, Ф3 не начинается, проект закрывается.
Цена чтения: gdocs-read приносит документ в контекст целиком через contextData, диапазон строк этого не режет (google-drive-docs, раздел 3.5). Корпус крупнее примерно 100 КБ (SYS_JOURNAL_2026 был 142 562 Б на 2026-09-14 — `projects/git-migration/NOT_TAKEN.md`) читается в среде с bash, где большой ответ инструмента харнесс кладёт в файл, и разбирается из файла.

Ф3. Переключение Claude Project. Исполнители — сессия SYS (полный текст нового мастер-промпта по `references/prompt-craft.md` Skill second-brain-engineer) и Андрей (вставка текста в проект). Результат — проект «Архивариус» стартует по этой папке.

Ф4. Разбор корпуса с лучшим выходом зонда. Исполнитель — сессия Архивариуса. Результат — признак достижения цели (раздел «Цель»).

## Параллельная ветка — практики сообщества

Разобраны 2026-10-10 ревизией denken, приняты Андреем в чате того же дня (запись Р-3 журнала). Исследование — `wiki/notes/RES-004.md`.

И-А. Детектор противоречий при записи решения. При команде !save, перед записью записи типа Решение, сессия ищет по оглавлению журнала проекта ключевые слова темы; при совпадении в новой записи — строка «заменяет Р-N» или «противоречит Р-N, вопрос Андрею». Адресат — `references/save.md` Skill second-brain-engineer. Исполнитель: сессия SYS готовит полный текст «было → стало», Андрей вносит. Опровергающий факт: через месяц в журналах снова есть вопрос, уже решённый раньше.

И-Б. Подшивка ценного ответа только с названным читателем. Ответ, стоивший исследования, подшивается в репозиторий, только если назван читатель — задача или проект, которые его используют. Без читателя ответ остаётся в чате. Адресат — тот же `references/save.md`, рядом с И-А. Полный текст правки И-А и И-Б «было → стало» — позиция AI-4 очереди `registry/maintenance-queue.md` (выдан Андрею в чате SYS 2026-10-10).

И-В. Контрольный набор вопросов как приёмка переноса, не как монитор. При приёмке переноса проекта в репозиторий, рядом с проверкой Контролёра, — пять вопросов о проекте («где ID книги X», «какой следующий шаг»), на которые незнакомая сессия должна ответить только по канону. Адресат — `references/migration.md` Skill second-brain-git, пункт 13.4. Опровергающий факт: три приёмки подряд набор не нашёл ни одного дефекта — набор снимается.

И-Г. Skills как код. Источник Skill — `skills/` репозитория, правка — коммитом с обратным чтением, Андрей загружает архив, собранный из репозитория. Снимает задачу `labs/sys/t-skills-mirror-drift.md`. Меняет процесс Андрея необратимо — до исполнения отдельная ревизия denken уровня Р3.
