# PLAN_ozon-main-photo — главное фото карточек Ozon

## Цель и финиш

Главное фото каждой карточки Ozon обоих кабинетов (ИП и Кипарис) — в формате 3:4 (соотношение ширины к высоте от 0,70 до 0,80), без искажения и потери галереи. Финиш — нет карточек «вне нормы, есть замена» по свежей описи, кроме тех, что Андрей решил не трогать. После финиша проект закрывается (статус в `registry/projects.md`), повторная опись — по запросу Андрея, без расписания.

Откуда проект: работа начата в проекте content (записи Р-12…Р-15 журнала `projects/content/LOG.md`, наряды Н-10.11-04 и Н-10.11-05) и выделена сюда 2026-11-10 по слову Андрея (запись Р-1 журнала этого проекта).

## Инварианты

1. Замена — только на первое фото карточки WB того же артикула и только если оно «лучше» по правилу ниже.
2. Запись — полным набором: первым фото WB, затем прежние фото в прежнем порядке без прежнего главного; цветовое фото и фото 360 — из снимка без изменений.
3. До записи — снимок всех фото каждой карточки в файл репозитория; откат — тем же инструментом со списком из снимка.
4. Боевая запись — только после «да» Андрея на конкретный список (файл с перечнем карточек) из режима «проверка». Одно «да» покрывает один названный список целиком.
5. Один воркфлоу на кабинет, у каждого свой ключ с правом записи; воркфлоу записи не публикуются.
6. Приборов наблюдения не заводим: новые карточки с узким фото ловит повторная опись по запросу Андрея или будущий конвейер слайдов проекта content.

## Правило «фото WB лучше» (все четыре условия)

1. Соотношение 0,70–0,80 и меньшая сторона не меньше 900 px.
2. На фото тот же товар и та же фасовка: объём или масса на этикетке совпадают с названием карточки Ozon.
3. Чистый снимок товара на однородном светлом фоне, без инфографики и текста поверх.
4. Этикетка не хуже, чем на текущем фото Ozon: не иноязычная там, где на Ozon русская.

Условие 1 проверяет скрипт; условия 2–4 — модель глазами, затем независимый приёмщик. Не прошло хоть одно — карточка не трогается, в отчёте «WB не лучше» с причиной.

## Как мы работаем дальше

Роли. Андрей — решения и одно «да» на список каждой волны. Чат проекта (руководитель) — разбирает с Андреем вопросы, пишет наряд, принимает итог по объекту. Claude Code на компьютере Андрея (диспетчер) — исполняет наряд до отчёта: фото на CDN Ozon и WB из облачной сессии закрыты, поэтому работа с фото — только там.

Порядок, шаг за шагом:

1. Андрей смотрит 4 карточки пилота на витрине и отвечает на три вопроса из `STATE.md`, раздел «Ждёт Андрея». Без ответа на вопрос 1 массовой замены нет.
2. Чат пишет наряд на волну 1 и выдаёт его Андрею для вставки в Claude Code. Волны:
   - волна 1 — узкие полосы (соотношение меньше 0,50) — самый большой видимый выигрыш;
   - волна 2 — 0,50–0,70 и шире 0,90, кроме карточек, которые по ответу на вопрос 2 не трогаем;
   - волна 3 — 0,80–0,90, только если по вопросу 3 Андрей сказал «менять».
3. Внутри наряда диспетчер:
   1. делает свежую опись тем же правилом, что Н-10.11-04, и сохраняет скрипт описи в `scripts/` этого проекта: карточки меняются, старый CSV для записи не годится;
   2. отбирает карточки волны и прогоняет правило «лучше»: модель смотрит пары фото пачками, приёмщик пересматривает выборку не меньше 10 % и все отказы;
   3. снимает снимок всех фото карточек волны в `waves/<номер>/snapshot.json`;
   4. прогоняет режим «проверка» и кладёт список к записи в `waves/<номер>/to_write.csv`;
   5. останавливается и показывает Андрею одну цифру и файл: «к записи N карточек, список такой-то» — Андрей отвечает «да» один раз на весь список;
   6. пишет пачками по 50 карточек на кабинет, каждую карточку читает обратно; любая отклонённая модерацией или снятая с продажи карточка — откат этой карточки и стоп волны;
   7. на следующий день перечитывает статус всех записанных карточек режимом «статус» (разовая проверка волны, не расписание);
   8. пишет отчёт `waves/<номер>/REPORT.md`, запись в `LOG.md`, строку в `STATE.md`.
4. Перед волной 1 инструменты записи меняются: белый список из 5 карточек пилота в коде заменяется проверкой «карточка есть в утверждённом списке `to_write.csv` этой волны». Это правка воркфлоу — она называется в поле РАЗРЕШЕНО наряда, паспорт дописывается.
5. После последней волны — финальная опись, итог в `LOG.md`, статус проекта «закрыт».

Граница с проектом content: его конвейер слайдов позже заменит галереи целиком. Этот проект чинит только главное фото сейчас; карточку, по которой конвейер слайдов уже начал работу, отсюда не трогаем — сверка по `projects/content/STATE.md` перед каждой волной.
