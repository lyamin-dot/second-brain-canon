# PLAN_obzor — страница «что у меня в разработке»

Летопись без Claude Project; работа идёт в сессиях Claude Code. Состояние — `STATE.md`, решения и тупики — `LOG.md`.

## Цель

Андрей открывает одну ссылку и за минуту видит все свои проекты и задачи: что сейчас в работе, что на паузе, что только идея, что уже работает, когда что-то последний раз двигалось, какой следующий шаг и что ждёт лично его. Страница собирается из канона сама; Андрей ничего в неё не вносит. Назначение — снять тревогу «что-то забыто» (слово Андрея, чат SYS 2026-10-31; запись Р-1 журнала).

## Финиш — проект закрывается, когда выполнены все четыре условия

1. Страница открывается по одной ссылке.
2. На ней все проекты из `registry/projects.md` — летописи, лаборатории и проекты с INDEX в Google Docs.
3. Страница обновляется без участия Андрея.
4. В каждом `STATE.md` летописи есть короткий блок для скрипта (раздел «Устройство», пункт 2).

После финиша страница остаётся инструментом; строка проекта в реестре получает статус «закрыт», а скрипт и способ обновления описываются там, где их найдёт следующая сессия (адрес — решение фазы Ф3).

## Инварианты

1. Страница закрытая: страница-артефакт claude.ai или файл на Google Диске Андрея, но не файл в этом репозитории. Причина: репозиторий пока публичный, а колонка «ждёт Андрея» может назвать личные дела — семейные документы, финансы (И-7 `second-brain-git`). Скрипт сборки может лежать в репозитории, если сам таких данных не содержит.
2. Страница собирается скриптом, а не пересказом модели. Модель нужна один раз — разметить проекты при старте (Ф1) — и для строк, которые скрипт не смог прочитать. Причина: пересказ двадцати файлов моделью дорог и каждый раз выходит по-разному.
3. Страница только показывает. Уведомлений, напоминаний и сигналов она не шлёт (предпочтение Андрея: не наращивать приборы наблюдения вокруг работы).
4. Источник правды о проекте — его собственные файлы канона. Страница — производная; если она расходится с файлом проекта, прав файл.

## Устройство (замысел, уточняется в Ф1)

1. Источники: `registry/projects.md` (состав, статус, носитель); `STATE.md` каждой летописи; `INDEX.md` каждой лаборатории; Зона А INDEX каждого проекта в Google Docs (читается через gdocs-read, Skill google-drive-docs); дата последнего коммита папки проекта (`git log`).
2. Блок для скрипта в начале `STATE.md` (заведён Ф2, запись Р-4 журнала): сразу после строки пути и пустой строки — строка-метка `<!-- obzor-блок: … -->`, под ней строки вида `> Поле: значение` до первой строки другого вида. Поля: `Состояние` — одно слово из словаря «в работе», «работает», «пауза», «идея», «закрыт»; `Дата` — ГГГГ-ММ-ДД последней записи по делу, а не дата правки блока; `Что это` — одна фраза; `Следующий шаг` — одна фраза; `Ждёт Андрея` — что нужно от Андрея, или «—»; `Срок` — необязательное, повторяемое: `ГГГГ-ММ-ДД — что`. Блок правится тем же шагом, что разделы ниже, и подчиняется `meta/CONTRACT_state-content.md` (следующий шаг, открытый вопрос, блокер, состояние с датой) — это не новый слой, а сжатый вход в те же категории. В блок не пишутся классы 1 и 2 И-7 `second-brain-git`: репозиторий публичный. Разбирает блок `meta/scripts/obzor_build.py`; строка не по форме — ошибка скрипта с именем проекта, страница не пересобирается.
3. Строка проекта на странице: что это одной фразой; состояние; когда последний раз двигалось; следующий шаг; что ждёт Андрея — отдельной колонкой.
4. Опора: скрипт `meta/scripts/readers_inventory.py` (ревизия системы, опись читателей 2026-10-30) уже проходит все проекты по клону — в Ф1 проверить, можно ли достроить его, а не писать второй.

## Фазы

| Фаза | Содержание | Готово, когда |
|---|---|---|
| Ф1 | первая версия страницы: сессия читает канон, размечает проекты, строит страницу-артефакт | Андрей получил ссылку и сказал, чего не хватает и что лишнее |
| Ф2 | блок для скрипта во всех `STATE.md`; скрипт строит страницу по блокам | страница пересобирается скриптом без модели и совпадает с Ф1 по составу |
| Ф3 | обновление без Андрея по расписанию (образец — снимок `registry/n8n-map.md`, который строит воркфлоу) | страница обновилась сама хотя бы один раз, проверено по дате на странице |

## Связи

- Харвест (`meta/PROTOCOL_harvest.md`) с этим проектом не сливается (запись Р-1 журнала). Связь в одну сторону: страница показывает, какие проекты двигались с прошлого харвеста, и харвест может читать только их; подготовительный шаг харвеста, закрывающий устаревшие записи «ждёт», делает страницу точнее.
- Ревизия системы (`labs/sys/t-system-revision.md`): контракт содержания `STATE.md` и скрипт его разбора принадлежат ей; блок фазы Ф2 согласуется с ней.
- Команды «!review все» и «!status» (Skill second-brain-engineer, раздел Р8) читают то же по запросу в чате; страница — их постоянная версия, команды остаются.
- После финиша Андрей решает по фактам страницы, вводить ли закрытый словарь статусов в реестре проектов и предел «не больше трёх проектов в работе одновременно» (предложение сессии SYS 2026-10-31, Андреем не принято и не отклонено).

## Риски

- Блок в `STATE.md` перестанет обновляться, и страница начнёт врать. Защита — дата блока и дата последнего коммита папки рядом на странице: расхождение видно глазом.
- Проекты с INDEX в Google Docs читаются только через воркфлоу n8n, а не клоном — эта часть дороже и может отставать от остальных.
- Гипотеза (не проверена): страницу-артефакт можно переопубликовать по тому же адресу из запланированной задачи; если нет — Ф3 выбирает файл на Google Диске.
