## Определение мусора

Мусор — то, у чего есть лучшая версия себя. Данные, лежащие в нескольких местах, остаются источниками до тех пор, пока собранная версия не построена и не проверена; только после этого старые места становятся мусором. Пробные воркфлоу и зонды мусором не являются — это инструменты, их не удалять и не архивировать (строка 6 `meta/PENDING_RULES.md`, подтвердил Андрей 2026-10-08). Старые воркфлоу, связанные с декларациями (семейство «Deklaration *», снятые Seed, Worker, Watch, Seed РОСС, Worker РОСС, мониторинги V.2 и прочие, которые карта Ф2 отнесёт к старой версии), перемещаются в архив n8n в конце работы над этим проектом — решение Андрея 2026-10-10 (запись Р-3 журнала); до этого не трогаются.

### 0. Итог проверки рабочей гипотезы

Гипотеза подтверждается с одним исключением и становится принципом архитектуры (после утверждения):
- Свойства АРТИКУЛА, одинаковые для всех четырёх кабинетов: номер декларации (и любого другого документа), даты документа, ТН ВЭД, ОКПД 2, «нужен КИЗ» (требование закона к товару). Истина — документы и сайт Liqui Moly, не кабинеты.
- Свойства КАРТОЧКИ (кабинет и юрлицо): что фактически стоит в карточке, вердикт площадки по документу, галка «Нужна маркировка КИЗ» (needKiz, площадка выводит её сама), галка «Подтверждаю нанесение маркировки» (kizMarked — заявление конкретного юрлица по закону о маркировке; с 2026-10-21 его значение для обоих кабинетов WB — «Нужен КИЗ» основного кабинета, запись Р-39, пункт 9), регистрация юрлица в «Честном знаке» по товарной группе.
- Почему исключение важно: копирование карточечного свойства между кабинетами — это ложное заявление второго юрлица (kizMarked) или блокировка карточки (needKiz без регистрации в «Честном знаке» — моторные масла кабинета WB ИП 08.10, `meta/PROTOCOL_wb-card-write.md` раздел 5). Исключение с 2026-10-21 (запись Р-39, пункты 9 и 10): needKiz и kizMarked обоих кабинетов WB берутся из «Нужен КИЗ» основного кабинета через лист «Снимок КИЗ». По слову Андрея это не ложное заявление: товар, которому нужен КИЗ, мы физически продаём только маркированным.
- Переходная оговорка: «нужен КИЗ» по артикулу сейчас берётся из основного кабинета WB, потому что там его проверили руками по каждому товару (решение Андрея 2026-10-09, `projects/deklaration-wb/LOG.md` Р-12). Цель 2.0 — вычислять его из ОКПД 2, ТН ВЭД и предмета по справочнику требований площадки (блок Б2), а основной кабинет оставить проверкой: расхождение вычисленного с ручной отметкой — строка сверки, а не молчаливая замена.

### 4. Книга 2.0

Одна книга Google Sheets «DEKL 2.0 — эталон и сверка» (создаётся в Ф5, блок Б3; регистрируется в `registry/documents.md` тем же шагом). Листы:

|---|---|---|---|

Правила книги и почему:
1. Ручной ввод и роботный вывод — разные листы. Причина: робот, пересобирающий лист целиком, стирает ручные колонки (корень R18; опасение уже записано для ARTIKEL_PROPS — `projects/deklaration-wb/STATE.md`, цель 5). Раздельные листы снимают вопрос целиком, а не дисциплиной.
2. Склейка — по ключу, никогда по номеру строки и не цепочкой IMPORTRANGE. Причина: позиционная склейка дала артикулу 1000 чужой номер Liqui Moly, причину доказать не удалось (`meta/PRODUCT_DATA_HIERARCHY.md` раздел 4).
3. Строка сверки — «артикул × кабинет», не «артикул» с колонками на каждый кабинет. Причина: четвёртый кабинет в широком листе — это новые колонки и правка всех формул; в длинном — новые строки. Человеческий широкий вид при желании строится фильтром поверх.
4. У каждого значения эталона есть «откуда». Причина: без него «пусто» неотличимо от «не искали», а ОКПД 2 по аналогии неотличим от ОКПД 2 из выписки.
5. Ошибка и пустая ячейка — не данные; проверки перед чтением из раздела 6 `meta/PRODUCT_DATA_HIERARCHY.md` выполняются роботом эталона до записи, и непрошедшая проверка останавливает пересборку.
6. Ловушки книг, уже оплаченные старой версией (`meta/DECLARATION_SCAN.md`, ловушки 1–3 и 6): схема узла Google Sheets обязана совпадать с заголовками листа, иначе узел падает; лист, в который робот дописывает строки, держится без формул — ячейку с формулой узел считает занятой и пишет ниже; узел в режиме autoMapInputData пишет только переданные поля — этим держатся ручные колонки рядом с роботными; дату робот пишет так, чтобы Google Sheets понял её как дату, иначе условное форматирование молча перестаёт работать.
7. Робот листа карточек останавливает запись, если площадка вернула меньше заданного минимума карточек (у WB — 150): пустой или обрезанный ответ не должен затирать лист (`projects/deklaration-wb/LOG.md` Р-8). Строка карточки, которую площадка больше не отдаёт, в листе остаётся — устаревшая строка отличается по времени обновления.

Почему отдельная книга, а не новые листы Price Master: (а) задание — свои таблицы 2.0 отдельно до переключения; (б) Price Master читают проекты вне 2.0 (wb-logistics — CURRENT и Artikel), и сбой робота 2.0 не должен их задевать; (в) мнение сессии — книгу оставить отдельной и после переключения, а Price Master держать как слой ключа товара. Решает Андрей.

### 6в. ОКПД 2: костыль до появления справочника (решение Андрея 2026-10-13, запись Р-13 журнала)

Почему костыль. Код ОКПД 2 (общероссийский классификатор продукции) в самих декларациях не указан: у 275 из 339 артикулов с действующей декларацией значение пусто. Справочника «код ТН ВЭД → код ОКПД 2» нет, собрать его сейчас из имеющихся документов нельзя. Андрей решил: полностью правильные коды сейчас не получить, это принято и отложено.

Что сделано. В листе «Эталон» книги 2.0 две последние колонки: okpd2_work (рабочий код) и okpd2_work_src (откуда он взят). Реальная колонка okpd2 не меняется и остаётся единственной настоящей. Правило подстановки действует только для артикулов, у которых «нужен КИЗ» равно «Да» и реальный ОКПД 2 пуст: (1) если для ТН ВЭД артикула известен ровно один код (3403199000 → 20.59.41.000, 3820000000 → 20.59.43.120, 2710199200 → 19.20.29.170), берётся он; (2) иначе берётся код той же группы по первым четырём знакам ТН ВЭД (2710 → 19.20.29.170, 3403 → 20.59.41.000, 3819 и 3820 → 20.59.43.120); (3) если ТН ВЭД не заполнен, подстановки нет. Каждая подстановка помечена словом КОСТЫЛЬ в okpd2_work_src и в колонке flags. На 2026-10-13: реальный код у 69 артикулов, костыль у 201 (12 по одному коду, 189 по группе, из них 150 — моторные масла с ТН ВЭД 2710198200), без кода остались 53 артикула с КИЗ «Да» и пустым ТН ВЭД.

Жёсткие ограничения костыля:
1. Колонку okpd2_work нельзя использовать как факт: ни один шаг записи на Wildberries или Ozon, ни одна сверка «артикул × кабинет» не читают её как источник истины, только колонку okpd2. Колонку okpd2_work можно показывать для оценки и для подготовки решений.
2. Прежнее правило строки ОКПД 2 в части 2 остаётся в силе: подбор по аналогии разрешён только по слову Андрея. Слово дано 2026-10-13 на все артикулы с КИЗ «Да»; на другие артикулы оно не распространяется.
3. Любая запись на Wildberries по-прежнему только после отдельного подтверждения Андрея.
4. Коды группы подобраны по трём известным парам из деклараций и одному предположению (3819 по аналогии с 3820), по классификатору не проверены. Для моторных масел 2710198200 код 19.20.29.170 взят с соседнего ТН ВЭД и, вероятно, неточен.

Как костыль убрать. Появляется проверенный справочник «ТН ВЭД → ОКПД 2» (источник — выписка декларации, Национальный каталог «Честного знака» или импортёр), Андрей утверждает его по группам; значения вносятся в лист «Ввод» с колонкой «откуда»; после этого строки okpd2_work_src со словом КОСТЫЛЬ исчезают сами, а колонки okpd2_work и okpd2_work_src удаляются из воркфлоу «DEKL 2.0 — Эталон» (узел 08A_Okpd2_Crutch) отдельным решением.
