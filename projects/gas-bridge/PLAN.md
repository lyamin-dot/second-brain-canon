## Цель

Этап А. Любая сессия Claude сама, без участия Андрея и без его включённого компьютера, читает, правит и откатывает код Google Apps Script его книг Google Sheets.

Этап Б. На этом инструменте расширять автономность системы: сессии проектов (юнит-экономика, учёт торговли на маркетплейсах) сами строят и чинят скрипты своих книг.

Книга `sku_cost_Шаблон` — не цель, а возможный подопытный; её код и карта кода — `projects/sku-cost/`.

## Границы этапа А

- Сессия читает, записывает и откатывает код. Функции запускает Андрей: запуск меняет данные книги необратимо, а запуск через интерфейс Google требует перевести каждую книгу в проект Google Cloud. Запуск — этап Б, отдельным решением.
- Запись — только в скрипты, у которых в таблице данных n8n `gas_allowlist` стоит доступ `write`. Строка с `write` добавляется только после «да» Андрея в чате. Чтение — любой скрипт, доступный аккаунту Андрея.
- Перед каждой записью создаётся версия проекта скрипта; откат — к номеру версии.
- Код книг в репозиторий не пишется: репозиторий публичный, запись в него необратима (`second-brain-git`, инвариант И-7).
- Clasp на компьютере Андрея — ручной запасной путь (Skill `clasp-apps-script`), не основа.

## Устройство (проект до приёмки)

- Ключ доступа n8n типа «Google OAuth2 API» с именем «Google Apps Script (Andrei)», право только `https://www.googleapis.com/auth/script.projects`, вход под аккаунтом Андрея. Экран согласия проекта Google Cloud — в статусе «In production»: в статусе «Testing» ключи живут 7 дней. Ключ создаётся после перевода в «In production», иначе вход придётся повторять. Право на Диск не нужно: по документации Google создание привязанного скрипта (метод projects.create с полем parentId), чтение и запись кода требуют только `script.projects`; проверяется пунктом 2 приёмки.
- Чтение — воркфлоу «Claude → Google Apps Script Read» (gscript-read): список файлов или код, плюс отпечаток проекта для сверки при записи.
- Запись — воркфлоу gscript-write, три операции. create — привязать новый скрипт к книге из `gas_allowlist`. write — сверить отпечаток основы → создать версию → заменить один файл целиком или фрагмент oldStr на newStr на сервере → прочитать обратно. rollback — создать версию текущего состояния, вернуть код версии с указанным номером, прочитать обратно. Через модель идёт только изменяемый файл или фрагмент; остальные файлы проекта воркфлоу берёт сам.
- `gas_allowlist` — таблица данных n8n: scriptId, spreadsheetId, title, access (`read` или `write`), added (кто и когда). Она же хранит идентификаторы скриптов. Найти скрипт по идентификатору книги интерфейс Google не умеет, поэтому для существующей книги идентификатор скрипта Андрей один раз берёт в редакторе: «Настройки проекта» → «Идентификатор скрипта».

## Ограничения Google — не дефект, не расследовать

- Метод записи (projects.updateContent) заменяет весь проект и версию не проверяет. Полной защиты от одновременной правки нет; сверка отпечатка основы сужает окно до секунд.
- Если Андрей правит код во вкладке редактора, открытой до записи сессии, его сохранение затрёт запись сессии. Без правок вкладка ничего не сохраняет.
- При входе Google показывает «Google hasn't verified this app»: приложение личное и не проверено Google. Проходится через «Advanced» → «Go to … (unsafe)».

## Контракт автопилота

Согласован Андреем 2026-10-18 словом «да» в чате SYS после ревизии denken уровня 2.

Критерий приёмки — по объекту, номер исполнения на каждый пункт:
1. Чтение: список файлов и код тестовой книги и книги `sku_cost_Шаблон` (8 файлов, как в выгрузке clasp).
2. Привязка: новый ключ привязывает скрипт к тестовой книге, которую создал не он, а подключённый Google Drive.
3. Запись: перед записью создана версия; обратное чтение показывает новый текст.
4. Откат: после отката отпечаток кода равен исходному.
5. Защиты: запись в скрипт вне `gas_allowlist` и запись с устаревшим отпечатком основы отклоняются воркфлоу, код не меняется.
6. Описание проекта записано и проверено обратным чтением.
