## 5. Инструменты n8n для git [источник: раздел 5]

git-read: webhook POST `{path, ref?}` → GitHub Contents API GET → `{text, sha, byteLength, encoding}`; SHA блоба — родная контрольная сумма, FNV-протез не нужен.
git-write: webhook POST `{path, newText, expectedSha, message}` → сверка `expectedSha` с текущим SHA (несовпадение — отказ с явной причиной, класс Т-05 закрыт архитектурно) → PUT → `{newSha, commitSha}`. Верификация — независимый git-read по пути, сверка SHA.
git-log: webhook POST `{path?, limit}` → список коммитов `{sha, date, message}`.
git-diff — вторая очередь, не пилот: сравнение двух ref по файлу, для приёмки правок по diff строк.
Действующие ID (подтверждено этой сессией прямым вызовом 2026-09-03, get_workflow_details, оба `active:true`): git-read `72DWYjGbeAxEgYwj`, git-write `Omt9oDYf7NthOw5T`.

## 10. Запрет Б-1 — счёт байт и контрольных сумм [источник: раздел 14.0, целиком]

Контрольная сумма (FNV-1a 32) и число байт НЕ являются доказательством ни целостности, ни потери. Хеш ловит невидимый символ, схлопнутый пробел и автозамену дефиса наравне с порчей текста и никогда не говорит, что именно изменилось. Годен ровно для одного: подтвердить, что два чтения одного файла внутри одной сессии дали одно и то же.
Запрещено по расхождению суммы или размера: останавливать фазу, возвращать перенесённые блоки, назначать пересев, требовать сверки байт-в-байт, объявлять потерю данных.
Факт правки файла между сессиями устанавливается modifiedTime (Drive metadata), не суммой. Расхождение суммы при неизменной длине — ожидаемое поведение, не сигнал.

## 16. Решения Андрея 2026-09-03 [источник: раздел 14.5]

(а) Очерёдность. Работы разделены по чатам, не по времени: один чат ведёт носитель CORE, второй — перенос файлов проектов. Правило naryad §7 «один файл — один наряд, в обе стороны» действует поверх разделения: наряды двух чатов не касаются одного файла. Это не параллельный пилот (см. §9 выше) — объекты разные.
(б) Приёмка переключения носителя. Шаг «неделя наблюдения» отменён — у него нет исполнителя (сессия не осознаёт нехватку блока как событие; монитор не отличает открытие файла человеком от чтения сессией). Взамен критерий: отказ приходит сам. Сессии, которой не хватит блока, откажется, и отказ придёт с именем и временем. Неделя без отказов по причине «этого нет в каноне» = переключение принято.
(в) Резерв мастер-промпта — предусловие переключения. Мастер-промпты нигде не резервируются: CORE Р.2 хранит URL, Skill хранит эталон, фактический текст живёт только в UI Anthropic — единственный объект системы без копии, его нельзя прочитать инструментом, сверить после правки и откатить. До вставки нового текста владелец сохраняет старый текст файлом — единственный откат, который будет. Наряд с DoD «промпт переключён» без этого файла не выдаётся и подлежит отказу по мандату.
