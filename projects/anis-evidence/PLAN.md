# Цель

Доказательная справка по анестезиологии, интенсивной медицине, неотложной медицине и терапии боли для практики владельца (Klinikum Wolfsburg, дополнительно Notarzt). Проект отвечает на клинические вопросы с опорой на Leitlinien и клинические исследования и накапливает вердикты, которые уже применены к практике.

Финиш не назван. По 4б.1 second-brain-git объект без названного финиша — лаборатория, и роли п. 4 к нему не применяются. Роли п. 4 применены здесь решением владельца от 2026-09-13; легализация — строка 4 `meta/PENDING_RULES.md`. Основание решения: закрытие задачи в лаборатории означает удаление её файла (4б.6), а клинический вердикт удалять нельзя — он отменяется новым вердиктом, но остаётся в истории.

# Инварианты проекта

И-A. Клинический вердикт и устройство проекта — разные носители. Вердикт идёт в `e-<тема>.md`, решение об устройстве проекта — в `LOG.md`. Смешение в одном файле ЗАПРЕЩЕНО.
И-Б. Вердикт без источника с годом и без названной силы рекомендации не записывается.
И-В. DOI, PMID, номер AWMF-Register, размер выборки, значение p попадают в repo только из поиска, выполненного в той же сессии. Запись такого числа по памяти ЗАПРЕЩЕНА. Вспомненное, но не проверенное исследование в repo не едет.
И-Г. У вердикта есть дата смерти — срок действия (Gültigkeit) источника, на котором он стоит. Поле обязательное. Источник без объявленного срока действия — поле пишется как год последнего пересмотра плюс пять лет с пометкой «оценка».
И-Д. Промпт проекта живёт в настройках Claude-проекта и имеет там единственный носитель. Копия промпта в repo ЗАПРЕЩЕНА (И-1 second-brain-git). В repo — только указатель и записи об изменении промпта в `LOG.md`.

# Когда пишется вердикт

Запись появляется только в трёх случаях. Обычный справочный ответ в repo не едет.

1. Владелец подтвердил в чате, что вердикт применён или применим к его практике.
2. Найден пробел в доказательной базе, у которого есть условие возврата (выход названного исследования, пересмотр названного Leitlinie).
3. Обнаружено расхождение между Hausstandard клиники и внешней доказательной базой.

Критерий держит файл от превращения в свалку справок. Ответ, который не изменит действие следующей сессии, — не вердикт.

# Форма записи

```
E-NN | В СИЛЕ | дата | клинический вопрос
  вердикт: …
  опора: источник, год, сила рекомендации   ← обязательно
  действует до: …                            ← обязательно
  расхождение с Hausstandard: …              ← по наличию
  подгруппы вне доказательной базы: …        ← по наличию

L-NN | дата | что искали
  почему не вышло: …          ← обязательно
  условие возврата: …         ← обязательно
  ближайшее по смыслу: …      ← по наличию
```

Статусы `E-NN`: `В СИЛЕ`, `ОТМЕНЕНО E-NN`, `ПРОСРОЧЕНО` (срок источника истёк, пересмотр не сделан).

Применяются без изменений положения second-brain-git 11.1–11.4: записи append-only; вердикт не редактируется, а отменяется новой записью со ссылкой; ретроспективная запись запрещена; поле по наличию, которого нет, не пишется ни прочерком, ни заглушкой; обязательное поле без содержания — запись не пишется.

`E-NN` и `L-NN` — две независимые последовательности, номера уникальны внутри своего файла (2.4). Ссылка на чужую запись пишется с именем файла: «E-07 файла e-nmba.md».

# Механика записи

Новый `e-<тема>.md` создаётся одним вызовом Git Commit Files вместе с правкой `EVIDENZ.md`. Запись двумя вызовами ЗАПРЕЩЕНА: состояние «файл темы есть, строки в списке нет» Каналом не обнаруживается.

Дозапись вердикта в существующий файл темы — Git Append, номер записи берётся из свежего чтения непосредственно перед вызовом.

Ротации в архив у клинического канона нет: канон не журнал. Файл темы, переросший потолок, делится по теме по правилу 6.3 second-brain-git — граница там, где меняется предмет, с именем, которое это говорит. Байтовый разрез запрещён.

# Риски

Р1. Файл темы наполняется справками вместо вердиктов. Держит критерий записи выше.
Р2. Вердикт переживает источник, на котором стоял. Держит обязательное поле «действует до» и статус `ПРОСРОЧЕНО`.
Р3. Пересечение с проектом ANAST_QUICKREF. Граница: там дословный текст Hausstandard, здесь внешняя доказательная база. Общее поле — только записи о расхождении по случаю 3.
