# Цель

Доказательная справка по анестезиологии, интенсивной медицине, неотложной медицине и терапии боли для практики владельца (Klinikum Wolfsburg, дополнительно Notarzt). Проект отвечает на клинические вопросы с опорой на Leitlinien и клинические исследования, накапливает вердикты и опрашивает владельца по накопленному.

Финиш не назван. По 4б.1 second-brain-git объект без названного финиша — лаборатория, и роли п. 4 к нему не применяются. Роли п. 4 применены решением владельца от 2026-09-13; легализация — строка 4 `meta/PENDING_RULES.md`.

# Язык

Язык разговора в Claude-проекте — немецкий, установлен владельцем 2026-09-13. Вопросы, ответы, опрос — по-немецки независимо от языка вопроса.

Язык канона репозитория — русский, как во всей системе. Записи `E`, `F`, `A` пишутся по-русски, клинические термины, названия руководств и дословные формулировки рекомендаций — по-немецки. Перевод немецкого названия руководства ЗАПРЕЩЁН: по переводу его не найти в реестре.

# Инварианты проекта

И-A. Клинический вердикт и устройство проекта — разные носители. Вердикт идёт в `e-<тема>.md`, решение об устройстве проекта — в `LOG.md`. Смешение ЗАПРЕЩЕНО.
И-Б. Вердикт без источника с годом и без названной силы рекомендации не записывается.
И-В. DOI, PMID, номер AWMF-Register, размер выборки, значение p попадают в repo только из поиска, выполненного в той же сессии. Запись такого числа по памяти ЗАПРЕЩЕНА.
И-Г. У вердикта есть срок действия источника. Поле обязательное. Источник без объявленного срока — год последнего пересмотра плюс пять лет с пометкой «оценка».
И-Д. Промпт проекта живёт в настройках Claude-проекта и имеет там единственный носитель. Копия промпта в repo ЗАПРЕЩЕНА (И-1 second-brain-git).
И-Е. Номера записей сквозные по проекту, а не по файлу. Запись переезжает между файлами темы при разрезе, ссылки на неё не рвутся.
И-Ж. Ярлык ответа при опросе ставит владелец. Агент ярлык не назначает и оценку знанию не выносит; он называет расхождение между ответом и записью — это факт, а не оценка.

# Нумерация

Три независимые сквозные последовательности на весь проект: `E-NNNN` — вердикт, `F-NNNN` — случай, `A-NNNN` — след опроса. Последний выданный номер каждой последовательности хранится в `EVIDENZ.md` и правится тем же действием, что и запись.

Ссылка пишется голым номером: «E-0042». Имя файла в ссылке НЕ указывается — файл меняется при разрезе, номер не меняется.

# Когда пишется запись

Вердикт `E` пишется только в трёх случаях. Обычный справочный ответ в repo не едет.
1. Владелец подтвердил, что вердикт применён или применим к его практике.
2. Найден пробел в доказательной базе с условием возврата.
3. Обнаружено расхождение между Hausstandard клиники и внешней доказательной базой.

Случай `F` пишется, когда разобран клинический случай — пережитый или смоделированный — и названа ошибка, которую владелец совершил или мог совершить. Формулировка ошибки берётся с его слов.

`A` пишется при каждом ответе в режиме опроса, без подтверждения: это факт события, а не суждение. Ответ без ярлыка строки не порождает.

```
  вердикт: …
  опора: источник, год, сила рекомендации   ← обязательно
  действует до: …                            ← обязательно

  подгруппы вне доказательной базы: …        ← по наличию

F-0007 | 2026-09-13 | краткое имя случая
  случай: пережитый | смоделированный        ← обязательно
  что разбирали: …                           ← обязательно
  ошибка, совершённая или возможная: …       ← обязательно
  чем закрыто: E-0042                        ← по наличию

A-0113 | 2026-09-20 | E-0042 | хорошо
```

Статусы `E`: `В СИЛЕ`, `ОТМЕНЕНО E-NNNN`, `ПРОСРОЧЕНО`.

Положения 11.1–11.4 second-brain-git действуют без изменений и здесь не пересказываются.

Строка `A` не содержит срока возврата. Сроки живут только в таблице ниже и меняются одной правкой для всего накопленного сразу.

# Опрос — команда `abfrage`

Запускается только словом владельца. Напоминаний, счётчиков созревшего и строк в начале сессии нет.

Пул опроса — записи `E` и `F` тех файлов тем, которые открыты в этой сессии. Запись в пуле, если: у неё нет ни одной строки `A`, либо срок по последней строке `A` наступил.

| ярлык | следующий показ |
|---|---|
| плохо | в этой же сессии и в каждом следующем опросе, пока не сменится |
| хорошо | через 7 дней |
| отлично | через 30 дней |
| надоело | через 90 дней |

Порядок в пуле: сперва `плохо`, затем записи без единой строки `A`, затем созревшие по дате — самые давно созревшие первыми.

Показ по одному: вопрос, ответ владельца, названное расхождение, ярлык, следующий вопрос. Списком ЗАПРЕЩЕНО — список позволяет подглядеть в соседние вопросы.

Вопрос ставится как клиническая ситуация, а не как цитата из руководства. Проверяется применение, а не память на формулировку.

Ярлыка «закрыть навсегда» нет: максимальный срок ухода — 90 дней.

# Разбор файла темы

Запускается, когда файл перерос потолок. Два шага, второй только при нужде.

Шаг 1 — схлопывание истории опроса. Для решения «когда спрашивать снова» значима только последняя строка `A` по каждой записи. Более ранние строки `A` удаляются. Часто этого достаточно, потому что строк `A` со временем становится кратно больше, чем записей `E` и `F`.

Шаг 2 — разрез по темам, если после схлопывания файл всё ещё велик. Граница проводится там, где меняется предмет, имя нового файла этот предмет называет (6.3 second-brain-git). Байтовый разрез ЗАПРЕЩЁН. Темы берутся из уже накопленного содержания; заранее сочинённая рубрикация ЗАПРЕЩЕНА. Номера записей при переезде не меняются (И-Е), строки в `EVIDENZ.md` правятся тем же действием.

# Механика записи

Новый `e-<тема>.md` создаётся одним вызовом Git Commit Files вместе с правкой `EVIDENZ.md`. Двумя вызовами ЗАПРЕЩЕНО: состояние «файл темы есть, строки в списке нет» Каналом не обнаруживается.

Дозапись в существующий файл темы — Git Append; номер берётся из свежего чтения `EVIDENZ.md` непосредственно перед вызовом.

При активной параллельной сессии Git Commit Files отбивается на проверке родителя, потому что его `expectedSha` — голова ветки. В этом случае используется Git Write пофайлово: его `expectedSha` — blob sha самого файла, и чужие коммиты в другие пути записи не мешают. Плата — потеря атомарности по нескольким файлам, поэтому для пары «файл темы + EVIDENZ.md» этот путь ЗАПРЕЩЁН — там ждём освобождения ветки.

Ротации в архив у клинического канона нет: канон не журнал.

# Риски

Р1. Файл темы наполняется справками вместо вердиктов. Держит критерий записи.
Р2. Вердикт переживает источник. Держат поле «действует до» и статус `ПРОСРОЧЕНО`.
Р3. Пересечение с ANAST_QUICKREF. Граница: там дословный Hausstandard, здесь внешняя доказательная база.
Р4. Ярлык `надоело` убирает вопрос на 90 дней независимо от качества ответа — слабое место замолкает молча. Принято сознательно: распоряжение вниманием за владельцем.
Р5. Пересечение с ANIS_Spiegel. Граница: там очередь тем стоит на входе и задаётся заранее, здесь опрос порождается из уже полученных ответов. Автоматического переноса тем между проектами нет.
