# PLAN_kontext-reduktion — уменьшение обязательного чтения

## Цель

Уменьшить объём текста, который сессия обязана прочитать, чтобы начать и вести работу в системе Second Brain: старт проекта, CORE, файлы состояния, Skills с пометкой «ОБЯЗАТЕЛЬНО», реестры. Уменьшать без потери содержания и без ослабления контракта записи и чтения.

## Финиш

Предложен Аргусом 2026-09-24, ждёт подтверждения владельца:
1. старт проекта SYS (Канал плюс CORE плюс основной файл проекта) — не больше 16 КБ;
2. обязательная часть каждого Skill с пометкой «ОБЯЗАТЕЛЬНО» — не больше 15 КБ, остальное читается по ссылке;
3. файл состояния каждого repo-проекта укладывается в бюджет чтения §4 second-brain-git.
Каждое число снимается с объекта (ответ Канала или клон), не по памяти.

## Инварианты

1. Ужимание текста запрещено (second-brain-git §5.1). Разрешены: перенос материала к читателю, которому он нужен; вынос в чтение по событию; удаление дубля с указателем; удаление устаревшего снимка чисел.
2. Контракт записи (CORE Р.6 базовый, `core/R-06a.md`) и контракт чтения (`core/R-07.md`) читаются на каждом старте, что бы ни снималось.
3. Один носитель у каждого правила (И-1): перенос — это перенос, а не копия.
4. Каждая мера замеряется до и после по объекту. Решение без замера «до» не принимается.
5. В журнал пишется и принятое, и отвергнутое, с причиной отказа (слово владельца 2026-09-24). Отвергнутое без причины не пишется.

## Риски

- Файл «по событию» не прочитан перед записью — запись без правила. Признак: запись в CHANGELOG вне закрытого словаря или журнальная запись без поля-симптома. Обратимость: высокая, откат — одна строка таблицы Манифеста.
- Две сессии правят один Skill и отдают владельцу полный текст — последняя заливка затирает первую. Мера: при выдаче полного текста называть якорь своей правки, чтобы её можно было перенести в чужую версию.
- Skill живёт в двух носителях — исходный Google Doc и залитая копия. Правка, не перенесённая в исходник, теряется при следующей заливке из него.
