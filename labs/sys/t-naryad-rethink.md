# Переосмысление Skill naryad: Андрей больше не шина между чатами

**Суть.** Skill naryad создавался, когда сессии не могли сами запускать друг друга, и держится на правиле «Андрей — шина»: Андрей носит наряды в другую среду и приносит ответы обратно. Андрей поручил переделать работу агентов так, чтобы на больших проектах он не носил задания и ответы. Эта задача держит принятую схему, результаты проб и решения Андрея до выдачи полного текста правок Skill naryad и avtopilot.

## Решение Андрея о схеме работы (чат SYS, 10.11)

Обсуждение и разработка нового — в чате Claude Project мелкими шагами, с Андреем на каждом шаге. Когда план готов, обдуман и проверен на ошибки, чат сам отмечает точку перехода, говорит «переходим в Code» и выдаёт один наряд; наряд подразумевает автономную работу. Исполнение — в Claude Code на компьютере Андрея. Примеры работы для автономного исполнения: переделка учёта юнит-экономики, создание контента для артикулов.

Уточнения, предложенные сессией и принятые в той же схеме:
- Признаки точки перехода (все сразу): план готов и для нового решения пройдена ревизия denken; у каждого пакета есть проверочный объект (число, отпечаток выдачи, сумма; пакет с текстом — второй круг приёмщика); всё, что может только Андрей, собрано одним списком до запуска; пакетов не меньше трёх.
- Наряд — самодостаточный контракт: цель и признак готовности объектом; окно дат цифрами; пакеты с проверочным объектом и пометкой «параллельно» или «последовательно» (последовательно — пакеты на общем ресурсе: один воркфлоу, функции, которые другой пакет измеряет); разрешённые правки списком; ручные действия Андрея списком; где остановиться; размер результатов; какие другие сессии пишут в репозиторий; куда записать итог. Пунктов, запрещённых Skill, в наряде нет. Механика инструментов проекта — в `PLAN.md` проекта, наряд ссылается на место, не переписывает.
- Исполнение: диспетчер в Code раздаёт пакеты помощникам; параллельно — где нет общего ресурса; у пишущего помощника своя копия репозитория; независимый приёмщик на каждый пакет; для денежных пакетов последняя проверка — сверка с отчётом площадки; пока идёт конвейер, в канон пишет только диспетчер.
- Возврат: итог — в канон проекта; Андрей говорит «конвейер закончил», чат сам читает канон и принимает по объекту; эстафету интегратор ставит вместо эстафеты диспетчера, а не рядом.
- Замер без нового прибора: итоговый отчёт следующего конвейера называет, сколько раз понадобился Андрей и сколько длилась работа.

Отвергнуто: диспетчер всегда в Code (разработка нового без разговора с Андреем — ошибка); диспетчер в чате Claude Project (нет копии репозитория с правом записи, скриптов, вложенных помощников; защита разрешений чата отклоняет правку общих объектов и правку текста запланированной задачи); команды агентов (экспериментальны, помощников хватает); сообщения между сессиями как возврат (этот чат их не принимает; возврат идёт через канон); Projects в claude.ai/code (на аккаунте Андрея их нет — снимок боковой панели 10.11).

## Опыт конвейера marketplace-rebuild К0–К6 (отчёты приёмщика и исполнителя, принесённые Андреем)

- Автономность безопасна там, где пакет проверяется числом; отдельный приёмщик нашёл настоящие ошибки в русском документе.

- Время исполнителя ушло на выяснение механики инструментов проекта, на пункт наряда, запрещённый Skill (строка PASSPORT), и на неточное окно дат («за октябрь»).
