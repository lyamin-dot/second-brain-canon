# Проверка размера дампов mkt2 и liquimoly_kb в ночном бэкапе сервера

Метка: РЫЧАГ. Заведена 2026-10-31 сессией SYS по решению Андрея на пакет харвеста 2026-10-31 («Да, все рекомендации»; находки Н-82 и Н-109, `meta/HARVEST_2026-10-31.md`, разделы 6 и 7).

## Суть

Скрипт ночного бэкапа сервера 2026-10-25 дополнен дампами баз `mkt2` и `liquimoly_kb` (`meta/CASES_server-tools.md`, раздел «Бэкап баз сервера n8n»). Проверка свежести в Workflow Health Monitor смотрит только `n8n_*.sql` (не меньше 50 МБ, моложе 26 часов); размер и свежесть двух новых дампов не проверяет никто (`meta/CASES_server-tools.md`, там же; `meta/CASES_sys-lab-closed-2026-10-27.md:188`). Правило Р23 Skill second-brain-engineer (`раздел «Р23. Скрипт по расписанию» SKILL.md (файл references/scheduled-scripts.md снят переносом 2026-11-06)`) требует проверять результат каждого шага скрипта по расписанию по объекту — сейчас объект ему не следует. Тот же класс, что Н-6 (база жила без копии, сводка давала ✅).

## Предложение

Добавить в проверку бэкапа по одной строке на каждый дамп: самый свежий файл по маске имени своей базы (не «последний файл в папке» — урок Х-114 списка ожидающих) моложе 26 часов и не меньше порога, снятого с текущих размеров (на 2026-10-27: mkt2 около 11 МБ, liquimoly_kb около 5 МБ — порог, например, половина текущего). Где проверять — в Health Monitor (правка воркфлоу n8n, пакет с «да» Андрея по Р10) или в самом скрипте бэкапа на сервере (рука Андрея).

## Условие приёмки

Сводка Health Monitor (или журнал скрипта) несёт строки по трём дампам; пробное отсутствие свежего дампа одной базы даёт ❌ именно по ней.

## Условие снятия

Размер и свежесть каждого дампа проверяются автоматически и проверены пробой; строка в `meta/CASES_server-tools.md` («размер дампов mkt2 и liquimoly_kb не проверяет никто») заменена описанием проверки.
