# Тело Git Replace набирается последовательностями \uXXXX

Суть: правило 8.2 Skill second-brain-git запрещает набирать кириллицу в теле вызова Канала последовательностями \uXXXX — содержимое не портится, но выход модели растёт в разы. Правило записано текстом и не держится: Skill сам называет нарушение на шести вызовах Git Replace харвеста 2026-10-08, и 2026-10-11 сессия Архивариуса (запись Р-25 журнала projects/archivarius/LOG.md) набрала так же тела четырёх вызовов Git Replace к projects/archivarius/STATE.md. Причина по 8.2: харнесс хранит прошлые тела execute_workflow экранированными, модель видит их и повторяет. Для дозаписи эту причину уже сняли кодом — Git Append File берёт текст из файла Drive; у Git Replace такого входа нет, oldStr и newStr набираются в теле.

Идея (не решение): вход Git Replace из файла Drive — {path, expectedSha, fileId, message}, где файл несёт oldStr и newStr, по образцу Git Append File. Это правка воркфлоу n8n — только после «да» Андрея (second-brain-engineer Р10). Довод против: ещё один шаг create_file и trash_file на каждую замену; для коротких замен (одно слово) он дороже набора.
