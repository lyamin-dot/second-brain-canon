# Харвест не видит проекты, перенесённые в репозиторий

Метка: РЫЧАГ. Заведена 2026-10-08 сессией SYS (Аргус) по вопросу Андрея «стоит ли запустить харвест на Git».

## Суть

Процедура `meta/PROTOCOL_harvest.md`, шаги 1 и 2, собирает опыт только из INDEX-документов Google Docs, перечисленных в `registry/documents.md`, блоки T-007 и T-009, — секции НАКОПЛЕННЫЙ ОПЫТ и РЕШЕНИЯ. Последний харвест — 2026-08-31, до переноса проектов в репозиторий; на Git харвест не запускался ни разу (Андрей, чат 2026-10-08).

На 2026-10-08 в `registry/projects.md` двенадцать проектов с носителем repo и две лаборатории. Их решения и тупики живут в `projects/<папка>/LOG.md` и в файлах задач `labs/<папка>/t-*.md`, а не в Docs. Пять INDEX из блока T-007 заморожены после переноса (N8N, WB_UE, WB_LOGISTICS, SYS, WB_REVIEWS); у OZON_UE канон перенесён в `labs/ozon-ue/`, но Зона А в Docs ещё не заморожена (`registry/projects.md`, раздел «Лаборатории»). Зона Б замороженных документов осталась в Docs и держит опыт с 31 августа до даты заморозки — поэтому шаги 1 и 2 нужны и дальше. Харвест по нынешней процедуре прочитал бы этот хвост и пропустил весь опыт, накопленный в репозитории после переноса.

ИСТОРИЯ ДИАГНОЗА: при заведении задачи 2026-10-08 считалось, что замороженных INDEX шесть (с OZON_UE) и что их чтение харвестом бесполезно, поэтому шаг 1 надо сузить до незамороженных. Опровергнуто той же сессией при подготовке правки процедуры: Зона А OZON_UE в Docs не заморожена, а Зона Б замороженных документов хранит непересённый опыт до даты заморозки.

Шаги 3–6 процедуры (очередь `registry/maintenance-queue.md`, вопросы о пересмотре `naryad`, пакет правок, сдвиг даты) от носителя не зависят и работают как есть.

## Предложение сессии

Дописать в `meta/PROTOCOL_harvest.md` шаг для repo-проектов и лабораторий: список папок — из `registry/projects.md`; по каждому `LOG.md` — записи Р и Т новее строки «последний харвест» (оглавление журнала по `second-brain-git` 7.6, в среде с клоном — `git log --since` и `grep`); по лабораториям — файлы задач, тронутые или удалённые после этой даты. Шаг 1 для Docs остаётся как есть (см. ИСТОРИЯ ДИАГНОЗА выше). Объём на 2026-10-08: около 390 записей Р и Т в двенадцати журналах и архиве журнала git-migration с датой не раньше 2026-08-31, плюс 63 файла задач двух лабораторий (счёт клоном, grep заголовков) — одна сессия целиком такой объём не прочитает. Правка файла репозитория — после «да» Андрея на текст «было → стало»; затем первый харвест на Git, в отдельной сессии.

## Ход

2026-10-08, сессия SYS. Шаг 1б дописан в `meta/PROTOCOL_harvest.md` (коммит a29abcd) и исполнен: первый харвест на Git прочитал 393 записи двенадцати журналов и 62 файла задач двух лабораторий, раздав их семи посредникам. Второй проход того же дня закрыл дыры первого: журналы Google Docs вне INDEX (SYS_JOURNAL_2026, JOURNAL_incidents, PROJECT_LOG_SYS), файлы STATE.md, PLAN.md и meta/, крупную задачу, просмотренную только поиском, и сверку по отставшему зеркалу вместо живых Skills. Процедура дополнена шестью правками (коммиты e6627bf, 7f0a65d, fdeb7be, a5b9b18, cfe3acb, f2ba1e4; blob c69e770 сверен с текстом, собранным до записи): отбор документов опыта в Docs по имени, однократное чтение замороженного документа и строка «прочитаны после заморозки», STATE.md, PLAN.md и meta/ в шаге 1б, сверка по живым Skills, форма большого пакета в шаге 5. Пакет находок (редакция 2, около 150 находок по группам А–З) выдан Андрею файлом harvest-2026-10-08.md в чате SYS; в репозитории он не хранится.

На 2026-10-09 шаг 5 не закрыт: ответы владельца на пакет приходят по частям (2026-10-09 другой сессией SYS позиция очереди G-1 снята как дубль, часть находок внесена владельцем прямо в живые Skills — см. `t-skills-mirror-drift.md`). Дата «последний харвест» не сдвинута, строка «прочитаны после заморозки» пуста. По шагу 6 в неё пойдут: N8N_INDEX (заморожен 2026-10-06), WB_UE_INDEX (2026-09-28), WB_LOGISTICS_INDEX (2026-10-04), SYS_INDEX (2026-09-30), WB_REVIEWS_INDEX (2026-10-05), PROJECT_LOG_SYS (2026-09-26); OZON_UE_INDEX — нет, его Зона А в Docs не заморожена.

## Условие снятия

Процедура харвеста читает repo-проекты и лаборатории, и по ней выполнен хотя бы один харвест — строка «последний харвест» сдвинута.
