# Харвест не видит проекты, перенесённые в репозиторий

Метка: РЫЧАГ. Заведена 2026-10-08 сессией SYS (Аргус) по вопросу Андрея «стоит ли запустить харвест на Git».

## Суть

Процедура `meta/PROTOCOL_harvest.md`, шаги 1 и 2, собирает опыт только из INDEX-документов Google Docs, перечисленных в `registry/documents.md`, блоки T-007 и T-009, — секции НАКОПЛЕННЫЙ ОПЫТ и РЕШЕНИЯ. Последний харвест — 2026-08-31, до переноса проектов в репозиторий; на Git харвест не запускался ни разу (Андрей, чат 2026-10-08).

На 2026-10-08 в `registry/projects.md` двенадцать проектов с носителем repo и две лаборатории. Их решения и тупики живут в `projects/<папка>/LOG.md` и в файлах задач `labs/<папка>/t-*.md`, а не в Docs. Шесть INDEX из блока T-007 заморожены после переноса (N8N, OZON_UE, WB_UE, WB_LOGISTICS, SYS, WB_REVIEWS). Харвест по нынешней процедуре прочитал бы замороженные документы и пропустил весь живой опыт с начала сентября.

Шаги 3–6 процедуры (очередь `registry/maintenance-queue.md`, вопросы о пересмотре `naryad`, пакет правок, сдвиг даты) от носителя не зависят и работают как есть.

## Предложение сессии

Дописать в `meta/PROTOCOL_harvest.md` шаг для repo-проектов и лабораторий: список папок — из `registry/projects.md`; по каждому `LOG.md` — записи Р и Т новее строки «последний харвест» (оглавление журнала по `second-brain-git` 7.6, в среде с клоном — `git log --since` и `grep`); по лабораториям — файлы задач, тронутые после этой даты. Шаг 1 для Docs сузить до INDEX, не замороженных переносом. Правка файла репозитория — после «да» Андрея на текст «было → стало»; затем первый харвест на Git, в отдельной сессии.

## Условие снятия

Процедура харвеста читает repo-проекты и лаборатории, и по ней выполнен хотя бы один харвест — строка «последний харвест» сдвинута.
