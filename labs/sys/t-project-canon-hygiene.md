# Гигиена канона проекта: правила вместо рассказов в PLAN.md, факты из журналов — к своему носителю

Анализ, из которого задача выросла, — `labs/sys/t-canon-after-synthesis.md`, вопрос 2 (файл снят этим же коммитом; читать по ref 421cb72). Решения Андрея по самой процедуре ещё нет.

## Проблема

После решения Андрея 2026-10-20 «Skill — инструкции для всех» файлы проектов стали носителями всего, что ушло из Skills: разбор `n8n-workflow-registry` 2026-10-21 дописал блоки в `projects/n8n/PLAN.md`, `projects/wb-reviews/PLAN.md`, `projects/wb-logistics/PLAN.md`, `registry/documents.md` и завёл файлы кейсов `meta/CASES_ozon-api.md`, `meta/CASES_wb-api.md`, `meta/CASES_external-access.md`. Качество этих файлов теперь важнее, чем раньше.

Замер того же разбора: из 456 проверенных единиц знания старого Skill 50 нашлись только в записях журналов LOG.md, а 124 — нигде, кроме самого Skill (примеры: лимит частоты Ozon на Client-Id, смысл статусов FBS, тождество выплаты Wildberries). Журнал — история, а не справочник: сессия, которой нужен факт, журнал не читает. Значит, у проектов нет шага «установленный факт из журнала переносится в PLAN.md или в файл кейсов своего домена», и эту роль до сих пор невидимо играл Skill.

Почему это не харвест: шаги харвеста (`meta/PROTOCOL_harvest.md`) собирают уроки проектов в правки Skills и протоколов; переписывать сами файлы проектов ни один шаг не велит. Почему не тот же синтез: закон синтеза «правило вместо истории» к журналу неприменим — LOG.md и есть история, он только дозаписывается (`second-brain-git` 11.1). Разбор 5.1 `second-brain-git` (перенос из STATE.md и PLAN.md) срабатывает по превышению бюджета чтения, то есть по объёму, а не по содержанию.

## Предложение сессии — процедура на один проект за раз, по слову Андрея

1. PLAN.md переписывается в форме правил; рассказы уходят ссылкой на запись журнала.
2. Факты, живущие только в журнале, выписываются в PLAN.md проекта или в файл кейсов своего домена (`meta/CASES_*.md`). Журнал не правится.
3. STATE.md — только то, что меняет действие следующей сессии.
4. Строки файлов кейсов, которые на деле относятся к одному воркфлоу (например, в `meta/CASES_wb-api.md`: `take` = 100 и окно 60 дней у Intake, ветка отмен Order Close v2, узел `06C_Map_Operation_Category`), переносятся к своему проекту — пункт 5 списка «Расширено» отчёта `meta/SYNTHESIS_n8n-workflow-registry_2026-10-21.md`.
5. Проверка сохранения — как в синтезе: таблица единиц до правки, независимый проверяющий старшего класса после.

Первые кандидаты — проекты с наибольшим числом фактов «только в журнале» по таблице поиска носителей разбора `n8n-workflow-registry`: wb-logistics и wb-ue. Таблица пока у Андрея файлом; в репозиторий — позиция AJ-31 Очереди.
