# Журнальные корпуса в Google Drive не внесены в строку заморозки харвеста

Метка: РУТИНА. Заведена 2026-10-11 сессией SYS (Аргус) на !save; захват из разговора об архитектуре проекта Архивариус в чате SYS того же дня.

## Суть

Шаг 1 `meta/PROTOCOL_harvest.md` при каждом запуске снимает дату изменения со всех документов опыта в Google Docs и полностью читает те, что изменены позже строки «последний харвест». Замороженный документ читается один раз и вносится в строку «прочитаны после заморозки» — после этого не читается. На 2026-10-11 в этой строке шесть документов INDEX и PROJECT_LOG_SYS, но нет журнальных корпусов SYS_JOURNAL_2026 (около 400 КБ), SYS_JOURNAL_2026_02, N8N_JOURNAL_2026 (около 276 КБ), JOURNAL_INCIDENTS и N8N_INCIDENT_LOG. Если в них больше никто не пишет, любое касание документа (служебная пометка, открытие с правкой) заставит харвест перечитать сотни килобайт без нового опыта. Пишут ли в них ещё — не проверено.

Связано: правило «не читать замороженные документы, кроме вопроса «где это было раньше»» предлагалось держать статусом рядом с ID в `registry/documents.md` (вариант 1 из разговора 2026-10-11); Андрей решение по этому варианту ещё не принял — вопрос записан в `projects/archivarius/STATE.md`, раздел «Открытые вопросы».

Проверено 2026-10-11 для N8N_INCIDENT_LOG (запись Р-20 журнала projects/archivarius/LOG.md): документ — не журнал, а устаревшая копия файла INCIDENT_LOG.md версии v1.1 от 2026-08-04; живой текст v1.3 лежит внутри Skill n8n-engineering-manual и содержит всё, что есть в документе. get_file_metadata: modifiedTime 2026-08-13T05:37:57Z — после этого в документ никто не писал. Строка registry/documents.md называет его «тот же спутник», то есть живым — это неверно. Кандидат в заморозку подтверждён.

## Следующий шаг

Для каждого из пяти корпусов снять дату последнего изменения (get_file_metadata) и найти последнюю запись в тексте; корпус без записей после переезда своего проекта в репозиторий — кандидат в заморозку. Предложить Андрею пометить их замороженными в `registry/documents.md` и внести в строку «прочитаны после заморозки».

## Условие снятия

Каждый из пяти корпусов либо внесён в строку «прочитаны после заморозки» с датой, либо назван живым с датой последней записи.
