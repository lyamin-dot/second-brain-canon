# Пересинхронизация skills/ с аккаунтом и переход к правкам Skills в репозитории

Метка: РЫЧАГ. Заведена 2026-09-26 сессией SYS (Аргус) по решению владельца в чате SYS того же дня.

## Суть

2026-09-26 в репозиторий заведено зеркало `skills/` (снимок аккаунта на 12:29 UTC) и принято решение о направлении потока: репозиторий → Customize. В тот же день владелец параллельно правил многие Skills прямо в Customize и не может перечислить, что именно изменил. Значит, зеркало уже отстало, а список открытых позиций очереди по Skills (C-2, C-3, C-4, E-2…E-5, V-1, Y-2, Q-7, AG-12, AG-14, AG-16, AG-17, U-1, AH-1) частично мог быть закрыт этими правками. Владелец также сообщил, что многофайловые Skills стало трудно править вручную по якорю — поэтому с этого момента правки Skills делает сессия в файлах `skills/`, а владелец только заливает zip.

## Шаги (одна сессия SYS, Cowork или чат проекта — там, где есть снимок Skills в песочнице)

1. Снять свежий снимок: `/mnt/skills/plugins/<имя>/` для тринадцати Skills владельца, посчитать `git hash-object` каждого файла и сравнить с blob sha в `origin/main:skills/`. Дата снимка — `manifest.json` в той же папке, поле updatedAt каждого Skill.
2. Для каждого изменившегося файла — построчный diff снимка против репозитория; перечень изменений записать в отчёт (это ответ на вопрос владельца «что было исправлено»).
3. Залить изменившиеся файлы в `skills/` тем же маршрутом, что и первый снимок (описан в `skills/README.md`): существующий файл — Git Write целиком нельзя (правило происхождения текста 4.5), поэтому — Git Replace фрагментами по diff либо, при большом diff, маршрут 9.4(б) из сессии Claude Code на репозитории. Приёмка — blob sha равен hash-object снимка.
4. Перепроверить по новому тексту открытые позиции очереди по Skills (перечень в разделе «Разбор открытых позиций по объекту — 2026-09-26» файла `registry/maintenance-queue.md`): что внесено — статус в очереди; что нет — внести правкой файла в `skills/` (Git Replace) и записать в очередь статус «ВНЕСЕНО В skills/, ждёт заливки zip».
5. Отдать владельцу список Skills, которые нужно перезалить zip-ом из репозитория. С этого момента цикл: правка в `skills/` → zip → Customize.

## Условие снятия

Все 52+ файла `skills/` равны снимку аккаунта по blob sha; ни одна открытая позиция очереди по Skills не ждёт правки вручную по якорю — каждая либо внесена в `skills/`, либо имеет статус с основанием; владелец перезалил перечисленные Skills.
