# Правки мастер-промпта проекта SYS после решений Р-111 и Р-3

Суть: мастер-промпт проекта «15.02_Поддержка Проекта Второй мозг» (SYS) после решения Р-111 журнала `projects/git-migration/LOG.md` описывает старт по прежнему составу CORE и требует проверки, которую агент выполнить не может. Правки вносит владелец в интерфейсе Claude Project: промпт живёт только там (см. `t-prompt-backup.md`). Эта задача — тело позиции AE-1 очереди `registry/maintenance-queue.md`; позиция и задача закрываются вместе.

Следующий шаг: владелец вносит четыре правки ниже и пишет одно слово подтверждения; следующая сессия SYS проверяет их по якорям на своём старте.

## Правка 1 — что значит «CORE прочитан целиком»

Якорь: `Точка входа — core/MANIFEST.md (прочитан целиком = прочитаны все файлы списка),`

Было:
```
   Точка входа — core/MANIFEST.md (прочитан целиком = прочитаны все файлы списка),
```
Стало:
```
   Точка входа — core/MANIFEST.md (прочитан целиком = прочитаны все файлы таблицы «Список»;
   таблица «По событию» на старте не читается — её файл читается перед своим видом записи),
```
Почему: с Р-111 в Манифесте две таблицы; слово «список» без названия таблицы допускает чтение обеих.

## Правка 2 — проверка пакета без сверки byteLength

Якорь: `Проверка каждого пакета: в ответе returned равен requested, массив missing пуст,`

Было:
```
   Проверка каждого пакета: в ответе returned равен requested, массив missing пуст,
   у каждого файла byteLength равен длине его text в байтах UTF-8.
   Любое из трёх не выполнено — чтение не состоялось.
```
Стало:
```
   Проверка каждого пакета: в ответе returned равен requested и массив missing пуст.
   Любое из двух не выполнено — чтение не состоялось.
   Поле byteLength с текстом не сверять: воркфлоу считает его из тех же байт, что и text,
   поэтому сравнение ничего не доказывает.
```
Почему: узел 04_Build_Response воркфлоу Git Read Batch (`uUwqH9RPjMfoax9M`) и Git Read (`72DWYjGbeAxEgYwj`) считает byteLength как Buffer.from(base64).length — из тех же байт, из которых декодирован text. Сверка сравнивает файл сам с собой. К тому же агент не может пересчитать байты UTF-8 у десятков килобайт текста без второй вставки всего текста в контекст — условие было невыполнимым и потому молча пропускалось. Та же правка внесена в Skills second-brain-git §7.1 и second-brain-engineer (блок !save).

## Правка 3 — пример признака CORE

Якорь: `(вид записи: 11/core/R-15.md/xxxxxxx)`

Было:
```
   из ответа пакета 2 (вид записи: 11/core/R-15.md/xxxxxxx).
```
Стало:
```
   из ответа пакета 2 (вид записи: 4/core/R-07.md/xxxxxxx).
```
Почему: с Р-110 файла `core/R-15.md` в CORE нет; с решения Р-3 журнала `projects/kontext-reduktion/LOG.md` в таблице «Список» четыре файла и последний — `core/R-07.md`. Пример в промпте — образец, по которому сессия строит строку ПАРОЛИ; неверный образец провоцирует списать число и путь с него, а не с Манифеста.

## Правка 4 — пакет 1 без `meta/header.md`

Якорь: `1а. Пакет 1: paths = ["meta/header.md", "core/MANIFEST.md", "labs/sys/INDEX.md"].`

Было:
```
   1а. Пакет 1: paths = ["meta/header.md", "core/MANIFEST.md", "labs/sys/INDEX.md"].
```
Стало:
```
   1а. Пакет 1: paths = ["core/MANIFEST.md", "labs/sys/INDEX.md"].
```
Ещё одна строка того же шага. Было: `шапка — meta/header.md, реестры — registry/.` Стало: `реестры — registry/.`
Почему: решение Р-3 журнала `projects/kontext-reduktion/LOG.md` — оба поля `meta/header.md` недействующие, чтение шапки ничего не доказывает. Мастер-промпты других проектов, читающие шапку, от этого не ломаются: файл остаётся в репозитории, они просто платят за лишние 1,5 КБ до своей правки.

Условие снятия: Готово = все четыре якоря «Стало» найдены в живом мастер-промпте сессией SYS на её старте; задача удалена из `labs/sys/` вместе со строкой в `INDEX.md`, позиция AE-1 очереди помечена ЗАКРЫТО тем же днём.
