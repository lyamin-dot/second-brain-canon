В очереди правок `registry/maintenance-queue.md` по этой теме уже стоят позиции AJ-51, AJ-52 и AJ-56 (их завели сессии-авторы отзывов); эта задача их не заменяет, а собирает основание и решает, что делать с остальным.

## Как читать

Отзывы принёс Андрей в чат SYS 2026-10-25 и 2026-10-26. Автор каждого — другая сессия; что она делала, эта сессия не наблюдала. Это показания, а не замеры: четыре отзыва, все из семьи проектов с книгами «Цены» и «Деньги». Сведения, которые эта сессия проверила сама, вынесены в раздел «Проверено по объекту».

## Отзывы

### 1. Сессия, правившая код книги с ценами (дословно)

> Про Skill для Google Apps Script — честно. Больше помог, чем мешал, но заметная часть была лишней.
> Помогло: правила моста. Писать только со свежим отпечатком проекта, называть версию для отката, проверять право записи по таблице допуска и не считать молчание моста разрешением. Код книг в репозиторий не класть. Предупредить тебя про открытую вкладку редактора. Отдавать полный файл, когда права записи нет. Без этого я бы, скорее всего, ошибся с «Ценой».
> Мешало: для правки кода без формул и оформления примерно две трети текста не нужны — локаль формул, объединения ячеек, закрепление строк, графики. Это около 10 тысяч слов чтения ради трёх правил. Ещё шаг «согласовать проект с Андреем» в порядке работы читается как обязательный стоп даже тогда, когда ты уже попросил внести правку.
> Предложение: в таблицу «что читать дальше» добавить строку «правка кода без формул и оформления — достаточно раздела 1 про живой текст и мост, разделы 2 и 4 не читать». Если хочешь, дам точный текст «было → стало».

### 2. Сессия, правившая скрипт «WB · Деньги» 34 раза, Skill не открывала

По её словам: Skill в сессии не загружался ни разу, хотя мастер-промпт проекта и описание Skill требуют читать его перед правкой скрипта книги. Порядок вызова моста она взяла из плана проекта gas-bridge (чтение, запись с отпечатком прошлой версии, откат), устройство книги — из кода самой книги (там уже есть перевод формул в локаль и защита именованных диапазонов). Почему не загрузила — гипотеза самой сессии: задача выглядела как «правка кода через мост», у моста есть свой подробный контракт, готовый код давал образец. О пользе Skill судить не взялась: работала без него.

### 3. Сессия, проверявшая вторую (сверила живой скрипт со Skill)

По её словам:
- Skill помогает: код книги когда-то строился по нему и несёт его правила, правка прошла почти без вреда.
- Три отклонения, которые Skill поймал бы: строки 1–6 дашборда перестали быть защищённой зоной параметров, а два комментария в коде обещали прежнее, карта ссылок перед изменением не строилась; артикул берётся по номеру колонки без проверки заголовка; очистка правил оформления пустым списком в четырёх местах (старый дефект).
- Пробелы Skill: правило «свежее чтение перед каждой записью» расходится с практикой — серии правок (25 и 9 фрагментов) брали отпечаток из ответа предыдущей записи, и мост принял все 36 записей; нет правила о серии замен фрагментов с локальной сборкой и побайтной сверкой; нет правила «сменил назначение участка листа — поправь комментарии».
- Причина, по её мнению: путь, которым шла вторая сессия (строка моста в реестре инструментов, контракт вызова моста, контракт автопилота), на Skill не указывает; в мастер-промпте проекта Skill упомянут только внутри абзаца об источниках. Резать Skill она не советует: чинить нужно путь к нему.

### 4. Сессия, проверявшая достоверность чисел книги (аудит без правки)

По её словам: она видела только начало основного файла Skill — после сжатия контекста остальное осталось обрезанным, и права записи по таблице допуска перепроверить она не могла. Помогло: читать скрипт мостом и не класть код в канон; правило «отчёт скрипта — гипотеза, проверять чтением»; таблица «что читать дальше». Мешало: нет пути «аудит без правки»; проверочные ячейки, равные нулю по построению, выглядят как доказательство. Своё предложение она записала в очередь правок (AJ-56).

## Проверено по объекту (сессия SYS, 2026-10-26)

1. Объём. Счёт слов Python по строкам, разделённым пробелами, редакция Skill 2026-10-22, снимок 2026-10-25: основной файл 7 946, вспомогательные файлы 8 121 (всего 16 067). Правка кода с одним вспомогательным файлом — от 8 555 до 11 838 слов, цифра «около 10 тысяч» верна. Разделы основного файла, которые правке кода без формул и разметки не нужны (локаль формул, объединения и закрепление, именованные диапазоны, даты и новый лист, таблица ошибок), — 2 018 слов, около четверти основного файла, а не две трети. Не путать: `wc -w` на русском тексте занижает втрое (2 680 вместо 7 946) — этим счётом пользоваться нельзя.
2. Правило свежего отпечатка. Прочитано определение воркфлоу моста (версия 57388d48-6ea9-4ee5-abfd-84101eed3165, обновлена 2026-10-18): при записи мост сам читает проект из Google и сравнивает присланный отпечаток с отпечатком только что прочитанного проекта; расхождение — отказ «STALE BASE». Отпечаток после записи (поле projectHashAfter) считается той же функцией по проекту, прочитанному после записи. Вывод: отпечаток из ответа предыдущей записи принимается, пока проект между записями никто не менял, а чужая правка в промежутке даёт отказ. Утверждение третьей сессии подтверждено кодом, а не только числом принятых записей. Следствие: слова Skill «свежим чтением непосредственно перед ней» строже механики; правка (А) из AJ-51 приводит их в соответствие.
3. Знает ли Skill, что сессия правит скрипт сама. Да: раздел «Порядок работы», абзац «Живой текст скрипта» — три случая (чтение и запись мостом при доступе write в таблице допуска; чтение мостом и полный текст на вставку Андрею без доступа; текст от Андрея, если мост не читает скрипт), откат, аварийный путь, предупреждение про открытую вкладку редактора. Запуск функций Skill сессии не разрешает: прогон остаётся за Андреем.
4. Что в Skill уже есть. Близкое к пункту (3) из AJ-56: раздел о проверке книги требует сверки «по всем неделям, где есть данные, а не по одной», формулой, с округлением. Нет: проверки нулевой по построению ячейки и пути «аудит без правки».
5. Решение Андрея того же дня (запись Р-38 журнала `projects/kontext-reduktion/LOG.md`): работа над размером и раскладкой Skill закрыта, Skill правятся только по нарушению, увиденному в живом чате; проба на двух заданиях и двух вариантах Skill second-brain-engineer не показала вреда от большого постоянного слоя (слабое доказательство — четыре чата). Следствие для этой задачи: прежнее предложение этой сессии вынести формульные разделы в отдельный файл снято как противоречащее решению; жалобы на размер (отзывы 1 и 4) остаются записанными наблюдениями без действия.

## Позиция сессии

Два нарушения из живых чатов: Skill не открыли (отзыв 2) и Skill прочитали обрезанным (отзыв 4); плюс одно противоречие самого Skill с механикой моста (пункт 2 выше) и два пробела в правилах. По Р-38 правки по таким случаям допустимы; сокращать и раскладывать — нет.
1. Текст Skill: позиции AJ-51 (А — отпечаток внутри серии; Б — серия замен фрагментов и правило о комментариях при смене назначения участка листа) и AJ-56 (аудит без правки); текст «было → стало» там уже лежит, выдаётся Андрею карточкой на сохранение.
2. Путь к Skill: AJ-52 (мастер-промпт проекта «Деньги») и вопрос Андрею о строке «перед правкой кода книги — Skill apps-script-sheets» в описании моста в реестре инструментов (`registry/tools.md`) и в контракте вызова моста (`projects/gas-bridge/PLAN.md`). Слова Андрея по строке пока нет.
3. Открыто: шаг «согласовать проект» (отзыв 1: читается как обязательная остановка после просьбы Андрея внести правку); нужна одна поясняющая фраза в Skill — решение Андрея.
4. Эксперимент по этому Skill не нужен: вопрос размера закрыт Р-38, четыре отзыва достаточны для правок, единственная проверка — пункт 2 раздела «Проверено по объекту» — сделана.
5. Предложение отзыва 1 (строка «разделы 2 и 4 не читать») не принято: таблица «что читать дальше» управляет только вспомогательными файлами, а разделы 2 и 4 несут правила, которые нарушаются и без формул (первая функция файла и запрет модального окна, общие имена функций в проекте из нескольких файлов, все чтения до первой записи).
