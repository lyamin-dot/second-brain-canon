# Карта реестров и реестр ключей доступа

Заведена 2026-10-31 (чат SYS). Предложение сессии, Андреем не принято и не отклонено.

## Суть

Андрей сказал, что у него есть список документов, цифрового контента, воркфлоу, ключей доступа и прочих данных, требующих структуры (чат SYS 2026-10-31). Реестры по классам уже есть: документы Google — `registry/documents.md`; воркфлоу n8n — `registry/n8n-map.md` (строится автоматически); содержимое внешних дисков — проект file-catalog; личные документы семьи — проект family-docs; финансовые документы — Finanz и DOSSIER. Нет одной карты: какой класс объектов где живёт, кто владелец, как наполняется (автоматически или руками), когда обновлялся.

Реестра ключей доступа (credentials) n8n нет вовсе. Практика сообщества — записывать, какие воркфлоу какой ключ используют, и регулярно менять ключи (обзор лучших практик n8n на till-freitag.com от 2026-03-08, прочитан веб-поиском 2026-10-31). Связанные задачи: `t-webhook-key-reuse.md`, `t-github-token-expiry.md`.

## Предложение

1. Одна страница-карта реестров: класс объектов → файл или книга-владелец → способ наполнения → дата обновления. Не новый общий каталог: реестры есть, не хватает карты.
2. Реестр ключей — только на Google Диске, не в публичном репозитории: имя ключа, сервис, какие воркфлоу его используют; без значений ключей. Наполнение — автоматически по инстансу n8n, а не руками.
