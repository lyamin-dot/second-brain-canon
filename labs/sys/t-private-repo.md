# Сделать репозиторий second-brain-canon приватным?

Метка: РУТИНА, вопрос Андрею. Заведена 2026-10-18 сессией SYS по решению А3 харвеста 2026-10-18 (файл meta/HARVEST_2026-10-18_answers.md, раздел «Часть А», А3).

## Суть

Правка текста не убирает уже утёкшее в публичный репозиторий: коммит остаётся в истории навсегда. Единственное действие, закрывающее и историю, — сделать репозиторий приватным. Переписывание истории отвергнуто (принудительная отправка в main запрещена, ломает все клоны).

## Что известно и что нет

Известно (проверено 2026-10-18): облачная сессия получает запись в репозиторий через добавление репозитория в сессию — приватность её не отрежет. Неизвестно: работает ли Канал (воркфлоу Git Read, Git Read Batch и другие) с приватным репозиторием — это зависит от того, читает ли он с ключом доступа GitHub. Клон «анонимно, без учётных данных» (Skill second-brain-git, термин «Среда с клоном») для приватного репозитория перестанет работать.

## Следующий шаг

Зонд: прочитать воркфлоу Git Read и Git Read Batch (поле credentials узлов загрузки) — идут ли запросы к GitHub с ключом. Потом — решение Андрея.

## Условие снятия

Андрей решил: репозиторий остаётся публичным (тогда задача снимается, защита — фильтр t-git-channel-secret-filter.md) или переводится в приватный (тогда — правка Skill second-brain-git, термин «Среда с клоном», и проверка Канала).
