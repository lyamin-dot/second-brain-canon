# Guard длины gdocs-read: реализовать либо явно отказаться

Суть: две задачи источника об одном предмете. Строка 315 (2026-08-07, наряд Н-07.08-04), дословно: «companion-правки к guard длины gdocs-read — (а) 07_Respond должен публиковать новое поле fullLength; (б) throw вместо success:false ломает текущих вызывающих — нужен переход caller-стороны на try/catch вокруг execute_workflow/get_execution до вставки кода в 06_Build_Response. Код и находки — ПРОГРЕСС Зоны Б, той же датой». Строка 354 (2026-08-10, переклассифицировано 2026-08-24), дословно: «наряд числится отработанным, guard длины в коде gdocs-read отсутствует — подтверждено дважды (Н-10.08-02, Н-10.08-03). Понижено с БЛОКЕР: активный риск тихой обрезки чтения закрыт независимым механизмом РЫЧАГ [ЦЕЛОСТНОСТЬ ЧТЕНИЯ] (byteLength+checkSum, боевой с 08-10, обязателен в мастер-промпте). Server-side throw остаётся желательным defense-in-depth, не блокером. Бесхозная копия удалена нарядом Н-24.08-03».

Следующий шаг: решение владельца — реализовать guard (тогда companion-правки (а)(б) строки 315 идут вместе с ним) либо явно отказаться.

Условие снятия (дословно из источника): строка 354 — «Готово = guard реализован в коде либо решение не реализовывать явно принято»; строка 315 — «Готово = 07_Respond обновлён, callers сверены, код вставлен и подтверждён read-back» (действует только при решении реализовать).
