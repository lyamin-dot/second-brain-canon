# Зеркало Skills в репозитории отстало от живых Skills

Метка: кандидат в БЛОКЕРы. Заведена 2026-10-09 сессией SYS (Аргус) на !save после харвеста 2026-10-08.

## Суть

Канон Skills — папка `skills/<имя>/` репозитория: правка вносится там, затем zip заливается в Customize (решение владельца 2026-09-26, `skills/README.md`, строка карты `skills/` в Skill `second-brain-git`). На деле поток идёт в обратную сторону: правки вносятся прямо в Customize, а зеркало не обновляется.

Факт, снятый сравнением `diff -rq` зеркала (клон, main 010b0a4) с живыми Skills сессии SYS 2026-10-09 около 21:00:
- различаются около тридцати файлов в семи Skills — `second-brain-engineer` (7 файлов, в зеркале нет `references/prompt-craft.md`), `second-brain-git` (5), `n8n-engineering-manual` (6, включая INCIDENT_LOG.md), `google-drive-docs` (7), `n8n-workflow-registry` (SKILL.md, в зеркале нет папки `references/`), `naryad` (2), `n8n-workflow-passport` (1); совпадают только `apps-script-sheets`, `denken`, `context-handoff`;
- 2026-10-08 вечером расходились только три Skill; рост за сутки — внесение находок харвеста 2026-10-08 прямо в Customize (живой `second-brain-engineer/references/save.md` сам называет «Правка 2026-10-09 (харвест 2026-10-08)»);
- ни в main, ни в ветках `claude/*` коммитов в `skills/` после 2026-10-08 22:00 нет — правки не потеряны в недоставленной ветке, их в репозитории нет вовсе.

## Риск

1. Потеря правок: любой, кто по правилу «канон — зеркало» соберёт zip из `skills/` и зальёт его, сотрёт все сегодняшние правки владельца. Прецедент того же класса — 2026-10-01: заливка без сверки стёрла бы пункт 13.6 (`projects/kontext-reduktion/LOG.md` Р-32).
2. Ложные находки: харвест и любая сверка «есть ли правило в Skill», сделанные по зеркалу, дают ошибку — харвест 2026-10-08 по зеркалу объявил отсутствующим описание книги ключей N8N_CREDENTIALS, которое в живом Skill было.
3. Слово «канон» в карте репозитория перестаёт быть правдой, а инвариант И-1 (один носитель) нарушен фактически: два носителя с разным текстом.

## Предложение сессии

Выбрать одно направление и записать его, а не держать два:
- (а) Канон — живой Skill в Customize, зеркало — резервная копия: после каждой правки владельца сессия с клоном снимает живые файлы и доставляет их в `skills/` маршрутом 9.4(б) (текст уже существует — моделью не набирается). Правка строки карты `skills/` в Skill `second-brain-git`.
- (б) Оставить канон в репозитории: тогда владелец перед заливкой правит `skills/`, а не Customize, — это та ручная синхронизация, которая уже не исполнилась.
Сессия рекомендует (а): поток (б) на деле не исполняется, а правило, которое не исполняется, хуже его отсутствия. Решение — за владельцем.

Ближайший шаг при любом решении: снять живые тексты семи Skills в `skills/` маршрутом 9.4(б) из среды, где проходит `git push --dry-run` (в сессии SYS 2026-10-09 push закрыт: репозиторий не в списке авторизованных).

## Условие снятия

`diff -rq` зеркала и живых Skills пуст, и в строке карты `skills/` Skill `second-brain-git` записано, какой из двух носителей канон и кто и когда синхронизирует второй.
