# Skill avtopilot — автономная разработка проекта после одного согласования

Метка: РЫЧАГ. Заведена 2026-10-13 сессией SYS (Аргус) по просьбе Андрея.

## Суть

Андрей в последнее время только соглашается с предложениями. Каждое его короткое «да» заставляет модель заново обработать весь разросшийся разговор. Он попросил новый Skill с такой работой: обсудить без лишнего контекста, проверить замысел Skill `denken`, а затем вести работу до конца без него — так же дёшево, как в Архивариусе, где большой массив разобрали параллельно в нескольких чатах.

## Решение (2026-10-13)

Принято, ревизия `denken` уровня 2 в чате сессии SYS 2026-10-13. Андрей ответил «Действуй!» на план после ревизии.

Отдельный тонкий Skill `avtopilot` с пятью воротами:
1. разговор — квитанция рамки, критерий приёмки объектом, все ручные действия Андрея одним списком, стоп-список;
2. ревизия `denken`;
3. контракт запуска одним текстом и одно «да» — список разрешённых правок в нём служит пакетом разрешения на правки воркфлоу;
4. исполнение — шина сессия-диспетчер, тяжёлое чтение раздаётся субагентам параллельно, в канон пишет только диспетчер;
5. приёмка — отдельный субагент сильного класса, не делавший работы, получает утверждения и задачу их опровергнуть; затем один отчёт Андрею.

Снят один барьер класса «твой» — правило Skill `naryad` «Андрей — шина, роли между собой не общаются, Руководитель не вызывает инструменты». Снят только внутри автономного режима. Цена снятия: пропадает взгляд Андрея между шагами. Компенсация: независимая приёмка по объекту.

Отвергнуто:
- новый маршрут внутри Skill `naryad` — основа naryad («Андрей — шина») противоречит автономному режиму, прививка сделала бы его противоречивым;
- протокол-файл в `meta/` — не срабатывает по слову в других проектах, а цикл нужен в любом проекте;
- ничего не заводить, раздавать субагентов по ситуации — каждый раз изобретается заново и без стоп-условий;
- раздел в Skill `second-brain-engineer` — тот читается на старте каждой сессии каждого проекта, автопилот нужен только по слову;
- проект archive-recon как пилот — его остаток работы ждёт двух ручных действий Андрея (запись Р-32 журнала `projects/archive-recon/LOG.md`);
- запланированная задача со свежей сессией как носитель по умолчанию — на аккаунте ни разу не создавалась, режим одобрения неизвестен; принят проверенный возврат в ту же сессию. (Так было на 2026-10-13. 2026-10-18 такая задача создана и отработала — раздел «Зонд запланированной задачи 2026-10-17…18»; носителем по умолчанию она от этого не стала, она второй носитель.)

Вердикт решаемости: решение есть. Вырождается, когда шаги строго последовательны: тогда параллельности нет и экономия сводится к отсутствию «да» Андрея.

## Зонд запланированной задачи 2026-10-17…18

Записан 2026-10-18 задним числом по решению харвеста 2026-10-18 (находка В11, файл `meta/HARVEST_2026-10-18_answers.md`). Что было:

Что зонд доказал: на этом аккаунте запланированная задача со свежей сессией создаётся из сессии; режим одобрения auto бывает и виден в ответе на создание; такая сессия без Андрея вызывает инструменты n8n, Google Drive и Канал записи репозитория и доводит работу до записи в канон.

Отправку сообщения Андрею запись Р-28 не подтверждает. Подтверждение итога в Р-28 — самопроверка сессии («кто подтвердил: не зафиксировано в источнике»), независимой приёмки не было.

Следствие для Skill: в абзаце «Долгое ожидание» запланированная задача со свежей сессией становится вторым проверенным носителем — правка Skill `avtopilot` по находке В11 ссылается на этот раздел.
