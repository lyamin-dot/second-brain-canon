# Реестры и проектные файлы называют устаревшее действующим

## Суть

Разбор корпусов WB_LOGISTICS_INDEX и WB_REVIEWS_INDEX вскрыл три места, где живой файл расходится с действительным положением дел:

1. `registry/protocols.md`, строка 16, перечисляет PROTOCOL_system-map как действующий протокол, тогда как паспорт (`n8n-workflow-passport`, SKILL.md, строка 10) его уже не называет.
2. Skill `n8n-workflow-registry`, SKILL.md, строки 177–178, про воркфлоу motor_oil отстаёт от перезалива 2026-07-29.
3. `projects/wb-logistics/STATE.md` и промпт этого проекта требуют заново назначать credential WB API после update_workflow, но правило roots R1b v4.4 говорит обратное. Кроме того, в корпусе нет адреса эндпоинта состава поставки WB — источники расходятся.

Опасность: сессия, читающая эти строки как действующие, повторит снятый шаг или пойдёт по несуществующему протоколу.

## Следующий шаг

По каждому пункту прочитать указанный файл целиком, сверить с источником правды (CORE и живой Skill), подготовить правку и выдать Андрею текст «было → стало» до внесения. Правку Skill в этой сессии не делать — только через общий пакет Архивариуса или по прямому решению Андрея.

## Условие снятия

Три строки в main соответствуют действующему положению, либо помечены устаревшими с датой и ссылкой на решение; адрес эндпоинта состава поставки WB назван в одном месте.
