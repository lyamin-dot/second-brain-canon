# Разбор: регулярный проход по ждущему Андрея — план и первый прогон

**Суть.** Андрей (чат Claude Code, 14.11) поручил пройти по проектам и лабораториям, выяснить, что из ждущего его решения можно сделать без него, сделать это и доложить одним отчётом; шаг сделать регулярным. План принят им в том же чате; процедура — `meta/PROTOCOL_razbor.md`. Отчёт первого прогона — `meta/RAZBOR_2026-11-14.md`.

## Решения Андрея (чат Claude Code 14.11)

1. План принят: один диспетчер с помощниками только на чтение, четыре класса (А, Б, В, УСТАРЕЛО), приёмка отдельным помощником, один доклад.
2. Первый прогон: потолок 2 млн токенов, остановка на 1 млн с оценкой остатка.
3. Работать последовательно по проектам, чтобы при исчерпании лимита был результат хотя бы по части.
4. Документ аудита `meta/AUDIT_system_2026-11-10.md` — тот самый «отчёт с вопросами»; ответы сессии на семь разделов «Что делать Андрею» даны в чате и переносятся в отчёт прогона.
5. Система должна знать план: будущий «разбор» идёт по `meta/PROTOCOL_razbor.md`.
6. В конце прогона — какие ошибки сделаны при разработке плана; учесть в процедуре (раздел «Уроки прогонов»).

## Отвергнуто при проектировании

- Отдельная сессия на каждый проект: несколько писателей в main сталкиваются, чисто завершившаяся сессия не обязана доложиться.
- Расписание: запланированной задаче со свежей сессией правила не дают править воркфлоу и запускать помощников; регулярность — слово Андрея.
- Правки воркфлоу n8n в первом прогоне: вторым пакетом после доклада.
