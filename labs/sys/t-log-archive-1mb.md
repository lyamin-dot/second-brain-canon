# Архив журнала git-migration приближается к пределу, после которого Канал его не прочитает

Суть: `projects/git-migration/LOG_ARCHIVE.md` весит около 405 КБ. Для файлов больше 1 МБ GitHub в ответе Contents API отдаёт поле content пустой строкой, а узел `n8n-nodes-base.github`, которым читают Git Read, Git Read Batch и Git Read Lines, берёт только это поле. Гипотеза: по такому файлу Канал вернёт пустой текст без ошибки, и запись по номеру из архива станет недостижима. При среднем темпе журнала 21,7 КБ в рабочий день предел — примерно через 28 рабочих дней. Зондом не проверено.

Следующий шаг: зонд — прочитать Git Read файл больше 1 МБ во временной ветке или в тестовом пути (не с именем LOG.md, LOG_ARCHIVE.md, NOT_TAKEN.md — second-brain-git 9.3) и посмотреть, что вернётся. Если гипотеза подтвердится — архив по периодам (`LOG_ARCHIVE_2026-09.md` и далее) либо запасной путь через download_url в узле чтения; решение владельца.

Условие снятия: Готово = зонд выполнен и записан в журнал проекта kontext-reduktion; при подтверждении — выбран и внедрён способ, при опровержении — задача закрыта с номером записи.

Ссылки: Р-10 журнала `projects/kontext-reduktion/LOG.md` (исследование, раздел «найдено попутно»); second-brain-git 5.2 в `references/rotation.md` (предел 1 МБ уже назван там как обязательный повод к ротации).
