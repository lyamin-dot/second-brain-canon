# Еженедельный снимок категорий SKU пишет пустые счётчики

Метка: РЫЧАГ. Заведена 2026-10-13 сессией SYS (Аргус) по слову Андрея: «сохрани как задачу в проект Юнит-Экономика Озона». ⚡ Находка лаборатории SYS — перепроверка аудита 2026-07-23 (пилот Skill avtopilot), пункт 8.

## Суть

Воркфлоу `qZWrl0MkRnZBipXA` «SKU Category Weekly Snapshot» активен, опубликованная версия запускается еженедельно. Узел `06_Is_Snapshot_Duplicate` (Code) возвращает новый объект `[{ json: { snapshot_date: snapshotDate, is_duplicate: isDuplicate } }]` и не передаёт входные поля дальше. Единственный вход узла записи `08_Write_Category_Snapshot` идёт из этой цепочки через `07_Skip_If_Duplicate_Snapshot`, режим записи `autoMapInputData`. Поэтому в лист снимков попадают только `snapshot_date` и `is_duplicate`, а период и счётчики категорий из `03_Calculate_Categories` — period_start, period_end, period_days, CORE_SKU, MARGIN_PROBLEM, SCALE_CANDIDATE, RETURNS_ATTENTION, LOW_PRIORITY, total_sku — теряются. История категорий SKU не копится.

Проверено 2026-10-13 чтением get_workflow_details двумя независимыми сессиями (проверяющий и приёмщик); в черновике и опубликованной версии код одинаков.

Второе. Черновик этого воркфлоу отличается от опубликованной версии: в черновике `Schedule Trigger` выключен (`disabled: true`). Публикация черновика после правки кода молча остановит расписание. Перед публикацией триггер в черновике нужно включить.

Не проверено: сам лист снимков — сколько строк с пустыми счётчиками уже накопилось. Сохранённых исполнений у воркфлоу нет (поиск исполнений 2026-10-13 вернул ноль), так что идёт ли расписание вообще, видно только по листу.

## Следующий шаг

1. Прочитать лист, куда пишет `08_Write_Category_Snapshot`: последние строки — даты и пустые ли счётчики.
2. Предложение правки (только после «да» Андрея): в коде `06_Is_Snapshot_Duplicate` вернуть входной снимок с добавленным признаком — `[{ json: { ...snapshotItems[0].json, is_duplicate: isDuplicate } }]` — с дословным текущим кодом и построчным сравнением; включить `Schedule Trigger` в черновике; опубликовать; проверить по листу после ближайшего прогона.
3. Решить, восстанавливать ли пропущенные недели.

## Условие снятия

В листе снимков появилась строка со счётчиками категорий после правки (дата и номер строки названы), черновик и опубликованная версия совпадают.
