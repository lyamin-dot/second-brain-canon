# Лист «Фин.результат по неделям» в книге Ozon «Деньги»

Суть: перенести на Ozon раскладку листа «Фин.результат по неделям» книги «WB · Деньги» (раскладка таблицы коллеги «112 MASTER»; правило листа WB — запись Р-85 журнала projects/wb-ue/LOG.md, PLAN.md проекта wb-ue) и проверить лист по отчётам Ozon «Начисления». Поручение Андрея, чат OZON_UE 2026-10-31.

## Решения Андрея (чат 2026-10-31)

- Эквайринг Ozon — в удержания (Д), в вознаграждение (В) — только комиссия за продажу и её возврат, как строка «Вознаграждение Ozon» отчёта Ozon. Довод: строка В сверяется с отчётом строка в строку; на листе WB В включает эквайринг и возмещения ПВЗ, потому что WB вычитает их до «к перечислению».
- Плана года для Ozon нет.
- Сводная таблица Ozon + WB по логике листа — задача интегратора (проект marketplace-rebuild), в лаборатории не ведётся; строка «⚡ Это затрагивает» — в projects/marketplace-rebuild/STATE.md.

## Дефект книги: деление логистики (доказан, лист «Деньги по неделям» не исправлен)

Сумма «Логистика до покупателя» + «Обратная логистика» книги равна отчёту до копейки, но делится неверно. Неделя 05.10: в «Обратной логистике» книги 11 274,87 ₽, а возвратных услуг по отчёту 4 556 ₽.

Механизм (функции bucketOf_ и buildWeeks_ файла oz_money_book):
- сервисные строки с «доставк», «логистик», «drop-off» в названии все уходят в «Обратную логистику», в том числе «Доставка до места выдачи» и Drop-off;
- строки типа returns без сторно кладут в «Обратную логистику» всю сумму, в том числе прямую логистику (код 32) и доставку (код 29) невыкупленных отправлений.

Ожидаемое деление по отчётам. Прямая логистика = Логистика + Доставка до места выдачи + Drop-off + силами Ozon. Возвратная = Обратная логистика + Обработка возвратов.

## Найдено попутно

- Штуки возвратов: у строк возврата в sales_raw_operations количество есть, но одно невыкупленное отправление даёт 3–4 строки (коды 32, 59, 45, 29), каждая с количеством 1. Складывать количество строк возврата нельзя. Лист считает возвращённые штуки только по строкам с выручкой меньше нуля (проба: B57090:X57400, gsheets-read 90322).
- В «Постоянных адресах» INDEX.md функции лент записаны в файле oz_money_tape.gs; в проекте скрипта этот файл называется weekly_history (bridge read list, исполнение 90291). Строка INDEX.md исправлена тем же коммитом, что заведение задачи.
- Шапка oz_money_book говорит, что история закупки читается из cost_price_history книги sku_cost_Шаблон; CFG читает книгу «Закупка» с 2026-10-18. Неверен только комментарий.
