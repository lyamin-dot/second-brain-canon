## Уроки для такой же связки у WB (записано по просьбе Андрея 2026-10-14)

1. Сначала проверить, что книга вообще обновляется сама: ячейка времени последнего прогона, прочитанная инструментом. Книга «Деньги» стояла 13 дней, и этого никто не видел; у WB запись «работает по расписанию» тоже не пережила проверки (Р-39 журнала WB_UE). Без живой книги Telegram две недели слал бы старые цифры.
2. Возраст книги проверяет n8n по метке времени, а не сама книга: книга, которая не запустилась, ничего о себе не напишет. Это единственная логика, которую стоит держать в воркфлоу; всё остальное (что считать отклонением, тексты) — в книге.
3. Читать ячейки по именованным диапазонам, одним запросом Sheets API values:batchGet с ranges=ИМЯ. Читатель WB DcIqwTVqBqMQyigs берёт dashboard!C79/C80 по адресу — первая же перестройка листа сдвинет адрес молча. Один несуществующий диапазон роняет весь запрос ошибкой 400 — это полезно: сразу видно, что скрипт книги не доехал.
4. Пороги — прогоном по истории, не на глаз (Skill apps-script-sheets, references/signal.md, пункт 9.5). Затраты, растущие с оборотом (закупка, комиссия, логистика), — долей выручки в процентных пунктах; прибыль — в рублях с полом материальности. Норма — медиана нескольких полных недель, а не среднее: разовые всплески её не двигают. Ориентир — 4–7 красных недель на 24; у Ozon вышло 5 из 30. Жёлтое — только в недельную сводку: у Ozon жёлтых недель 14 из 30, тревогой это быть не может.
5. Сводку отправлять один раз на новую закрытую неделю, а не в фиксированный день недели. У WB данные приходят пачкой еженедельно (WB RAW Finance Sync, среда), поэтому «неделя закрыта» у WB определяется не тем, что источник дошёл до следующего дня, как у Ozon, а приходом отчёта за неделю; курьер — ежедневный, с памятью последней отправленной недели (static data). Ручной запуск эту память не сохраняет.
6. Неполная закрытая неделя (меньше 7 дней с данными) должна быть сбоем, а не молча выпадать из нормы — у Ozon это нашлось только сверкой сводки с листом (неделя 28.09–04.10).
7. Telegram — parse_mode HTML и экранирование & < >: Markdown падает на подчёркиваниях в именах.
8. Скрипт книги: константы — на своём листе по подписи (читаются до перестройки, ручной ввод не теряется); Telegram — отдельным файлом .gs в том же проекте плюс одна строка в setupAll; править только по живому тексту скрипта, который прислал владелец, — техдок отстаёт.
9. Воркфлоу через MCP: timezone и errorWorkflow из кода не применяются — выставлять операцией setWorkflowSettings и сверять; ключ HTTP-узла автоматически не привязывается. Логику узла Code проверить в node на настоящих данных листа до публикации.

Следующий шаг: Андрей вставляет оба файла и запускает setupAll, вписывает строку PASSPORT в description воркфлоу; затем приёмка: плановые прогоны 15 и 16.10, сводка за неделю 05.10–11.10 в Telegram, сверка чисел сводки с «Деньги по неделям», независимый приёмщик.
