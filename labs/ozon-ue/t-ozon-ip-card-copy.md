Заведена 2026-10-22 по поручению Андрея (чат проекта OZON_UE 2026-10-21…22: «Создай инструмент переноса карточек из основного кабинета на Озоне в кабинет ИП. Учти опыт коллег из ВБ», «Вариант Б — вторая независимая витрина», «Решения принимай сам», команды /denken и /avtopilot). Это план и контракт автопилота; исполнение не начато.

Почему задача здесь, а не в отдельном проекте. Решение card-content-sync 2026-10-18 (`projects/card-content-sync/LOG.md`, запись Р-11) говорит: работа с карточками Ozon — отдельный будущий проект. Проекта нет, а задача кабинета Ozon ИП (`t-ozon-ip-cabinet.md`) живёт в этой лаборатории, поэтому перенос заведён задачей лаборатории. Если в файле появятся фазы с общим финишем сверх этого контракта — разворачивать в летопись по `second-brain-git` 4б.7. Решение сессии по автопилоту, владельцу отдельно не задано; в чате 2026-10-21 Андрей план с этим пунктом видел и не возразил.

## Что решено и почему

1. **Способ — новые карточки ИП методом `/v3/product/import`, аналог переноса через Excel** (слово Андрея 2026-10-21 и 2026-10-22: «вторая независимая витрина»).
   Отвергнуто: привязка к карточкам основного кабинета методом `/v1/product/import-by-sku`. Причины: товар ИП встаёт в ту же карточку и открепить его нельзя (вторичный источник uniseller, первоисточник не прочитан); магазины соперничают за одного покупателя; Андрей не хочет необратимых условий; метод не копирует свою карточку и отказывает, если копирование запрещено (swagger.json). Защиту от копирования в основном кабинете НЕ трогаем — это настройка варианта привязки, к переносу она отношения не имеет.
2. **Инструмент — копия JSON карточки с заменой нескольких полей, а не сборка карточки по полям, как на WB.** Ответ `/v4/product/info/attributes` основного кабинета несёт почти ровно тело `/v3/product/import`: `description_category_id`, `type_id`, `name`, `offer_id`, `attributes` (в том числе описание 4191 и рич-контент 11254), `complex_attributes` (видео), `images`, `primary_image`, `color_image`, `pdf_list`, габариты и вес, `barcode`/`barcodes`, `model_info` (swagger.json, прочитан 2026-10-22). Инструмент берёт этот JSON и меняет только: артикул (обрезка пробелов по краям — урок WB), штрихкод (пункт 3), цену и валюту (пункт 4), НДС (пункт 5), `promotions` = `DISABLE` для `REVIEWS_PROMO` (платная акция «Ускоренный сбор отзывов» — не включать). Сверка — сравнение двух JSON за вычетом этих полей.
3. **Штрихкоды.** Ozon: «два продавца не могут использовать одинаковые штрихкоды, даже если продают один и тот же товар»; штрафов пока нет, правило закреплено в «Комиссиях и тарифах», предупреждение приходит после создания карточки; нарушением НЕ считается, если магазин первым добавил штрихкод на площадку или у товара есть код маркировки в «Честном знаке» (seller-edu.ozon.ru, раздел «Штрихкоды», прочитан встроенным браузером 2026-10-22). Основной кабинет добавил коды первым, значит у ИП они были бы нарушением. Решение:
   - товар без маркировки — карточка создаётся без штрихкода, затем `/v1/barcode/generate` выдаёт уникальный штрихкод Ozon (до 100 товаров за запрос, 20 запросов в минуту);
   - маркируемый товар — штрихкод основной карточки (GTIN), он нужен для кода «Честного знака» и подпадает под исключение.
   Последствие для Андрея: на FBS товар без маркировки, отгружаемый из ИП, несёт штрихкод ИП (Ozon: добавить штрихкод нужно до отгрузки, иначе не компенсируют потерянные возвраты). Печать — в кабинете ИП, «Скачать штрихкоды».
   Отвергнуто: те же коды производителя у обоих магазинов — прямо запрещено правилом Ozon, а штраф обещан. Слова SelSup о штрафе 5 ₽ за единицу с 01.12.2026 первоисточником не подтверждены: Ozon пишет «пока не начисляем».
4. **Цена — текущая цена товара в основном кабинете (`/v5/product/info/prices`), остатки 0.** Без остатков товар не продаётся; после модерации он виден в кабинете, но не покупателям (swagger.json, `/v3/product/import`). Цены ИП Андрей потом ставит сам — витрина независимая.
5. **НДС** — ставка ИП от Андрея (ручное действие 2). Без неё запись не начинается.
6. **Что не переносится:** остатки; отзывы и рейтинг (их у новой карточки нет по определению); декларации и сертификаты — на Ozon они не атрибуты, а отдельные документы `/v2/product/certificate/create`, их ставит проект «Декларации и коды 2.0» по эталону, как на WB.
7. **Моторные масла — после регистрации ИП в «Честном знаке»**, по образцу WB (`projects/card-content-sync/LOG.md`, запись Р-12, пункт 5). Остальные маркируемые и немаркируемые — сразу.
8. **ТН ВЭД** — эталон ARTIKEL_PROPS, колонка N; при пустом эталоне — значение основной карточки с пометкой «не эталон» в отчёте (тот же рецепт, что на WB, запись Р-12, пункт 7).

## Контракт автопилота

- **Цель.** В кабинете Ozon ИП есть карточки всех товаров основного кабинета, кроме моторных масел, — независимые (свой SKU), без остатков, со своим штрихкодом у немаркируемых. Основной кабинет не меняется.
- **Критерий приёмки.** По каждому товару волны: у ИП есть товар с нашим артикулом; SKU ИП ≠ SKU основного; категория, тип, название, описание 4191 побайтно, характеристики, рич-контент 11254, число фото, наличие видео, габариты и вес совпадают с основным; немаркируемый — штрихкод ИП не совпадает ни с одним штрихкодом основного, маркируемый — совпадает с GTIN основного; остаток 0; акция `REVIEWS_PROMO` не включена; статус модерации не `failed_*` либо причина отказа выписана; в основной кабинет не ушло ни одного запроса записи. Проверяет отдельный субагент, который работу не делал.
- **Пакеты работы.** Этапы 1–5 выше; класс модели — диспетчер сам, субагенты среднего класса только для выдач API длиннее сотни товаров, приёмщик — сильного класса.
- **Разрешённые правки.** Привязка ключей к узлам `PWFVE0UbM3ajvVFc` и его прогон; создание нового воркфлоу-инструмента и его паспорта; новый лист в книге «Описания карточек»; создание товаров, штрихкодов ИП и медиа в кабинете ИП; записи в этот файл, в `t-ozon-ip-cabinet.md`, строку в INDEX.md, `registry/documents.md`, `meta/CASES_ozon-api.md`, строку «От соседнего проекта» в `projects/deklaration-v2/STATE.md`. Живые воркфлоу не правятся. Цены, остатки и карточки основного кабинета не меняются.
- **Особые стопы.** SKU товара ИП совпал с SKU основного; ошибка в теле ответа при коде 200, которой нет в этом файле; в волне больше 5 процентов ошибок или отказов модерации; лимит ассортимента или суточного создания меньше остатка манифеста; товар ИП оказался в продаже; любой запрос записи с ключом основного кабинета; Ozon потребовал оплату или предложил платную услугу при создании; плюс общий стоп-список Skill `avtopilot`.
- **Ручные действия Андрея:** этап 0, два пункта. Других нет.

## Ревизия denken, уровень 3 (2026-10-22)

Уровень 3 — создание сотен карточек и штрихкодов в чужом для системы кабинете; штрихкод, присвоенный товару, изменить и удалить можно не всегда (seller-edu, раздел «Когда не получится удалить и изменить штрихкод»).

- Жёсткие барьеры: нет ключа ИП (снимает только Андрей); лимиты Ozon на создание; правило уникальности штрихкода; документацию Ozon сервер n8n не читает (тайм-аут, `PLAN.md` card-content-sync, «Факты зондов») — читается встроенным браузером.
- Твои барьеры: решение «Ozon — отдельный проект» (запись Р-11 card-content-sync) — снято, цена ноль, вынос в летопись одним коммитом. Решение «масла после „Честного знака“» — оставлено.
- Свои (додумал сам): цена ИП = цене основного; артикул ИП = артикулу основного с обрезкой пробелов; штрихкод Ozon вместо кода производителя у немаркируемых; рич-контент и видео переносятся (на WB рич не переносили); ночного робота для ИП не заводить — приёмщик читает API сам (предпочтение Андрея не наращивать контрольные механизмы).
- Вердикт решаемости: решение есть, не вырожденное.
- Самое слабое звено: штрихкоды. Решение пункта 3 добавляет Андрею работу на отгрузке (штрихкод ИП на немаркируемом товаре). Наблюдаемый факт ошибки: Ozon отказывает в создании без штрихкода или `/v1/barcode/generate` не выдаёт код — тогда стоп и вопрос.
- Второе слабое: перенос видео и рич-контента ссылками на хранилище Ozon не проверен; на WB видео прошло по ссылке HLS, а `/v3/product/import` принимает только MP4 или MOV. Факт ошибки: статус `skipped`/`failed` у медиа в `/v1/product/import/info` на пробе — тогда видео уходит в хвосты, волны идут без него.
- Разрыв ЕСЛИ–ТО, закрытый: «если остаток 0, товар не продаётся» — основание в swagger.json («не будет виден пользователям, пока вы не выставите его на продажу»).
- Вычеркнуто: отдельный робот-накопитель карточек ИП; колонки ИП в `Artikel` (это другая задача); сверка описаний с книгой «Описания карточек» (сравнивается с живой основной карточкой).
- Противоречие: витрина должна быть независимой (полный контент, свой штрихкод), а инструмент — дешёвым и простым. Развязка по уровню системы: карточка целиком копируется одним JSON, отличие держат только пять полей; сверка — разность двух JSON минус эти поля.
- Отклонено: привязка `import-by-sku` (необратима, конкурирует сама с собой); те же коды производителя (правило Ozon); штатный «перенос карточек» Ozon между аккаунтами — передача по документам, платная, решение по документам Ozon (ppc.world, 29.09.2023).
