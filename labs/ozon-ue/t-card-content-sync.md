# Синхронизация описаний карточек во всех четырёх магазинах

Суть: Андрей меняет описание товара в одной шаблонной Google-таблице, и это изменение доходит до карточки товара во всех четырёх магазинах — Ozon и Wildberries, у каждого маркетплейса по магазину двух разных юрлиц (основное юрлицо и ИП, разное налогообложение). Сейчас описания меняются заливкой Excel-шаблона в каждом кабинете отдельно.

Решения Андрея (чат 2026-10-04):
- Платные сервисы управления карточками (SelSup, MPsklad, Topseller) не используются. Инструменты — Google-таблицы и воркфлоу n8n, по образцу обновления деклараций соответствия в проекте `projects/deklaration-ozon/` (воркфлоу Ozon Upload `BLNA8sbdnLtuz7Uj`, WB Sync `QCQI6utFFH3dvTJT`). Задача `t-selsup-trial` закрыта этим же коммитом.
- Ассортимент магазинов между собой не сравнивается: магазины принадлежат разным юрлицам.
- У Андрея есть 1С УНФ и модули iTone; в эту систему они не входят.

Состояние на 2026-10-04 (прочитано в сессии):
- Кабинет Ozon ИП: воркфлоу выгрузки товаров `PWFVE0UbM3ajvVFc` создан 2026-09-28 и ни разу не запускался (search_executions: 0 исполнений) — ключ API ИП в n8n, по всей видимости, не заведён; задача `t-ozon-ip-cabinet`.
- Второй магазин на Wildberries в каноне не описан нигде: нет ни credential, ни листа с его карточками. Источник «четыре магазина» — слова Андрея 2026-10-04.
- Главная таблица товаров — Price Master!Artikel (задача `t-product-data-model`): наш артикул, SKU Ozon основного юрлица, карточка WB (L). Все карточки WB основного кабинета — лист WB_Cards_Staging, робот `fGHfVrI58Ws1wfTw`.
- Уроки записи в WB из проекта deklaration-ozon (`PLAN.md`, раздел «Wildberries — перенос и обновление деклараций»; `LOG.md` Р-30): `/content/v2/cards/update` заменяет карточку целиком — только чтение → правка → запись карточки из свежего чтения того же прогона; WB отклоняет всю склейку (imtID), если в ней есть карточка с ошибкой; ответ 200 не значит, что карточка применена — итог читать в `content/v2/cards/error/list`.

Следующий шаг: наряд Н-04.10-01а (выдан в чате проекта 02_Unit_Econ._Ozon 2026-10-04) — фазы Ф0 (инвентаризация четырёх кабинетов и зонд только на чтение) и Ф1 (книга-шаблон и воркфлоу в режиме «проверка», без записи в карточки). Боевая запись в карточки — отдельным нарядом после приёмки Ф1.

Условие снятия: по 4б.7 задача с фазами разворачивается в летопись `projects/card-content-sync/` в начале Ф0; задача закрывается тем же коммитом.
