# Очередь на обслуживание — материал, ждущий правки Skill или CORE

Заведена 2026-09-06 при разборе PROJECT_LOG_SYS (решение LOG.md проекта git-migration, Р-40).

Что здесь лежит: позиции, чей адрес назначения — Skill или раздел CORE, а не папка проекта. Сессия ни то, ни другое править не может: правка Skill — операция владельца, правка CORE — команда «обслуживание». Очередь закрывает разрыв между «известно, куда это должно лечь» и «оно там лежит».

Чего здесь НЕ лежит: сам текст правила. Позиция несёт формулировку в одну-две строки и адрес источника; полная редакция берётся из замороженного источника в момент внесения. Второй копии текста система не заводит (И2).

Читается по триггеру «обслуживание», не на старте сессии.

Закрытые позиции и проза датированных разделов-разборов живут в `registry/maintenance-queue-archive.md`. Здесь — только открытые позиции; по вопросу «чем закончилась закрытая позиция» читается архив.

Правила ведения:
- У каждой позиции есть дата смерти. К дате не внесено — позиция не протухает молча, а возвращается вопросом владельцу. «Отложить до обслуживания» без даты — запрещённая формулировка.
- Внесённая позиция получает статус ВНЕСЕНО с датой и адресом в целевом носителе, а при следующем вывозе уезжает в `registry/maintenance-queue-archive.md`. Вывоз копится и идёт партиями: он возможен только маршрутом 9.4(б) из сессии с открытым push, а сессия, работающая только Каналом, строку вывезти не может и только ставит ей статус. След внесения сохраняется там, а здесь живут только открытые позиции. Прежнее основание не удалять строку («DELETE каналом записи не покрыт») отменено 2026-09-24: удаление пути покрыто Git Commit Files (8.3 `second-brain-git`), а вывоз уже существующего текста идёт маршрутом 9.4(б) скриптом — Р-21 и Р-22 журнала `projects/kontext-reduktion/LOG.md`.
- Позиция, чьё содержание уже живёт в целевом носителе, заводится со статусом ДУБЛЬ и адресом — чтобы её не открыли заново.
