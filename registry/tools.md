ДВА РАЗНЫХ КАНАЛА, НЕ ПУТАТЬ (правка 2026-09-07, разбор протокола «обслуживание»):
— прямой `git push` из облачной песочницы сессии закрыт прокси: чтение репозитория открыто, запись нет. Это граница платформы, чинить нечего, обход искать не нужно;
— канал записи — перечисленные здесь воркфлоу. Они вызываются по HTTP, PUT выполняет сервер n8n, а не песочница, поэтому канал работает из любой среды: Claude Project, Cowork, Claude Code. Формулировка «писать из этой среды нельзя» относится только к прямому push и никогда — к каналу.
Непокрытая каналом операция — повод остановиться и назвать её, а не обходить прямым git (`second-brain-git` §6a).

Git Read Lines | W2lw8WIAIrwoPDUT | два режима одним воркфлоу — срез строк и поиск по регулярке. Вход POST {path, from?, to?, ref?, pattern?, flags?, before?, after?, limit?}; режим задаётся наличием pattern. Без pattern (mode=lines) — прежний контракт: from обязателен, строки с 1 включительно, to не задан — до конца. С pattern (mode=pattern) — from и to необязательны и задают окно поиска, по умолчанию весь файл; pattern — регулярное выражение JS рантайм-строкой new RegExp(pattern, flags), литералов regex в коде узла нет (баг SDK на \s\S\d\w, n8n-engineering-manual §4.7); flags — только из imsu, g и y отбрасываются узлом, потому что lastIndex делает re.test построчно невоспроизводимым; before и after — число строк контекста до и после совпавшей строки (default 0); limit — максимум блоков в matches (default 20).
