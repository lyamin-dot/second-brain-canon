## 4. GOOGLE SHEETS

### 4.0 Чтение Google Sheets — только gsheets-read (n8n `kRz5VVlxA1LiY7KG`)

body `{fileId, mode: "meta"|"range", sheetName?, range?, render?, maxRows?}` → `{success, fileId, mode, spreadsheetTitle, sheets, sheetName, range, render, rows, rowCount, returnedRows, truncated, maxRows, reason}`.
Вызов — `n8n:execute_workflow`, `executionMode: manual` (в production тело ответа не возвращается и execution не виден — R4). Вебхук закрыт Header Auth, в отличие от `gdocs-read`.

Порядок работы: СНАЧАЛА `mode:"meta"` — список листов с их размерами. Диапазон вслепую не запрашивать. Затем `mode:"range"` на конкретный лист.

Обязательные поля: `fileId` всегда; `mode` всегда (иное значение → throw); `sheetName` при `mode:"range"`. Имя листа экранируется внутри воркфлоу, руками кавычки не подставлять.

`range` — A1 без имени листа (`A1:G12`). Без него читается весь лист.

`render`: `UNFORMATTED_VALUE` — числа числами (по умолчанию); `FORMATTED_VALUE` — как отображается в интерфейсе; `FORMULA` — текст формул вместо результатов. Формулу (VLOOKUP, IMPORTRANGE) не отдаёт ни один текстовый экспорт и ни один другой режим — только `FORMULA`.

Даты приходят сериальными числами Google Sheets, не строками.

Три состояния ответа, которые НЕЛЬЗЯ путать:
- `success:true`, `truncated:false` — диапазон прочитан целиком.
- `success:true`, `truncated:true` — в диапазоне больше строк, чем `maxRows` (по умолчанию 500); вернулись только первые. Возвращённые строки НЕ являются всем диапазоном — сузить диапазон или поднять `maxRows`. Число реальных строк — в `reason` и `rowCount`.
- `success:true`, `rows:[]` с текстом EMPTY RANGE в `reason` — диапазон прочитан успешно и он пуст. Sheets API не присылает поле `values`, когда данных нет. Это НЕ провал чтения.
При `success:false` смотреть `reason`: он отдельно различает выключенный Sheets API в GCP-проекте `decent-surf-488714-u4` (SERVICE_DISABLED — не проблема расшаривания), файл не найден или не расшарен на SA, и отказ по правам.

ЗАПРЕЩЕНО для Sheets:
- `read_file_content` (MCP) — §0 п.2 действует и для таблиц: на файле в мегабайты обрезка на ~130 КБ гарантирована, а адресации по листам и диапазонам нет вовсе.
- Экспорт в `text/csv` через `download_file_content` — Google экспортирует ТОЛЬКО ПЕРВЫЙ ЛИСТ, без предупреждения. На многолистовом файле это тихая потеря остальных листов.
- Добавлять в `gsheets-read` запись. Инструмент read-only по замыслу: чтение и запись в одном вебхуке с произвольным `fileId` расширяют blast radius (R12).

Разрешено для разового разбора таблицы целиком, только в Cowork: `download_file_content` с `exportMimeType: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` → файл на диск → `openpyxl` (`data_only=False` — формулы, `data_only=True` — значения). В чат этот путь не переносить: бинарь уходит base64 в контекст и портится (§2.2 п.4, §10).

Критерий выбора между путями: `gsheets-read` — когда нужно посмотреть (структура, диапазон, формула). Cowork с .xlsx — когда нужно посчитать по всему массиву в десятки тысяч строк.

### 4.1 Создание таблиц — только через Apps Script

Скрипт вставляется в script.google.com и запускается вручную (Run) — не создавать Sheets напрямую.

ПЕРЕД ЛЮБОЙ ПЕРЕДЕЛКОЙ СУЩЕСТВУЮЩЕЙ КНИГИ читать парный Skill `apps-script-sheets`. Три ловушки оттуда, каждая из которых уже стоила полного прогона:
- `setFormula` пишет формулу буквально, без перевода в локаль книги (ru_RU: разделитель `;` и `\` в массивах);
- редактор Apps Script запускает первую функцию файла, а не выбранную мысленно;
- очистка листа без предварительного поиска ссылок на него убивает чужие формулы молча.

Прочие правила этого раздела:
- условное правило форматирования называется `whenFormulaSatisfied`, не `whenFormula`;
- единое пространство имён, одна `onOpen`, константы с префиксом;
- `parseFloat(x)||0` при чтении параметров даёт тихий ноль — всегда валидировать пороги: падать при невалидном пороге, не подставлять 0 молча;
- условное форматирование пересоздавать через Apps Script (`setupConditionalFormatting()`), не чинить в UI вручную.

### 4.2 Google Sheets node (n8n)
- Get Row(s) без фильтров; колонка A:A может прийти как `'A: field'` — проверять оба варианта имени.
- `returnAllMatches`+`limit` конфликтуют — использовать только `limit`. Delete Start Row — через expression.
- `documentId`/`sheetName` через expression `={{ 'ID' }}`. Разделитель формул — `;`. Прямая ссылка `=sheet!$K$4` вместо VLOOKUP. IMPORTRANGE ломается на таблицах >18000 строк — писать напрямую из n8n.
- `defineBelow` может не генерироваться SDK — использовать `autoMapInputData`, затем донастраивать маппинг в UI.
- Агрегация по дню: COUNTIFS/SUMIFS с границами суток (`">="&A2` / `"<"&(A2+1)`).
- Schema cache: после структурных правок — Refresh columns list → Save → Publish.
- 429 при appendOrUpdate → Wait 2с и повторить; удаление >5 строк — splitInBatches(5)+Wait(2s), защита заголовка `if(min(rows)<=1)throw`. `appendOrUpdate` всегда с явными `matchingColumns` (иначе тихие дубли); составной `matchingColumns` матчит только первую колонку — составной ключ собирать в одну колонку.
- Частые правки нескольких файлов подряд — пауза 1–2с между batchUpdate-вызовами, при 429 повторить.

### 4.3 Формулы
- Локаль таблицы проверять ДО генерации формул: функции RU (`ЕСЛИ`) или EN (`IF`) — по локали конкретной таблицы, иначе `#NAME?`.
- FILTER: нет нативного OR — использовать арифметику `(усл1)+(усл2)>0`; всегда оборачивать в `IFERROR(...,"текст")` — пустой результат без обёртки даёт ошибку в ячейке.
- `TEXTJOIN(IF(...))` при автозаполнении не вычисляется как массив без `ARRAYFORMULA()` — оборачивать обязательно.

### 4.4 Apps Script / PDF → текст
Единственный рабочий путь PDF→Doc из Apps Script — Drive API v2: `Drive.Files.insert(metadata, blob, {convert:true})`; v3 не работает для конвертации. Требует подключения сервиса Drive v2 в проекте Apps Script.
