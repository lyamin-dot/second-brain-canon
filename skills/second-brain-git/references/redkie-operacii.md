# second-brain-git — редкие операции

Файл Skill `second-brain-git`. Читается, когда операция началась: перенос документа из Google Docs в репозиторий и его приёмка, заморозка носителя, разрез файла core/, ротация журнала; а также две процедуры без постоянного читателя — замер доли «вне ролей» в лаборатории и опровержение бюджетов старта. Ротацию журнала начинает сессия, у которой оглавление журнала вышло выше бюджета чтения (раздел «Ротация журнала», пункт 1), — поэтому указатель на этот файл стоит и в разделе «Роли файлов проекта» основного файла. Остальная механика (транспорт, доказательство записи, маршрут доставки в main) — основной файл SKILL.md этого Skill.

## Стоп-правила
- Перенос по буквам и результат по смыслу одновременно не требовать.
- Перенос не считать принятым по одной проверке из двух; совпадение размеров и сумм приёмкой не считать.
- Контролёру не давать выводы и итоговые числа переносившего; экзамен, составленный до разбора по всему источнику, не применять.
- Меньше трёх кругов Контролёра не делать; владельцу между кругами не докладывать.
- Приёмку переноса не объявлять, пока перенос не в main.
- Ссылку на результат прошлой сессии входом задания не считать; над каналом доставки не работать, пока результат существует в единственном экземпляре в среде сессии.
- Источник не замораживать и не удалять до предъявленной приёмки.
- Заморозку или перенос носителя не считать законченными, пока не выведены все его писатели и читатели.
- Предмет механики прежнего носителя (поля и зоны Docs, пароли-канарейки, мониторы размера зон, счётчики байт Docs) не переносить — строка в NOT_TAKEN.md.
- Запись о баге, задаче, состоянии не переносить как действующую без сверки с живой системой.
- core/ не резать не по границе блока T-NN; байтовый разрез не делать; разрез не считать завершённым до удаления монолита; монолит не удалять до приёмки.
- Git Commit Files с телами новых файлов для разреза не использовать.
- Новый материал не класть в файл core/ другой темы ради свободных байт; суффикс без значения не давать; существующие суффиксные файлы ради правила не пересобирать.
- Разрез и ротацию не начинать в сессии, где маршрут (б) неисполним — позиция в Очереди.
- Ротацию серией Git Append в архив с Git Write журнала не делать; запись при ротации не делить; ротацию по размеру всего файла не делать; ротацию не откладывать без позиции; ротацию не закрывать отчётом — только тремя проверками.
- Внешние ссылки при ротации не править; номера Р и Т не переиспользовать; записи по прежнему общему счётчику не переименовывать.

## Как делать

### Ротация журнала
Ротация переносит существующие записи LOG.md в LOG_ARCHIVE.md: ни один байт уезжающего текста не набирается моделью, запись не делится, номер не теряется и не повторяется.
1. Когда: сессия, у которой оглавление журнала вышло выше бюджета чтения по сумме возвращённых байт, — той же сессией, тем же нарядом, до закрытия наряда. Обязательный предел по размеру — файл, который GitHub перестаёт отдавать через Contents API (1 МБ). Закончить не может — позиция в Очереди с путём файла, числом байт и датой смерти.
2. Что уезжает, строго по порядку, до ухода под бюджет: (1) записи со статусом ОТМЕНЕНО Р-NN (отменившая остаётся; ЧАСТИЧНО ОТМЕНЕНО не уезжает); (2) тупики, чьё условие возврата наступило и отработано, и тупики с прочерком, чей фикс внесён в CORE или Skill; (3) решения В СИЛЕ, чей номер назван основанием в PLAN.md проекта, в core/ или в Skill (поиском номера, не оценкой смысла) — в шапке LOG.md остаются номер и адрес правила; (4) самые старые записи подряд от начала файла, целиком.
3. Транспорт — один коммит, меняющий архив и журнал вместе, маршрутом (б): скрипт собирает тело из текущих версий обоих файлов в main, журнал режется по границе записи, уезжающее дописывается в конец архива без изменения прежних байт.
4. Закрытие — три проверки на main после свежего fetch: (1) blob sha обоих файлов равен посчитанному скриптом до коммита; (2) прежний архив — точное байтовое начало нового; (3) множество номеров Р и Т по всей истории обоих файлов за вычетом номеров журнала и архива пусто, пересечения журнала с архивом нет. Проверка 3 не видит безномерных блоков — закрывает только вместе с 1 и 2. Незакрытая ротация откатывается к коммиту до её начала.
5. Шапка LOG.md: перечень уехавших номеров и правило «номера, которого нет здесь, лежит в архиве». Р-NN и Т-NN — две независимые последовательности, каждая сквозная на журнал и архив; следующий номер — свежим чтением по своей шкале. Разрыв номеров проверяется проверкой 3 как возможная потеря.

### Разрез core/
Граница файла core/ — по смыслу: файл — тема с названным читателем; блок T-NN — минимальная единица, не режется никогда.
1. Новый материал — в файл своей темы.
2. Файл, переросший разумный для раздела размер, делится по теме: граница — смена предмета, имя это говорит (R-12-harvest.md, R-12-vychitanie.md).
3. Тематического шва нет — файл остаётся целым; число байт — в карту разделов справочно.
4. Как делить:

| Что | Чем |
|---|---|
| весь разрез | один коммит: новые файлы, удаление старого, правка `core/MANIFEST.md` и карты разделов; приёмка — скриптом до коммита, по старому файлу из рабочего дерева |
| тела новых файлов | маршрут (б): скрипт собирает их из байтов старого по границам блоков T-NN |
| правка Манифеста и карты разделов | текст этой сессии; скрипт вносит его тем же коммитом |

5. Приёмка скриптом до коммита: сумма байт новых файлов равна байтам старого с точностью до заголовков; каждый T-NN старого файла найден ровно в одном новом; Манифест и карта перечитаны, sha названы.
6. Маркеры T-NN остаются в тексте; карта разделов ведёт «раздел → файлы → блоки».
7. Существующий суффиксный файл пересобирается только при первой содержательной правке его раздела после снятия заморозки либо при отказе разрешения адреса — тем же коммитом, что правка, по шагам 2–5.

### Перенос из Docs
Перенос принят, только когда смысл подтвердил независимый читатель, видящий лишь источник и цель, а цель доступна из main.
1. Переносится смысл: действующие правила, инварианты, контракты, состояние, открытые вопросы, опыт; след, отменённое, пересказ чужого носителя — строка в NOT_TAKEN.md с адресом. Источник замораживается, не удаляется.
2. Разбор по ролям включает право чинить перекрёстные ссылки, заголовки, разрывы фраз; побайтово переносятся идентификаторы, пути, номера параграфов, собственные названия, числа, даты, метки приоритета.
3. Записи о багах, задачах, состоянии сверяются с живой системой (воркфлоу n8n, таблица, файл): исправленное или снятое едет историей с датой исправления.
4. Вход задания — в repo или целиком в тексте задания. Выход выносится по постоянному адресу раньше, чем улучшается способ доставки.
5. Приёмка — «Приёмка переноса»; доставка — «Перенос закончен только в main»; заморозка — «Заморозка носителя».

### Приёмка переноса
Две независимые проверки (а) и (б); при переносе проекта — ещё (в).
1. Снимок источника — дважды: в начале переноса и в начале приёмки (у документа Docs — byteLength и checkSum ответа gdocs-read). Расхождение называется в отчёте, выдающий задание решает, заморожен ли источник; при адресации строками проверяется, совпало ли содержание адресованных строк.
2. Перенос режет файл на блоки — карта разбиения до записи проверяется на сплошность и непересечение: блоки покрывают файл от первой до последней строки без дыр и наложений.

(а) Транспорт: построчное сравнение записанного с эталоном из версии до записи, исполнителем внутри задания, каждое расхождение объяснено; непустой diff — транспорт не принят. Плюс инвентаризация идентификаторов: все ID источника извлекаются регулярным выражением, каждый найден в цели или в NOT_TAKEN.md с адресом.

| Вид идентификатора | Форма |
|---|---|
| Drive | fileId |
| n8n | ID воркфлоу |
| записи и задачи | номера Р/Т/Н |
| наряды | Н-ДД.ММ-NN |
| исполнения n8n | «execution N», «executions N–M» и каждый номер диапазона; выражение принимает множественное число и диапазон через тире или дефис |
| ссылки на канон | «CORE Р.N» |

(б) Смысл: Контролёр — независимая сессия, читает только замороженный источник и цель, поштучно по каждой записи: вопрос, решение, «почему», все отвергнутые (счётом), «кто подтвердил», «обратимость», «допущение», «условие возврата», статус; не появилось ли утверждений, которых нет в источнике; не искажены ли числа, ID, даты, имена. Вердикт по записи: цело / потеря / искажение / не найдено.
- Задание Контролёру выдаётся вместе с заданием на перенос, без выводов и итоговых чисел переносившего.
- Контролёр — отдельный агент (субагент через Agent tool или отдельная сессия) без доступа к рассуждениям переноса и вердиктам прошлых кругов.
- Записи Контролёру — Git Read Lines диапазоном с верхней границей `to` (без `to` возвращается остаток файла с чужими вердиктами).
- Материал, читаемый сессией целиком на старте (CORE, список задач), — ещё экзамен: вопросы, составленные после разбора и до переноса, только по переезжающему материалу.
- Контролёр выдаёт раздел ПРЕДЛОЖЕНИЯ: по каждому классу дефектов — правку протокола или Skill с файлом, якорем и текстом «было → стало».
- Круги: Контролёр прогоняется заново после каждого круга исправлений, включая сверку самих исправлений; минимум три круга подряд, сама сессия, без обращения к владельцу; круг с новыми дефектами — правка и следующий круг, пока круг не пройдёт без новых дефектов. Владельцу — один доклад по итогам последнего круга.

(в) Контрольный набор при переносе проекта, рядом с Контролёром: пять вопросов о проекте («где ID книги X», «какой следующий шаг»), на которые незнакомая сессия отвечает только по канону; неверный или ненайденный ответ — дефект переноса. Снимается после трёх приёмок подряд без дефекта.

### Заморозка носителя
Действует для любой заморозки или переноса носителя — документа Google Docs, журнала, файла репозитория. Только после предъявленной приёмки. Тем же действием:
1. Носитель помечается в своём реестре: документ Google — словом ЗАМОРОЖЕН с датой в строке `registry/documents.md`.
2. Имя, ID и путь носителя ищутся механически, как в шаге 3 раздела «Правка Skill: приёмка, зеркало, копии, архив для заливки» Skill `redaktura`: клоном по всему репозиторию — core/ (маршрутные таблицы), meta/ (протоколы), meta/prompts/ (зеркала мастер-промптов), projects/, labs/ — и по папке Skills; воркфлоу n8n — поиском ID документа клоном в `registry/n8n-map.md` (строки `D|<ID документа>|<ID воркфлоу>|<узел>…`); при сомнении — `get_workflow_details` воркфлоу-кандидатов.
3. Каждая находка, которая велит писать в носитель или читать его как действующий, тем же действием переадресуется на новый носитель; в Skill, живом мастер-промпте или воркфлоу — текстом «было → стало» владельцу с позицией в Очереди.

### Перенос закончен только в main
Порядок строгий:
1. проверки «Приёмки переноса»;
2. доставка в main по «Маршруту доставки в main»;
3. чтение Каналом;
4. заморозка источника;
5. объявление приёмки и доклад владельцу.
Доставка проверяется снаружи ветки — чтением `projects/<имя>/STATE.md` через Git Read или Git Read Batch; «could not be found» — доставки нет. В отчёте обязательна строка «main <sha головы> содержит projects/<имя>/STATE.md, blob <sha> — прочитано Каналом, исполнение <номер>». Не доставлено — «перенос НЕ доставлен в main, лежит в ветке <имя>».

### Замер доли «вне ролей» в лаборатории
Диагностика к различению летописи и лаборатории — проверка утверждения «у лаборатории есть или нет сквозной хроники»:
1. ручная разметка границ «в ролях / вне ролей» на тексте INDEX-документа лаборатории;
2. подсчёт `len(text.encode('utf-8'))` раздельно по каждому сегменту, не построчной машинной классификацией;
3. поправка на CRLF-нормализацию при чтении через gdocs-read: расхождение общего размера равно числу строк файла, по байту на строку;
4. подкатегория «хроника сессий» внутри «вне ролей» — отдельной суммой, где применимо.

### Опровержение бюджетов старта
1. Эстафета, в которой вердикт ЭСТАФЕТА вынесен по исчерпанию контекста до закрытия наряда, а старт или чтение CORE названы в строке СТОИМОСТЬ среди потребителей, записывается в LOG.md тупиком по форме журнала.
2. Первый такой тупик — запись без пересмотра; второй — пересмотр бюджета при ближайшем харвесте.
3. Новый замер цены или бюджета записывается в журнал проекта, который его снял, вместе с прежним значением, которое он сменяет.
