# second-brain-git — ротация журнала

Часть Skill second-brain-git. Читать: перед ротацией LOG.md. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

5.2. LOG.md — ротация в LOG_ARCHIVE.md. Исполнитель и момент: сессия, у которой оглавление журнала (7.6, строка «оглавление журнала») вышло выше бюджета чтения по сумме возвращённых байт, — той же сессией, тем же нарядом, до закрытия наряда. Размер всего файла поводом к ротации не является: журнал читается оглавлением и записями по номеру (4, Р-11 журнала projects/kontext-reduktion/LOG.md). Предел, который ротацию всё же требует, — размер файла, при котором GitHub перестаёт отдавать его содержимое через Contents API (1 МБ): такой файл Канал прочитать не сможет. Если сессия закончить ротацию не может — позиция в Очереди с путём файла, числом байт и датой смерти; «отложить без позиции» ЗАПРЕЩЕНО (10.5).

Состав уезжающего задаётся признаками строго в порядке, до ухода под бюджет:
1. записи со статусом ОТМЕНЕНО Р-NN (отменившая остаётся);
2. тупики, чьё условие возврата наступило и отработано, и тупики с прочерком, чей фикс внесён в CORE или Skill;
3. решения В СИЛЕ, чей номер назван как основание в PLAN.md этого проекта, в файле core/ или в Skill, — в шапке LOG.md остаётся номер и адрес правила; критерий — поиск номера, не оценка смысла;
4. самые старые записи подряд от начала файла, целиком.

Запись не делится.

5.3. Транспорт ротации — один коммит, меняющий архив и журнал вместе, по маршруту 9.4(б). Тело собирается скриптом из текущих версий обоих файлов в main: журнал режется только по границе записи, уезжающее дописывается в конец архива без изменения прежних байт. Серия Git Append в архив с Git Write журнала для ротации НЕ применяется: текст уезжающих записей при этом набирается моделью (4.5). Сессия в среде, где 9.4(б) неисполним, ротацию не начинает — позиция в Очереди по 5.2.

Ротация закрывается не отчётом, а тремя проверками на main после свежего fetch:
1. blob sha обоих файлов равен sha, посчитанному скриптом до коммита;
2. прежний архив — точное байтовое начало нового;
3. множество номеров Р и Т по всей истории обоих файлов за вычетом номеров журнала и архива пусто, и пересечения журнала с архивом нет.

Проверка 3 не видит безномерных блоков, поэтому закрывает ротацию только вместе с 1 и 2. Незакрытая ротация откатывается к коммиту до её начала.

5.4. Ссылочность после ротации держится шапкой LOG.md: перечень уехавших номеров и правило «номера, которого нет здесь, лежит в архиве». Номерное пространство Р-NN/Т-NN сквозное, номера не переиспользуются; внешние ссылки при ротации не правятся. Р-NN и Т-NN — две независимые последовательности, у каждой свой счётчик. «Сквозное» означает: одна последовательность на журнал и архив вместе, номер не переиспользуется после ротации. Оно НЕ означает общий счётчик для Р и Т. Записи, сделанные когда-то по общему счётчику, не переименовываются — append-only; следующие номера каждой последовательности берутся из свежего чтения по своей шкале.
