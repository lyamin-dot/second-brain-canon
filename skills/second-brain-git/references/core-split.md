6. Разрез core/

ЗАКОН РАЗДЕЛА. Граница файла core/ проводится по смыслу, а не по байтам: файл — это тема с названным читателем, и делит его только смена предмета. Почему: читатель ищет правило по теме через Манифест и карту разделов; граница, проведённая по числу байт, разрезает тему и отправляет его в два файла за одним правилом, а размер файла цену читателя не определяет — её определяет сумма прочитанного (4.5). Отсюда — 6.1–6.8: размещение по теме, деление по шву, отказ делить без шва, скрипт вместо набора.

6.1. Единица хранения — смысл с названным читателем, не байты. Файл core/ — раздел R-NN канона или его тематическая часть; блок T-NN — минимальная единица, которая не режется никогда.

6.2. Новый материал идёт в файл своей темы. Наличие свободных байт в другом файле основанием для размещения не является: материал, положенный туда, где есть место, читатель по теме не найдёт.

6.3. Файл core/, переросший разумный для одного раздела размер, делится ПО ТЕМЕ, а не по байтам: граница — там, где меняется предмет, с именем, которое это говорит (R-12-harvest.md, R-12-vychitanie.md), никогда — суффикс без значения.

Как делить:

| Что | Чем | Почему |
|---|---|---|
| весь разрез | одним коммитом: новые файлы, удаление старого, правка core/MANIFEST.md и карты разделов; приёмка по 6.8 | — |
| тела новых файлов | маршрут 9.4(б): скрипт собирает их из байтов старого по границам блоков T-NN | тела — уже существующий текст; набор моделью его меняет (4.5) |
| правка Манифеста и карты разделов | текст этой сессии; скрипт вносит его тем же коммитом | это новый текст, его набирает сессия |

Git Commit Files с телами новых файлов в вызове для разреза ЗАПРЕЩЁН: тела — уже существующий текст, класс Р-79 (4.5). Сессия, в которой 9.4(б) неисполним, разрез не начинает — позиция в Очереди с путём файла и датой смерти (10.5).

6.4. Если тематического шва нет — файл остаётся целым, каким бы ни был его размер; число байт заносится в карту разделов справочно, позиция в Очередь по одному размеру не заводится. Байтовый разрез ЗАПРЕЩЁН.

6.5. Существующие суффиксные файлы не пересобираются ради правила: отказов адресации через карту не наблюдалось, а пересборка без отказа — работа без читателя. Условие пересборки — первая содержательная правка соответствующего раздела после снятия заморозки либо отказ разрешения адреса, пришедший сам. Пересборка — тем же коммитом, что правка, по 6.3 и тем же маршрутом 9.4(б).

6.6. Маркеры T-NN остаются в тексте как провенанс блока независимо от файла, в котором блок лежит; карта разделов ведёт «раздел → файлы → блоки». Почему: ссылка «CORE Р.N» и номер блока разрешаются через карту (3.3), а не через имя файла.

6.8. Приёмка деления: сумма байт новых файлов равна байтам старого с точностью до заголовков; каждый T-NN старого файла найден ровно в одном новом; Манифест и карта перечитаны, sha названы.
