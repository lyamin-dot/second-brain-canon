# second-brain-git — лаборатория

Часть Skill second-brain-git. Читать: перед любой работой с папкой labs/. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

4б. Лаборатория

ЗАКОН РАЗДЕЛА. Лаборатория — множество независимых задач без общего финиша. Роли её файлов и отсутствие потолка выводятся из этого одного свойства: у независимых задач нет общего следующего шага, поэтому нет STATE, PLAN и LOG; задача — единица смысла, поэтому её не режут и не ограничивают байтами; читатель на старте выбирает задачу, поэтому платит только за список. Пункт, который этому свойству противоречит (фазы, общий шаг, названный финиш), означает, что перед тобой уже не лаборатория (4б.7).

4б.1. Различение летописи и лаборатории — один признак: назван ли финиш.

| Признак | Сущность | Роли файлов |
|---|---|---|
| финиш назван; достигнут — папка закрывается | проект-летопись, projects/<имя>/ | четыре роли, 4 |
| финиша нет; тема, задачи друг в друга не переходят | лаборатория, labs/<имя>/ | две роли, 4б.3 |

Роли 4 применяются только к летописи. Почему один признак: всё остальное (размер, число задач, наличие хроники) у обеих сущностей бывает любым и различения не даёт.

4б.2. Лаборатория лежит в labs/<имя>/. Имя папки — по 2.1. Имя берётся из того, как объект называет владелец, а не из имени файла-артефакта.

4б.3. Роли файлов лаборатории — две, других нет.

| Роль | Содержание | Предел | Читатель и момент |
|---|---|---|---|
| INDEX.md | список живых задач: имя файла, одна строка сути, метка приоритета, возраст; у задачи с эстафетой — пометка «активная эстафета «<метка>»» (Skill context-handoff, раздел 8). Тел задач нет | не в байтах: одна строка на задачу | старт каждой сессии лаборатории, до выбора задачи |
| t-<имя>.md, по файлу на задачу | тело одной задачи: суть, следующий шаг или предложение, условие снятия, ссылки | не в байтах: задача — единица смысла | сессия, выбравшая эту задачу по INDEX.md |

STATE.md, PLAN.md и LOG.md в лаборатории не заводятся: у независимых задач нет общего следующего шага, при отсутствии финиша нет фаз. Это свойство сущности, не пробел. RULES.md и NOT_TAKEN.md не заводятся тоже — третьей роли нет.

Потолка в байтах у файла лаборатории нет и не будет. Почему: ограничитель, у которого нет ни одного разрешённого следствия, ограничителем не является — сократить файл ЗАПРЕЩЕНО 5.1 как ужимание, отказать в записи ЗАПРЕЩЕНО 14, разрезать задачу ради числа запрещено самой природой задачи как единицы смысла. Признак, что сессия пошла по ложному пути: она выводит «разумный» потолок INDEX.md по аналогии с потолками летописи — аналогия числа не определяет, у PLAN.md и LOG.md одинаковый по характеру читатель при разных числах.

Вес лаборатории удерживает устройство INDEX.md, а не число: список держит строку сути и не держит тел задач, поэтому читатель на старте платит за INDEX.md, а не за всю папку. Снимки этой цены с датами — references/costs.md, раздел «Старт лаборатории». Файл, переросший разумный размер, разбирается по 4б.7 — разворачивается в летопись, если он на самом деле проект. Это решение по существу задачи, а не по её весу.

[основание: GIT-30]

4б.3.1. Метод замера доли «вне ролей». Это диагностика к 4б.1, а не отдельный критерий признания лабораторией: инструмент проверить конкретное утверждение вида «у лаборатории есть или нет сквозной хроники».
Шаги:
1. ручная разметка границ «в ролях 4б.3 / вне ролей» на тексте INDEX-документа лаборатории;
2. подсчёт `len(text.encode('utf-8'))` раздельно по каждому сегменту — не построчной машинной классификацией: строка не совпадает с границей роли;
3. поправка на CRLF-нормализацию при чтении через `gdocs-read`: наблюдаемое расхождение общего размера равно числу строк файла в байтах, по одному байту на строку;
4. подкатегория «хроника сессий» внутри «вне ролей» считается отдельной суммой, где применимо.
Допущение «у лаборатории нет сквозной хроники» закрыто как отменённое: хроника весома и есть.
[основание: GIT-31]

4б.4. INDEX.md — файл-список папки по 3.2: Канал каталог не перечисляет, поэтому состав папки для читателя без клона существует только в этом списке.

4б.5. Атомарность. Создание задачи и закрытие задачи выполняются одним вызовом Git Commit Files, включающим и файл задачи, и правку INDEX.md. Запись двумя вызовами ЗАПРЕЩЕНА. Почему: состояние «файл задачи есть, строки в списке нет» Каналом не обнаруживается (3.2), поэтому оно делается недостижимым, а не обнаруживаемым.
Git Commit Files принимает INDEX.md целиком, поэтому его новый текст собирается вычёркиванием или вставкой строки в текст, полученный ответом чтения в этой же сессии, и принимается diff-ом по исключению 4.5 (references/write.md): строка вычёркивается из наличного текста, а не восстанавливается по памяти. Текст INDEX.md, не прочитанный в этой сессии, в вызов не идёт никогда.
Признак правильного исхода: diff нового INDEX.md против прочитанного показывает ровно вставленную или ровно вычеркнутую строку и ничего больше.
[основание: GIT-32]

4б.6. Закрытие задачи — удаление её файла и её строки в INDEX.md (одним вызовом, 4б.5). Архивного файла нет: снятое читается из истории по ref родителя коммита удаления, поэтому второй носитель для закрытых задач не нужен (И-1).
Исключение — задача, чей текст стал адресом строк основания (Skill, отчёт синтеза, файл кейсов). Перед закрытием её текст переносится скриптом без изменений, кроме строки-пути, в постоянный живой файл — файл кейсов meta/CASES_<тема>.md или файл проекта, — чтобы номера строк в адресах остались верны; ссылки на прежний путь переадресуются по 2.5 тем же коммитом, что закрытие. Это не второй носитель: задача удаляется, текст живёт в одном месте. Почему: строка основания называет путь, которого в рабочем дереве больше нет; чтобы прочитать его из истории, нужен номер коммита, которого строка не называет, а поиск по клону и Канал по пути его не находят. Признак: файл задачи назван в строке основания живого Skill или отчёта синтеза. [основание: GIT-33]

4б.7. Задача, в чьём файле появились фазы, общий следующий шаг или названный финиш, задачей быть перестала — она разворачивается в папку-летопись по 4 (новый проект — references/migration.md, 12); целью становится то, ради чего она росла. Признак — по тексту файла, не по числу байт: размер о сущности ничего не говорит (4б.1).

4б.8. Старение. Возраст задачи = дата чтения минус дата последнего коммита, тронувшего её файл. Задача, не тронутая более 30 суток, помечается в INDEX.md как лежалая. Читатель — сессия лаборатории, момент — старт, до выбора задачи. Пометка ничего не удаляет и не закрывает. В текст задачи дата не пишется: дату даёт git, а записанная дата стареет молча.

Чем брать дату:

| Среда | Инструмент | Как |
|---|---|---|
| с клоном | `git log -1 --format=%cI -- <путь>` | один вызов на всю папку через `git log --name-only` |
| без клона | воркфлоу Git Log | только с limit, равным необходимому |

Git Log тянет данные узлом httpRequest и потому ДОРОГ: при limit=1 около 4,5 КБ в контекст при полезном выходе около 150 Б, линейно по limit (грязный воркфлоу — 7.6; замер 2026-09-18 и его адрес — references/costs.md). Пометка лежалости целой лаборатории через Git Log — самая дорогая операция старта, какая в этом контракте вообще предусмотрена; если клон есть, звать Git Log для неё — ошибка выбора инструмента.

4б.9. Номер пункта снят и не переиспользуется. Прежний пункт 4б.9 — правило о файле лаборатории, оказавшемся над потолком в байтах, — отменён вместе с потолком (4б.3). Журналы ссылаются на «§4б.9» в прежнем смысле, поэтому номер под новое правило не занимается.
[основание: GIT-34]

4б.10. Реестр. Лаборатория заводится строкой в registry/projects.md, раздел «Лаборатории»: лаборатория | папка | носитель | статус — тем же коммитом, что создание INDEX.md. Закрытие — смена статуса, не удаление (как 12.4). Почему: без строки в реестре лаборатория для читателя реестра не существует.
