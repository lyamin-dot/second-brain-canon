# second-brain-git — лаборатория

Часть Skill second-brain-git. Читать: перед любой работой с папкой labs/. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

4б. Лаборатория

4б.1. Две сущности, одно различение. Проект-летопись — папка с названным финишем: финиш достигнут, папка закрывается. Лаборатория — папка с темой без финиша; задачи внутри независимы и друг в друга не переходят. Признак один: назван ли финиш. Не назван — лаборатория. Роли 4 применяются только к летописи.

4б.2. Лаборатория лежит в labs/<имя>/. Имя папки по 2.1. Имя берётся из того, как объект называет владелец, а не из имени файла-артефакта.

4б.3. Роли файлов лаборатории — две, других нет.

| Роль | Содержание | Предел | Читатель и момент |
|---|---|---|---|
| INDEX.md | список живых задач: имя файла, одна строка сути, метка приоритета, возраст. Тел задач нет | не в байтах: одна строка на задачу | старт каждой сессии лаборатории, до выбора задачи |
| t-<имя>.md, по файлу на задачу | тело одной задачи: суть, следующий шаг или предложение, условие снятия, ссылки | не в байтах: задача — единица смысла | сессия, выбравшая эту задачу по INDEX.md |

Потолка в байтах у файла лаборатории нет и не будет. Ограничитель, у которого нет ни одного разрешённого следствия, ограничителем не является: сократить файл запрещено 5.1 как ужимание, отказать в записи запрещено 14, разрезать задачу ради числа запрещено самой природой задачи как единицы смысла.

Вес лаборатории удерживает устройство INDEX.md, а не число: список держит строку сути и не держит тел задач. Замер 2026-09-26 по labs/sys/: читатель на старте платит 6 494 Б за INDEX.md при полном весе лаборатории 53 023 Б — в восемь раз меньше суммы файлов (прежний замер 2026-09-18: 5 785 из 37 818 Б). Файл, переросший разумный размер, разбирается по 4б.7 — разворачивается в летопись, если он на самом деле проект. Это решение по существу задачи, а не по её весу.

STATE.md, PLAN.md и LOG.md в лаборатории не заводятся: у независимых задач нет общего следующего шага, при отсутствии финиша нет фаз. Это свойство сущности, не пробел.

4б.3.1. Метод замера доли «вне ролей» — диагностика к 4б.1, не отдельный критерий признания лабораторией, а инструмент проверить конкретное утверждение вида «у лаборатории есть/нет сквозная хроника». Шаги: (1) ручная разметка границ «в ролях 4б.3 / вне ролей» на тексте INDEX-документа лаборатории; (2) подсчёт `len(text.encode('utf-8'))` раздельно по каждому сегменту — не построчной машинной классификацией; (3) поправка на CRLF-нормализацию при чтении через `gdocs-read`: наблюдаемое расхождение общего размера равно числу строк файла в байтах, по одному байту на строку; (4) подкатегория «хроника сессий» внутри «вне ролей» считается отдельной суммой, где применимо. Метод применён трижды — SERVER (LOG.md git-migration Р-61), N8N и OZON_UE (Р-63) — во всех трёх подтвердил, что хроника весома и есть; на этом основании допущение «у лаборатории нет сквозной хроники» закрыто как отменённое (Р-68).

4б.4. INDEX.md — файл-список папки по 3.2.

4б.5. Атомарность. Создание задачи и закрытие задачи выполняются одним вызовом Git Commit Files, включающим и файл задачи, и правку INDEX.md. Запись двумя вызовами ЗАПРЕЩЕНА: состояние «файл задачи есть, строки в списке нет» Каналом не обнаруживается (3.2), поэтому оно делается недостижимым, а не обнаруживаемым. Git Commit Files принимает INDEX.md целиком, поэтому его новый текст собирается вычёркиванием или вставкой строки в текст, полученный ответом чтения в этой же сессии, и принимается diff-ом по исключению 4.5 (references/write.md). Текст INDEX.md, не прочитанный в этой сессии, в вызов не идёт никогда.

4б.6. Закрытие задачи — удаление её файла и её строки в INDEX.md. Архивного файла нет: снятое читается из истории по ref родителя коммита удаления.

4б.7. Задача, в чьём файле появились фазы, общий следующий шаг или названный финиш, задачей быть перестала — она разворачивается в папку-летопись по 4; целью становится то, ради чего она росла. Признак — по тексту файла, не по числу байт.

4б.8. Старение. Возраст задачи = дата чтения минус дата последнего коммита, тронувшего её файл. Задача, не тронутая более 30 суток, помечается в INDEX.md как лежалая. Читатель — сессия лаборатории, момент — старт, до выбора задачи. Пометка ничего не удаляет и не закрывает. В текст задачи дата не пишется.

Чем брать дату: в среде с клоном — `git log -1 --format=%cI -- <путь>`, один вызов на всю папку через `git log --name-only`. Воркфлоу Git Log звать только в среде без клона и только с limit, равным необходимому: он тянет данные узлом httpRequest и потому ДОРОГ — при limit=1 около 4,5 КБ в контекст при полезном выходе около 150 Б, линейно по limit (грязный — 7.6, цена — references/costs.md). Пометка лежалости целой лаборатории через Git Log — самая дорогая операция старта, какая в этом контракте вообще предусмотрена; если клон есть, звать Git Log для неё — ошибка выбора инструмента.

4б.9. Номер снят и не переиспользуется.

4б.10. Реестр. Лаборатория заводится строкой в registry/projects.md, раздел «Лаборатории»: лаборатория | папка | носитель | статус — тем же коммитом, что создание INDEX.md. Закрытие — смена статуса, не удаление (как 12.4). Без строки в реестре лаборатория для читателя реестра не существует.
