# second-brain-git — цены и бюджеты в байтах

Часть Skill second-brain-git. Читать: когда решение опирается на цену транспорта или бюджет старта в байтах. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

Бюджеты, снятые с объекта 2026-09-24: старт сессии repo-проекта — meta/PENDING_RULES.md 1 377 Б + projects/git-migration/STATE.md 8 855 Б = 10 232 Б (после разбора по 5.1, Р-4 журнала `projects/kontext-reduktion/LOG.md`). Команда, читающая CORE (!save, харвест и прочие по мастер-промпту) — core/MANIFEST.md 7 599 Б + 4 файла таблицы «Список» 8 234 Б = 15 833 Б, двумя вызовами Git Read Batch; файлы таблицы «По событию» в эту сумму не входят и оплачиваются только сессией, у которой событие наступило (Р-111 журнала git-migration, Р-3 журнала kontext-reduktion). Признак старта CORE по 7.2 на эту дату: 4 / core/R-07.md / 21e479d. Прежний замер 2026-09-18 (38 293 Б, 11 файлов и meta/header.md) — до этих решений.

Оба числа — гипотезы от даты замера, а не нормы, и сверяются с объектом при каждой ревизии контракта. Повторять их по памяти или переносить из прошлой редакции ЗАПРЕЩЕНО: CORE и STATE меняются, и перенесённое число врёт молча.

Опровергаются эстафетой, в которой вердикт ЭСТАФЕТА вынесен по исчерпанию контекста до закрытия наряда и старт либо чтение CORE названы в строке СТОИМОСТЬ среди потребителей. Такая эстафета записывается в LOG.md тупиком по форме 11. Первый такой тупик — запись без пересмотра; второй — пересмотр бюджета при ближайшем харвесте. Превышение бюджета ростом файлов — сигнал харвесту по 5.5, не отказ и не блок.

Цена транспортов. Читатель — сессия; задача — «достать одну запись из журнала»; даты снятия названы. Доказательства (номера исполнений) — записи Р-100 и Р-102 журнала git-migration.

| Транспорт | Цена | Дата |
|---|---|---|
| клон, извлечение фрагмента | 0,19× размера файла | 2026-09-17 |
| Git Read Lines, pattern, с контекстом записи | 0,18× | 2026-09-17 |
| Git Read Lines, pattern, только заголовки записей | 0,015× без конверта, около 0,06× с конвертом | 2026-09-17; основание уточнено 2026-09-24 (Р-10 журнала projects/kontext-reduktion/LOG.md): 0,015× посчитано без конверта ответа, а соседние строки таблицы — с конвертом |
| Git Read Lines по известному номеру строки | 0,11× | 2026-09-17 |
| сплошное чтение суженным вызовом | около 1,0× плюс конверт около 1,1 КБ | 2026-09-17 |
| то же без сужения | 3,38× | 2026-09-17 |
| Git Log, limit=1 | около 4,5 КБ при полезных 150 Б | 2026-09-18 |

Сплошное чтение суженным вызовом и клон стоят одинаково — 1,0×: тело файла приходит один раз и там, и там. Разница между ними не в цене, а в том, что клон есть не везде. А вот на ИЗВЛЕЧЕНИИ ФРАГМЕНТА клон стоит 0,19×, и сплошное чтение проигрывает впятеро и больше — поэтому «прочитать файл целиком и найти нужное глазами» правильным ответом не является нигде, кроме случая, когда нужен весь файл.

Конверт в 1,1 КБ — оценка по составу ответа, а не измерение: харнесс не отдаёт размер своего ответа в байтах. Названа оценкой и повторению как измерение не подлежит.

Приём, разделяющий две причины дороговизны: вызвать `get_execution(includeData:true)` с заведомо несуществующим именем узла в `nodeNames`. Тогда `runData` придёт пустым, и всё, что осталось в ответе, — это утечка узла, а не дублирование по графу.
