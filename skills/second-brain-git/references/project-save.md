# second-brain-git — save по проекту, Очередь, правила PLAN.md

Часть Skill second-brain-git. Читать: перед save по проекту в repo, перед новой позицией Очереди или сменой её статуса, перед записью дополнительной роли файла проекта или аномалии в PLAN.md, перед записью факта соседнему проекту, целиком, один раз за сессию. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md. Файл выделен из references/write.md 2026-10-23 (шаг 6 плана `meta/PLAN_skill-layers_2026-10-20_v3.md`), текст пунктов перенесён без изменений.

4.6. Дополнительные роли и отступления от бюджета чтения. Проект может иметь роли сверх четырёх и бюджет чтения, отличный от таблицы 4, если выполнены три условия сразу:
1. материал не ложится ни в одну из четырёх ролей по правилу 4.2;
2. роль или изменённый бюджет объявлены в PLAN.md этого проекта с содержанием, числом, читателем и моментом чтения;
3. решение записано в LOG.md этого проекта с основанием, по которому его можно оспорить.
Отступление действует только в объявившем его проекте.

Агентская копия на английском (предпочтение Андрея — две версии рабочих документов) — частный случай дополнительной роли. Её шапка называет парный файл; для пары в meta/, у которой нет своего журнала, условие 3 этого пункта не требуется — пару объявляет шапка. Правка одного файла пары — тем же коммитом правка другого; перед записью копии сверяются по составу: разделы, правила, числа, исключения. Расхождение, найденное позже, — стоп и вопрос Андрею, какая копия права; тихо выравнивать нельзя, и ни одна копия не главная автоматически. Почему: агент исполняет английскую копию, Андрей решает по русской, и каждый считает свою верной. Признак: шапки пары объявляют главной разные копии, или в одной копии больше разделов, чем в другой. [основание: GIT-55]

4.7. Правила записи PLAN.md. Аномалия, которую признали нормой (ожидаемое постоянное состояние, намеренный дубль, известное расхождение), записывается с пометкой «не дефект, не расследовать» и причиной — там, где на неё наткнётся следующий читатель: в PLAN.md рядом с описанием объекта или в файле meta/, который описывает этот объект.
Почему: без пометки каждая следующая сессия заново принимает норму за дефект и тратит ход на расследование.
Образцы — «ожидаемое постоянное состояние» в projects/wb-reviews/PLAN.md, «дубли article_1 намеренные» в meta/DECLARATION_SCAN.md.

10. Save по проекту в repo

Граница: когда сохранять, что захватывать и с чьего согласия — Skill second-brain-engineer (Р6 захват, Р7 !save, Р16 регистрация обязательств); здесь — куда и чем ложится каждая запись в repo.

10.1. Список [ЗАХВАЧЕНО] показывается и записывается без ожидания; согласие — сама команда !save (second-brain-engineer, Р7).

10.2. Определить проект по registry/projects.md. Не определился — запись остаётся в чате, не угадывать.

10.3. Маршрут по типу:

| Что произошло | Куда |
|---|---|
| сдвинулось состояние | STATE.md |
| принято решение, провалилась попытка, случилась незапланированная отладка | LOG.md |
| изменилось правило проекта | PLAN.md |
| ничего из трёх | написать «решений нет» явно |

Молчание = save не закрыт.

10.4. Записать по 8; несколько файлов — по 8.6. Сверить с бюджетом чтения (4–6); превышение — по 5.5, не отказ.

10.5. Факт, который сессия правит сама, и факт, который правит только владелец.
- Факт, требующий правки CORE или задачи лаборатории labs/sys/, — правится до конца сессии.
- Документ SYS_INDEX в Google Docs заморожен: решено 2026-09-23 (запись Р-109 журнала projects/git-migration/LOG.md), заморожен 2026-09-30 (запись Р-123 того же журнала) — в него не писать. Своего INDEX в Docs у repo-проекта нет.
- Факт, требующий правки Skill или мастер-промпта, — позиция в Очереди через Git Append File (запасной путь — Git Append) с датой смерти. «Отложить до харвеста» без позиции ЗАПРЕЩЕНО.

Статус позиции Очереди начинается одним словом из закрытого словаря; всё прочее — после точки с запятой.

| Слово | Когда | После слова |
|---|---|---|
| ОТКРЫТА | позиция заведена, текст правки владельцу ещё не выдан | — |
| ЖДЁТ | текст выдан или работа сделана, ждёт действия владельца (заливки, решения, вставки в промпт) или харвеста | чего именно |
| ВНЕСЕНО | правка стоит в целевом носителе и проверена по объекту | дата и адрес |
| СНЯТА | не вносится | дата и причина |
| ДУБЛЬ | содержание уже живёт в носителе, в другой открытой позиции или задаче лаборатории | адрес |

Форма: «ВНЕСЕНО 2026-10-13 — <адрес>; отложено 2026-10-10 до пакета Архивариуса». При смене статуса новое слово с датой встаёт в начало, прежний текст уходит после точки с запятой и не стирается. Других первых слов нет: «ждёт» строчными, «отложено», «частично», «ЗАКРЫТО», «ВЫПОЛНЕНО», «СНЯТ» — нарушение формы.
Почему: открыта ли позиция, решает разбор по первому слову, и скрипт делает его без ошибок; слово в середине истории («до внесения», «внесено в составе») такой разбор обманывает.
[основание: GIT-61]

Позиция, которая ссылается словом ДУБЛЬ на другую позицию, держит своё содержание только пока та открыта или внесла его в носитель. Поэтому при снятии позиции те, что ссылаются на неё словом ДУБЛЬ, тем же действием получают статус заново. Почему: содержание, переданное по ссылке позиции, которую потом сняли, выпадает из Очереди молча — первым словом статуса оно закрыто, а в носителе его нет. Признак: позиция со статусом ДУБЛЬ указывает на позицию со статусом СНЯТА. [основание: GIT-62]

10.6. Факт, полезный соседнему проекту, пишется одной строкой в STATE.md соседа, в раздел «От соседнего проекта» (раздел заводится первой такой строкой), с датой и адресом решения в своём журнале — тем же шагом, на котором факт узнан, не дожидаясь !save (момент и тег захвата — second-brain-engineer, Р6).
Почему: пересказ в чате записью не считается — сессия соседа чат не читает.
Сосед, приняв факт, переносит его в свой PLAN.md или LOG.md и вычёркивает строку.
Запись в чужую папку подчиняется 8.9: если сессия соседа работает одновременно, путь называется в рамке.
Образец — разделы «От соседнего проекта» в projects/deklaration-ozon/STATE.md и projects/deklaration-wb/STATE.md.
Обратная сторона — перед проектированием нового шага смотреть журнал соседа по тому же объекту — правило поиска: second-brain-engineer, Р9.
