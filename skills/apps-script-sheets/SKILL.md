# apps-script-sheets

Что происходит внутри книги Google Sheets, когда её перестраивает Apps Script; откуда сессия берёт код скрипта книги и как вносит правку. Чтение и запись Drive, `gsheets-read`, `gdocs-*` — Skill `google-drive-docs`.

## Стоп-правила

- Ни одна ячейка не стирается и разметка не сдвигается, пока `findRefs` не показал все формулы всех листов, которые ссылаются на этот лист.
- «Лист пуст, можно занимать» по прочитанному диапазону не выводится.
- Код скрипта правится только по живому тексту (см. «Живой текст скрипта»); по технической документации книги, своей копии из прошлой сессии, старой справочной копии в Drive — нельзя.
- Правка формул или кода рабочей книги — только после согласования с Андреем, что чиним и что строим; и когда сессия пишет мостом сама. Если план уже согласован в чате или записан в `PLAN.md` проекта — назвать адрес согласования и идти дальше.
- Запись мостом — только при строке `gas_allowlist` с доступом `write`, прочитанной в этой сессии; память прошлой сессии и этот Skill признаком не являются.
- Строку с доступом `write` в `gas_allowlist` добавлять только после слова Андрея в чате.
- Запись мостом — только с `projectHash` из свежего `read` или `projectHashAfter` предыдущей записи той же серии; отказ по устаревшему отпечатку — перечитать и повторить от нового текста.
- Файл, пришедший с `truncated:true`, неполон — по нему не править.
- Правку, которая не помещается в один уникальный фрагмент, не писать файлом целиком — только серией фрагментов.
- Код книги, прочитанный мостом, в репозиторий не пишется — ни целиком, ни фрагментом; в канон идут имена файлов, функций и отпечаток проекта.
- Запуск функций книги сессией не обещать и не планировать: мост пишет код, функции запускает Андрей.
- Сессия через clasp не пишет и такую правку не планирует.
- Подворкфлоу gas-bridge «· Call» не вызывать.
- Точечные патчи «было → стало» для ручной вставки не выдавать — только полный текст файла.
- Шаг «прочитать оформление через `gsheets-read`» в план и эстафету не ставить.
- При аудите проверочные ячейки, равные нулю по построению (разность двух сумм из одних данных), доказательством не считать.
- Разделитель формул не переносить из другой книги, прошлой сессии или записи в каноне и не выводить из формулы, прочитанной `gsheets-read` в `FORMULA`.
- Формулу не писать без перевода в разделитель этой книги.
- Конвертер разделителя (`loc_`) и `alert_` из старых образцов книг не брать — они написаны раньше и несут исправленные ошибки; писать заново.
- Дробь в формуле — всегда с ведущим нулём (`0.5`, не `.5`); имя листа с точкой или запятой — только в одинарных кавычках.
- Формулу с литералом массива не писать через `gsheets-*` (`values.update` `USER_ENTERED`) — только из Apps Script.
- В тяжёлой книге опытных зондов, которые пишут и ждут пересчёта, не делать — только чтение уже записанного.
- Итог прогона не выводить модальным окном (`getUi().alert()`): только журнал и всплывающая подсказка.
- `setupAll` — три блока в таком порядке: все чтения → расчёт в памяти → все записи. Новый шаг сборки берёт данные из чтений этого блока и источник второй раз не читает. Почему это стоп: Apps Script копит записи и сбрасывает их при первом чтении после них, каждое такое чтение ждёт пересчёта книги — в тяжёлой книге это упирается в потолок 6 минут.
- После первой записи главная функция книгу не читает — ни для отчёта, ни для проверки записанного; исключение — зонд разделителя первым шагом записей в лёгкой книге.
- Чтения заняли больше 4 минут — запись не начинать.
- Срыв прогона по времени не лечить вторым «страховочным» триггером: повтор упирается в тот же потолок и прячет причину.
- Вызов сервиса Google на каждую строку цикла (`Utilities.formatDate` по десяткам тысяч строк) не писать: результат запоминать по ключу или считать арифметикой по серийному номеру даты.
- Шаг чтения источника не удался — книгу не трогать.
- Неразобранное число не подставлять нулём (`Number(x) || 0`): записать в проблемы шага со счётом строк.
- Медленное необязательное действие не ставить шагом основного прогона — только отдельным пунктом меню, последним.
- Колонку источника не брать голым номером без проверки заголовка по этому номеру.
- В проекте из нескольких файлов не заводить имён функций и глобальных переменных, совпадающих с другими файлами; `onOpen` — одна.
- `setConditionalFormatRules([])` перед записью правил не делать: набор правил листа собирать в массив и писать одним вызовом.
- Перед любой очисткой листа — снимок листа (формула, иначе значение) текстом на скрытый лист `_dashboard_backup`; в тяжёлой книге вместо него — «Файл → Создать копию» и «Файл → История версий».
- Строки зоны параметров (1–`CTRL_LAST_ROW`) при перестройке не очищаются.
- Ручной ввод не перетирается: в колонки и ячейки, которые Андрей ведёт руками, скрипт пишет только в пустую ячейку или в ячейку, равную снимку «_авто» (см. «Ручной ввод»); `clear()` по всему листу не делается, очищаются только диапазоны, перечисленные в скрипте явно.
- Ручной ввод на перестраиваемом листе не возвращать по номеру строки — только по ключу; ключ не совпал — значение по умолчанию.
- Существующий именованный диапазон не удалять и не пересоздавать — перенаправлять `setRange`.
- Чужие именованные диапазоны (в которые пишет n8n) расширять только отдельным пунктом меню и по явному решению, никогда заодно с оформлением.
- Перед записью в существующую колонку — прочитать её `gsheets-read` с `render:"FORMULA"`: в колонку, которую заполняет формула (`ARRAYFORMULA`, `IMPORTRANGE`, `FILTER`, построчная), значения не пишутся ни скриптом, ни n8n, ни руками.
- На лист, на который другие книги ссылаются адресами через `IMPORTRANGE`, колонки в середину не вставлять — только последней.
- Новая книга не читает расчётные листы тяжёлой книги — только сырой источник и минимум справочных листов; расчётный лист тяжёлой книги — только отдельным пунктом меню.
- Удаление листа ради предела ячеек — сначала архивная копия книги, само удаление решает Андрей.
- Служебный блок с именованными ячейками, которые читает n8n, не двигать: место для блока выше забирать у соседей сверху.
- Новый воркфлоу ради проверки возраста книги не заводить — встраивать в воркфлоу, который и так читает книгу, или строкой в существующий ежедневный монитор.
- Задачу о расписании не закрывать ручным запуском или числом удачных дней — только первым плановым прогоном при уже стоящей проверке возраста метки.
- Триггер по времени без нужды не переставлять; время прогонов брать из журнала выполнений, не из кода.

## Как делать

### Порядок работы

1. **Разведка.** `gsheets-read` `mode:"meta"` → список листов; затем `mode:"range"` с `render:"FORMULA"` по каждому рабочему листу, колонки до Z. Перед добавлением метрики — лист целиком в `FORMULA`, включая строки за пределами известной разметки. Изменилась подпись строки — спросить Андрея.
2. **Карта зависимостей.** Прогнать `findRefs` (обходит все листы и выписывает каждую формулу, ссылающуюся на заданный лист) и `showMap` (выгружает на лист `_map` метаданные, локаль и разделитель, листы, именованные диапазоны, формулы); только после этого решать о разметке.
3. **Проект.** Согласовать с Андреем (стоп-правило).
4. **Скрипт.** По соглашениям ниже и стоп-правилам.
5. **Прогон.** `setupAll` запускает Андрей: без доступа `write` — после вставки файла; с доступом `write` — после записи сессией мостом.
6. **Проверка.** Результат читать самому через `gsheets-read`; отчёт скрипта — гипотеза. Для записи мостом: поля ответа — сигнал, доказательство — новое чтение проекта.

### Живой текст скрипта и путь правки

Живой текст — то, что стоит в проекте скрипта книги в эту минуту; резервная копия `.gs`, которую Андрей положил в Drive для этой правки после своей последней правки кода, — тоже живой текст.

| Книга | Чтение живого текста | Как вносится правка |
|---|---|---|
| скрипт доступен аккаунту Андрея, в `gas_allowlist` доступ `write`, прочитано в этой сессии | мост, операция `read` | сессия пишет мостом (`write`) — полным файлом или заменой одного уникального фрагмента |
| скрипт доступен аккаунту Андрея, доступа `write` нет (строки нет или `read`) | мост, операция `read` | полным текстом файла на вставку для Андрея |
| мост недоступен или скрипт мостом не читается | текст присылает Андрей: в чат или копией `.gs` в Drive, которую сессия читает целиком через `gdocs-read` | полным текстом файла на вставку для Андрея |

- Отказ моста «NOT ALLOWED» на запись — доступа `write` нет, правка идёт полным текстом для Андрея.
- Идентификатор скрипта — из `gas_allowlist` или из «Мои проекты» на script.google.com; проверить ссылкой на книгу на странице «Описание проекта» скрипта.
- Ответ моста читать только тем сужением, которое названо в контракте.
- В отчёте о правке назвать `versionBefore` — по нему откат (операция `rollback`).
- **Серия фрагментов:** (1) собрать серию на копии живого текста; (2) проверить локально `node --check`; (3) записать фрагменты по очереди; (4) после последнего — новое чтение мостом и побайтное сравнение с копией. Новый файл тоже пишется сериями замен по границам функций, так чтобы каждая промежуточная версия была синтаксически цельной.
- Правка, которая меняет назначение участка листа (неочищаемая зона параметров стала пересобираемым блоком), перед записью строит карту ссылок на участок и тем же действием правит комментарии и описания констант, которые обещают прежнее.
- После записи мостом сказать Андрею: вкладку редактора скрипта, открытую до записи, перед своей правкой в ней перезагрузить.
- **Полный текст на вставку** (нет `write`): Андрей выделяет всё в редакторе и вставляет файл целиком. Перед выдачей — сверка с живым текстом, а не со своей рабочей копией; в сопроводительном сообщении — короткий перечень изменённых функций.
- **Аварийный путь clasp** (сервер n8n и мост недоступны): правит только Андрей на своём компьютере — свежий `clasp clone` или `clasp pull` в чистую папку непосредственно перед правкой, затем `clasp push`; первая же сессия после этого читает проект мостом, чтобы получить новый отпечаток.

### Аудит без правки

Задача «можно ли верить числам книги»: скрипт читается мостом (`read`); в канон идёт пересказ логики по функциям, не код. Проверить: (1) каждый поясняющий текст и подпись управляющей ячейки против того, что делает скрипт; (2) проверочные ячейки (стоп-правило); (3) числа книги сверить с внешним отчётом по неделям и по каждой статье.

### Оформление и проверка данных образца — скрипт-дамп

`gsheets-read` оформления и проверок данных не отдаёт. Задача про оформление образца начинается со скрипт-дампа, который запускает Андрей: `getNumberFormats`, `getBackgrounds`, `getColumnWidth`, `getRowHeight`, `getConditionalFormatRules`, `getCharts`, `getDataValidations` → снимок на отдельный лист или в отдельную книгу → сессия читает снимок `gsheets-read`.

### Соглашения, от которых зависят другие части

- **`setupAll` — первая функция файла:** от этого зависит прогон Андрея из редактора (кнопка «Выполнить» берёт первую функцию).
- **Управляющие ячейки зоны параметров** снимаются до очистки и возвращаются на те же адреса — с подписями, заливкой и предупреждением в заголовке, кто на них ссылается: от их адресов зависят формулы других листов; значение пишется только в пустую ячейку.
- **Метка последнего прогона** (дата и время) — в известной ячейке у каждого скрипта с расписанием: её читает внешний исполнитель, проверяющий возраст книги.
- **Колонка, которую дописывает робот n8n, — без формул:** вычисление — в роботе или в колонке правее; сигнал по таким строкам — условным форматированием (узел n8n считает ячейку с формулой занятой).
- **Текст тревоги** собирается формулами в книге; n8n читает именованные ячейки (тексты, метку прогона, последнюю дату данных) одним запросом. Воркфлоу — курьер с одной своей проверкой: метка старше порога или ячейку не прочитать — сам отправляет «книга не обновлялась»; иначе пусто — молчит, непусто — отправляет.
- **Тревога построена**, когда найден воркфлоу, который читает её ячейки, он опубликован, и приход сообщения проверен по факту.

### Ручной ввод

- **Колонка, где рядом автоматические значения и правки владельца:** скрипт держит на скрытом листе «_авто» снимок значений, которые он собрал в прошлый раз; ячейка, отличная от снимка, — правка владельца и не перезаписывается; ячейка, равная снимку, обновляется, и снимок обновляется вместе с ней.
- **Ключ возврата ручного ввода:** параметр или порог — по подписи или имени диапазона в соседней ячейке, строка товара — по артикулу (SKU).
- **Инструкция Андрею на ручную правку ячеек** в листе с повторяющимися ключами называет признак, уникальный в листе (ключ + дата начала, значение соседней колонки), а не номер строки или один ключ.

### Расписание и свежесть

- Расписание считается работающим, когда метка на листе показывает дату планового прогона И её возраст проверяет внешний исполнитель — воркфлоу n8n по своему расписанию. Пока такой проверки нет — сначала встроить её.
- Внешний исполнитель читает метку последнего прогона и последнюю дату данных; метка старше порога или ячейку не прочитать — сам отправляет сообщение. Метка прогона нужна и там, где проверка уже читает дату данных.

## Адреса и ловушки

- Адреса книг и документов — в реестре `registry/documents.md`; воркфлоу — `registry/n8n-map.md`; мост gas-bridge и ID таблицы `gas_allowlist` — `registry/tools.md`, строка gas-bridge.
- `setFormula`/`setFormulas` молча пишут формулу буквально, без перевода в локаль книги (в книге с `;` запятые дают `#ERROR!`, точка в дроби — ошибку разбора), — проверяй разделитель книги: в лёгкой книге зондом `=SUM(1,2)` на временном листе, в тяжёлой — чтением живой многоаргументной формулы `getFormula()`.
- Шаг с вызовом сервиса на каждую строку молча идёт неровно: время скачет в разы при тех же данных и доходит до потолка 6 минут; падение выглядит как «тяжёлая книга» или «данные не пришли» — проверяй циклы на вызовы `Utilities`/`SpreadsheetApp` до оптимизации чтения.
- Журнал выполнений проекта хранит прогоны около 7 дней — причину упавшего прогона снимать сразу.
- `clasp push` молча заменяет весь проект содержимым локальной папки, без версии и без сверки отпечатка: устаревшая папка стирает правку, сделанную мостом, — перед push только свежий `clasp clone`.
- В формулах Google Sheets `""=0` даёт `FALSE`, а `AND`/`OR` вычисляют все аргументы: защита от деления на ноль через `AND(x<>0; y/x>1)` молча даёт `#DIV/0!` — проверяй делитель через `IF`.
- Редактор Apps Script молча запускает первую функцию файла (первое нажатие на `onOpen` только строит меню) — проверяй, что `setupAll` стоит первой.
- Удаление именованного диапазона молча переписывает все ссылающиеся формулы в `#REF!`, пересоздание имени их не чинит — проверяй, что имя перенаправлено `setRange`, а не удалено.
- `setValue`/`setValues` молча превращают строку, начинающуюся с `=`, в формулу (заголовок «=== РАЗДЕЛ ===» становится `#ERROR!`, n8n получает мусорные имена полей) — проверяй: строке на `=+-@` ведущий апостроф (только строкам, не числам) и формат `@` на ячейках текста.
- Дата, собранная как полночь UTC, молча ложится в ячейку со сдвигом на пояс книги (46286,083), и `SUMIFS` по датам теряет граничный период — проверяй перевод в местную дату перед записью, совпадение пояса проекта скрипта с `getSpreadsheetTimeZone()` и целые числа в `UNFORMATTED_VALUE`.
- Одно имя функции или глобальной переменной в двух файлах проекта молча берёт последнее загруженное определение — проверяй имена во всех файлах проекта, прочитанных мостом.
- `getDataValidations()` молча даёт `null` на шапке и строке-подсказке — проверяй правила по нескольким строкам с реальными данными.
- Стирание управляющей ячейки (может стоять в любой колонке любого листа) молча обнуляет цепочку `FILTER` и все листы, считаемые из неё, — проверяй `findRefs` до стирания.
- `SUMIFS` по пустому окну молча даёт 0 вместо «данных нет» — проверяй гард по обеим границам данных: `=IF(OR(B$3<FIRST_DATA_DATE,B$3>LAST_DATA_DATE),"", <формула> )`.
- Диапазон с жёстким потолком (`A3:A5000`, именованный до строки 50 000) молча недосчитывает выросший лист; `getLastRow()` на листе с разливом `FILTER` молча занижает границу в разы — проверяй сумму диапазона против суммы колонки.
- Построчные формулы молча не распространяются на добавленные или вставленные строки, `SUMIFS` считает пустоту нулём — проверяй расчётные колонки в новых строках.
- Колонка, вставленная в середину листа-хаба, молча сдвигает чтение чужих `IMPORTRANGE` на соседнюю колонку — проверяй, что новая колонка последняя.
- Зеркало склейки `IMPORTRANGE` молча перестаёт расти на диапазоне, зашитом в формуле, — проверяй обе границы: сетку листа и диапазон в формуле.
- `MAXIFS`/`MINIFS` внутри `ARRAYFORMULA` молча возвращают одно значение на всю колонку — проверяй колонку на одинаковые числа там, где они обязаны различаться.
- Запись значения в зону разлива массивной формулы молча ломает её в `#REF!`; число, вписанное поверх построчной формулы, молча расходится с ней — проверяй колонку в `FORMULA` перед записью.
- Узел Google Sheets n8n при добавлении строк молча считает ячейку с формулой занятой и дописывает ниже конца разлива — проверяй, что в колонке робота нет формул.
- Ключ числом с одной стороны и текстом с другой (`1058.0` против `1058`) молча даёт ноль совпадений, а обновление-вставка плодит дубли — проверяй один тип с обеих сторон (`TO_TEXT`).
- `VLOOKUP` при двух строках ключа молча берёт первую — проверяй `=COUNTA(A2:A)-COUNTUNIQUE(A2:A)` = 0.
- `IFERROR` вокруг `IMPORTRANGE` молча прячет отказ доступа (кнопка «Разрешить доступ» не появляется) и несовпадение типов ключа — проверяй результат чтением; доступ выдавай отдельной ячейкой без `IFERROR`.
- Две цепочки `IMPORTRANGE` рядом молча расходятся построчно после первого отличия в числе или порядке строк — проверяй, что склейка идёт по ключу.
- `IFERROR` вокруг `FILTER`, которому не хватило строк, молча даёт пустоту (статья 0, итог завышен) — проверяй число прошедших условие строк против выведенных.
- `SUMIFS`/`COUNTIFS` молча не различают регистр, а `QUERY` и `=` различают — проверяй написание категорий в источнике.
- `COUNTIFS(диапазон;"<>")` молча считает `""`, возвращённую формулой, — считай `SUMPRODUCT(LEN(диапазон)>0)`.
- `headers.indexOf(имя)` при двух одинаковых заголовках молча берёт левый, узел чтения n8n — правый — проверяй, что заголовок найден ровно один раз.
- Простой триггер `onEdit` молча не срабатывает на изменение формулой, `IMPORTRANGE` или записью из n8n — проверяй, что колонка-триггер правится руками.
- Пересоздание триггера по времени молча ставит время заново (`atHour` — любая минута часа, `nearMinute` — ±15 минут), и в день перестановки прогона может не быть — проверяй возраст метки.
- Срыв расписания Apps Script молча перемежается: книга пересчитывается в один день и срывается в соседние — проверяй возраст метки внешним исполнителем.
- Процентный формат молча умножает хранимое число на 100 при показе, суффикс «п.п.» — нет — проверяй величину в ячейке на конкретном числе после смены формата.
- `TEXTJOIN` с `ignore_empty = TRUE` молча выбрасывает задуманные пустые строки-отбивки — проверяй, что для сообщения с абзацами стоит `FALSE`.
- `autoResizeColumn` молча растягивает колонку под самую длинную строку на всю ширину экрана — проверяй, что ширина колонки с длинным текстом задана числом.

## Куда писать результат

- Частные факты книги — её разделитель, часовой пояс и его совпадение с поясом проекта скрипта, контрольные числа, тяжесть — в канон её проекта или лаборатории, не в этот Skill.
- В канон по правке кода — имена файлов и функций, отпечаток проекта, `versionBefore`; текст кода — нет.
