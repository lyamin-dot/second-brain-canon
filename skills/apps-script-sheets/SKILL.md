## 0. ДВА ПРАВИЛА БЕЗ ИСКЛЮЧЕНИЙ

**0.1. Ни одна ячейка не стирается, пока не построена карта ссылок на неё.** Перед любой очисткой, перестройкой или сдвигом разметки листа — обойти ВСЕ листы книги и найти формулы, которые на этот лист ссылаются (§4.6, `findRefs`). Вывод «лист пуст, можно занимать», сделанный по прочитанному диапазону, ничего не стоит: диапазон почти всегда у́же листа.

**0.2. Формула, записанная через `setFormula` или `setFormulas`, попадает в ячейку БУКВАЛЬНО.** Перевода в локаль книги не происходит. У книг Андрея локаль `ru_RU`. Подробно — §2.1.

## 1. ПОРЯДОК РАБОТЫ

1. **Разведка.** `gsheets-read` mode `meta` → список листов. Затем `mode:"range"` с `render:"FORMULA"` по каждому рабочему листу. Читать ШИРЕ, чем кажется нужным: колонки до Z, а не до J. Стоимость лишней колонки — ноль, стоимость пропущенной — §3.1. Контракт ответа и признак `truncated` (больше 500 строк — вернулась только часть) — `google-drive-docs` §4.0.
   **Живой текст скрипта — только тот, что прислал Андрей.** Сессия сама его не прочитает: Apps Script API не даёт сервисному аккаунту доступа к личным скриптам (воркфлоу gscript-read так и не заработал, `projects/wb-ue/STATE.md`). Обход — Андрей кладёт резервную копию `.gs` в Drive, и сессия читает её целиком через `gdocs-read` (`projects/wb-ue/LOG.md`, запись о сервисном аккаунте и Apps Script API). Техническая документация книги отстаёт от кода: править по техдоку вместо кода запрещено — так 2026-09-30 правка `oz_goods_book.gs` зашла в тупик (`labs/ozon-ue/t-goods-book-script.md`), а по журналу OZON_UE_INDEX 2026-09-27 и 2026-09-29 расхождение кода с документацией дало 19 003 ₽ в чужой статье. Своя рабочая копия из прошлой сессии — тоже не живой текст: Андрей мог править файл руками.
   **Книга скрипту не принадлежит.** Андрей правит книгу руками параллельно скрипту. Поэтому перед добавлением метрики лист читается целиком в режиме `FORMULA`, включая строки за пределами известной разметки; изменившаяся подпись строки — не признак правки скрипта, спросить дешевле (`projects/wb-ue/LOG.md`, Р-50). Как скрипт обходится с колонками владельца — §4.2.
   Оформление — числовые форматы, ширины колонок, высоты строк, заливку, шрифт, правила условного форматирования, графики — `gsheets-read` не отдаёт ни в одном режиме: в его ответе есть только значения и формулы. Если задача про оформление образца, первым шагом идёт скрипт-дамп, который Андрей запускает сам: он читает `getNumberFormats`, `getBackgrounds`, `getColumnWidth`, `getRowHeight`, `getConditionalFormatRules`, `getCharts` и пишет снимок на отдельный лист или в отдельную книгу, а сессия потом читает этот снимок обычным `gsheets-read`. Шаг «прочитать оформление через gsheets-read» в план и в эстафету не ставится — он неисполним (позиция AG-18 очереди, сессия OZON_UE 2026-09-26).
2. **Карта зависимостей.** Прогнать `findRefs` и `showMap` (оба — §4.6). Только после этого принимать решения о разметке.
3. **Проект.** Согласовать с Андреем: что чиним, что строим, где что лежит. Гейт обязателен: правку формул в рабочей книге откатить можно только историей версий и только всю книгу целиком — вместе со всем, что в ней изменилось после.
4. **Скрипт.** Один файл, идемпотентный, со всеми обязательными частями из §4.
5. **Прогон.** Андрей вставляет и запускает `setupAll`. Скрипт не падает на первой ошибке (§4.4) — один прогон показывает все проблемы и время каждого шага.
6. **Проверка.** Читать результат самому через `gsheets-read`, не по отчёту скрипта. Отчёт скрипта — гипотеза.

Правки после первого прогона давать **полным текстом файла на вставку**: Андрей выделяет всё в редакторе Apps Script и вставляет файл целиком. Перед выдачей — сверка с живым текстом, который прислал Андрей (пункт 1 выше), а не со своей рабочей копией; в сопроводительном сообщении — короткий перечень изменённых функций, чтобы правку можно было проверить глазами. Так выданы `oz_goods_book.gs` и `oz_price_book.gs` 2026-10-06, и так хочет Андрей.
ИСТОРИЯ ДИАГНОЗА: до 2026-10-09 здесь стояло обратное правило — «точечные патчи функций в формате „было → стало“, не переписывание файла», с доводом, что пятая полная перезаливка 1300 строк — счёт, который платит Андрей. Отменено предпочтением владельца и практикой 2026-10-06 (противоречие В9 харвеста 2026-10-08): ручная вставка нескольких патчей в разные места файла дороже и опаснее одной полной вставки — пропущенный или вставленный не туда патч не виден до прогона.

## 2. ЛОВУШКИ APPS SCRIPT

### 2.1. Локаль формул (самая дорогая)

Распространённое и ложное убеждение: «Apps Script принимает формулы в американской записи и сам переводит их в локаль». Нет (§0.2). В `ru_RU`:
- разделитель аргументов — `;`, а не `,`
- разделитель колонок в массивах — `\`, а не `,`
- разделитель строк в массивах — `;` (как в US)
- десятичный разделитель в числе — `,`, а не `.`: `0.95` в формуле даёт ошибку разбора

Формула с запятыми даёт `#ERROR!` в каждой ячейке. Симптом: полторы тысячи ошибок разом, ровно по числу записанных формул. Формула с дробным литералом даёт `#ERROR! (Formula parse error)` и тянет за собой всё, что на неё ссылается: книга «Цена» 2026-09-28 уронила так 3 304 формулы из 3 304 (позиция AH-5).

**Решение.** Код пишет формулы в американской записи (так их проще читать и сверять), а каждая формула перед записью проходит через контекстный конвертер. Разделитель определяется опытом, не списком локалей:

```javascript
var SEP = ',';

// Зонд пишет в книгу и ждёт пересчёта: только лёгкая книга и только первым шагом записей (§4.8).
function detectSeparator_(ss) {
  var tmp = ss.insertSheet('_probe_' + new Date().getTime());
  var ok = false;
  try {
    tmp.getRange('A1').setFormula('=SUM(1,2)');
    SpreadsheetApp.flush();
    ok = (tmp.getRange('A1').getDisplayValue() === '3');
  } finally {
    ss.deleteSheet(tmp);
  }
  return ok ? ',' : ';';
}

function loc_(f) {
  if (SEP === ',') return f;
  var out = '', stack = [], inStr = false, inName = false;
  for (var i = 0; i < f.length; i++) {
    var ch = f.charAt(i);
    if (inStr || inName) {                        // "строка" и 'имя листа' не трогаем
      out += ch;
      var q = inStr ? '"' : "'";
      if (ch === q) {
        if (f.charAt(i + 1) === q) { out += q; i++; }   // удвоенная кавычка внутри
        else { inStr = false; inName = false; }
      }
      continue;
    }
    if (ch === '"') { inStr = true; out += ch; continue; }
    if (ch === "'") { inName = true; out += ch; continue; }
    if (ch === '(' || ch === '{') { stack.push(ch); out += ch; continue; }
    if (ch === ')' || ch === '}') { stack.pop(); out += ch; continue; }
    if (ch === ',') {
      out += (stack.length && stack[stack.length - 1] === '{') ? '\\' : ';';
      continue;
    }
    // десятичная точка между цифрами → запятая
    if (ch === '.' && /[0-9]/.test(f.charAt(i - 1)) && /[0-9]/.test(f.charAt(i + 1))) { out += ','; continue; }
    out += ch;
  }
  return out;
}

function setF_(rng, formula) {
  rng.setFormula(loc_(formula));
  return rng;
}
```

Контекст обязателен. Наивная замена всех запятых ломает `TEXT(x,"#,##0")` — запятая внутри строкового литерала часть формата числа, а не разделитель. Имя листа в одинарных кавычках (`'Деньги, 2.0'!A1`) тоже не трогается: запятая и точка в нём — часть имени. Возврат диапазона нужен, чтобы работала цепочка `setF_(...).setNumberFormat(...)`.

Дробь без ведущего нуля (`.5`) конвертер не видит: точка не стоит между цифрами. Писать всегда `0.5`. Имя листа с точкой или запятой писать только в одинарных кавычках: `Sheet2.1!A1` без кавычек конвертер испортит в `Sheet2,1!A1`.

Конвертер проверен в node 2026-09-28 на пяти формулах: дробь с форматом `"#,##0.00"`, имя листа с запятой и точкой, массив `{…}` в SPARKLINE, имя листа с удвоенной кавычкой, дробь `.5`.

Проверка после правки: каждая запись формулы в файле — это `setF_(…)` либо `setFormulas(…)` массива, каждый элемент которого уже прошёл `loc_`; прямой `.setFormula(` без `loc_` допустим только в зонде. Колонку формул писать одним вызовом `setFormulas` на диапазон, а не циклом `setFormula` по ячейкам: так пишут все три книги §8 (замера цикла по ячейкам нет).

### 2.2. Редактор запускает ПЕРВУЮ функцию файла; итог — без модального окна

Выпадающий список «Выполнить» подставляет функцию, идущую в файле первой. Если первой стоит `onOpen`, первое нажатие построит меню и ничего больше не сделает — выглядит как успешный прогон. Второе нажатие упадёт с `Cannot call SpreadsheetApp.getUi() from this context`.

**Решение.** Главная функция (`setupAll`) — первая в файле. `onOpen` обёрнута в `try/catch`.

Итог прогона выводится НЕ модальным окном. `SpreadsheetApp.getUi().alert()` держит выполнение, пока в таблице не нажато «ОК». Редактор считает это ожидание временем работы скрипта и на шестиминутном потолке пишет `Exceeded maximum execution time`, хотя сама работа заняла меньше минуты. Книги «Цена» и «Деньги» 2026-09-28: два сорванных прогона (журналы 08:47→08:53 и 11:34→11:40), при том что обычный прогон занимает 34–53 секунды; версию «виновато чтение тяжёлой книги» опроверг журнал времени шагов (§4.4, позиция AH-6). Полный текст — в журнал, первая строка — всплывающей подсказкой:

```javascript
function alert_(msg) {
  Logger.log(msg);   // полный отчёт: редактор скриптов → «Выполнения»
  try { SpreadsheetApp.getActiveSpreadsheet().toast(String(msg).split('\n')[0], 'Ozon', 15); }
  catch (e) {}
}
```

Первую строку отчёта строить так, чтобы её хватало для решения: «Готово за 37 с» или «Готово С ОШИБКАМИ за 44 с».

### 2.3. Объединение части существующего объединения запрещено

Симптом: `Чтобы объединить или разделить ячейки, необходимо выделить весь диапазон`. Причина: предыдущая версия скрипта объединила `A1:L1`, новая пытается объединить `A1:H1`.

**Решение.** В начале перестройки — `breakApart()` по ВСЕМУ листу, а не по очищаемой части. `breakApart` не стирает содержимое: значение остаётся в левой верхней ячейке бывшего объединения.

```javascript
sh.getRange(1, 1, sh.getMaxRows(), sh.getMaxColumns()).breakApart();
```

Отдельно: объединение, пересекающее границу очищаемой области (например с 6-й по 8-ю строку при очистке с 7-й), даст ту же ошибку на `clear`. Разъединение по всему листу закрывает и этот случай.

**Копирование формулы тащит за собой объединение исходной ячейки.** `copyTo(..., PASTE_FORMULA, false)` вправо по листу с закреплённой колонкой A роняет весь шаг: объединение через границу закрепления Google запрещает. Поэтому `breakApart()` по всему листу нужен и перед `copyTo`, а не только перед `clear`.

**Закрепление колонок при объединённых строках.** `setFrozenColumns(n)` падает, если на листе есть строки, объединённые через границу закрепления, — например строки инструкции на всю ширину листа: закреплять часть объединения Google запрещает (книга «Цена», редакция 1, 2026-09-28, позиция AH-8). Решение, проверенное на трёх книгах: закреплять только строки до шапки таблицы включительно, колонки не закреплять, а строки инструкции собрать в группу — знак «−» слева от номеров строк сворачивает их, и закреплённая зона становится узкой:

```javascript
var HEAD_ROW = 10;          // строка шапки таблицы; строки 2–8 — инструкция листа

// Вызывать ПЕРВЫМ при пересборке листа: снимает закрепление и группу прошлого прогона,
// иначе глубина группы растёт с каждым запуском.
function unfreeze_(sh) {
  sh.setFrozenRows(0); sh.setFrozenColumns(0);
  var g = sh.getRange('2:8');
  for (var i = 0; i < 5 && sh.getRowGroupDepth(2) > 0; i++) g.shiftRowGroupDepth(-1);
}

// Вызывать ПОСЛЕДНИМ, когда лист построен.
function freezeHead_(sh) {
  sh.setFrozenRows(HEAD_ROW);
  sh.getRange('2:8').shiftRowGroupDepth(1);
}
```

### 2.4. Удаление именованного диапазона необратимо ломает ссылки

При удалении имени Google переписывает ВСЕ формулы, которые на него ссылались, в `#REF!` — в самом тексте формулы. Создание имени заново их не чинит: ссылки уже нет, есть `#REF!`.

**Следствие:** пересоздавать именованный диапазон (remove + set) можно только если все формулы, которые им пользуются, будут переписаны скриптом ПОСЛЕ этого. Любая формула, оставленная от прежней версии, превратится в мёртвый `#REF!`.

**Решение.** Существующее имя не удалять, а перенаправлять: `namedRange.setRange(новыйДиапазон)` — ссылки формул при этом живы. Порядок в `setupAll`: сначала разметка, потом именованные диапазоны, потом ВСЕ формулы.

```javascript
function setName_(ss, name, rng) {
  var ex = ss.getNamedRanges().filter(function (n) { return n.getName() === name; })[0];
  if (ex) ex.setRange(rng); else ss.setNamedRange(name, rng);
}
```

### 2.5. setValues превращает строку с «=» в живую формулу

При выгрузке карты таблицы текст формулы, записанный через `setValues`, становится формулой и считается в контексте нового листа. Вместо `=$B$2-6` в отчёте оказывается `#VALUE!`.

**Решение.** Ведущий апостроф плюс текстовый формат. При чтении через API апостроф не возвращается.

```javascript
function asText_(s) { return /^[=+\-@]/.test(s) ? "'" + s : s; }
// и перед записью: rng.setNumberFormat('@').setValues(...)
```

### 2.6. Новый лист по умолчанию 1000 строк

Выгрузка карты или бэкапа может не поместиться. Перед `setValues` проверять `getMaxRows()` и добавлять строки.

### 2.7. Дата из скрипта сдвигается на часовой пояс

Дата, собранная в скрипте как полночь UTC (`Date.UTC(...)`, арифметика суток в миллисекундах), записанная в ячейку как есть, ложится со сдвигом на пояс книги: 46286,083 вместо 46286. На вид дата та же. Но фильтр `SUMIFS(…,">="&начало,…,"<="&конец)` выбрасывает граничную неделю, и сумма периода молча меньше (книга «Деньги», лист «Деньги по неделям», неделя 21.09.2026, позиция AH-7).

**Решение.** Внутри скрипта считать в UTC сколько угодно, а перед записью переводить в местную дату:

```javascript
function localDate_(d) { return new Date(d.getUTCFullYear(), d.getUTCMonth(), d.getUTCDate()); }
```

`new Date(год, месяц, день)` строит полночь в часовом поясе ПРОЕКТА СКРИПТА, а ячейка читается в поясе КНИГИ. Приём верен, пока они совпадают: сверить «Настройки проекта» скрипта с `ss.getSpreadsheetTimeZone()`. У привязанного скрипта книг Андрея оба пояса одинаковые — проверено результатом, а не настройками: после `localDate_` даты недель в книге «Деньги» стали целыми.

Проверка: чтение колонки дат через `gsheets-read` с `render:"UNFORMATTED_VALUE"` — даты обязаны прийти целыми числами.

## 4. ОБЯЗАТЕЛЬНЫЕ ЧАСТИ ЛЮБОГО ТАКОГО СКРИПТА

### 4.1. Идемпотентность

Повторный прогон приводит книгу в то же состояние, а не накапливает.

**Условное форматирование.** Набор правил листа собирается целиком в массив и записывается ОДНИМ вызовом `setConditionalFormatRules(rules)`. Предварительная очистка пустым списком запрещена: метод и так заменяет весь список правил листа, а очистка превращает любой обрыв между ней и записью — по времени, по отказу службы, по ошибке при сборке — в потерю ВСЕХ правил листа. След такого обрыва неотличим от «шаг не запускали»: и там, и там ноль правил. Ровно так 2026-09-27 витрина oz_dashboard осталась без шести правил (позиция AH-4).

**Графики.** Перед построением — удалить все графики листа: замены целиком одним вызовом у них нет, поэтому здесь предварительная очистка верна. Объединения, закрепление и группы строк — §2.3.

### 4.2. Зона параметров

Строки 1–`CTRL_LAST_ROW` не очищаются при перестройке: тогда адреса управляющих ячеек не меняются и формулы других листов, которые на них ссылаются, править не нужно вообще (история — §3.1). Управляющие ячейки снимаются до очистки зоны и возвращаются после — с подписями, заливкой и явным предупреждением в заголовке, кто на них ссылается. Значение записывается ТОЛЬКО если ячейка пуста: введённое вручную не перетирается никогда.

Колонки и ячейки, которые ведёт Андрей руками (не управляющие, а данные — пометки, поправки, ручные цены), скрипт пишет только в пустую ячейку и никогда не делает `clear()` по всему листу: очистка всего листа стирает ручную правку, и следующая пересборка молча откатывает её — так ручной подъём границы в `weekly_history!11` дважды откатывался пересборкой (`projects/wb-ue/LOG.md`, Р-41). Очищать — только свои диапазоны, перечисленные в скрипте явно.

Ручной ввод, который живёт на перестраиваемом листе (параметр, ячейка что-если, цена для проверки у товара), читается ДО перестройки и возвращается на место по ключу, а не по номеру строки: параметр или порог — по подписи или имени диапазона в соседней ячейке, строка товара — по SKU. Ключ не совпал — значение не принимается, ставится значение по умолчанию: иначе при сдвиге разметки в слот попадёт чужое число.

### 4.3. Бэкап перед перестройкой

Перед любой очисткой — полный снимок листа (формула, если есть, иначе значение) на скрытый лист `_dashboard_backup`, текстом. Стоит один вызов, окупается один раз в жизни.

Исключение — тяжёлая книга (§3.7): снимок средствами Apps Script читает лист целиком и в потолок выполнения не укладывается. Там страховка перед правкой — «Файл → Создать копию» и «Файл → История версий»: обе делаются на стороне Google и стоят ноль времени выполнения.

### 4.4. Пошаговый прогон вместо fail-fast

Падение на первой ошибке означает один круг «правка — прогон — сообщение» на каждую мелочь. Каждый шаг выполняется в своей обёртке, ошибки копятся, отчёт в конце показывает все — и время каждого шага. Время по шагам — единственный способ отличить медленный шаг от чужой причины (пример — §2.2).

```javascript
var problems = [], times = [];
function step(name, fn) {
  var s0 = new Date();
  try { return fn(); }
  catch (e) { problems.push('✗ ' + name + '\n   ' + (e && e.message ? e.message : e)); return null; }
  finally {
    var line = name + ': ' + ((new Date() - s0) / 1000).toFixed(1) + ' с';
    times.push(line); console.log(line);
  }
}
```

`step` возвращает результат шага, поэтому шаг чтения пишется как `var src = step('чтение источника', function () { return readSource_(); });` и дальше проверяется на `null`: не прочитан источник — книга не трогается.

### 4.5. Проверка должна ловить не только ошибки формул

Проверка «нет `#ERROR!`/`#REF!`/`#NAME?`» отрапортовала «всё хорошо» на полностью мёртвой книге: формулы были синтаксически корректны, источник пуст. Отсутствие ошибки — не признак жизни.

**В отчёт всегда добавлять признак живости:** число строк в листе-источнике и границы периода расчёта. Строка «Строк в источнике: 0» видна мгновенно. Эти числа берутся из блока чтений; проверка того, что записано, — §4.8.

**Если книга сворачивает сырые данные — добавлять сверку.** Сумма свёрнутого минус сумма источника по той же денежной колонке, обязана быть 0,00. Не ноль — строки потерялись при свёртке, и цифрам книги верить нельзя. Во всех трёх книгах по сырым данным (§8) сверка «Получили» стоит в отчёте прогона и 2026-09-28 дала 0,00 ₽.

Как считать сверку, чтобы она что-то доказывала:
- **По всем неделям, где есть данные, а не по одной.** Одна неделя не ловит ошибку разнесения между периодами: на ней суммы совпадают, а ошибка сидит в соседних (`projects/wb-ue/LOG.md`, Р-52; сверка книги «Товары» с «Деньгами» за окно 29.06–27.09). То же правило для сигналов — §9.8.
- **Формулой в самой таблице, а не перебором строк через API.** Сопоставление строк листа по номеру в голове модели дало ложное расхождение по выручке и логистике — сместилась нумерация, а не данные (Р-45).
- **С `ROUND(…;2)`.** Без округления точный ноль печатается как `0,000000001`, и строка сверки перестаёт читаться взглядом (Р-48).

**Лист сценариев «что-если» проверяется дважды:** с пустым вводом (результат обязан совпасть с фактами) и с заполненным — иначе ошибка в ветке, которая включается только при вводе, не видна до первого использования (`labs/ozon-ue/t-books-followups.md`).

### 4.6. Две служебные функции в меню

- `showMap` — выгружает на лист `_map`: метаданные книги (в том числе локаль и определённый разделитель), состав листов с числом строк, ВСЕ именованные диапазоны с адресами, все формулы рабочих листов. Это то, из чего собирается документация и чем восстанавливаются потери: снимок `_map`, сделанный до разрушительного прогона, позволил вернуть затёртые управляющие ячейки.
- `findRefs` — обходит все листы и выписывает каждую формулу, ссылающуюся на заданный лист. Карта зависимостей, без которой правило §0.1 не выполнить.

### 4.7. Пункты меню разделять по охвату, и говорить об этом вслух

«Пересобрать всё» и «Только починить формулы» — разные вещи, и второй НЕ трогает оформление, тексты пояснений и генерируемые листы. Написать об этом прямо в тексте пункта меню и в документации: иначе правка текста, применённая вторым пунктом, молча игнорируется, и это выглядит как «патч не сработал». Ровно так была потеряна сессия отладки.

Медленное действие — отдельным пунктом с пометкой в названии («Подтянуть старый калькулятор для сравнения (медленно)»), а не шагом основного прогона. Тяжёлый и необязательный пункт ставится в меню **последним**: первый пункт нажимают первым (OZON_UE_INDEX 2026-09-27).

### 4.8. Все чтения — до первой записи

Apps Script копит записи и сбрасывает их в книгу при первом же чтении после них, а сброс ждёт пересчёта. Поэтому любое чтение, стоящее ПОСЛЕ записи, стоит одного пересчёта книги; в тяжёлой книге это упирается в потолок выполнения (§3.7, позиция AH-3).

**Решение.** `setupAll` делится на три блока в таком порядке: все чтения → расчёт в памяти → все записи. После первой записи главная функция книгу не читает — ни в отчёте шага, ни для проверки записанного. Проверка записанного (ошибки формул, живые значения на листах) — отдельной функцией, запускаемой по желанию, либо сессией через `gsheets-read` (§1, шаг 6).

Одно допустимое исключение — зонд разделителя `detectSeparator_` (§2.1): он пишет и читает, но стоит ПЕРВЫМ шагом блока записей, когда накопленных записей ещё нет, и только в лёгкой книге. В тяжёлой книге `flush` зонда падает (§3.7), и разделитель определяется чтением живой формулы в блоке чтений:

```javascript
// Ячейка с заведомо многоаргументной формулой, которая в книге уже считается правильно.
function detectSeparatorByRead_(sh, a1) {
  var f = sh.getRange(a1).getFormula();
  if (!f) throw new Error('В ' + a1 + ' нет формулы — разделитель не определить');
  return f.indexOf(';') >= 0 ? ';' : ',';
}
```

Перед блоком записей — предохранитель: если чтения съели больше 4 минут, запись не начинается, и книга остаётся прежней, а не оборванной посреди листов. Число 4 — запас до шестиминутного потолка под запись, а не замер: запись трёх книг §8 занимает меньше минуты.

```javascript
function setupAll() {
  var t0 = new Date();
  var problems = [], times = [];
  function step(name, fn) { /* как в §4.4 */ }
  // отчёт начинается с перевода строки: первая строка сообщения уходит в подсказку (§2.2)
  function report_() { return '\n\nВремя по шагам:\n' + times.join('\n') + (problems.length ? '\n\nПроблемы:\n' + problems.join('\n') : ''); }

  // 1. чтения …  2. расчёт …
  if ((new Date() - t0) / 1000 > 240) { alert_('Чтение заняло больше 4 минут — запись не начата.' + report_()); return; }
  // 3. записи …
}
```


### 4.9. Расписание и триггеры: работает только то, что видно по объекту

Триггер ежедневного обновления считается работающим, только когда метка последнего прогона на самом листе (у книг Ozon — ячейка «Снимок сделан» на листе «Параметры») показывает сегодняшний день. Текст скрипта, документация и слова «триггеры включены» доказательством не являются: три книги юнит-экономики Ozon не обновлялись с 28–30 сентября при обещанных ежедневных триггерах, и это нашлось только чтением «Снимок сделан» (`labs/ozon-ue/t-goods-book-script.md`, 2026-10-05). Следствия:
- скрипт с расписанием обязан писать метку последнего прогона (дата и время) в известную ячейку — без неё работу расписания проверить нечем;
- задача о расписании закрывается успешным **плановым** прогоном, прочитанным через `gsheets-read`, а не ручным запуском: ручной запуск доказывает код, но не триггер.

Простой триггер `onEdit` срабатывает только на ручную правку ячейки человеком. Изменение значения формулой, `IMPORTRANGE` или записью из n8n его не вызывает. Триггер, повешенный на колонку-формулу, молчит всегда: в Price Master `onPriceEdit` следил за колонкой G, а G — формула, поэтому история цен пополнялась только ручным запуском `updateHistory` (`labs/ozon-ue/t-cost-history-copy.md`, 2026-10-06). Реакцию на изменение формулы делать триггером по времени со сравнением с прошлым снимком.

| Ручная правка Андрея пропала после пересборки | `clear()` по всему листу или запись в непустую ячейку владельца | §4.2 |
| `Exceeded maximum execution time` или `Service timed out` в тяжёлой книге | чтение после записи или `flush` ждёт пересчёта всей книги; сначала исключить модальное окно (§2.2) | §4.8, §3.7 |
