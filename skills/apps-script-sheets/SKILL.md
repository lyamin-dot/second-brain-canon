# apps-script-sheets

Что происходит внутри книги Google Sheets, когда её перестраивает Apps Script; откуда сессия берёт код скрипта книги и как вносит правку. Чтение и запись Drive, `gsheets-read`, `gdocs-*` — Skill `google-drive-docs`.

## Стоп-правила

- Ни одна ячейка не стирается и разметка не сдвигается, пока `findRefs` не показал все формулы всех листов, которые ссылаются на этот лист.
- «Лист пуст, можно занимать» по прочитанному диапазону не выводится.
- Код скрипта правится только по живому тексту (см. «Живой текст скрипта»); по технической документации книги, своей копии из прошлой сессии, старой справочной копии в Drive — нельзя.
- Правка формул или кода рабочей книги — только после согласования с Андреем, что чиним и что строим; и когда сессия пишет мостом сама. Если план уже согласован в чате или записан в `PLAN.md` проекта — назвать адрес согласования и идти дальше.
- Запись мостом — только при строке `gas_allowlist` с доступом `write`, прочитанной в этой сессии; память прошлой сессии и этот Skill признаком не являются.
- Строку с доступом `write` в `gas_allowlist` добавлять только после слова Андрея в чате.
- Запись мостом — только с `projectHash` из свежего `read` или `projectHashAfter` предыдущей записи той же серии; отказ по устаревшему отпечатку — перечитать и повторить от нового текста.
- Файл, пришедший с `truncated:true`, неполон — по нему не править.
- Код книги, прочитанный мостом, в репозиторий не пишется — ни целиком, ни фрагментом; в канон идут имена файлов, функций и отпечаток проекта.
- Сессия через clasp не пишет и такую правку не планирует.
- Подворкфлоу gas-bridge «· Call» не вызывать.
- `setConditionalFormatRules([])` перед записью правил не делать: набор правил листа собирать в массив и писать одним вызовом.
- Перед любой очисткой листа — снимок листа (формула, иначе значение) текстом на скрытый лист `_dashboard_backup`; в тяжёлой книге вместо него — «Файл → Создать копию» и «Файл → История версий».
- Строки зоны параметров (1–`CTRL_LAST_ROW`) при перестройке не очищаются.
- Ручной ввод не перетирается: в колонки и ячейки, которые Андрей ведёт руками, скрипт пишет только в пустую ячейку (или в ячейку, равную снимку «_авто», — «Ручной ввод и колонки владельца»); `clear()` по всему листу не делается, очищаются только диапазоны, перечисленные в скрипте явно.
- Существующий именованный диапазон не удалять и не пересоздавать — перенаправлять `setRange`.
- Чужие именованные диапазоны (в которые пишет n8n) расширять только отдельным пунктом меню и по явному решению, никогда заодно с оформлением.
- Перед записью в существующую колонку — прочитать её `gsheets-read` с `render:"FORMULA"`: в колонку, которую заполняет формула (`ARRAYFORMULA`, `IMPORTRANGE`, `FILTER`, построчная), значения не пишутся ни скриптом, ни n8n, ни руками.
- На лист, на который другие книги ссылаются адресами через `IMPORTRANGE`, колонки в середину не вставлять — только последней.
- Удаление листа ради предела ячеек — сначала архивная копия книги, само удаление решает Андрей.
- Контрольные проверки главной таблицы не прошли — дальше её не читать и сообщить Андрею.

## Как делать

### Порядок работы

1. **Разведка.** `gsheets-read` `mode:"meta"` → список листов; затем `mode:"range"` с `render:"FORMULA"` по каждому рабочему листу, колонки до Z, а не до J. Перед добавлением метрики — лист целиком в `FORMULA`, включая строки за пределами известной разметки. Изменилась подпись строки — спросить Андрея, а не перепроверять свой код.
2. **Карта зависимостей.** Прогнать `findRefs` и `showMap`; только после этого решать о разметке.
3. **Проект.** Согласовать с Андреем (стоп-правило).
4. **Скрипт.** Один файл, идемпотентный, со всеми частями «Обязательные части скрипта». Файл, добавляемый в проект с другими файлами, — проверка имён (ловушка «одна область видимости»).
5. **Прогон.** `setupAll` запускает Андрей: без доступа `write` — после вставки файла; с доступом `write` — после записи сессией мостом. Мост функций не запускает; запуск функций сессией не обещать и не планировать.
6. **Проверка.** Результат читать самому через `gsheets-read`; отчёт скрипта — гипотеза. Для записи мостом: поля ответа — сигнал, доказательство — новое чтение проекта.

### Живой текст скрипта и путь правки

Живой текст — то, что стоит в проекте скрипта книги в эту минуту; резервная копия `.gs`, которую Андрей положил в Drive для этой правки после своей последней правки кода, — тоже живой текст.

| Книга | Чтение живого текста | Как вносится правка |
|---|---|---|
| скрипт доступен аккаунту Андрея, в `gas_allowlist` доступ `write`, прочитано в этой сессии | мост, операция `read` | сессия пишет мостом (`write`) — полным файлом или заменой одного уникального фрагмента |
| скрипт доступен аккаунту Андрея, доступа `write` нет (строки нет или `read`) | мост, операция `read` | полным текстом файла на вставку для Андрея |
| мост недоступен или скрипт мостом не читается | текст присылает Андрей: в чат или копией `.gs` в Drive, которую сессия читает целиком через `gdocs-read` | полным текстом файла на вставку для Андрея |

- Отказ моста «NOT ALLOWED» на запись — доступа `write` нет, правка идёт полным текстом для Андрея.
- Идентификатор скрипта берётся из `gas_allowlist` или из «Мои проекты» на script.google.com и проверяется ссылкой на книгу на странице «Описание проекта» скрипта.
- Ответ моста читать только тем сужением, которое названо в контракте.
- В отчёте о правке назвать `versionBefore` — по нему откат (операция `rollback`).
- **Серия фрагментов.** Правка, которая не помещается в один уникальный фрагмент, идёт серией замен фрагментов, а не записью файла целиком: (1) собрать серию на копии живого текста; (2) проверить локально `node --check`; (3) записать фрагменты по очереди; (4) после последнего — новое чтение мостом и побайтное сравнение с копией. Новый файл тоже пишется сериями замен по границам функций, так чтобы каждая промежуточная версия была синтаксически цельной.
- Правка, которая меняет назначение участка листа (неочищаемая зона параметров стала пересобираемым блоком), перед записью строит карту ссылок на участок и тем же действием правит комментарии и описания констант, которые обещают прежнее.
- После записи мостом сказать Андрею: вкладку редактора скрипта, открытую до записи, перед своей правкой в ней перезагрузить.
- **Полный текст на вставку** (нет `write`): Андрей выделяет всё в редакторе и вставляет файл целиком. Перед выдачей — сверка с живым текстом, а не со своей рабочей копией; в сопроводительном сообщении — короткий перечень изменённых функций. Точечные патчи «было → стало» не выдавать.
- **Аварийный путь clasp** (сервер n8n и мост недоступны): правит только Андрей на своём компьютере — свежий `clasp clone` или `clasp pull` в чистую папку непосредственно перед правкой, затем `clasp push`; первая же сессия после этого читает проект мостом, чтобы получить новый отпечаток.

### Аудит без правки

Задача «можно ли верить числам книги»: скрипт читается мостом (`read`); в канон идёт пересказ логики по функциям, не код. Проверить: (1) каждый поясняющий текст и подпись управляющей ячейки против того, что делает скрипт; (2) проверочные ячейки, равные нулю по построению (разность двух сумм из одних данных), доказательством не считать; (3) числа книги сверить с внешним отчётом по неделям и по каждой статье (см. «Сверка»).

### Оформление и проверка данных образца — скрипт-дамп

`gsheets-read` оформления не отдаёт ни в одном режиме. Задача про оформление образца начинается со скрипт-дампа, который запускает Андрей: `getNumberFormats`, `getBackgrounds`, `getColumnWidth`, `getRowHeight`, `getConditionalFormatRules`, `getCharts`, `getDataValidations` → снимок на отдельный лист или в отдельную книгу → сессия читает снимок `gsheets-read`. Шаг «прочитать оформление через gsheets-read» в план и эстафету не ставить.

### Формулы: разделитель и конвертер

- Разделитель аргументов определяется в каждой книге при каждом прогоне: в лёгкой книге — зондом `detectSeparator_` первым шагом блока записей; в тяжёлой — чтением живой формулы `detectSeparatorByRead_` в блоке чтений. Не переносить из другой книги, прошлой сессии, записи в каноне; не выводить из формулы, прочитанной `gsheets-read` в `FORMULA`.
- Код пишет формулы в американской записи; каждая формула перед записью проходит `loc_`. Каждая запись формулы в файле — `setF_(…)` либо `setFormulas(…)` массива, каждый элемент которого прошёл `loc_`; прямой `.setFormula(` без `loc_` — только в зонде. Колонку формул писать одним `setFormulas` на диапазон.
- Дробь писать с ведущим нулём (`0.5`, не `.5`); имя листа с точкой или запятой — только в одинарных кавычках.
- Формулу с литералом массива писать из Apps Script, а не через `gsheets-*` (`values.update` `USER_ENTERED`).
- Функции `loc_` и `alert_` при переносе кода из образца брать отсюда, не из образца.

```javascript
var SEP = ',';

// Зонд пишет в книгу и ждёт пересчёта: только лёгкая книга и только первым шагом записей.
function detectSeparator_(ss) {
  var tmp = ss.insertSheet('_probe_' + new Date().getTime());
  var ok = false;
  try {
    tmp.getRange('A1').setFormula('=SUM(1,2)');
    SpreadsheetApp.flush();
    ok = (tmp.getRange('A1').getDisplayValue() === '3');
  } finally {
    ss.deleteSheet(tmp);
  }
  return ok ? ',' : ';';
}

// Тяжёлая книга: ячейка с заведомо многоаргументной формулой, которая уже считается правильно.
function detectSeparatorByRead_(sh, a1) {
  var f = sh.getRange(a1).getFormula();
  if (!f) throw new Error('В ' + a1 + ' нет формулы — разделитель не определить');
  return f.indexOf(';') >= 0 ? ';' : ',';
}

function loc_(f) {
  if (SEP === ',') return f;
  var out = '', stack = [], inStr = false, inName = false;
  for (var i = 0; i < f.length; i++) {
    var ch = f.charAt(i);
    if (inStr || inName) {                        // "строка" и 'имя листа' не трогаем
      out += ch;
      var q = inStr ? '"' : "'";
      if (ch === q) {
        if (f.charAt(i + 1) === q) { out += q; i++; }   // удвоенная кавычка внутри
        else { inStr = false; inName = false; }
      }
      continue;
    }
    if (ch === '"') { inStr = true; out += ch; continue; }
    if (ch === "'") { inName = true; out += ch; continue; }
    if (ch === '(' || ch === '{') { stack.push(ch); out += ch; continue; }
    if (ch === ')' || ch === '}') { stack.pop(); out += ch; continue; }
    if (ch === ',') {
      out += (stack.length && stack[stack.length - 1] === '{') ? '\\' : ';';
      continue;
    }
    // десятичная точка между цифрами → запятая
    if (ch === '.' && /[0-9]/.test(f.charAt(i - 1)) && /[0-9]/.test(f.charAt(i + 1))) { out += ','; continue; }
    out += ch;
  }
  return out;
}

function setF_(rng, formula) {
  rng.setFormula(loc_(formula));
  return rng;
}
```

### Обязательные части скрипта

Скрипт, который перестраивает книгу, переживает повторный прогон, обрыв посередине и ручную правку Андрея и сам показывает, что сделал.

- **Главная функция `setupAll` — первая в файле.** `onOpen` — в `try/catch`.
- **Итог прогона — не модальным окном** (`getUi().alert()` не использовать): полный отчёт в журнал, первая строка — всплывающей подсказкой; первая строка достаточна для решения: «Готово за 37 с» или «Готово С ОШИБКАМИ за 44 с».

```javascript
function alert_(msg) {
  Logger.log(msg);   // полный отчёт: редактор скриптов → «Выполнения»
  try { SpreadsheetApp.getActiveSpreadsheet().toast(String(msg).split('\n')[0], 'Отчёт прогона', 15); }
  catch (e) {}
}
```

- **Идемпотентность.** Повторный прогон приводит книгу в то же состояние. Условное форматирование — одним `setConditionalFormatRules(rules)` (стоп-правило). Графики — перед построением удалить все графики листа.
- **Порядок пересборки листа:** снять закрепление и группу прошлого прогона (`unfreeze_`) → разметка → именованные диапазоны (`setName_`: есть имя — `setRange`, нет — `setNamedRange`) → ВСЕ формулы → закрепление (`freezeHead_`) последним.
- **Закрепление на листе с инструкцией:** закреплять только строки до шапки включительно, колонки не закреплять, строки инструкции собрать в группу.

```javascript
var HEAD_ROW = 10;          // строка шапки; строки 2–8 — инструкция листа
function unfreeze_(sh) {    // ПЕРВЫМ при пересборке: иначе глубина группы растёт с каждым запуском
  sh.setFrozenRows(0); sh.setFrozenColumns(0);
  var g = sh.getRange('2:8');
  for (var i = 0; i < 5 && sh.getRowGroupDepth(2) > 0; i++) g.shiftRowGroupDepth(-1);
}
function freezeHead_(sh) {  // ПОСЛЕДНИМ, когда лист построен
  sh.setFrozenRows(HEAD_ROW);
  sh.getRange('2:8').shiftRowGroupDepth(1);
}
```

- **Все чтения — до первой записи.** `setupAll` = все чтения → расчёт в памяти → все записи. После первой записи главная функция книгу не читает — ни для отчёта, ни для проверки записанного; проверка записанного — отдельной функцией по желанию или сессией через `gsheets-read`. Исключение — зонд разделителя первым шагом блока записей в лёгкой книге. Перед блоком записей — предохранитель: чтения заняли больше 4 минут — запись не начинается.
- **Пошаговый прогон.** Каждый шаг в своей обёртке, ошибки копятся, отчёт в конце показывает все ошибки и время каждого шага. Шаг чтения вернул `null` — книга не трогается.

```javascript
function setupAll() {
  var t0 = new Date();
  var problems = [], times = [];
  function step(name, fn) {
    var s0 = new Date();
    try { return fn(); }
    catch (e) { problems.push('✗ ' + name + '\n   ' + (e && e.message ? e.message : e)); return null; }
    finally {
      var line = name + ': ' + ((new Date() - s0) / 1000).toFixed(1) + ' с';
      times.push(line); console.log(line);
    }
  }
  // отчёт начинается с перевода строки: первая строка сообщения уходит в подсказку
  function report_() { return '\n\nВремя по шагам:\n' + times.join('\n') + (problems.length ? '\n\nПроблемы:\n' + problems.join('\n') : ''); }

  // 1. чтения: var src = step('чтение источника', function () { return readSource_(); }); if (!src) …
  // 2. расчёт …
  if ((new Date() - t0) / 1000 > 240) { alert_('Чтение заняло больше 4 минут — запись не начата.' + report_()); return; }
  // 3. записи …
}
```

- **Причину упавшего прогона снимать из журнала выполнений сразу** (страница «Выполнения» редактора, «Мои выполнения» на script.google.com; хранит около 7 дней): время начала, длительность, статус, строки `console.log`. Сессия читает страницу сама во встроенном браузере, если он ей доступен.
- **Неразобранное число — в `problems`, не ноль.** `Number(x) || 0` не использовать; текст разбирать по записи числа источника (не угадывать по одному значению), неразобранное — в `problems` шага со счётом строк.
- **Признак живости в отчёте прогона:** число строк в листе-источнике и границы периода расчёта (из блока чтений).
- **Договорённость между частями книги — проверкой в отчёте:** одинаковые номера строк на двух листах-слоях — сравнить подписи строк; зашитый адрес — искать по заголовку; число периодов из комментария — посчитать на листе.
- **Служебные функции в меню:** `showMap` — выгружает на лист `_map` метаданные книги (локаль и определённый разделитель), листы с числом строк, все именованные диапазоны с адресами, все формулы рабочих листов; запускать до любой перестройки. `findRefs` — обходит все листы и выписывает каждую формулу, ссылающуюся на заданный лист.
- **Пункты меню по охвату, вслух:** «Пересобрать всё» и «Только починить формулы» — разные пункты; в тексте пункта и в документации книги написано, что второй не трогает оформление, тексты пояснений и генерируемые листы. Медленное действие — отдельным пунктом с пометкой «(медленно)», тяжёлый и необязательный пункт — последним в меню.
- **Колонка источника — по заголовку,** функцией, которая падает, если заголовок найден не ровно один раз (сравнение по тексту без пробелов по краям). Если дубль в источнике убрать нельзя — колонка задаётся номером, и при каждом прогоне проверяется: заголовок по номеру равен ожидаемому, число одноимённых заголовков равно известному; не совпало — шаг падает.

```javascript
function colByHeader_(headers, name) {
  var hits = [];
  headers.forEach(function (h, i) { if (String(h).trim() === name) hits.push(i); });
  if (hits.length !== 1) throw new Error('Заголовок «' + name + '» найден ' + hits.length + ' раз, колонки: ' + hits.map(function (i) { return i + 1; }).join(', '));
  return hits[0];
}
```

- **Проект из нескольких файлов:** перед добавлением файла или функции прочитать мостом имена функций и глобальных переменных во ВСЕХ файлах проекта и не заводить совпадающих; одна `onOpen`, константы с префиксом.
- **Часовой пояс:** в каждой книге сверить «Настройки проекта» скрипта с `ss.getSpreadsheetTimeZone()`; совпадение доказывает чтение колонки дат `render:"UNFORMATTED_VALUE"` (целые числа), а записывается оно в канон проекта книги.

### Ручной ввод и колонки владельца

- **Зона параметров:** управляющие ячейки снимаются до очистки и возвращаются после — с подписями, заливкой и предупреждением в заголовке, кто на них ссылается; значение записывается только в пустую ячейку.
- **Ручной ввод на перестраиваемом листе** (параметр, ячейка что-если, цена для проверки) читается ДО перестройки и возвращается по ключу, не по номеру строки: параметр — по подписи или имени диапазона в соседней ячейке, строка товара — по артикулу (SKU). Ключ не совпал — ставится значение по умолчанию.
- **Колонка, где рядом автоматические значения и правки владельца:** скрипт держит на скрытом листе «_авто» снимок значений, которые он собрал в прошлый раз; ячейка, отличная от снимка, — правка владельца и не перезаписывается; ячейка, равная снимку, обновляется, и снимок обновляется вместе с ней.
- **Инструкция человеку на ручную правку ячеек** в листе с повторяющимися ключами называет признак, уникальный в листе (ключ + дата начала, значение соседней колонки), а не номер строки или один ключ.
- Новую книгу проектировать так, чтобы ручной ввод и вывод скрипта были на разных листах.

### Проверка результата

- После любой правки формул результат читать и сверять с тем, что обязано получиться; отсутствие `#ERROR!` ничего не доказывает.
- **Сверка книги, сворачивающей сырые данные:** сумма свёрнутого минус сумма источника по той же денежной колонке = 0,00 — формулой в самой таблице, с `ROUND(…;2)`, по всем неделям, где есть данные; и каждая статья книги — отдельно со строкой внешнего отчёта (сверка итога разнесение по статьям не доказывает).
- **Лист «что-если»** проверять дважды: с пустым вводом (совпадает с фактами) и с заполненным.
- **«Странный ноль» статьи:** прежде чем чинить, проверить, есть ли для этой статьи источник в этом листе вообще.
- **Ключ сравнения:** обе стороны — к одному типу (`TO_TEXT` с обеих сторон); перед сверкой по ключу — `=COUNTA(A2:A)-COUNTUNIQUE(A2:A)` = 0.
- **Доступ `IMPORTRANGE`:** выдавать отдельной ячейкой без `IFERROR` — `=IMPORTRANGE("<ID>";"Лист!A1")`, нажать «Разрешить доступ», очистить ячейку; после вставки формулы читать результат `gsheets-read`.
- **`IFERROR` вокруг `FILTER`** — только с контрольной ячейкой или строкой отчёта: сколько строк источника прошло условие и сколько вывелось.
- **Склейка цепочек `IMPORTRANGE`** — по ключу (`VLOOKUP`/`XLOOKUP`), а не рядом построчно.
- **Регистр:** колонку с двумя написаниями одного значения приводить к одному в источнике, а не подбирать функцию.
- **Значение на дату по строкам** (вместо `MAXIFS` в `ARRAYFORMULA`) — считать скриптом и писать значениями; `BYROW`/`MAP` с `LAMBDA` — только после сверки с расчётом скрипта на тех же строках.
- **Контрольный пример главной таблицы** (товарные данные, декларации): перед построением чего-либо на её чтении прогнать проверки — у таблицы товарных данных `meta/PRODUCT_DATA_HIERARCHY.md`, раздел «6. Проверки перед чтением»; у реестра деклараций — `meta/DECLARATION_SCAN.md`, абзац «Признаки поломки»; новую главную таблицу заводить сразу с контрольным примером (значение у известного ключа, число строк против источника, построчное совпадение ключей), записанным в каноне её проекта.

### Тяжёлая книга и рост

- Тяжёлая книга (пересчёт минутами): опытных зондов, которые пишут и ждут результата, не делать — только чтение уже записанного; снимок листа скриптом заменить копией и историей версий Google.
- Новая книга не читает расчётные листы тяжёлой книги — берёт сырой источник и минимум справочных листов; расчётный лист тяжёлой книги — только отдельным пунктом меню.
- У книги, которая растёт каждую неделю, сумму сеток листов (`gsheets-read` `meta`) сверять с пределом 10 000 000 ячеек и считать запас в неделях.
- Колонку, которую дописывает робот, строить без формул: вычисление — в роботе или в колонке правее; сигнал по таким строкам — условным форматированием.
- Построчные формулы заменять одной `ARRAYFORMULA` в первой строке данных с открытым диапазоном; добавив строки к листу с построчными формулами — продлить формулы.
- Диапазоны — открытые от первой строки, где данные реально начинаются (`Лист!$P$2:$P`); где открытый неприменим — потолок с запасом от `getMaxRows()` и сверка суммы диапазона с суммой колонки.
- При росте источника зеркала `IMPORTRANGE` проверять обе границы: сетку листа и диапазон в формуле склейки.

### Расписание и триггеры

- Скрипт с расписанием пишет метку последнего прогона (дата и время) в известную ячейку.
- Расписание считается работающим, когда метка на листе показывает дату планового прогона И возраст метки проверяет внешний исполнитель (см. «Свежесть»). Задача о расписании закрывается первым успешным плановым прогоном, прочитанным через `gsheets-read` (не ручным запуском), — если такая проверка уже стоит; пока её нет — сначала встроить проверку, а не считать дни.
- Время прогонов брать из журнала выполнений, не из кода; триггер без нужды не переставлять.
- Реакцию на изменение формулы делать триггером по времени со сравнением с прошлым снимком, не `onEdit`.

### Оформление

- Цветовая шкала — построчно, крайние точки — перцентили 10/50/90.
- Дельты в рублях — цветом текста по знаку, без заливки; дельты в процентах — расходящаяся заливка с краями −20% … 0 … +20%, только по колонке с одной единицей.
- Ухудшение = отрицательная дельта для всех строк (затраты в витринах хранятся со знаком минус); ветку «для затрат наоборот» не писать; строки, где рост — ухудшение, — знак в формуле (см. «Сигнал»).
- Единицы, которые глазом не различить, — форматом ячейки: `'+0.0" п.п.";-0.0" п.п.";0.0" п.п."'` против `'+0.0%;-0.0%;0.0%'`; сменив один на другой — проверить величину в ячейке на конкретном числе. В текст тревоги — величина в одной единице для всех строк (обычно деньги).
- Пороги тревог — построчные колонки «порог ₽» и «порог %» со ссылкой на общее значение по умолчанию; пустой порог — критерий не применяется. Пороги тревог живут в ячейках и переживают пересборку по ключу; пороги сигнала — в коде.
- Спарклайн — из понедельной витрины через `OFFSET` по счётчику недель, с `ARRAYFORMULA(ABS(...))`, в локали книги:

```
=IFERROR(SPARKLINE(ARRAYFORMULA(ABS(OFFSET(weekly_history!$A$5,0,MAX(1,WEEKS_N-12),1,MIN(13,WEEKS_N)))),
  {"charttype","line";"color","#5B8FF9";"linewidth",2;"empty","ignore"}),"")
```

- Графики — по отдельному транспонированному блоку (`TRANSPOSE`) внизу дашборда, не транспонированием в опциях; ряды фильтровать по наличию данных; ряды с разными базами в стопку не складывать.
- Порядок колонок витрины — одним списком букв (`var MIRROR_COLS = ['A','B','C','E','F','D','G','H'];`); менять вместе с ним шапку блока, числовые форматы и адреса цветовых правил; лист-источник не переставлять.
- **Текст тревоги** собирается формулами в книге; n8n читает именованные ячейки (тексты, например `TG_WEEKLY_TEXT`, `TG_ALERT_TEXT`, метку прогона, последнюю дату данных) одним запросом. Воркфлоу — курьер с одной своей проверкой: метка старше порога или ячейку не прочитать — сам отправляет «книга не обновлялась»; иначе пусто — молчит, непусто — отправляет. Служебный блок не двигается никогда: место для блока выше забирать у соседей сверху.
- Тревога считается построенной, когда найден воркфлоу, который читает её ячейки, он опубликован, и приход сообщения проверен по факту.
- В `TEXTJOIN` для сообщения с абзацами — `ignore_empty = FALSE`.

### Сигнал витрины

Сигнал отвечает на вопрос «этот период отличается от обычного?»; красный читается как «стало хуже». Раньше — свежесть данных.

1. **Одна база на вердикт:** все критерии одного сигнала сравнивают с одной базой; первым делом проверять, на какую колонку смотрит каждый критерий.
2. **Знак — в формуле отклонения, не в цвете:** строки, где рост — ухудшение (возвраты, доля удержания, брак), помечаются флагом и знак переворачивается в самой формуле. Тест: период с идеальным результатом (ноль возвратов) обязан дать положительное отклонение.

```javascript
function devRub_(r) {
  var body = '$B' + r + '-$F' + r;
  return '=IF(OR($B' + r + '="",$F' + r + '=""),"",' +
         (sig_(r).inv ? '-(' + body + ')' : body) + ')';
}
```

3. **Две семьи строк:** масштабируемые (себестоимость, логистика, приёмка, эквайринг, комиссии, удержания) — долей от драйвера (обычно выручки), отклонение в п.п.; драйвер — тот, который не содержит другую проблему. Немасштабируемые и итоги (хранение, штрафы, разовые списания, прибыль, маржа, средний чек) — абсолютом в % от нормы. Итог в семью «доля» не переводить.
4. **Пол материальности** — одна абсолютная сумма на книгу, мельче — не окрашивается; **порог красного** — построчный, в единицах семьи. Абсолютный порог долей от нормы строки не назначать. Зелёный — не хуже нормы либо хуже, но мельче пола; жёлтый — хуже заметно; красный — хуже сверх порога строки.
5. **Порог — прогоном по истории:** (1) собрать ряд из понедельного листа — значение и норма на тот момент, норму воспроизводить точно как книга и сверить с живым значением последнего периода (расхождение больше пары процентов — модель не та); (2) отбросить периоды без полного окна нормы; (3) прогнать сетку кандидатов — таблица «кандидат → красных / жёлтых / зелёных»; (4) взять значение на плато. Ориентир: 4–7 красных на 24 периода. В документацию по каждому порогу: число, сколько раз сработало бы, плато, какую аномалию поймало.
6. **Скользящая норма:** в пояснении на витрине написать «зелёный — как в последние N периодов, а не „хорошо“».
7. **Цвет и деньги рядом:** абсолютная сумма отклонения — отдельной колонкой, по знаку, рядом с сигналом; короткое пояснение под блоком и лист-руководство из массива в коде с разделом «разбор по следу» («итог ниже нормы» → приход выше/ниже нормы → удержания / объём и цена).
8. **Правка правила:** прогнать старый и новый вердикт по всей истории и выписать периоды, где они разошлись.
9. **Неполный закрытый период:** книга считает число дней с данными в каждом закрытом периоде; дней меньше календаря — отдельная строка в тексте тревоги «в неделе такой-то нет данных за N дней». Текущий незакрытый период — не сбой.

### Свежесть автоматического выхода

- Возраст книги, бэкапа, сводки проверяет внешний исполнитель — воркфлоу n8n по своему расписанию: читает метку последнего прогона книги и последнюю дату данных; метка старше порога или ячейку не прочитать — сам отправляет сообщение. Метка прогона нужна и там, где проверка уже читает дату данных.
- Новый воркфлоу ради этого не заводится: проверка встраивается в воркфлоу, который и так читает книгу (курьер), или одной строкой в существующий ежедневный монитор.
- Порог возраста — выше наибольшего нормального возраста и ниже возраста при одном пропуске; считать от двух ритмов: ритма прихода данных (пила) и нормального возраста метки в момент проверки. Тот же метод прогона по истории.
- Ветку «старое» проверить подменой метки: прогнать воркфлоу с подменённой меткой и убедиться, что сообщение пришло.

Приём, работу которого доказывает внешний исполнитель (курьер), считать работающим только по состоянию исполнителя в `registry/n8n-map.md` и журнале проекта книги.
3. Порядок: сигнал («Сигнал витрины») — ЗАЧЕМ; конструктор — ЧТО строить; этот Skill — КАК записать.
4. ## Адреса и ловушки

- Адреса книг и документов — в реестре `registry/documents.md`; воркфлоу — `registry/n8n-map.md`; мост gas-bridge и ID таблицы `gas_allowlist` — `registry/tools.md`, строка gas-bridge.
- `setFormula`/`setFormulas` молча пишут формулу буквально, без перевода в локаль книги, — проверяй разделитель книги (зонд или живая формула) и пропускай формулу через `loc_`.
- Редактор Apps Script молча запускает первую функцию файла (первое нажатие на `onOpen` только строит меню) — проверяй, что `setupAll` стоит первой.
- Удаление именованного диапазона молча переписывает все ссылающиеся формулы в `#REF!`, пересоздание имени их не чинит — проверяй, что имя перенаправлено `setRange`, а не удалено.
- `setValue`/`setValues` молча превращают строку, начинающуюся с `=`, в формулу (заголовок «=== РАЗДЕЛ ===» становится `#ERROR!`, n8n получает мусорные имена полей) — проверяй: строке на `=+-@` ведущий апостроф (только строкам, не числам) и формат `@` на ячейках текста.
- Дата, собранная как полночь UTC, молча ложится в ячейку со сдвигом на пояс книги (46286,083), и `SUMIFS` по датам теряет граничный период — проверяй перевод в местную дату перед записью и целые числа в `UNFORMATTED_VALUE`.
- Одно имя функции или глобальной переменной в двух файлах проекта молча берёт последнее загруженное определение — проверяй имена во всех файлах проекта.
- `getDataValidations()` молча даёт `null` на шапке и строке-подсказке — проверяй правила по нескольким строкам с реальными данными.
- Стирание управляющей ячейки (может стоять в любой колонке любого листа) молча обнуляет цепочку `FILTER` и все листы, считаемые из неё, — проверяй `findRefs` до стирания.
- `SUMIFS` по пустому окну молча даёт 0 вместо «данных нет» — проверяй гард по обеим границам данных: `=IF(OR(B$3<FIRST_DATA_DATE,B$3>LAST_DATA_DATE),"", <формула> )`.
- Диапазон с жёстким потолком (`A3:A5000`, именованный до строки 50 000) молча недосчитывает выросший лист; `getLastRow()` на листе с разливом `FILTER` молча занижает границу в разы — проверяй сумму диапазона против суммы колонки.
- Построчные формулы молча не распространяются на добавленные или вставленные строки, `SUMIFS` считает пустоту нулём — проверяй расчётные колонки в новых строках.
- Колонка, вставленная в середину листа-хаба, молча сдвигает чтение чужих `IMPORTRANGE` на соседнюю колонку — проверяй, что новая колонка последняя.
- Зеркало склейки `IMPORTRANGE` молча перестаёт расти на диапазоне, зашитом в формуле, — проверяй обе границы.
- `MAXIFS`/`MINIFS` внутри `ARRAYFORMULA` молча возвращают одно значение на всю колонку — проверяй колонку на одинаковые числа там, где они обязаны различаться.
- Число, вписанное поверх построчной формулы, молча расходится с ней — проверяй колонку в `FORMULA` перед записью.
- Узел Google Sheets n8n при добавлении строк молча считает ячейку с формулой занятой и дописывает ниже конца разлива — проверяй, что в колонке робота нет формул.
- Ключ числом с одной стороны и текстом с другой (`1058.0` против `1058`) молча даёт ноль совпадений, а обновление-вставка плодит дубли — проверяй один тип с обеих сторон.
- `VLOOKUP` при двух строках ключа молча берёт первую — проверяй уникальность ключа источника.
- `IFERROR` вокруг `IMPORTRANGE` молча прячет отказ доступа (кнопка «Разрешить доступ» не появляется) и несовпадение типов ключа — проверяй результат чтением, доступ выдавай без `IFERROR`.
- Две цепочки `IMPORTRANGE` рядом молча расходятся построчно после первого отличия в числе или порядке строк — проверяй склейку по ключу.
- `IFERROR` вокруг `FILTER`, которому не хватило строк, молча даёт пустоту (себестоимость 0, прибыль завышена) — проверяй число прошедших условие строк против выведенных.
- `SUMIFS`/`COUNTIFS` молча не различают регистр, а `QUERY` и `=` различают — проверяй написание категорий в источнике.
- `COUNTIFS(диапазон;"<>")` молча считает `""`, возвращённую формулой, — считай `SUMPRODUCT(LEN(диапазон)>0)`.
- `headers.indexOf(имя)` при двух одинаковых заголовках молча берёт левый, узел чтения n8n — правый — проверяй заголовок функцией `colByHeader_`.
- Простой триггер `onEdit` молча не срабатывает на изменение формулой, `IMPORTRANGE` или записью из n8n — проверяй, что колонка-триггер правится руками.
- Пересоздание триггера по времени молча ставит время заново (`atHour` — любая минута часа, `nearMinute` — ±15 минут), и в день перестановки прогона может не быть — проверяй возраст метки.
- Срыв расписания Apps Script молча перемежается: книга пересчитывается в один день и срывается в соседние — проверяй возраст метки внешним исполнителем, а не числом удачных дней.

## Куда писать результат

- Частные факты книги — её разделитель, часовой пояс и его совпадение с поясом проекта скрипта, контрольные числа, тяжесть — в канон её проекта или лаборатории, не в этот Skill.
- В канон по правке кода — имена файлов и функций, отпечаток проекта, `versionBefore`; текст кода — нет.
- Документация порогов — рядом с витриной (число, срабатывания, плато, пойманная аномалия).
