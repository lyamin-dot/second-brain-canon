## 0. ДВА ПРАВИЛА БЕЗ ИСКЛЮЧЕНИЙ

**0.1. Ни одна ячейка не стирается, пока не построена карта ссылок на неё.** Перед любой очисткой, перестройкой или сдвигом разметки листа — обойти ВСЕ листы книги и найти формулы, которые на этот лист ссылаются (§4.6, `findRefs`). Вывод «лист пуст, можно занимать», сделанный по прочитанному диапазону, ничего не стоит: диапазон почти всегда у́же листа.

**0.2. Формула, записанная через `setFormula`, попадает в ячейку БУКВАЛЬНО.** Перевода в локаль книги не происходит. У книг Андрея локаль `ru_RU`. Подробно — §2.1.

## 1. ПОРЯДОК РАБОТЫ

1. **Разведка.** `gsheets-read` mode `meta` → список листов. Затем `mode:"range"` с `render:"FORMULA"` по каждому рабочему листу. Читать ШИРЕ, чем кажется нужным: колонки до Z, а не до J. Стоимость лишней колонки — ноль, стоимость пропущенной — §3.1.
2. **Карта зависимостей.** Прогнать `findRefs` (§4.6) и `showMap` (§4.5). Только после этого принимать решения о разметке.
3. **Проект.** Согласовать с Андреем: что чиним, что строим, где что лежит. Гейт обязателен — правки формул в рабочей книге необратимы через историю версий только целиком.
4. **Скрипт.** Один файл, идемпотентный, со всеми обязательными частями из §4.
5. **Прогон.** Андрей вставляет и запускает `setupAll`. Скрипт не падает на первой ошибке (§4.4) — один прогон показывает все проблемы.
6. **Проверка.** Читать результат самому через `gsheets-read`, не по отчёту скрипта. Отчёт скрипта — гипотеза.

Правки после первого прогона давать **точечными патчами функций** в формате «было → стало», не переписыванием файла. Пятая полная перезаливка 1300 строк — это счёт, который платит Андрей.

## 2. ЛОВУШКИ APPS SCRIPT

### 2.1. Локаль формул (самая дорогая)

Распространённое и ложное убеждение: «Apps Script принимает формулы в американской записи и сам переводит их в локаль». Нет. `setFormula` кладёт строку как есть. В `ru_RU`:
- разделитель аргументов — `;`, а не `,`
- разделитель колонок в массивах — `\`, а не `,`
- разделитель строк в массивах — `;` (как в US)

Формула с запятыми даёт `#ERROR!` в каждой ячейке. Симптом: полторы тысячи ошибок разом, ровно по числу записанных формул.

**Решение.** Код пишет формулы в американской записи (так их проще читать и сверять), а единственная точка записи прогоняет их через контекстный конвертер. Разделитель определяется опытом, не списком локалей:

```javascript
var SEP = ',';

function detectSeparator_(ss) {
  var tmp = ss.insertSheet('_probe_' + new Date().getTime());
  var ok = false;
  try {
    tmp.getRange('A1').setFormula('=SUM(1,2)');
    SpreadsheetApp.flush();
    ok = (tmp.getRange('A1').getDisplayValue() === '3');
  } finally {
    ss.deleteSheet(tmp);
  }
  return ok ? ',' : ';';
}

function loc_(f) {
  if (SEP === ',') return f;
  var out = '', stack = [], inStr = false;
  for (var i = 0; i < f.length; i++) {
    var ch = f.charAt(i);
    if (inStr) {
      out += ch;
      if (ch === '"') {
        if (f.charAt(i + 1) === '"') { out += '"'; i++; }
        else { inStr = false; }
      }
      continue;
    }
    if (ch === '"') { inStr = true; out += ch; continue; }
    if (ch === '(' || ch === '{') { stack.push(ch); out += ch; continue; }
    if (ch === ')' || ch === '}') { stack.pop(); out += ch; continue; }
    if (ch === ',') {
      out += (stack.length && stack[stack.length - 1] === '{') ? '\\' : ';';
      continue;
    }
    out += ch;
  }
  return out;
}

function setF_(rng, formula) {
  rng.setFormula(loc_(formula));
  return rng;
}
```

Контекст обязателен. Наивная замена всех запятых ломает `TEXT(x,"#,##0")` — запятая внутри строкового литерала часть формата числа, а не разделитель. Возврат диапазона нужен, чтобы работала цепочка `setF_(...).setNumberFormat(...)`.

Проверка после правки: ни одного прямого `.setFormula(` в файле, кроме зонда и самого `setF_`.

### 2.2. Редактор запускает ПЕРВУЮ функцию файла

Выпадающий список «Выполнить» подставляет функцию, идущую в файле первой. Если первой стоит `onOpen`, первое нажатие построит меню и ничего больше не сделает — выглядит как успешный прогон. Второе нажатие упадёт с `Cannot call SpreadsheetApp.getUi() from this context`.

**Решение.** Главная функция (`setupAll`) — первая в файле. `onOpen` обёрнута в `try/catch`. Любой вывод в интерфейс — через обёртку, которая падает в `Logger` при отсутствии UI:

```javascript
function alert_(msg) {
  try { SpreadsheetApp.getUi().alert(msg); }
  catch (e) { Logger.log(msg); }
}
```

### 2.3. Объединение части существующего объединения запрещено

Симптом: `Чтобы объединить или разделить ячейки, необходимо выделить весь диапазон`. Причина: предыдущая версия скрипта объединила `A1:L1`, новая пытается объединить `A1:H1`.

**Решение.** В начале перестройки — `breakApart()` по ВСЕМУ листу, а не по очищаемой части. `breakApart` не стирает содержимое: значение остаётся в левой верхней ячейке бывшего объединения.

```javascript
sh.getRange(1, 1, sh.getMaxRows(), sh.getMaxColumns()).breakApart();
```

Отдельно: объединение, пересекающее границу очищаемой области (например с 6-й по 8-ю строку при очистке с 7-й), даст ту же ошибку на `clear`. Разъединение по всему листу закрывает и этот случай.

**Копирование формулы тащит за собой объединение исходной ячейки.** `copyTo(..., PASTE_FORMULA, false)` вправо по листу с закреплённой колонкой A роняет весь шаг: объединение через границу закрепления Google запрещает. Поэтому `breakApart()` по всему листу нужен и перед `copyTo`, а не только перед `clear`.

### 2.4. Удаление именованного диапазона необратимо ломает ссылки

При удалении имени Google переписывает ВСЕ формулы, которые на него ссылались, в `#REF!` — в самом тексте формулы. Создание имени заново их не чинит: ссылки уже нет, есть `#REF!`.

**Следствие:** пересоздавать именованный диапазон (remove + set) можно только если все формулы, которые им пользуются, будут переписаны скриптом ПОСЛЕ этого. Любая формула, оставленная от прежней версии, превратится в мёртвый `#REF!`.

**Решение.** Порядок в `setupAll`: сначала разметка, потом именованные диапазоны, потом ВСЕ формулы. Ни одна формула не должна пережить пересоздание имени.

### 2.5. setValues превращает строку с «=» в живую формулу

При выгрузке карты таблицы текст формулы, записанный через `setValues`, становится формулой и считается в контексте нового листа. Вместо `=$B$2-6` в отчёте оказывается `#VALUE!`.

**Решение.** Ведущий апостроф плюс текстовый формат. При чтении через API апостроф не возвращается.

```javascript
function asText_(s) { return /^[=+\-@]/.test(s) ? "'" + s : s; }
// и перед записью: rng.setNumberFormat('@').setValues(...)
```

### 2.6. Новый лист по умолчанию 1000 строк

Выгрузка карты или бэкапа может не поместиться. Перед `setValues` проверять `getMaxRows()` и добавлять строки.

## 4. ОБЯЗАТЕЛЬНЫЕ ЧАСТИ ЛЮБОГО ТАКОГО СКРИПТА

### 4.1. Идемпотентность

Повторный прогон приводит книгу в то же состояние, а не накапливает. Перед добавлением: снять все правила условного форматирования (`setConditionalFormatRules([])`), удалить все графики листа, разъединить объединения.

### 4.2. Зона параметров

Строки 1–`CTRL_LAST_ROW` не очищаются при перестройке. Управляющие ячейки снимаются до очистки зоны и возвращаются после — с подписями, заливкой и явным предупреждением в заголовке, кто на них ссылается. Значение записывается ТОЛЬКО если ячейка пуста: введённое вручную не перетирается никогда.

### 4.3. Бэкап перед перестройкой

Перед любой очисткой — полный снимок листа (формула, если есть, иначе значение) на скрытый лист `_dashboard_backup`, текстом. Стоит один вызов, окупается один раз в жизни.

### 4.4. Пошаговый прогон вместо fail-fast

Падение на первой ошибке означает один круг «правка — прогон — сообщение» на каждую мелочь. Каждый шаг выполняется в своей обёртке, ошибки копятся, отчёт в конце показывает все.

```javascript
var problems = [];
function step(name, fn) {
  try { fn(); }
  catch (e) { problems.push('✗ ' + name + '\n   ' + (e && e.message ? e.message : e)); }
}
```

### 4.5. Проверка должна ловить не только ошибки формул

Проверка «нет `#ERROR!`/`#REF!`/`#NAME?`» отрапортовала «всё хорошо» на полностью мёртвой книге: формулы были синтаксически корректны, источник пуст. Отсутствие ошибки — не признак жизни.

**В отчёт всегда добавлять признак живости:** число строк в листе-источнике и границы периода расчёта. Строка «Строк в источнике: 0» видна мгновенно.

### 4.6. Две служебные функции в меню

- `showMap` — выгружает на лист `_map`: метаданные книги (в том числе локаль и определённый разделитель), состав листов с числом строк, ВСЕ именованные диапазоны с адресами, все формулы рабочих листов. Это то, из чего собирается документация и чем восстанавливаются потери: снимок `_map`, сделанный до разрушительного прогона, позволил вернуть затёртые управляющие ячейки.
- `findRefs` — обходит все листы и выписывает каждую формулу, ссылающуюся на заданный лист. Карта зависимостей, без которой правило §0.1 не выполнить.

### 4.7. Пункты меню разделять по охвату, и говорить об этом вслух

«Пересобрать всё» и «Только починить формулы» — разные вещи, и второй НЕ трогает оформление, тексты пояснений и генерируемые листы. Написать об этом прямо в тексте пункта меню и в документации: иначе правка текста, применённая вторым пунктом, молча игнорируется, и это выглядит как «патч не сработал». Ровно так была потеряна сессия отладки.

## 7. АНТИПАТТЕРНЫ

- НЕ делать вывод «лист пуст» по прочитанному диапазону — читать шире и прогонять `findRefs`.
- НЕ очищать лист целиком, если на нём может лежать чужой параметр.
- НЕ писать формулы с запятыми без конвертера.
- НЕ ставить `onOpen` первой функцией файла.
- НЕ пересоздавать именованный диапазон, оставляя формулы прежней версии.
- НЕ переписывать весь файл скрипта ради правки в две строки — давать патч функции «было → стало».
- НЕ считать отчёт скрипта доказательством: результат читать самому через `gsheets-read`.
- НЕ расширять и не двигать чужие именованные диапазоны заодно с оформлением.
- НЕ строить одну цветовую шкалу на разноразмерные строки.
- НЕ класть в одну колонку две единицы без подписи в формате ячейки (§5).
- НЕ смешивать «к прошлому периоду» и «к норме» в одном вердикте (§9.1).
- НЕ переворачивать знак только в правиле раскраски (§9.2).
- НЕ назначать порог, не посчитав, сколько раз он сработал бы на истории (§9.5).
- НЕ считать «на текущем периоде ничего не изменилось» доказательством безопасности правки правила (§9.8).
