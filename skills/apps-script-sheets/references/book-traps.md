# apps-script-sheets — ловушки самой книги

Часть Skill apps-script-sheets. Читать: перед правкой или сборкой формул витрины и перед любой работой с тяжёлой книгой, целиком, один раз за сессию. Номера параграфов — прежние, общие со SKILL.md; ссылки на параграфы других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

Редакция 2026-10-20.

## 3. ЛОВУШКИ САМОЙ КНИГИ

**Закон раздела: книга Google Sheets ошибается молча.** Почти каждая ловушка ниже кончается не ошибкой в ячейке, а правдоподобным неверным числом: нулём вместо «данных нет», пустотой вместо «нет доступа», первой из двух строк, соседней колонкой, одним значением на всю колонку. Формула, которая не показала `#ERROR!`, ничего не доказала. Поэтому после любой правки формул результат читается и сверяется с тем, что обязано получиться (сверка — SKILL.md §4.5, контрольный пример — в конце этого раздела), а не принимается по отсутствию ошибки.

### 3.1. Управляющие ячейки живут где угодно

Ячейки, на которых держится аналитический слой книги — начало и конец периода, числовой параметр, — могут стоять в любой колонке любого листа, в том числе на листе, который выглядит пустым. Лист выглядит пустым, когда прочитан диапазоном у́же самого листа: ячейка в колонке K не попадает в чтение `A1:J24`.

Стирание такой ячейки идёт по цепочке без единой ошибки: границы периода обнулились → формулы `FILTER`, которые на них ссылаются, перестают отдавать строки → лист, который они наполняют, пустеет → обнуляются все листы, которые считаются из него.

Правило: «лист пуст, можно занимать» не выводится из прочитанного диапазона — сначала карта ссылок на лист (SKILL.md §0.1, `findRefs` — §4.6) и чтение шире, чем кажется нужным (SKILL.md §1, шаг «Разведка»). Решение для своей книги — зона параметров в первых строках листа, которая не очищается ни при какой операции, со сводным экраном ниже неё: правило в SKILL.md §4.2.
Признак: после перестройки одного листа обнулились другие листы, ошибок формул нет.
Основание: 1 случай, последний не позднее 2026-09-26 — отчёт синтеза, правило ASS.3.1.

### 3.2. Затраты хранятся со знаком минус

В витринах Андрея комиссия, логистика, хранение, штрафы и себестоимость лежат отрицательными числами. Отсюда одно правило направления для светофоров и дельт: **ухудшение = отрицательная дельта, для всех строк без исключения**. Отдельная ветка «для затрат наоборот» не пишется: при минусовом знаке затрат она переворачивает смысл дважды и красит рост затрат зелёным.

Исключение — строки, где рост означает ухудшение: §9.2.
Признак: светофор зелёный на росте затрат.
Основание: 1 случай, последний не позднее 2026-09-26 — отчёт синтеза, правило ASS.3.2.

### 3.3. Пустое окно SUMIFS возвращает 0, а не пусто

`SUMIFS` по окну, в котором нет ни одной строки, возвращает 0. Ноль и «данных нет» — разные вещи: будущие недели понедельной витрины показывают нули, и любой график обрывается в ноль на последних колонках.

**Решение:** каждую формулу периода оборачивать в проверку по ОБЕИМ границам данных — и по последней дате, и по первой:

```
=IF(OR(B$3<FIRST_DATA_DATE,B$3>LAST_DATA_DATE),"", <исходная формула> )
```

Левая граница нужна не меньше правой. Гард только по последней дате оставляет нули во всех периодах ДО начала реальных данных; ряд наполовину из нулей, отданный в бэктест порогов (§9.5), даёт пол материальности 0 ₽ — то есть пол, который не гасит ничего.
Основание: 2 случая, последний в сентябре 2026 (день не записан) — отчёт синтеза, правило ASS.3.3.гард.

Вторая ловушка того же места: в Google Sheets `""=0` даёт `FALSE`. Знаменатель проверять И на пустую строку, И на ноль, иначе деление на пустую строку даёт `#DIV/0!` на всех будущих периодах.
Основание: 1 случай, последний не позднее 2026-09-26 — отчёт синтеза, правило ASS.3.3.пустая.

Третья ловушка знаменателя: `AND` и `OR` вычисляют ВСЕ аргументы, а не останавливаются на первом ложном. Защита вида `AND(E>0, R/(F/E)>порог)` при E=0 даёт `#DIV/0!` всей формуле, а внутри цепочки `IF` — и всем следующим веткам. Деление ставить только в ветку `IF` после проверки:

```
=IF(IF(AND(N(E11)>0,N(F11)>0),R11/(F11/E11),0)>P_LOG, "логистика дорога для цены", … )
```

Признак: `#DIV/0!`, хотя проверка знаменателя в формуле стоит.
Основание: 1 случай, последний 2026-09-28 — отчёт синтеза, правило ASS.3.3.AND.

`N()` вокруг проверяемых ячеек нужен, если там может стоять пустая строка из формулы: по правилу сравнения Google Sheets текст больше любого числа, поэтому `"">0` должно давать TRUE, и проверка пропустит пустоту к делению. В книгах Андрея это не проверялось; `N()` безвреден в любом случае. Где в проверяемых ячейках числа, записанные скриптом, формула может стоять и без `N()`.
Основание: правило конструкции без случая отказа; происхождение — свойство сравнения Google Sheets, в книгах не проверено; пример формулы без `N()` — отчёт синтеза, правило ASS.3.3.N.

### 3.4. Диапазоны с жёстким потолком

Формула, которая считает по `A3:A5000`, когда на листе 15 000 строк, недосчитывает сумму молча, без ошибки. То же у именованных диапазонов: диапазон до строки 50 000 на листе, который вырос дальше.

**Решение:** открытый диапазон от первой строки данных — вида `Лист!$P$2:$P`, без нижней границы. Первая строка — та, где данные реально начинаются, а не «на всякий случай» на строку ниже: диапазон с третьей строки при данных со второй теряет значение второй строки в каждом периоде, где оно стоит.
Если открытый диапазон где-то всё же неприменим — потолок брать с запасом от `getMaxRows()` и сверять сумму диапазона с суммой всей колонки.
Не путать: «границу вычислять при каждом прогоне от `getLastRow()` и подставлять в текст формулы» — на деле `getLastRow()` возвращает последнюю строку с содержимым по мнению Google и на листе, который заполняет формула-разлив (`FILTER`), занижает её в разы; вычисленный так потолок молча недосчитывает.
Признак: суммы тихо меньше, чем в источнике.
Основание: 4 случая, последний 2026-09-28 — отчёт синтеза, правило ASS.3.4.открытый.

**Построчные формулы не растут вместе с листом.** Формулы, стоящие в каждой строке отдельно, кончаются там, где их когда-то протянули. Строки, добавленные внизу листа или вставленные в середину, приходят без формул: значение в них пусто, `SUMIFS` считает пустоту нулём, и итог искажается молча. Добавить строки мало — нужно продлить формулы. Долговременное лечение: одна `ARRAYFORMULA` в первой строке данных на всю колонку с открытым диапазоном — тогда рост данных не требует ручных действий.
Признак: новые строки листа без значений расчётных колонок, итог (например прибыль) завышен или занижен без ошибки.
Основание: 2 случая, последний 2026-10-02 — отчёт синтеза, правило ASS.3.4.построчные.

**Лист-хаб: колонки только в конец.** На лист, на который другие книги ссылаются по адресам ячеек (через `IMPORTRANGE` с адресом вида `Лист!X2:X`), колонки в середину не вставляются: внешняя ссылка — это текст адреса в чужой книге, вставка его не сдвигает, и чужая формула начинает читать соседнюю колонку. Новую колонку добавлять последней. Построчные формулы и диапазоны с жёстким потолком на вставленные строки тоже не распространяются (абзацы выше).
Признак: формула в другой книге читает соседнюю колонку.
Основание: 1 случай, последний 2026-10-03 — отчёт синтеза, правило ASS.3.4.хаб.

**Зеркало из склейки `IMPORTRANGE` имеет две границы.** Первая — сетка листа (число строк и колонок), вторая — последний диапазон, жёстко записанный в формуле склейки. Реальная граница — меньшая из двух. Автоматическое расширение сетки снимает только первую; рост источника за вторую не попадает в зеркало без ошибки. При росте источника проверять обе.
Признак: зеркало перестало расти, ошибки нет.
Основание: 1 случай, последний 2026-10-05 — отчёт синтеза, правило ASS.3.4.зеркало.

**Чужие именованные диапазоны** (те, в которые пишет n8n) расширяются только отдельным пунктом меню и по явному решению, никогда заодно с оформлением.
Основание: правило конструкции без случая отказа; происхождение — первая редакция Skill 2026-09-26 (коммит зеркала 93d9de6) — отчёт синтеза, правило ASS.3.4.чужие-имена.

### 3.5. Один источник ≠ все статьи

Лист, который считает статьи расходов из одного источника, видит только те категории, что в этом источнике есть. Если источник содержит только строки продаж, статья «Хранение», которая приходит отдельной категорией в другом листе, будет структурно всегда нулём.

Правило: прежде чем чинить «странный ноль», проверить, есть ли для этой статьи источник в этом листе вообще.
Признак: статья всегда ноль, во всех периодах.
Основание: 1 случай, последний не позднее 2026-09-26 — отчёт синтеза, правило ASS.3.5.

### 3.6. ARRAYFORMULA не разворачивает MAXIFS

`MAXIFS`, `MINIFS` и подобные агрегаторы с условиями внутри `ARRAYFORMULA` не считаются построчно, а возвращают ОДНО значение на всю колонку — без ошибки и без предупреждения. Если так ищется «значение на дату» (например дата действующей закупочной цены), каждая строка получает одну и ту же дату, и всё, что считается от неё, неверно: товары с историей позже этой даты получают ноль, остальные — значение на эту дату.

**Признак:** колонка одинаковых чисел там, где они обязаны различаться.

**Решение:** «значение на дату» по строкам считать скриптом и писать значениями — так считают книги-образцы по сырым данным (references/samples.md, §8), у которых сверка с источником (SKILL.md §4.5) дала 0,00. Вариант формулой через `BYROW` или `MAP` с `LAMBDA` в книгах Андрея не проверялся: применять только после сверки с расчётом скрипта на тех же строках.
Основание: 1 случай, последний 2026-09-28 — отчёт синтеза, правило ASS.3.6.

### 3.7. Тяжёлая книга: flush, чтение после записи, снимок, предел ячеек

Тяжёлая книга — та, где пересчёт идёт минутами: десятки листов, несколько листов по десяткам тысяч строк с массивными формулами, зеркало через `IMPORTRANGE`. Какие книги Андрея тяжёлые — сказано в каноне их проектов, не здесь. В тяжёлой книге четыре вещи, безобидные в лёгкой, срывают прогон или запись:

1. **`SpreadsheetApp.flush()` гарантированно даёт `Service timed out: Spreadsheets`.** Причина не в объёме вызова: flush ждёт, пока книга закончит ВЕСЬ отложенный пересчёт. Следствие: определять что-либо опытным зондом, который пишет в книгу и ждёт результата, здесь нельзя — только чтением того, что в книге уже записано и уже считается правильно. Как так определить разделитель формул — SKILL.md §4.8.
   Основание: 1 случай, последний 2026-09-27 — отчёт синтеза, правило ASS.3.7.flush.
2. **Чтение после записи** (механизм и правило — SKILL.md §4.8) здесь упирается в потолок выполнения: каждое чтение после записи стоит пересчёта всей книги. Признак — `Exceeded maximum execution time`, иногда без указания на функцию в стеке; диагноз по одному логу не ставится.
   Не путать: та же ошибка бывает модальным окном, которое ждёт нажатия «ОК» (SKILL.md §2.2), а не чтением после записи. При повторе ошибки сначала исключить модальное окно; механизм сброса записей при чтении от этого не отменяется.
   Основание: 2 случая, последний 2026-09-27 — отчёт синтеза, правило ASS.3.7.чтение.
3. **Снимок листа средствами Apps Script неисполним**: он читает лист целиком и в потолок выполнения не укладывается. Чем его заменить — SKILL.md §4.3.
   Основание: 1 случай, последний 2026-09-27 — отчёт синтеза, правило ASS.3.7.снимок.
4. **Предел книги — 10 миллионов ячеек.** Google Sheets считает сетку всех листов книги — строки × колонки, пустые строки и колонки сетки тоже, а не только заполненные. У предела книга не принимает новых ячеек, и робот n8n, который дописывает строки, перестанет их дописывать. Размер сетки каждого листа даёт `gsheets-read` в режиме `meta`; у книги, которая растёт каждую неделю, сумму сеток листов сверять с пределом и считать запас в неделях. Освобождает место удаление листов, которые никто не читает; удаление листа необратимо для живой книги, поэтому сначала делается архивная копия книги, а само удаление решает Андрей.
   Признак: книга, куда дописывают сырые данные, перестала принимать строки; сумма сеток листов близка к 10 000 000.
   Основание: 1 случай, последний 2026-10-17 — отчёт синтеза, правило ASS.3.7.предел.

Ложная ошибка «Document … is missing» при обращении к тяжёлой книге — симптом инструмента чтения, не этой книги: `google-drive-docs`, references/sheets.md, §4.0.

**Практический вывод.** Новая книга не читает расчётные листы тяжёлой книги вовсе, а берёт сырой источник и минимум справочных листов. Даже чтение одного справочного листа тяжёлой книги может съесть потолок выполнения; справочный лист, который нужен постоянно, держать копией в лёгкой книге. Если книге всё же нужен расчётный лист тяжёлой книги — только отдельным пунктом меню (SKILL.md §4.7).
Признак: прогон книги через раз падает по шестиминутному потолку, и последний записанный шаг журнала стоит прямо перед чтением тяжёлой книги.
Основание: 2 случая, последний 2026-10-18 — отчёт синтеза, правило ASS.3.7.источник.

### 3.8. Колонку, которую заполняет формула, не писать значениями

В колонку, которую заполняет формула — `ARRAYFORMULA`, `IMPORTRANGE`, `FILTER` или построчная формула, — значения не пишутся ни скриптом, ни n8n, ни руками:
- запись в зону разлива массивной формулы ломает её: формула показывает `#REF!` («массив не может быть развёрнут, так как перезапишет данные»);
- число, вписанное поверх построчной формулы, молча расходится с ней: ячейка больше не считается, а выглядит как остальные.

**Правило:** перед любой записью в существующую колонку прочитать её через `gsheets-read` с `render:"FORMULA"` и убедиться, что там значения, а не формулы (как читать книгу перед правкой — SKILL.md §1, шаг «Разведка»). Колонку, которую дописывает робот, строить без формул: вычисление — либо в роботе, либо в отдельной колонке правее, куда робот не пишет; сигнал по таким строкам — условным форматированием, а не формулой в колонке робота.
Узел Google Sheets в n8n при добавлении строк считает ячейку с формулой занятой даже при пустом результате и дописывает ниже конца разлива — механика узла: `n8n-engineering-manual`, references/roots.md, правило R6.6.
Признак: `#REF!` в массивной формуле после записи; робот дописывает строки далеко ниже данных.
Основание: 1 случай, последний 2026-09-30 — отчёт синтеза, правило ASS.3.8.

### 3.9. Ключ сравнения: один тип с обеих сторон и уникальность

**Тип.** Ключ, который в одном источнике хранится числом, а в другом текстом (`1058.0` против `1058`, число против ячейки в текстовом формате `@`), не совпадает ни разу и без ошибки. При обновлении-вставке по такому ключу вместо обновления появляются дубли. Перед сравнением обе стороны приводятся к одному типу — в формулах (`TO_TEXT` с обеих сторон) и в узлах n8n (`n8n-engineering-manual`, references/roots.md, правило R6.8).
Признак: сверка по ключу даёт ноль совпадений, или обновление-вставка плодит дубли.
Основание: 2 случая, последний 2026-10-04 — отчёт синтеза, правило ASS.3.9.тип.

**Уникальность.** Если у ключа в источнике две строки, `VLOOKUP` молча берёт первую, и сверка выдаёт ложное «расходится». Перед построением сверки по ключу проверить источник на повторы: `=COUNTA(A2:A)-COUNTUNIQUE(A2:A)` обязано дать 0.
Признак: ложное «расходится» у одного ключа.
Основание: 1 случай, последний 2026-10-04 — отчёт синтеза, правило ASS.3.9.уникальность.

**`IFERROR` прячет причину пустоты.** Формула вида `IFERROR(VLOOKUP(ключ;IMPORTRANGE("<ID книги>";"Лист!A2:E");5;FALSE);"")` показывает пустую ячейку без ошибки в двух случаях, которые на глаз неотличимы:
1. книге не выдан доступ к другой книге: `IMPORTRANGE` отдаёт ошибку «нужно разрешение», `IFERROR` её глотает, и кнопка «Разрешить доступ» не появляется никогда;
2. ключ в одной книге число, в другой текст: `VLOOKUP` не находит совпадения.

Порядок: доступ выдавать отдельной ячейкой без `IFERROR` — `=IMPORTRANGE("<ID>";"Лист!A1")`, нажать «Разрешить доступ», затем очистить ячейку; ключи с обеих сторон приводить к тексту через `TO_TEXT`; после вставки формулы читать результат через `gsheets-read`, а не довольствоваться отсутствием ошибки.
Признак: новая формула пуста во всех строках, ошибки нет.
Основание: 1 случай, последний 2026-10-04 — отчёт синтеза, правило ASS.3.9.IFERROR.

### 3.10. Склейка цепочек IMPORTRANGE — по ключу, не по номеру строки

Две цепочки `IMPORTRANGE`, поставленные рядом, совпадают построчно только до первого расхождения в числе или порядке строк; дальше строка получает данные чужого товара. Соседние данные из другой цепочки подтягивать по ключу (артикулу) — `VLOOKUP` или `XLOOKUP` с ключом по правилам §3.9, — а не ставить рядом.
Признак: у товара чужой номер или чужое значение из соседней цепочки.
Основание: 1 случай, последний 2026-10-06 — отчёт синтеза, правило ASS.3.10.ключ.

`FILTER`, которому не хватает строк листа, отдаёт ошибку «Result was not automatically expanded, please insert more rows». Обёртка `IFERROR` превращает её в пустоту: например себестоимость становится нулём, прибыль завышается молча. `IFERROR` вокруг `FILTER` оставлять только с проверкой числа строк: сколько строк в источнике прошло условие и сколько вывелось — в отчёт или в контрольную ячейку рядом.
Признак: себестоимость (или другая статья) ноль, итог завышен, ошибки нет.
Основание: 1 случай, последний 2026-09-28 — отчёт синтеза, правило ASS.3.10.FILTER.

### 3.11. Сравнение текста: регистр и пустая строка

- `SUMIFS` и `COUNTIFS` регистр не различают («FBS» = «Fbs»); `QUERY` и сравнение `=` различают. Колонка с двумя написаниями одного значения даёт разные итоги в разных формулах. Лечение — привести написание к одному в источнике, а не подбирать функцию под данные.
  Признак: итоги по одной категории расходятся между формулами.
  Основание: 1 случай, последний 2026-09-28 — отчёт синтеза, правило ASS.3.11.регистр.
- `COUNTIFS(диапазон;"<>")` считает непустой и пустую строку `""`, которую вернула формула. Пустые по смыслу ячейки, заполненные формулой, считать через `SUMPRODUCT(LEN(диапазон)>0)`.
  Основание: правило конструкции без случая отказа; происхождение — харвест 2026-10-08, находка Б4 (коммит зеркала 217f03c) — отчёт синтеза, правило ASS.3.11.пустая.

### 3.12. Колонка по заголовку: заголовок обязан встречаться один раз

Скрипт, который читает лист-источник, находит колонку по тексту заголовка, а не по номеру: книга скрипту не принадлежит (SKILL.md §1), и колонку, вставленную руками, номер не заметит. Но `headers.indexOf(имя)` при двух одинаковых заголовках молча берёт левый, а нужным может быть правый. Узел чтения Google Sheets в n8n на тех же дублях поступает наоборот — берёт правый (`n8n-engineering-manual`, references/roots.md, правило R6.4): один и тот же лист два читателя понимают по-разному.

Правило: колонку искать функцией, которая падает, если заголовок найден не ровно один раз; сравнение — по тексту без пробелов по краям.

```javascript
function colByHeader_(headers, name) {
  var hits = [];
  headers.forEach(function (h, i) { if (String(h).trim() === name) hits.push(i); });
  if (hits.length !== 1) throw new Error('Заголовок «' + name + '» найден ' + hits.length + ' раз, колонки: ' + hits.map(function (i) { return i + 1; }).join(', '));
  return hits[0];
}
```

Если дубль в источнике убрать нельзя (лист ведёт не скрипт), нужная колонка задаётся номером — и номер проверяется при каждом прогоне: заголовок по этому номеру равен ожидаемому, а число одноимённых заголовков равно известному. Не совпало — шаг падает (§4.4 SKILL.md), а не читает соседнюю колонку. Голый жёсткий номер без такой проверки ломается при первой вставке колонки (§3.4).
Признак: колонка прочитана не та, ошибки нет; в шапке источника два одинаковых заголовка.
Основание: 1 случай, последний 2026-06-30 — отчёт синтеза, правило ASS.3.12.

### Контрольный пример главной таблицы

У главной таблицы — таблицы товарных данных, которую читают все, и таблицы деклараций — записывается контрольный пример с известным ответом и счётные проверки: значение у одного известного ключа, число строк против числа строк источника, построчное совпадение ключей с источником. Перед тем как строить что-либо на чтении такой таблицы, прогнать проверки; не прошли — дальше не читать и сообщить Андрею. Новую главную таблицу заводить сразу с таким примером.
Почему: тихо неверные данные главной таблицы (закон раздела) расходятся по всем её читателям; известный ответ ловит сдвиг, который не даёт ни одной ошибки.
Где записаны сами проверки: у таблицы товарных данных — `meta/PRODUCT_DATA_HIERARCHY.md`, раздел 6; у реестра деклараций — `meta/DECLARATION_SCAN.md`, абзац «Признаки поломки». У новой главной таблицы — в каноне её проекта.
Основание: 1 случай, последний 2026-10-06 — отчёт синтеза, правило ASS.3.контроль.
