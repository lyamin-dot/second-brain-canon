## Витрины юнит-экономики («норма → отклонение → светофор»)

### Знак и направление

- Затраты (комиссия, логистика, хранение, штрафы, себестоимость) в витринах хранятся отрицательными. Ухудшение = отрицательная дельта для всех строк; ветку «для затрат наоборот» не писать.
- Строки, где рост — ухудшение (возвраты, доля удержания, брак), помечаются флагом, и знак переворачивается в самой формуле отклонения, не в цвете. Тест: период с идеальным результатом (ноль возвратов) обязан дать положительное отклонение.

```javascript
function devRub_(r) {
  var body = '$B' + r + '-$F' + r;
  return '=IF(OR($B' + r + '="",$F' + r + '=""),"",' +
         (sig_(r).inv ? '-(' + body + ')' : body) + ')';
}
```

### Сигнал витрины

Сигнал отвечает на вопрос «этот период отличается от обычного?»; красный читается как «стало хуже».

1. **Одна база на вердикт:** все критерии одного сигнала сравнивают с одной базой; при разборе первым делом — на какую колонку смотрит каждый критерий.
2. **Две семьи строк:** масштабируемые (себестоимость, логистика, приёмка, эквайринг, комиссии, удержания) — долей от драйвера (обычно выручки), отклонение в п.п.; драйвер — тот, который не содержит другую проблему. Немасштабируемые и итоги (хранение, штрафы, разовые списания, прибыль, маржа, средний чек) — абсолютом в % от нормы. Итог в семью «доля» не переводить.
3. **Пол материальности** — одна абсолютная сумма на книгу, мельче — не окрашивается; **порог красного** — построчный, в единицах семьи. Абсолютный порог долей от нормы строки не назначать. Зелёный — не хуже нормы либо хуже, но мельче пола; жёлтый — хуже заметно; красный — хуже сверх порога строки.
4. **Порог — прогоном по истории, не на глаз:** (1) собрать ряд из понедельного листа — значение и норма на тот момент; норму воспроизводить точно как книга и сверить с живым значением последнего периода (расхождение больше пары процентов — модель не та); (2) отбросить периоды без полного окна нормы; (3) прогнать сетку кандидатов — таблица «кандидат → красных / жёлтых / зелёных»; (4) взять значение на плато. Ориентир: 4–7 красных на 24 периода. В документацию по каждому порогу: число, сколько раз сработало бы, плато, какую аномалию поймало.
5. **Где хранить пороги:** пороги сигнала — в коде; пороги тревог — построчными колонками «порог ₽» и «порог %» в ячейках, со ссылкой на общее значение по умолчанию, пустой порог — критерий не применяется; переживают пересборку по ключу.
6. **Скользящая норма:** в пояснении на витрине написано «зелёный — как в последние N периодов, а не „хорошо“».
7. **Цвет и деньги рядом:** абсолютная сумма отклонения — отдельной колонкой, по знаку, рядом с сигналом; короткое пояснение под блоком и лист-руководство из массива в коде с разделом «разбор по следу» («итог ниже нормы» → приход выше/ниже нормы → удержания / объём и цена).
8. **Правка правила:** прогнать старый и новый вердикт по всей истории и выписать периоды, где они разошлись.
9. **Неполный закрытый период:** книга считает число дней с данными в каждом закрытом периоде; дней меньше календаря — отдельная строка в тексте тревоги «в неделе такой-то нет данных за N дней». Текущий незакрытый период — не сбой.

### Оформление витрины

- Цветовая шкала — построчно, крайние точки — перцентили 10/50/90.
- Дельты в рублях — цветом текста по знаку, без заливки; дельты в процентах — расходящаяся заливка с краями −20% … 0 … +20%, только по колонке с одной единицей.
- Проценты и процентные пункты — разными форматами: `'+0.0" п.п.";-0.0" п.п.";0.0" п.п."'` против `'+0.0%;-0.0%;0.0%'`.
- В текст тревоги — величина в одной единице для всех строк (обычно деньги).
- Спарклайн — из понедельной витрины через `OFFSET` по счётчику недель, с `ARRAYFORMULA(ABS(...))`, в локали книги:

```
=IFERROR(SPARKLINE(ARRAYFORMULA(ABS(OFFSET(weekly_history!$A$5,0,MAX(1,WEEKS_N-12),1,MIN(13,WEEKS_N)))),
  {"charttype","line";"color","#5B8FF9";"linewidth",2;"empty","ignore"}),"")
```

- Графики — по отдельному транспонированному блоку (`TRANSPOSE`) внизу дашборда; ряды фильтровать по наличию данных; ряды с разными базами в стопку не складывать.
- Порядок колонок витрины — одним списком букв (`var MIRROR_COLS = ['A','B','C','E','F','D','G','H'];`); менять вместе с ним шапку блока, числовые форматы и адреса цветовых правил.
- Лист-источник витрины не переставлять: на его колонки ссылаются тексты тревог и плитки.
- Именованные ячейки для курьера Telegram — тексты (например `TG_WEEKLY_TEXT`, `TG_ALERT_TEXT`), метка прогона, последняя дата данных.

## Книги по сырым данным (лаборатория юнит-экономики Ozon)

- Скрипт читает сырой источник и справочники, сворачивает в памяти, пишет факты значениями, а что-если, распределение расходов и диагнозы — формулами поверх фактов.
- Раскладка каждого листа: строки 1–8 — инструкция (вопрос, решение, источник, формулы, чего не знает, что-если), строка 10 — шапка, данные с 11-й.
- Закрепление: только строки до шапки включительно, колонки не закреплять, строки инструкции собрать в группу; снимать закрепление и группу первым шагом пересборки, ставить последним.

```javascript
var HEAD_ROW = 10;          // строка шапки; строки 2–8 — инструкция листа
function unfreeze_(sh) {    // ПЕРВЫМ при пересборке: иначе глубина группы растёт с каждым запуском
  sh.setFrozenRows(0); sh.setFrozenColumns(0);
  var g = sh.getRange('2:8');
  for (var i = 0; i < 5 && sh.getRowGroupDepth(2) > 0; i++) g.shiftRowGroupDepth(-1);
}
function freezeHead_(sh) {  // ПОСЛЕДНИМ, когда лист построен
  sh.setFrozenRows(HEAD_ROW);
  sh.getRange('2:8').shiftRowGroupDepth(1);
}
```

- Пустая жёлтая ячейка — «как в фактах», очистка ячейки возвращает к фактам; ручной ввод возвращается по ключу.
- В отчёте прогона — время шагов, число строк источника, границы периода и сверка: сумма свёрнутого минус сумма источника по денежной колонке = 0,00 — формулой в самой таблице, с `ROUND(…;2)`, по всем неделям, где есть данные; и каждая статья книги — отдельно со строкой внешнего отчёта площадки (сверка итога разнесение по статьям не доказывает).
- Лист «что-если» проверять дважды: с пустым вводом (совпадает с фактами) и с заполненным.
- «Значение на дату» по строкам (дата действующей закупочной цены) — считать скриптом и писать значениями; `BYROW`/`MAP` с `LAMBDA` — только после сверки с расчётом скрипта на тех же строках.

## Книги сверки (источник против кабинетов)

- Каждый сверяемый параметр — в нескольких колонках подряд: «истина» (из документа-источника), «указано в первом кабинете», «указано во втором кабинете»; значение площадки в колонку истины не пишется. Это пример, не общее правило.
