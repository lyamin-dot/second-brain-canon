## 0. Две аксиомы

Всё остальное в этом файле — частные случаи двух утверждений. Если правило ниже кажется странным, оно выводится из одной из этих аксиом; если новый факт не выводится ни из одной — это кандидат в новый корень.

### A1. Ни один отчёт инструмента не является доказательством состояния

Доказательство существует в двух видах и только в двух: **объект воздействия** (строка появилась в целевой таблице, изменился Doc, выросла таблица в БД) и **факт исполнения** (`get_execution` по реальному прогону). Всё прочее — отчёт инструмента о себе, а не о системе.

Наблюдавшиеся частные случаи — все до единого приводили к ложному выводу:

| Отчёт, который врёт | Что он на самом деле значит | Корень |
| :-- | :-- | :-- |
| MCP пишет «...credentials must be configured manually» | Безусловный шаблонный текст, печатается всегда | R1a |
| `get_workflow_details` не показывает поле `credentials` | Инструмент не возвращает его НИКОГДА, ни на одной HTTP/Sheets-ноде | R1a |
| `validate_workflow` и `update_workflow` прошли без ошибок | Схема валидна; применились ли параметры — неизвестно | R1b |
| `active: true` | Что-то исполняется; совпадает ли оно с видимым в редакторе — неизвестно | R2 |
| execution со статусом `success` | Движок не упал; данные могли не записаться | R4 |
| Имя параметра в JSON | Не описывает семантику флага, иногда описывает выключенное состояние | R17 |
| `description` воркфлоу | Гипотеза автора о воркфлоу, не его поведение | §9 |
| Веб-сниппет, память сессии, вчерашний ID | Кэш неизвестного возраста | §9 |

Практическое следствие для диагностики: **диагностика по факту исполнения всегда приоритетнее диагностики по конфигурации.** Читать `get_execution` и объект воздействия прежде, чем строить гипотезы по `get_workflow_details.nodes` и по тексту предупреждений.

### A2. Штатный режим отказа n8n — тишина, а не ошибка

Для движка «ноль items», «поле пропущено», «параметр не применился» — не аварии, а нормальные исходы. Ошибка приходит громко; потеря приходит молча. Поэтому каждая запись и каждая правка требуют отдельной сверки того, что предполагалось изменить.

| Что теряется молча | Корень |
| :-- | :-- |
| Вся цепочка ниже, если на ноде 0 items | R3 |
| Сбойный item на `continueErrorOutput` с неподключённым output(1) | R5 |
| Поле, которому передан `null`, при Sheets `appendOrUpdate` | R6 |
| `maxTries` / `waitBetweenTries`, записанные через SDK | R1b |
| Ветка IF/Switch и fx-режим выражения после `update_workflow` | R1b |
| Третий вход Merge при `numberOfInputs` по дефолту | R9 |
| Items, не попавшие ни в одну ветку Switch без fallback | R8 |
| Item, прошедший сквозь disabled-ноду | R3 |
| Второй триггер одного типа при вызове через MCP | R10 |
| Строки при type-несоответствии в `matchingColumns` (вместо дублей — не ошибка) | R6 |

## 1. Инфраструктура

| Параметр | Значение |
| :-- | :-- |
| URL | https://liamin-n8n.duckdns.org |
| Версия n8n | 2.20.9 (self-hosted, Docker Compose) |
| Timezone сервера | Europe/Berlin |

Версия важна не сама по себе: на 2.20.9 недоступен `setWorkflowSettings.errorWorkflow` (§8) и сломана Raw-сериализация динамического тела HTTP (§4.8). Timezone сервера — причина R7.

Номер версии здесь набит руками и сессией не проверяется: MCP его не отдаёт. На нём висят два правила сразу, поэтому при первом же расхождении поведения с §8 или §4.8 версию перепроверять в UI, а не считать написанное здесь фактом.

Инвентарь подключений (ID таблиц, Client-Id, параметры credential, состояние pgvector) — **n8n-workflow-registry**, здесь не дублируется. Одно исключение, потому что ошибка необратима и стоит переиндексации: embedding-модель для `liquimoly_kb` — `voyage-3` (1024d), НЕ `voyage-3-lite` (512d).

### 1.1 Webhook — никогда через curl/bash

Egress proxy блокирует домен `liamin-n8n.duckdns.org`. Единственный путь — `n8n:execute_workflow` через MCP. Формат: `inputs.type=webhook`, `inputs.webhookData.method=POST`, `inputs.webhookData.body={...}`. Любой другой формат (например `payload` вместо `webhookData`) даёт молчаливый `status:error`.

**`executionMode` — только `manual`.** В `production` webhook-воркфлоу не создаёт видимого execution: ни `get_execution`, ни `search_executions` его не находят, тело ответа не возвращается. Наблюдаемость есть только в manual *(→ R4)*.

`get_execution` требует ОБА параметра — `workflowId` и `executionId`. Без `workflowId` сервер отдаёт «not found» даже для реального успешного прогона в любом режиме, включая manual. Симптом неотличим на глаз от истинной нетрейсируемости R4, поэтому прежде чем записать «not found» как подтверждение R4 — проверить, что переданы оба параметра.

## 3. Соглашения именования

- Воркфлоу: `[Источник] [Тип] [Действие]` — WB RAW Finance Sync, Ozon Reviews Response.
- Ноды: `NN_Название` (двузначный номер). Параллельные ветки — `06A_`, `06B_`.
- Google Sheets: snake_case — wb_raw_report_V2, sku_category_history.
- `raw_key` — композитный ключ строки RAW, свой на каждый источник. Форматы намеренно разные, RAW-слои не объединяются, сравнение между источниками — по Артикулу. Конкретные формулы ключа по источникам и эндпоинтам — n8n-workflow-registry §3.

## 8. Неустранимые особенности платформы

Дизайном не убираются, помнить.

- **`EXECUTIONS_DATA_PRUNE`** обязателен (иначе ~93MB/день); `SAVE_ON_SUCCESS=none` — следствие для отладки *(R4)*.
- **Второго канала верификации записи не существует.** Воркфлоу append/replace/overwrite перечитывают файл у себя в коде, но при production-запуске через MCP ответ до вызывающего не доходит, а `get_execution` по такому запуску отдаёт «not found». Не путать «в коде есть read-back» с «я видел результат read-back» *(A1)*.
- **`setWorkflowSettings.errorWorkflow`** доступен только с 2.29.0+. Следствие измерено 2026-09-26 по строкам W файла `registry/n8n-map.md`: из 91 активного воркфлоу `errorWorkflow` не задан у 67. Если смотреть только на те, что реально тикают по расписанию (39 штук; ещё 20 активных расписаний припаркованы интервалом в 100 месяцев и более), то `errorWorkflow` отсутствует у 26 из 39, явная таймзона — у 32 из 39, и ни того, ни другого нет у 25. Правило T2 слой 4 и гейт T4 качество 8 описывают, как должно быть; состояние инстанса другое, и ссылаться на них как на факт нельзя. Числа выводятся заново: поля 8 и 10 строки W (таймзона и errorWorkflow).
- **Drive MCP `create_file`:** write-scope периодически отваливается → создать Doc вручную, заполнить через gdocs-overwrite (независимый OAuth); переподключение коннектора — только в новой сессии.
- **Файл, куда пишет сервис-аккаунт, должен быть ему расшарен (Editor).** Иначе `success:false`, `bytesRead:0`, «file not found OR not shared to SA». Проверять `get_file_permissions` ДО первой записи.
- **Квота Sheets — на потребителя credential, не на воркфлоу** *(R6)*.

## 9. Принципы проектирования

Не правила механики (те в §4–§6), а решения о форме системы.

- **RAW first, separation of concerns.** RAW ≠ аналитика, разные слои и разные воркфлоу.
- **Propose before implement.** Вариант на согласование раньше записи.
- **Параметры там, где используются** (sku_cost, а не общий CONTROL_PANEL).
- **Намерение должно читаться на графе.** Сознательный терминал ведёт в именованный NoOp, а не висит в пустоте; один путь лучше fan-in, который потом надо объяснять словами.
- **Узел выбирается по свойствам, а не по удобству**, когда воркфлоу существует ради конкретного ресурса (контекст, квота, память) — см. R4 про `contextData` и R6 про счётчик квоты.
- **Негативный тест на сбойный элемент ставить в СЕРЕДИНУ проверочного списка, не последним:** поставленный последним, сдвиг индексов не проявляется, и тест физически не может провалиться по нужной причине *(R5)*.
- **Правило Skill — рамка, а не закон.** Если рамку нужно сдвинуть и это обосновано — сдвигать, зафиксировав чем именно; стопориться на формулировке хуже, чем осознанно от неё отступить.
