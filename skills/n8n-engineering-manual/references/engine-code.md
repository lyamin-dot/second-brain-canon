## 4. Механика движка (продолжение): RAW-слой и Code-узел

**4.1 RAW-слой.** RAW = данные как есть, без фильтрации. Никогда не фильтровать по типу операции в RAW. Аналитика — только поверх RAW, отдельным слоем. Почему: отфильтрованное при загрузке уже не восстановить из своего слоя, а новый тип операции, о котором фильтр не знал, исчезает молча. [основание: ENG-01 · правило §4.1]

**4.2 Code node — форма.**

```js
const result = [];
result.push({ json: { field: value } });
return result;
```

**4.2.1 Режим выбирают по тому, чем пользуется код.** Run Once for All Items → `$input.all()` → массив (агрегация, expand). Run Once for Each Item → item (маппинг). `$json` и `$input.item` — режим «для каждого», `$input.all()` — режим «для всех».
- Почему: в режиме «для всех» `$json` не падает, а молча берёт первый элемент (три элемента на входе — код видит один из трёх).
- Обратная сторона: `$input.all()` в режиме «для каждого» падает ошибкой «Can't use .all() here».
- [основание: ENG-02 · правило §4.2.1]

**4.2.2 В Code-нодах внутри пайплайна ВСЕГДА spread: `({ ...src, newField })`.** Почему: item, собранный заново из перечисленных полей, теряет все неперечисленные — без ошибки *(A2)*. Признак: в целевой таблице появляются почти пустые строки, счётчики теряются молча. [основание: ENG-03 · правило §4.2.2]

**4.2.3 Полная замена кода при правке, не частичная.** Принятие предложенной замены — по §2.4 (дословный текущий код и построчное сравнение). [основание: ENG-04 · правило §4.2.3]

**4.2.4 Regex через SDK.** Литералы `\s \S \d \w` ломаются при записи через SDK → `var anyChar='[\\s\\S]'; new RegExp('...'+anyChar+'...')`. [основание: ENG-05 · правило §4.2.4]

**4.2.5 Внутри цикла SplitInBatches `throw` останавливает весь батч, а не одну строку.** Вместо `throw` — вернуть item со статусом ошибки и разобрать статус отдельной ветвью *(→ T3)*. Признак: один плохой элемент (например пустой ответ модели) прерывает обработку всей пачки. [основание: ENG-06 · правило §4.2.5]

**4.2.6 `axios`/`fetch` заблокированы** без `NODE_FUNCTION_ALLOW_EXTERNAL=axios` в .env и падают тихо. [основание: ENG-07 · правило §4.2.6]

**4.2.7 Встроенные модули Node** (например `crypto` для хэша) доступны в Code-узле только при переменной окружения `NODE_FUNCTION_ALLOW_BUILTIN`. Прежде чем строить на встроенном модуле — пробный прогон, который показывает, что модуль доступен; без такой пробы считать без встроенного модуля (хэш — чистым JavaScript). [основание: ENG-08 · правило §4.2.7]

**4.2.8 `$env` не работает вообще**, бросает в рантайме. [основание: ENG-09 · правило §4.2.8]

**4.2.9 Ключ доступа (credential) Code-узлу недоступен.** `this.helpers.httpRequestWithAuthentication` отвечает ошибкой «The function "helpers.httpRequestWithAuthentication" is not supported in the Code Node». Вызов с ключом — только отдельным узлом HTTP Request; `catch`, который не передаёт ошибку дальше, в Code-узле не ставить.
- Почему: `try/catch` вокруг такого вызова превращает отказ в зелёный прогон — вызова не было, а исполнение `success`.
- [основание: ENG-10 · правило §4.2.9]

**4.2.10 Память воркфлоу между прогонами (static data) меняется только в плановом прогоне.** Память, которую код ведёт через `$getWorkflowStaticData` («последняя отправленная неделя», «уже виденные ID»), сохраняется только в плановом прогоне опубликованной версии. Ручной и пробный запуск (`execute_workflow` в режиме `manual`, кнопка в редакторе) её изменений не сохраняет. Запуск боевым вебхуком не проверялся.
- Следствие 1: после ручного запуска сводки следующий плановый прогон пришлёт ту же сводку ещё раз. Это ожидаемое поведение, а не дефект: причину повтора не искать, владельца предупредить до ручного запуска.
- Следствие 2: «сдвинуть» память ручным пробным прогоном нельзя. Ручной прогон проверяет код, память проверяется плановым прогоном; где повтор сообщения недопустим, ручной пробный прогон не делается вовсе.
- Признак: повтор уже отправленного сообщения в первом плановом прогоне после ручного.
- [основание: ENG-11 · правило §4.2.10]
