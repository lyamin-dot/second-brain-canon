# Разметка переноса google-drive-docs, 2026-11-03

Источник: архив `skills/_v1/google-drive-docs/` (SKILL.md и references/: basis.md, docs-read.md, docs-write.md, failures.md, infra.md, mcp.md, sheets.md). Строки очереди для этого Skill нет: позиция AJ-72 закрыта, шаг 2 критериев называет только AJ-71, AJ-73, AJ-75, AJ-76 — из очереди ничего не забиралось. Новый Skill: `skills/google-drive-docs/SKILL.md` и один файл `references/sys-canary.md` (тип «Объект»: правило самопроверки пути записи). Процедуры П поместились в «Как делать».

Сокращения в колонке «Куда забрано»: ЧЧ — «Что читать»; СП/<группа> — «Стоп-правила», подраздел; КД/<подраздел> — «Как делать»; АЛ/<группа> — «Адреса и ловушки»; КП — «Куда писать результат»; n8n-маршрут — строка «ситуация → `n8n-engineering-manual`, раздел …» вместо дубля.

Как применялся признак (для проверки шага 4):
- С — любой запрет и любая обязательная проверка перед записью, перезаписью, удалением; правило вида «всегда X», у которого есть явная противоположность («только gdocs-read» ↔ «не read_file_content»), переписано запретом. «Обязательно дают пометку», «обязательно перечитать» — переписаны запретом. Протокол удаляющего replace разложен: запреты — СП, откат — КД.
- Ф-ловушка — вызов инструмента (коннектор Drive, воркфлоу gdocs-*, gsheets-*, Sheets API, rclone, Apps Script) прошёл без ошибки, а результат неверен: файл затёрт, дубль, обрезка, не тот лист, формула вместо текста, `#ERROR!`/`#NAME?` в ячейке; и случаи, где ошибка видна, но причина из неё не видна: «Document … is missing» у тяжёлой книги, 404/403 нерасшаренного файла, `success:false` при состоявшейся записи (`VERIFY-READ-FAILED`, `occurrencesChanged>0`, «content mismatch»), «does not exist» у ключа в кэше, 400 на весь `batchGet`, `invalid_grant` клиента «Testing», 503 тяжёлой книги, «Too Many Requests» при вызове, который мог уже записать. Видимая ошибка с видимой причиной («Missing folder_name or parent_id», «Column to Match On required», `REPLACE_ANCHOR_NOT_UNIQUE`, `SOURCE_NOT_ACCESSIBLE`, SERVICE_DISABLED, ошибка о триггере со списком триггеров, `whenFormula` — скрипт падает) — О; действие при ней, если оно есть, — П.
- П — операции нашей системы: поиск ID инструмента по строке реестра, вызов инструментов Google через n8n MCP, контракты и порядок работы gdocs-read, gdocs-append v2, gdocs-replace v2, gdocs-overwrite v2, gdocs-apply-from-file, Create Folder, gsheets-read, gsheets-append, порядок путей для большого текста, вопрос «обычный или красивый?», создание файла и книги для робота, диагностика двух путей доступа, сверка крупного документа, проверка копии и бэкапа, заливка Skill. Контракты инструментов-воркфлоу взяты как П (а не «Объект»): это вход в операцию системы, как маршрут Канала.
- П-соглашение — названа зависящая часть: «Лист — единица владения» (робот, пересобирающий лист целиком, и скрипт книги; на этот абзац ссылается `apps-script-sheets`).
- Объект — правило одного построенного воркфлоу: самопроверка пути записи (SYS Canary, по `registry/tools.md`) → `references/sys-canary.md`.
- Ф-адрес — имена воркфлоу инструментов (сопоставление «инструмент → имя воркфлоу» есть только в Skill, в реестре его нет) — одна таблица в КД/ID воркфлоу инструмента; ID, сигнатуры, GDOCS_APPLY_FROM_FILE, TEST_GDOCS_APPLY, строки C, ID документов — в реестре: одна строка «адреса — в реестре».
- М — маршруты в другие Skills и файлы, таблица «Быстрый выбор инструмента» (задача → инструмент), триггеры описания; n8n-маршруты вместо дублей (ниже, «Решения по n8n-engineering-manual»).
- О — устройство API Google, Drive, Apps Script, rclone и хорошие приёмы без зависящей части: синтаксис запроса search_files, `excludeContentSnippets`/`snippetVerbosity`, блок `<style>` вместо инлайн-стилей, имя без .txt, `copy_file` на 1–3 КБ больше, `verifiedBy` в `reason`, тире в якоре матчится штатно, ключ сервисного аккаунта не протухает, `whenFormulaSatisfied`, `FILTER` без OR, пауза 1–2 с между `batchUpdate`, apt-пакет rclone без Mega, конвертация PDF → Doc через Drive API v2, соотношения `fileSize` к экспорту (числа оставлены внутри строки ловушки как пример).
- И — «Почему», «Не путать» с прежней формулировкой, «Признак», [основание: …], редакции, даты, номера исполнений, «наблюдение не перепроверено» как история (там, где оно меняет доверие к ловушке, оставлено словами «не перепроверено»), ссылки на задачи `labs/…` как основание, весь basis.md, кроме раздела правил правки.
- Номерные перекрёстные ссылки (§3.2, E16, R6.7, T2 слой 3, 7.6, 8.3, Р15) не забирались: каждая мысль стоит один раз по месту действия, внутренние ссылки — по заголовку нового текста, ссылки на другие Skills — по имени Skill и заголовку раздела.

Решения по n8n-engineering-manual (правило уже стоит в новом SKILL.md того Skill — здесь маршрут, не дубль):
- вызов только `execute_workflow`, не curl/bash; форма `inputs`/`webhookData`/`formData` без `type`; имя триггера из `get_workflow_details` или `registry/tools.md`; `executionMode: "manual"`, production невидим; `get_execution` без `workflowId` — «not found»; верить ошибке сервера → ЧЧ, «Вызов воркфлоу из сессии» (СП и КД), «Инструменты MCP и отчёты»;
- `nodeNames`, `truncateData`, `tail` не режут `contextData` узла `httpRequest`; лечение утечки → ЧЧ, «Воркфлоу ради экономии контекста», «Инструменты MCP и отчёты»; частный факт «у gdocs-read и gdocs-apply-from-file узлы загрузки `httpRequest`» и порядок чтения статуса — забраны здесь (КД/Вызов инструмента Google п. 4), там их нет;
- версия, которую исполняет ручной запуск → ЧЧ, «Версии, публикация, редактор»; судьба ненужного воркфлоу → ЧЧ, «Снятие с публикации»; обрыв ответа создающего вызова → ЧЧ, СП «Запись и публикация воркфлоу»;
- привязка ключа сессией (`setNodeCredential`), публикация привязки, сверка `credentials`, новый узел без ключа (E12) → ЧЧ, «Ключи доступа», «После записи»; «после `update_workflow` ключ сбрасывается» → АЛ/Движок n8n, СП «Доказательство и состояние»;
- R6 узла Sheets: `autoMapInputData` и формула, колонка с формулой во входе, `appendOrUpdate` с явными `matchingColumns`, составной ключ, тип и чистота ключа, удаление строк и барьер, 429 → ожидание дольше минуты, порядок `batchGet` по полю `range`, шапка — договор с читателями → ЧЧ, «Google Sheets» (СП, КД, АЛ) и «Соглашения, от которых зависят другие части»;
- запасная константа и неизвестное значение (R19) → ЧЧ, «Неизвестное значение»; для Apps Script (`parseFloat(x)||0`) стоп и ловушка забраны здесь — там правило о листах n8n, не о скрипте;
- тихие отказы движка (production `started`, 0 items, disabled, `neverError`, триггер не тикает, потери записи кодом целиком, `.to([a,b])`, HTTP-узел заменяет `json`, `executeOnce`, смена типа ключа у узла Sheets в редакторе, поле выражения без `={{ … }}`) → АЛ/Движок n8n, три строки;
- `N8N_ENCRYPTION_KEY` вне бэкапа → ЧЧ, «Инструменты MCP и отчёты»;
- не стоит в n8n-engineering-manual и забрано здесь своим типом: «inputs, не data; POST явно» (Ф-ловушка), «не больше двух одновременных `execute_workflow`» (С), «при `running` новый вызов не запускать» (С), `handlingExtraData`, Refresh columns list, Limit после чтения, IMPORTRANGE > 18 000, `'A: field'`, тяжёлая книга узлом, именованные диапазоны и 400 на весь `batchGet`, `cellFormat` USER_ENTERED, «Column to Match On» не обходить переключением, «does not exist» в кэше ключа, ключ на всех узлах записи одним вызовом, повтор Drive/Docs/Sheets не больше 3 попыток. Противоречие: «ключ на всех узлах записи одним вызовом» против стоп-правила n8n «Миграцию ключа у многих узлов сразу не делать» и «больше трёх узлов — после подтверждения»; в новом тексте строка несёт ссылку на это стоп-правило, противоречие не снято (так было и в старом тексте).
