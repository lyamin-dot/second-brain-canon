# second-brain-engineer — основания правил и устройство Skill

Редакция 2026-11-01. Кто читает: синтез (`meta/PROTOCOL_knowledge-synthesis.md`), харвест, сессия, которая правит Skill или оспаривает правило. Исполнитель правил этот файл не читает: ему нужны условие, действие, «почему» и «не путать», и они остались в правиле. Ярлык `[основание: X]` в тексте правила разрешается строкой `- X (...)` ниже; продолжение многострочного основания — строки с отступом в два пробела. Сам текст оснований перенесён скриптом байт в байт (`meta/scripts/restructure_sbe_2026-10-22.py`).

## Устройство Skill

**Один регламент для всех проектов.** Этот Skill — единственное место регламента Второго мозга для всех Claude Project: мастер-промпт проекта несёт только адрес проекта, триггер старта, слова-команды и особенности проекта (Р2), а старт, захват, !save и команды исполняются отсюда. Почему: копии регламента в нескольких мастер-промптах расходятся между собой за неделю. Основание: решение Андрея 2026-10-06, позиции AH-13 и AH-23 `registry/maintenance-queue.md`. Когда правка этого Skill начинает действовать — Р13 (references/permissions.md).

**Как устроен этот текст.** Каждое правило держит четыре вещи: что делать и когда; почему — механизм одной-двумя фразами; признак, если ситуация неочевидна; строку основания. Строка основания несёт счёт случаев, дату последнего и адрес каждого случая. Адрес называет сам случай — запись журнала, урок, файл задачи, строку отчёта посредника, — а не сводку, которая о нём упоминает, и перед записью проверяется существующим (`meta/PROTOCOL_knowledge-synthesis.md`, элемент правила «основание»). Так пишутся все строки с 2026-10-22. Строки прежней формы «Основание: N случаев, последний <дата> — отчёт синтеза, правило <номер>» (решение Андрея 2026-10-20) разрешаются таблицей «правило → случаи» отчёта `meta/SYNTHESIS_second-brain-engineer_2026-10-20.md` по номеру правила. Решение или слово Андрея как основание пишется одной строкой с датой и местом записи, без отчёта. Рассказов случаев, номеров исполнений и истории правок в Skill нет: Skill читается целиком при каждом срабатывании, и каждая строка истории оплачивается в каждой сессии. Почему правило менялось — история коммитов зеркала `skills/second-brain-engineer/` и отчёты синтеза `meta/SYNTHESIS_*`. Правку этого Skill готовят по `meta/PROTOCOL_knowledge-synthesis.md`: кластер переписывается правилом, урок не дописывается. Основание: решения Андрея 2026-10-18 и 2026-10-20 (`projects/knowledge-synthesis/HISTORY_2026-10-18_to_2026-10-21.md`, разделы «Решения Андрея 2026-10-18» и абзац «Решения Андрея 2026-10-20 по отчёту синтеза `second-brain-git`», пункт 5).

**Как устроен Skill.** Этот файл читается всегда. Остальное лежит в references/ и читается перед своим действием, целиком, по таблице ниже. Номера пунктов общие для всех файлов Skill: ссылка «Р13» означает раздел Р13, в каком бы файле он ни лежал; таблица называет файл. Номера разделов прежние и при раскладке и синтезе не перенумеровываются: на них ссылаются другие файлы и другие Skills.

Правило раскладки — по моменту действия. Правило лежит там, где сессия находится в момент, когда оно должно сработать. Раздел, чья строка ТРИГГЕР называет конкретное событие или действие и чей момент наступает, когда сессия уже открыла файл этого действия, лежит в references/ и назван в таблице ниже. В этом файле — разделы, чей ТРИГГЕР — «любое действие», «любое утверждение» или «любая запись»; захват (Р6) — он срабатывает почти в каждом ответе; и правила, чей момент наступает до открытия файла действия и чьё нарушение меняет работающую систему (вопрос до правки воркфлоу и его форма, Р10), — со стопом в начале файла действия. Правило о работе вне Skill ставится в то, что сессия читает в момент действия: строку инструмента `registry/tools.md`, контракт вызова, скрипт-проверку (пункт 16). Новое правило обязано назвать триггер и момент, и они определяют место; правило без триггера в Skill не входит. Почему по моменту, а не только по триггеру: раскладка по триггеру держит постоянный слой, который модель читает при каждой загрузке Skill, от роста правилами одного вида действия, но правило в файле по действию трижды не исполнилось: дважды сессия в момент действия этот файл не открыла (Р21, Р10), в третьем случае (форма вопроса) открыт ли файл, не установлено; а хуже ли большой постоянный слой, проба на четырёх чатах не показала, и работа над раскладкой ради размера закрыта (запись Р-38 журнала `projects/kontext-reduktion/LOG.md`). Существующие правила по этому закону не перекладываются: перенос — только по нарушению, увиденному в живом чате (решение Андрея 2026-10-26, `projects/kontext-reduktion/STATE.md`, строка 37). Основание: решение Андрея 2026-10-20 (`meta/PLAN_skill-layers_2026-10-20_v3.md`, раздел 2) — раскладка по триггеру; исключение Р21 — 1 случай, последний 2026-10-20 — отчёт синтеза, правило «раскладка.Р21»; поправка «по моменту действия» — основание design-13.
