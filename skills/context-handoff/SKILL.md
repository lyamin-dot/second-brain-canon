# context-handoff

Протокол эстафеты между сессиями: оценка «переносить или продолжать», запись блока `## ЭСТАФЕТА` в канон проекта, подхват блока новой сессией. Эстафета применяется, когда накопленный контекст стал заметно дороже преамбулы новой сессии (мастер-промпт, Skills, стартовые чтения), а не когда «устали».

## Стоп-правила

### Граница применимости
- Skill загружается только по явной команде; до первой команды его в контексте нет, и Claude ничего не отслеживает.
- Проактивных предупреждений «пора переносить» не давать; все оценки выполняются в момент команды, ретроспективно.
- Решение об эстафете принимает пользователь: Claude оценивает и рекомендует, действует только по команде «эстафета».
- Не предлагать /compact и /clear — в claude.ai и Cowork их нет; исходов три: ПРОДОЛЖАТЬ, ЭСТАФЕТА и новый чат, ВЫНЕСТИ в файл.
- Не применять Skill по собственной инициативе и при общих разговорах о контексте, лимитах, токенах.

### Стоп-линия
Запись эстафеты ЗАПРЕЩЕНА, пока верно любое (запрет действует и по прямой команде «эстафета», до устранения блокера):
- выполнена деструктивная запись (replace, overwrite) без обратного чтения;
- ожидается результат воркфлоу;
- есть незаписанные `[ЗАХВАЧЕНО]` — захваты записываются до эстафеты (Skill `second-brain-engineer`, разделы «Р6. Захват», «Р7. !save»);
- открыта операция, разрыв которой оставит систему в промежуточном состоянии.

Порядок жёсткий: сначала закрыть стоп-линию, потом эстафета.
Стоп-линия — не незакрытая фаза: стоп-линия запрещает запись, незакрытая фаза меняет только рекомендацию, и по прямой команде запись выполняется.

### Оценка
- Собственное ощущение («кажется, я путаюсь») признаком надёжности не является; считать только внешне наблюдаемые события.
- Посреди операции эстафету не рекомендовать: рекомендуется завершить текущую фазу и после этого перенести; формулировать именно так, не как «продолжаем».
- Приоритет при конфликте: сохранность данных > точность работы > экономия контекста; экономия не оправдывает разрыв незавершённой операции.
- Шкалы СТОИМОСТЬ и НАДЁЖНОСТЬ считать обе и не смешивать.

### Блок и запись
- Все поля блока обязательны; пустое пишется «нет», не удаляется.
- Блок — одна строка, без перевода строки внутри, не более 1 КБ.
- ЦЕЛЬ, ЗАПРЕТЫ, РЕШЕНО, СЛЕДУЮЩИЙ ШАГ при превышении лимита не резать никогда.
- Чужой блок (поле ЧАТ не совпадает с текущей сессией) не перезаписывать, независимо от давности: показать и спросить.
- Эстафету писать заменой, не дозаписью; gdocs-append для эстафеты не годится.
- Якорь замены — вся текущая строка блока, не одни слова «## ЭСТАФЕТА».
- `success: true` записью не подтверждается; подтверждает только обратное чтение.
- Блок старой многострочной формы (Docs или файл задачи) не убирать заменой: вопрос Андрею.
- В блок не класть ссылки вместо фактов («см. CORE §12»): нести добытое значение, а не адрес.
- Пункт ДОБЫТО без метки Ф или Г не писать.
- Эстафету не писать вместо канона: задачи живут в каноне проекта как задачи.

### Подхват
- Данные протухшей эстафеты (ОБНОВЛЕНО старше 7 дней или СТАТУС: stale) как факты не использовать.
- Пункты с меткой [Г] без перепроверки выводов не строить.
- План не переизобретать: отрабатывать СЛЕДУЮЩИЙ ШАГ.
- Пересказывать блок целиком первым сообщением нельзя: только ЦЕЛЬ, ЗАПРЕТЫ, СЛЕДУЮЩИЙ ШАГ.
- Блок не использовать как живой, если он не обновлён после новых решений.

## Как делать

### Команды

| Команда | Действие |
|---|---|
| эстафета? | Только оценка по «Оценка: стоимость и надёжность»; вердикт по форме «Форма вердикта». В носитель НЕ писать |
| эстафета | Стоп-линия, запись по «Протокол записи», верификация, затем сказать «Эстафета записана в [ПРОЕКТ]. Открывай новый чат.» |
| эстафета в [ПРОЕКТ] | То же, в носитель указанного проекта |
| эстафета устарела | Поставить СТАТУС: stale в блоке («Подхват в новой сессии», «Кто ставит stale») |

Если после «эстафета?» пользователь решил продолжить в этом же чате, Skill уже в контексте, и Claude может добавлять одну строку статуса в конце ответа.

### Оценка: стоимость и надёжность

Перенос не бесплатен: новая сессия заново платит преамбулу — порядка 15 КБ. Две шкалы независимы; считать обе.

#### Шкала СТОИМОСТЬ
Считается всё, что вошло в контекст с начала сессии: вставленные документы, прочитанные файлы и выхлопы инструментов, развёрнутые ответы Claude, созданные артефакты. Оценка грубая, в КБ, по порядку величины; погрешность в разы допустима. Ориентир: экран плотного текста ≈ 3 КБ, крупная статья или выхлоп исследования ≈ 8–10 КБ, INDEX-файл — десятки КБ.

| Уровень | Объём сессии | Смысл |
|---|---|---|
| 🟢 | до ~30 КБ | перенос убыточен: преамбула дороже накопленного |
| 🟡 | ~30–60 КБ | перенос окупается, если фаза закрыта |
| 🔴 | свыше ~60 КБ | перенос окупается заметно |

#### Шкала НАДЁЖНОСТЬ
Признаки (только внешне наблюдаемые):
- перечитан файл, уже прочитанный в этой сессии;
- Claude противоречит решению, принятому ранее в этой же сессии;
- Claude спросил факт, который пользователь уже давал;
- пользователь сказал «мы это уже обсуждали» или «я тебе говорил»;
- две итерации без нового проверяемого результата.

| Уровень | Условие |
|---|---|
| 🟢 | признаков нет |
| 🟡 | один признак |
| 🔴 | два и более |

При 🟡 и выше по НАДЁЖНОСТИ — сначала re-anchor, до любой рекомендации: вслух повторить ЦЕЛЬ, действующие ЗАПРЕТЫ и СЛЕДУЮЩИЙ ШАГ. Не удалось воспроизвести или пользователь поправил — деградация подтверждена. Воспроизвелось точно — признак был ложным, уровень снижается.

#### Совмещение шкал

| СТОИМОСТЬ | НАДЁЖНОСТЬ | Рекомендация |
|---|---|---|
| 🟢 | 🟢 | ПРОДОЛЖАТЬ |
| 🟢 | 🟡 | ПРОДОЛЖАТЬ после повтора цели, запретов и следующего шага (re-anchor) |
| 🟢 | 🔴 | ЭСТАФЕТА — контекст мешает, хотя и дёшев |
| 🟡 | 🔴 | ЭСТАФЕТА — контекст мешает |
| 🟡 | 🟢/🟡 | ЭСТАФЕТА, если фаза закрыта; иначе — закрыть фазу |
| 🔴 | любая | ЭСТАФЕТА, если фаза закрыта; иначе — закрыть фазу |

«Фаза закрыта» = завершён шаг обслуживания, закрыта задача либо готов артефакт, и нет незавершённой записи. Незакрытая фаза перевешивает уровни шкал.

#### Форма вердикта
По команде «эстафета?» — ровно четыре строки, без развёрнутых рассуждений:

```
СТОИМОСТЬ: 🟡 ~45 КБ
НАДЁЖНОСТЬ: 🟢 признаков нет
ФАЗА: закрыта / не закрыта — [что именно висит]
ВЕРДИКТ: ПРОДОЛЖАТЬ | ЭСТАФЕТА | ЗАКРЫТЬ ФАЗУ, ЗАТЕМ ЭСТАФЕТА
```

### Формат блока ЭСТАФЕТА

Форму читает новая сессия при подхвате и замена по якорю; менять нельзя. Одна строка, поля через « | », без перевода строки внутри, не более 1 КБ:

```
## ЭСТАФЕТА | СТАТУС: active | ОБНОВЛЕНО: YYYY-MM-DD HH:MM | ЧАТ: [короткая метка сессии] | ЦЕЛЬ: одна фраза — что должно быть достигнуто | СОСТОЯНИЕ: где остановились | ЗАПРЕТЫ: что нельзя делать в этой задаче (must-not, контракты, форматы) | ДОБЫТО [Ф/Г]: факты из дорогих чтений — ID, значения, результаты проверок | РЕШЕНО: решения сессии, ещё не попавшие в CORE/CHANGELOG | ТУПИКИ: что проверено и НЕ сработало — с причиной | СЛЕДУЮЩИЙ ШАГ: один исполнимый шаг, без «продолжить работу» | ЯКОРЯ: ID файлов, воркфлоу, номера строк
```

- Все поля обязательны; пустое — «нет».
- В ДОБЫТО каждый пункт несёт метку: Ф = проверено чтением (прочитано в этой сессии), Г = гипотеза (всё, что не прочитано: вспомнено, выведено, предположено). Метки соответствуют меткам происхождения Skill `second-brain-engineer`, раздел «Р15. Провенанс и верификация — единый стандарт».
- Статусы: active, stale.
- Если блок больше 1 КБ, резать снизу вверх в таком порядке:
  1. ЯКОРЯ — оставить только нужные для СЛЕДУЮЩЕГО ШАГА;
  2. ТУПИКИ — оставить только последний;
  3. ДОБЫТО — оставить только пункты, нужные для СЛЕДУЮЩЕГО ШАГА.
- Если после реза не влезает — содержимое переросло эстафету и должно жить в каноне проекта как задача; сказать об этом пользователю.

### Протокол записи

Протокол один для всех носителей; для проекта в репозитории и лаборатории шаги 2 и 5 читаются по «Границы».

1. Проверить стоп-линию. Не прошла — назвать блокер и остановиться.
2. Прочитать текущий носитель: Зону А INDEX проекта.
3. Проверка конфликта. Если блок `## ЭСТАФЕТА` уже есть и поле ЧАТ не совпадает с текущей сессией — НЕ перезаписывать; показать существующий блок и спросить.
4. Собрать блок по «Формат блока ЭСТАФЕТА». Проверить объём, при необходимости резать в заданном порядке.
5. Записать заменой, не дозаписью: эстафета всегда одна, последняя.
   - Якорь замены — ВСЯ текущая строка блока, начинающаяся с «## ЭСТАФЕТА», в точности как прочитана на шаге 2. Перед заменой проверить уникальность якоря (`text.count`).
   - Инструмент — gdocs-apply-from-file, режим replace: новая строка блока — файлом-источником в папке, доступной сервисному аккаунту, старая — полем `search` (Skill `google-drive-docs`, разделы «gdocs-apply-from-file», «gdocs-replace v2»).
   - Блока нет — тем же инструментом по якорю строки SENTINEL: якорь заменяется на «строка эстафеты + перевод строки + та же строка SENTINEL»; строка SENTINEL остаётся последней строкой Зоны А.
   - Блок старой многострочной формы — вопрос Андрею.
6. Верифицировать обратным чтением.
7. Сказать: «Эстафета записана в [ПРОЕКТ]. Открывай новый чат.»

### Подхват в новой сессии

Отдельной команды не требуется: носитель читается по мастер-промпту — Зона А и STATE.md на старте, файл задачи лаборатории при взятии задачи.

1. Проверка свежести. ОБНОВЛЕНО старше 7 дней либо СТАТУС: stale — объявить вслух: «Эстафета протухла, работаю с нуля».
2. Проверка расшифровки. Первым сообщением назвать вслух ЦЕЛЬ, ЗАПРЕТЫ и СЛЕДУЮЩИЙ ШАГ — тремя строками.
3. Пункты с меткой [Г] — гипотезы; перед выводами перепроверить.
4. Отработать СЛЕДУЮЩИЙ ШАГ.

#### Кто ставит stale
- Новая сессия — сразу после первого содержательного шага, если она отклонилась от СЛЕДУЮЩЕГО ШАГА или обнаружила, что состояние изменилось.
- Пользователь — командой «эстафета устарела».
- Автоматически по 7 дням статус не меняется: срок проверяется при чтении.
- В лаборатории тот, кто ставит stale, тем же действием снимает пометку «активная эстафета» в строке задачи INDEX.md (правкой фрагмента, как в «Границы», подраздел «Лаборатория в репозитории»).

### Границы

Эстафета — оперативный чекпоинт, не летопись: Skill не пишет в CORE и CHANGELOG и не отменяет !save (захваты записываются до эстафеты, не вместо неё). Эстафета живёт в каноне проекта, где идёт работа.

#### Носитель эстафеты

| Где идёт работа | Носитель | Когда читает новая сессия |
|---|---|---|
| проект с INDEX в Google Docs | блок `## ЭСТАФЕТА` в Зоне А INDEX проекта | на старте, по мастер-промпту |
| проект в репозитории (`projects/<имя>/`) | первая строка раздела «Следующий шаг» в STATE.md проекта | на старте, по мастер-промпту |
| лаборатория в репозитории (`labs/<имя>/`, в том числе SYS) | блок `## ЭСТАФЕТА` в конце файла задачи `t-<имя>.md`, над которой шла работа, и пометка в строке этой задачи в INDEX.md | при взятии этой задачи; на старте пометка в INDEX.md говорит, что блок есть |

SYS — лаборатория: эстафета работы над задачей SYS пишется по правилу лаборатории ниже; работа над проектом из `projects/`, которая ведётся в чате SYS, пишет эстафету в STATE.md этого проекта.

#### Проект в репозитории
Своего INDEX в Google Docs у проекта нет. Отдельным блоком по «Формат блока ЭСТАФЕТА» эстафета не пишется: роль СОСТОЯНИЯ и СЛЕДУЮЩЕГО ШАГА несёт первая строка раздела «Следующий шаг» в STATE.md. Команда «эстафета» для такого проекта означает обновить STATE.md по маршруту Skill `second-brain-git`, раздел «Save по проекту» (сдвинулось состояние → STATE.md), записью по разделам «Чем писать» и «Доказательство записи» того Skill. Стоп-линия и «Протокол записи» (шаги 1, 3, 4, 6, 7) действуют без изменений; шаг 2 читается как «прочитать STATE.md проекта», шаг 5 — как «записать по `second-brain-git`, разделы «Чем писать» и «Доказательство записи»».

#### Лаборатория в репозитории
У лаборатории нет ни Зоны А, ни STATE.md — только INDEX.md со строкой на задачу и файл `t-<имя>.md` на каждую задачу (Skill `second-brain-git`, раздел «Лаборатория»).
- Блок `## ЭСТАФЕТА` пишется в конец файла той задачи, над которой шла работа; поля и лимит — по «Формат блока ЭСТАФЕТА».
- В строке этой задачи в INDEX.md ставится пометка «активная эстафета «<метка из поля ЧАТ>»».
- Обе записи — правкой фрагмента; файл целиком не переписывать.
- Блок есть — заменяется вся его строка целиком (якорь — строка, прочитанная на шаге 2). Блока нет — последняя непустая строка файла заменяется ею же плюс переводом строки и блоком. Если такая строка встречается в файле не один раз — якорем берутся две последние непустые строки (правка фрагмента принимает только текст, встречающийся в файле ровно один раз).
- Транспорт, вариант 1: в сессии, где прошла проба `git push --dry-run` (Skill `second-brain-git`, раздел «Push: проверка и открытие»), обе правки уходят одним коммитом клоном прямо в main и проверяются чтением с origin/main после свежего fetch (Skill `second-brain-git`, раздел «Маршрут доставки в main»); коммит, оставленный в ветке, доставкой не считается.
- Транспорт, вариант 2: через Канал — Git Replace (Skill `second-brain-git`, разделы «Git Replace с русским текстом», «Параллельные сессии») по очереди, не одновременно: сначала блок, потом пометка. Блок пишется по-русски; у Git Replace с русским текстом есть слабое место — набор последовательностями \uXXXX, что с ним делать — Skill `second-brain-git`, разделы «Git Replace с русским текстом», «Набор кириллицы в вызовах Канала».
- Конфликт записи — как в «Протокол записи», шаг 3: блок с другим полем ЧАТ не перезаписывать, показать и спросить. Блок старой многострочной формы — вопрос Андрею.
- Протокол записи: шаг 2 читается как «прочитать файл задачи и её строку в INDEX.md», шаг 5 — как «записать правкой фрагмента по этому подразделу». Стоп-линия, проверка свежести и проверка расшифровки («Подхват в новой сессии») — без изменений.
- Активных эстафет в лаборатории может быть несколько — по одной на задачу; общего предела нет. «Эстафета всегда одна, последняя» значит одна на файл задачи.
- Новая сессия читает блок при взятии задачи, а не на старте лаборатории; пометка в INDEX.md говорит, что блок есть.
- Задача закрывается по Skill `second-brain-git`, раздел «Лаборатория»: файл удаляется вместе с блоком, строка INDEX.md вместе с пометкой; отдельно снимать не нужно.

## Куда писать результат

Результат команды «эстафета» — блок в носителе по таблице «Носитель эстафеты» и фраза «Эстафета записана в [ПРОЕКТ]. Открывай новый чат.» после обратного чтения. Результат «эстафета?» — четыре строки вердикта в чат, ничего в носитель.
