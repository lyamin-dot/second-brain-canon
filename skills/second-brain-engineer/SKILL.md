# SECOND BRAIN — ПОЛЕВОЙ РЕГЛАМЕНТ

Редакция 2026-10-22.

Формат каждого блока: **ТРИГГЕР** — когда применять. **ДЕЙСТВИЕ** — что делать, по порядку. **ПРОВЕРКА** — чем доказать, что сделано. Нет проверки — блок не закрыт.

Этот файл читается всегда. Остальное лежит в references/ и читается перед своим действием целиком, по таблице ниже; номера разделов сквозные и не перенумеровываются (на них ссылаются другие файлы и другие Skills). Действие, для которого свой файл не прочитан, — то же нарушение, что действие без этого Skill. Почему Skill устроен так и откуда взялись слои — references/basis.md, раздел «Устройство Skill» (читает тот, кто Skill правит, не тот, кто исполняет).

## Р0. Два носителя — один разделитель

**ТРИГГЕР.** Любое действие с документом системы.

**ДЕЙСТВИЕ.**
- Определить носитель документа. Docs → этот Skill целиком. Repo `lyamin-dot/second-brain-canon` → чтение и запись по `second-brain-git`; поведение (когда, зачем, с чьего согласия) — по этому Skill.
- Граница трёх Skills, одна для обоих носителей: этот Skill отвечает «что делать, когда и с чьего согласия»; `second-brain-git` — «как физически прочитать и записать файл репозитория»; `google-drive-docs` — то же для Google Docs и Sheets. Механика из них сюда не переписывается — только ссылка на пункт. Почему: копия механики расходится с источником, и сессия исполняет устаревшую. [основание: SKILL-01]
- Носитель проекта — колонка «носитель канона» в `registry/projects.md`. Проект не найден там и нет INDEX в Docs — проекта не существует, не угадывать.
- CORE живёт в repo (`core/`, состав — `core/MANIFEST.md`). Старый CORE в Docs (ID — `registry/documents.md`, строка CORE) — исторический источник, для принятия решений не читается.

**ПРОВЕРКА.** В ответе назван носитель и файл, из которого он прочитан: `registry/projects.md`; для Docs-проекта ID его INDEX — `registry/documents.md`.

## Р6. Захват

**ТРИГГЕР.** Любой ответ, в разговоре которого появилось то, чего ещё нет в каноне проекта: задача, идея, вопрос без ответа, решение, баг, результат, внешнее событие.

**ДЕЙСТВИЕ.** В конце того же ответа, не прерывая работу, одним блоком:
```
[ЗАХВАЧЕНО]
→ [<ТЕГ>] <Тип>: <текст>
```
- Типы: Задача, Идея, Вопрос, Решение (с датой), Баг (симптом | причина, если известна), Результат (что исправлено → что получилось), Событие (внешнее: тариф, API, квота, версия, поведение платформы).
- Тег — проект, которому факт принадлежит, а не проект, в котором идёт сессия. Баг n8n как платформы (узел, движок, SDK, MCP) — тег [N8N], адрес `projects/n8n/STATE.md`. Баг бизнес-воркфлоу другого проекта — тег того проекта и строка «⚡ Это затрагивает [ПРОЕКТ]: [что]» (Р9). Проект неясен — `[?] Не классифицировано: <текст>`, не угадывать.
- Баг — сразу предложить записать, не ждать конца сессии. После трёх и более захватов подряд и в конце сессии с захватами — предложить !save. Пересказ уже записанного захватом не является.
- Трение. Когда правило, процедура или инструмент мешают результату работы, сессия вправе отметить это одной строкой в ответе — «Трение: <что мешает> → <чему мешает>» — без разбора, без вопроса и без отдельного захвата. Это снятый запрет, а не обязанность и не ритуал: когда трения нет, строки нет. В канон трение попадает захватом типа Идея с тегом [SYS] только тогда, когда Андрей его подхватил. [основание: SKILL-02]

Три случая, которые не ждут !save: каждый записывается тем шагом, на котором возник. Почему: следующая сессия читает канон, а не чат, и факт, отложенный до !save, до неё может не дойти.
- **Смена предмета или цели работы** посреди проекта — отдельное решение, а не продолжение прежнего. Захват типа Решение, вопрос Андрею и запись в журнал решений проекта (`second-brain-git` 11) — до того, как работа продолжится по-новому. Частное решение, которое сессия приняла сама «по аналогии» с прежним, не спросив Андрея, в записи помечается словами «по аналогии, владельцу не задано». Признак: делается уже не то, что записано целью в `PLAN.md` или INDEX. [основание: SKILL-03]
- **Созданный сессией объект, который нужен после неё**, получает адрес в каноне тем же шагом, которым создан, — до следующего шага работы и до отправки Андрею в чат; в ответе называется этот адрес. Почему: следующая сессия ищет по канону и реестрам; рабочая папка сессии пропадает вместе с сессией и другим сессиям не видна, файл в чате другие сессии не читают, а объект, записанный только в самом инструменте, находится разве что по совпавшему слову. Признак: сессия называет Андрею файл, документ или воркфлоу, которого нет ни в одном файле канона.

  | Что создано | Куда тем же шагом |
  |---|---|
  | документ или таблица Google | строка в `registry/documents.md`; право на эту запись — Р13 |
  | файл — пакет вопросов, отчёт, скрипт, выгрузка, данные — в рабочей папке сессии или на компьютере Андрея | репозиторий, по правилам `second-brain-git`; файл, который публичному репозиторию запрещён (`second-brain-git`, И-7), — Google Drive и строка в `registry/documents.md` |
  | воркфлоу n8n | строка в каноне своего проекта: ID, имя, назначение, опубликован или нет (repo-проект — `STATE.md`, маршрут `second-brain-git` 10.3; проект в Docs — его INDEX по Р7); паспорт и строка PASSPORT в описании воркфлоу — Skill `n8n-workflow-passport` |

  Отправка файла в чат и файл в рабочей папке записью не считаются. [основание: SKILL-04]
- **Факт, полезный соседнему проекту**, — захват с тегом соседа; тем же шагом, на котором узнан, он ложится одной строкой в `STATE.md` соседа с пометкой «⚡ Это затрагивает <сосед>: что, где проверить» — адрес и форма строки: `second-brain-git` 10.6. Сказанное в чате записью не считается: соседняя сессия чат не читает. Образец — `meta/DECLARATION_COMMON.md`, раздел 4. [основание: SKILL-05]

**ПРОВЕРКА.** Захват виден в том же ответе, где возник; у каждой строки есть тег и тип. Смена цели — запись в журнале названа номером до продолжения работы; созданный объект — его адрес назван в ответе, а строка в `registry/documents.md`, файл в репозитории или строка в каноне проекта видны обратным чтением (Р15).

## Р10. Воркфлоу n8n — вопрос до вызова

**ТРИГГЕР.** Любой вызов, который меняет воркфлоу n8n: update_workflow, create_workflow_from_code поверх существующего воркфлоу, restore_workflow_version, publish_workflow, unpublish_workflow, archive_workflow.

**ДЕЙСТВИЕ.** До вызова — вопрос в чате: «Воркфлоу [имя], узел [имя]. Планирую: [описание]. Подтверждаешь?» — и ждать явного «да». Просьба Андрея изменить воркфлоу этим «да» не является: просьба называет цель, а вопрос показывает, что именно изменится и в каком узле. Исключения (записанный пакет разрешения, поручение «реши сам» в пределах задачи), копия воркфлоу перед отладкой и запись решения в паспорт — references/permissions.md, прочитать до вызова.
Почему правило стоит здесь, а не только в references/: 2026-10-23 сессия проекта SYS загрузила этот Skill, файл полномочий не открыла и изменила воркфлоу без вопроса (`meta/TEST_skill-layers_2026-10-22_report.md`, раздел «Повтор в живых чатах проекта SYS 2026-10-23»). Правило, нарушение которого меняет работающую систему, держится в слое, который читается всегда.

**Форма любого вопроса, требующего «да» Андрея** — о воркфлоу, о записи, об удалении, о правке документа: три строки простыми словами, коды и номера пунктов только в скобках после слов.
ВОПРОС: что меняется.
ЕСЛИ «ДА»: ближайшее наблюдаемое последствие для работы Андрея.
ЕСЛИ «НЕТ»: что останется как есть и чем это грозит.
В одном сообщении не больше трёх таких вопросов. В вопросе о правке воркфлоу сессия кроме того предлагает сохранить копию воркфлоу перед правкой и называет запись решения в паспорт после неё.
Почему форма стоит здесь, а не только в references/permissions.md: проба 2026-10-26 — сессия, у которой форма лежала только в файле полномочий, в обоих заданиях задала вопрос без трёх строк и не предложила копию; сессия, у которой то же правило стояло в постоянном слое, оба раза исполнила его. Причина (не открыт файл или не исполнено прочитанное) не установлена.

**ПРОВЕРКА.** В чате до меняющего вызова видны вопрос в названной форме и «да» Андрея, либо назван адрес записанного пакета разрешения.

## Р14. Запреты

**ТРИГГЕР.** Любое действие.

1. Деструктив без подтверждения. Формат: «Собираюсь [действие] на [объект]. Это изменит [что]. Подтверждаешь?» Любой объект: воркфлоу, строки Sheets, Drive, repo, >3 нод. Почему: удалённое и перезаписанное в Docs, Sheets, Drive и воркфлоу n8n сессия сама не вернёт; в репозитории прежний текст остаётся в истории коммитов, но и возврат оттуда — отдельная запись, которую сделает уже не та, кто удалил.
2. Структурные изменения INDEX и мастер-промпта попутно — без отдельного явного «да» Андрея в чате и без текста «было → стало». Исключение — критический баг, ломающий систему прямо сейчас.
3. Второй носитель одного документа. Docs или repo — одно. Почему: два носителя расходятся, и неизвестно, какой прав.
4. «Отложить» без адреса: правку Skill, мастер-промпта или CORE — без позиции в `registry/maintenance-queue.md` с датой смерти (очередь читает харвест, Р11); прочую находку — без задачи в `labs/sys/` (Р16). Почему: отложенное без адреса не прочтёт ни одна следующая сессия.
5. Считать запись выполненной по ответу инструмента (Р15).
6. Хранить в Skill ID и адреса, у которых есть реестр: документы Docs — `registry/documents.md`; git-канал и repo — `registry/`; таблицы Sheets и доменные детали — `n8n-workflow-registry`. Три реестра, три класса объектов, пересечений нет. Таблица или документ, созданные сессией, регистрируются в `registry/documents.md` (Р6): Skill `n8n-workflow-registry` сессия не правит, а объект без адреса потеряется до ближайшей правки Skill.

**ПРОВЕРКА.** Перед действием из запретов 1 и 2 в чате видны вопрос в названном формате или текст «было → стало» и «да» Андрея; у отложенной правки или находки назван адрес — позиция Очереди или задача `labs/sys/`; запись считается выполненной только по обратному чтению (Р15).

## Р15. Провенанс и верификация — единый стандарт

**ТРИГГЕР.** Любое утверждение о состоянии системы; любая запись.

**ЗАКОН.** Утверждение верно только для того чтения объекта, из которого оно взято. Всё, чего сессия не прочитала в самом объекте, — память, пересказ или старая запись, и решение на этом не принимается: объект читается до решения, либо утверждение пишется словами «Гипотеза (не проверена):». Ответ посредника (Р21) годится, чтобы выбрать следующий шаг, но не для записи в канон, пока сессия не прочитала источник сама. Почему: записанное когда-то выглядит как факт, закрывает поиск и молча стареет — следующая сессия не ищет того, что «уже известно». [основание: SKILL-06]

**ДЕЙСТВИЕ.**
1. Каждое утверждение несёт метку происхождения: ПРОЧИТАНО В ЭТОЙ СЕССИИ (файл), ПРОЧИТАНО ПОСРЕДНИКОМ (кто и какой объект — Р21) или ВСПОМНЕНО. Четвёртой метки нет; уверенность происхождением не является. Решение цитируется вместе со статусом: отметка об отмене часто стоит в хвосте записи. Кто читал источник, тот и прав — независимо от роли в наряде и класса модели. Расхождение факта с ожиданием — стоп и вопрос, не тихая правка.
2. **Слово Андрея** «сделал», «удалил», «внёс» — для сессии ВСПОМНЕНО: Андрей помнит действие, а объект сессия не видела. Задача, закрываемая по такому слову, закрывается только после чтения объекта; до того она открыта, а в ответе стоит «по словам Андрея, объект не прочитан». [основание: SKILL-07]
3. Что считается чтением объекта — по виду утверждения:

| Вид утверждения | Что прочитать до решения или до записи в канон | Что чтением не считается |
|---|---|---|
| **Утверждение о состоянии**: «работает», «выключен», «опубликован», «внесено», «удалено» — в `STATE.md`, INDEX, задачу, журнал | номер исполнения, поле ответа инструмента или строку объекта; способ проверки пишется рядом с утверждением, без него — «Гипотеза (не проверена):» | прежняя запись о состоянии |
