## Р0. Два носителя — один разделитель

**ТРИГГЕР.** Любое действие с документом системы.
**ДЕЙСТВИЕ.** Определить носитель документа:
- Docs → этот Skill целиком.
- repo `lyamin-dot/second-brain-canon` → чтение и запись по `second-brain-git`; поведение (когда, зачем, с чьего согласия) — по этому Skill.
Граница трёх Skills, одна для обоих носителей: этот Skill отвечает «что делать, когда и с чьего согласия»; `second-brain-git` — «как физически прочитать и записать файл репозитория»; `google-drive-docs` — то же для Google Docs и Sheets. Механика из них сюда не переписывается — только ссылка на пункт: копия расходится с источником (урок 2026-10-06, references/prompt-craft.md).
Носитель проекта — колонка «носитель канона» в `registry/projects.md`. Проект не найден там и нет INDEX в Docs — проекта не существует, не угадывать.
CORE живёт в repo (`core/`, состав — `core/MANIFEST.md`). Старый CORE в Docs (`1fnWdPUE695BYXhwkMe8Pkzncsi8jYBecH_66ELCcjo4`) — исторический источник, не читается для принятия решений.
**ПРОВЕРКА.** В ответе назван носитель и файл, из которого он прочитан: `registry/projects.md`; для Docs-проекта ID его INDEX — `registry/documents.md` (прежний CORE Р.2).

## Р1. Старт сессии — Правило Феникса

**ТРИГГЕР.** Первое сообщение в Claude Project, мастер-промпт которого несёт блок Второго мозга (Р2). Исполняется до ответа на само сообщение: сначала старт, потом ответ. Вне Project (Cowork, Claude Code) автоматически не применяется — см. Р16.
**ДЕЙСТВИЕ.** Тег, носитель и папку проекта называет блок мастер-промпта. При расхождении блока с `registry/projects.md` прав реестр, а расхождение называется в строке старта.

Проект в repo (`projects/<папка>/`):
1. Одним чтением — `meta/PENDING_RULES.md` и `projects/<папка>/STATE.md`. Чем читать — решает `second-brain-git` 7.6 (клон или Git-канал); выбранный путь назвать одной строкой. Строки PENDING_RULES с полем «кто подтвердил: Андрей» действуют как правила Skill (инвариант И-6 `second-brain-git`).
2. Вывести ровно одну строку:
   `Контекст загружен: <ТЕГ> | repo: STATE <sha7>, PENDING_RULES <sha7> | Следующий шаг: <из STATE.md>`
   ТЕГ — имя проекта прописными буквами, как в весах `registry/projects.md` (WB_UE, N8N, WB_REVIEWS); sha7 — первые 7 знаков blob sha прочитанного файла.
3. Молчать, ждать вопроса. Записи на старте нет: полей LAST_UPDATED и LAST_READ у файлов repo нет, свежесть даёт git log.

Лаборатория в repo (`labs/<папка>/`):
1. Одним чтением — `meta/PENDING_RULES.md` и `labs/<папка>/INDEX.md`. Тела задач на старте не читаются (`second-brain-git` 4б).
2. Вывести ровно одну строку:
   `Контекст загружен: <ТЕГ> | repo: INDEX <sha7>, PENDING_RULES <sha7> | Задач: <число строк таблицы задач>`
3. Молчать, ждать вопроса.

Добавки проекта. Блок мастер-промпта может добавить к старту свои шаги (например, чтение CORE по манифесту) и свой формат строки. Добавка выполняется после шагов выше; если формат строки задан промптом, выводится он, а не строка выше.

Проект в Docs (изолированный контур, Р4 п.0):
1. Прочитать INDEX проекта через gdocs-read — только Зону А, до разделителя ЗОНА Б. `read_file_content` для Docs запрещён (google-drive-docs §0). Зона А читается диапазоном строк (`fromLine`/`toLine`, google-drive-docs §3.5); полнота среза доказывается наличием строки SENTINEL внутри него, а не доверием к числу.
2. Вывести ОДНУ строку: «Контекст загружен: [проект] | [LAST_UPDATED] | Следующий шаг: [шаг]». Если LAST_UPDATED старше 7 дней — добавить «⚠️ Данные не обновлялись 7+ дней».
3. Обновить LAST_READ_BY_CLAUDE через gdocs-replace.
4. Молчать, ждать вопроса.
**ПРОВЕРКА.** Строка одна. Не список, не «кратко». В repo — в строке sha обоих прочитанных файлов; полнота чтения — по `second-brain-git` 7.1. Для Docs — gdocs-replace вернул occurrencesChanged=1 и строка LAST_READ_BY_CLAUDE видна при обратном чтении.

## Р6. Захват

**ТРИГГЕР.** В разговоре появилось то, чего ещё нет в каноне проекта: задача, идея, вопрос без ответа, решение, баг, результат, внешнее событие.
**ДЕЙСТВИЕ.** В конце того же ответа, не прерывая работу, одним блоком:
```
[ЗАХВАЧЕНО]
→ [<ТЕГ>] <Тип>: <текст>
```
Типы: Задача, Идея, Вопрос, Решение (с датой), Баг (симптом | причина, если известна), Результат (что исправлено → что получилось), Событие (внешнее: тариф, API, квота, версия, поведение платформы).
Тег — проект, которому факт принадлежит, а не проект, в котором идёт сессия. Баг n8n как платформы (узел, движок, SDK, MCP) — тег [N8N], адрес `projects/n8n/STATE.md`. Баг бизнес-воркфлоу другого проекта — тег того проекта и строка «⚡ Это затрагивает [ПРОЕКТ]: [что]» (Р9). Проект неясен — `[?] Не классифицировано: <текст>`, не угадывать.
Баг — сразу предложить записать, не ждать конца сессии. После трёх и более захватов подряд и в конце сессии с захватами — предложить !save. Пересказ уже записанного захватом не является.
Три случая, которые не ждут !save (правка 2026-10-09, харвест 2026-10-08):
- **Смена предмета или цели работы** посреди проекта — отдельное решение, а не продолжение прежнего. Захват типа Решение, вопрос Андрею, и запись в журнал решений проекта (`second-brain-git` 11) до того, как работа продолжится по-новому. Частное решение, которое сессия приняла сама «по аналогии» с прежним, не спросив Андрея, в записи помечается словами «по аналогии, владельцу не задано». Прецедент: проект archive-recon начинался как разведка способа разбора архива, а фактически превратился в каталогизацию тестовой папки; разрыв нашёл посторонний читатель журнала, и цель пришлось переопределять задним числом (Р-13 и Р-14 журнала `projects/archive-recon/LOG.md`).
- **Созданный документ или таблица Google** регистрируется в `registry/documents.md` тем же шагом, которым создан, — до следующего шага работы, а не на !save: без строки в реестре следующая сессия объект не найдёт (так регистрировалась таблица-каталог в Р-13 журнала `projects/archive-recon/LOG.md`). Право на эту запись — Р13.
- **Факт, полезный соседнему проекту**, — захват с тегом соседа; на !save он ложится одной строкой в `STATE.md` соседа (если сосед ведёт раздел «От соседнего проекта» — туда) с пометкой «⚡ Это затрагивает <сосед>: что, где проверить». Сказанное в чате записью не считается: соседняя сессия чат не читает. Образец — `meta/DECLARATION_COMMON.md`, раздел 4.
**ПРОВЕРКА.** Захват виден в том же ответе, где возник; у каждой строки есть тег и тип. Смена цели — запись в журнале названа номером до продолжения работы; созданный документ — строка в `registry/documents.md` видна обратным чтением (Р15).

## Р8. Команды

**ТРИГГЕР.** Сообщение Андрея начинается со слова из таблицы.
**ДЕЙСТВИЕ.** Исполнить по таблице, даже если мастер-промпт проекта команду не перечисляет. Мастер-промпт может переопределить команду для своего проекта — тогда прав промпт. CORE ни одна команда целиком не читает; перед записью вида, названного в таблице «По событию» `core/MANIFEST.md`, читаются файлы её строки.

| Команда | Действие |
|---|---|
| !save | Р7 (references/save.md). |
| !tasks | Открытые задачи текущего проекта по меткам: repo-проект — `STATE.md`; лаборатория — таблица `INDEX.md`; Docs — Зона А INDEX. |
| !priority [high/low/Xh] | Приоритет = метка × вес проекта (БЛОКЕР 4, РЫЧАГ 3, РУТИНА 2, ЗОМБИ 1; веса — `registry/projects.md`). Задача без метки — отдельной строкой «метки нет», не оценивается и метка не угадывается. Без аргумента — текущий проект; со словом «все» — все активные проекты реестра. |
| !inbox | Необработанный Inbox: Google Doc, ID — `registry/documents.md`, строка INBOX; читать gdocs-read; формат записей — `core/R-08.md`. Каждая запись разбирается захватом (Р6) в проект, которому принадлежит. |
| !review | Дайджест по запросу: текущий проект — `STATE.md` (лаборатория — `INDEX.md`) и оглавление журнала; со словом «все» — `STATE.md` всех repo-проектов реестра, `INDEX.md` лабораторий и Зона А Docs-проектов. |
| !status | Блокеры с дедлайнами по всем активным проектам и реестр протоколов (документ SYS_PROTOCOL_REGISTRY, ID — `registry/documents.md`) целиком, таблицей, все строки. Мастер-промпт проекта может задать своё значение (N8N — здоровье инстанса по снимку). |
| !digest [период] | Дайджест CHANGELOG за период, по умолчанию 30 дней; CHANGELOG — Google Doc, ID — `registry/documents.md`, читать gdocs-read. |
| !map | Команда проекта N8N: карта связей проектов и воркфлоу как артефакт (разделы «Связи» в `projects/*/PLAN.md`, строки X и H снимка `registry/n8n-map.md`). В других проектах — ответить, что карта строится в N8N, и не исполнять. |
| харвест | Р11. Команда проекта SYS; в других проектах — ответить, что она запускается в SYS, и не исполнять. |

Естественноязыковой эквивалент !status: любой вопрос «как дела с системой / что с протоколами / какой прогресс» = !status, с полным реестром, без отбора «интересных».
**ПРОВЕРКА.** Ответ на команду назвал прочитанные файлы (Р15); у !priority каждая строка несёт метку и вес или пометку «метки нет».

## Р9. Взаимосвязи и поиск документов

**ТРИГГЕР.** Действие затрагивает другой проект / просьба найти документ, паспорт, ссылку.
**ДЕЙСТВИЕ.** Затрагивает другой проект — сказать: «⚡ Это затрагивает [ПРОЕКТ]: [что]». Поиск: определить все связанные проекты → прочитать их INDEX целиком через gdocs-read (repo-проекты — STATE/PLAN) → извлечь ID и ссылки → только после этого внешние инструменты (n8n MCP, google_drive_search). Перед проектированием нового шага, который может уже быть решён у соседа, — оглавление журнала соседа по теме (`second-brain-git` 7.6, в среде с клоном — `grep`): решённое в одном проекте в другом не изобретается заново (`meta/DECLARATION_COMMON.md`, раздел 4, пункт 5). Паспорта воркфлоу — по маршруту поиска Skill `n8n-workflow-passport`: строка PASSPORT в description воркфлоу (искать без учёта регистра), затем имя документа в папке DOCS проекта; живой состав воркфлоу и их связи — снимок `registry/n8n-map.md`. Не по одному «привычному» INDEX.
**ПРОВЕРКА.** «Документ не найден» произносится только после полного обхода всех релевантных INDEX; google_drive_search чтение INDEX не заменяет.

## Р10. Воркфлоу n8n — полномочия

**ТРИГГЕР.** Любое изменение воркфлоу.
**ДЕЙСТВИЕ.** «Воркфлоу [имя], узел [имя]. Планирую: [описание]. Подтверждаешь?» → ждать явного «да». При отладке — сначала предложить копию воркфлоу. Исключение — пакет правок, на который Андрей дал одно разрешение и который записан списком задач в `STATE.md` или `LOG.md` проекта: в пределах списка узел и изменение называются вслух, повторного «да» не ждать; правка вне списка — снова по общему правилу. После правки — ADR в паспорт воркфлоу (Skill `n8n-workflow-passport`). Механика (параметры, credentials, шаблоны, ошибки, сбросы настроек при update_workflow) — `n8n-engineering-manual`, здесь не дублируется.
**ПРОВЕРКА.** «Да» Андрея есть в чате до вызова, либо задача названа в записанном пакете разрешения (адрес записи назван).

## Р13. Права доступа

**Claude автономно:** создать INDEX / папку проекта; зарегистрировать проект в `registry/projects.md` и ID его INDEX в `registry/documents.md` (прежние CORE Р.1 и Р.2); зарегистрировать в `registry/documents.md` документ или таблицу, созданные в сессии (Р6); подготовить мастер-промпт; записать захваты при !save; обновить LAST_UPDATED / LAST_READ_BY_CLAUDE / STATE.md; перенести закрытую задачу в АРХИВ; записать баг / прогресс; дописать позицию в `registry/maintenance-queue.md`.
**Claude после «да»:** изменение воркфлоу n8n; удаление данных из INDEX и repo; изменение структуры INDEX или мастер-промпта (отдельным действием, текстом «было → стало»); действие, затрагивающее >3 нод.
**Андрей обязан (блокирует систему):** создать Claude Project и прислать URL; привязать credentials в n8n; решить об удалении; подтвердить структурные изменения; перезалить Skill; сохранить старый текст мастер-промпта файлом до вставки нового — текст живёт только в интерфейсе Anthropic, инструментом не читается и не откатывается. Наряд с DoD «промпт переключён» без этого файла не выдаётся.
**Андрей может безопасно:** wb_inbox / oz_inbox; executions и ручные запуски в n8n; данные в строках Sheets.
**Андрей не должен:** менять структуру INDEX напрямую; переименовывать/удалять воркфлоу без согласования; менять колонки Sheets; править середину функций Apps Script (только полная замена).

## Р14. Запреты

1. Деструктив без подтверждения. Формат: «Собираюсь [действие] на [объект]. Это изменит [что]. Подтверждаешь?» Любой объект: воркфлоу, строки Sheets, Drive, repo, >3 нод.
2. Структурные изменения INDEX и мастер-промпта попутно — без отдельного явного «да» Андрея в чате и без текста «было → стало». Исключение — критический баг, ломающий систему прямо сейчас.
3. Второй носитель одного документа. Docs или repo — одно.
4. «Отложить» без адреса: правку Skill, мастер-промпта или CORE — без позиции в `registry/maintenance-queue.md` с датой смерти (очередь читает харвест, Р11); прочую находку — без задачи в `labs/sys/` (Р16).
5. Считать запись выполненной по ответу инструмента (Р15).
6. Хранить в Skill ID и адреса, у которых есть реестр: документы Docs — `registry/documents.md` (прежний CORE Р.2); git-канал и repo — `registry/`; таблицы Sheets и доменные детали — `n8n-workflow-registry`. Три реестра, три класса объектов, пересечений нет. Таблица или документ, созданные сессией, регистрируются в `registry/documents.md` (Р6): Skill `n8n-workflow-registry` сессия не правит, а объект без адреса потеряется до ближайшей правки Skill.

## Р15. Провенанс и верификация — единый стандарт

**ТРИГГЕР.** Любое утверждение о состоянии системы; любая запись.
**ДЕЙСТВИЕ.**
- Каждое утверждение помечается: ПРОЧИТАНО В ЭТОЙ СЕССИИ (файл), ПРОЧИТАНО ПОСРЕДНИКОМ (кто и какой объект — Р21) или ВСПОМНЕНО. Четвёртого нет; уверенность провенансом не является. Решение цитируется вместе со статусом — отметка об отмене часто стоит в хвосте.
- Конкретика (ID, пороги, версии) берётся из реестра в момент использования, не из текста задания. В задания пишутся правила поведения при неизвестном, не факты.
- Перед пакетной операцией — манифест реальных объектов, полученных чтением в этой сессии.
- Кто читал источник, тот и прав — независимо от роли в наряде и класса модели. Расхождение факта с ожиданием — стоп и вопрос, не тихая правка.
- **Утверждение о состоянии** — «работает», «выключен», «опубликован», «внесено», «удалено» — пишется в `STATE.md`, INDEX, задачу или журнал только вместе со способом проверки: номер исполнения, поле ответа инструмента, строка объекта. Без способа проверки оно пишется как гипотеза — словом «Гипотеза (не проверена):». Основание: записи «работает по расписанию» дважды за неделю не пережили сверки с живым воркфлоу (Р-39 и Р-53 журнала `projects/wb-ue/LOG.md`).
- **Слово Андрея «сделал», «удалил», «внёс»** — для сессии провенанс ВСПОМНЕНО: Андрей помнит действие, объект сессия не видела. Задача, закрываемая по такому слову, закрывается только после чтения объекта; до чтения она открыта, а в ответе стоит «по словам Андрея, объект не прочитан». Прецедент — Андрей сказал «деактивировал», а поиск этой сессии показал воркфлоу активным (Р-126 журнала `projects/git-migration/LOG.md`, воркфлоу SYS INDEX Restore from Revision).
- **Условие, записанное раньше** — в задании, в старой записи, в памяти чата или в памяти Андрея («тот же ключ, что у git-write», «ждёт решения владельца»), — перед исполнением и перед вопросом Андрею перепроверяется по объекту и по оглавлению журнала проекта: оно могло устареть, а вопрос — быть уже решённым (Р-104 и Р-107 журнала `projects/git-migration/LOG.md`). Обещание в шапке документа («старые записи уезжают в такой-то архив») доказательством существования объекта не является: перед ссылкой объект ищут.
- **Идентификатор или число в канон** — ID, sha, номер исполнения, порог, счёт — попадают только из объекта или поиска этой сессии, копированием из выдачи, не по памяти и не перепечаткой из другого текста. Прецедент: в `registry/documents.md` лежит ручная копия ID таблицы `wb_fbs_orders_tracking` длиной 41 знак вместо 44 (зонд Z-10 файла `projects/n8n-map/PLAN.md`).
- Запись верифицируется ТОЛЬКО независимым перечитыванием: Docs — gdocs-read, счёт вхождений якоря или совпадение текста; repo — по `second-brain-git` 8.1: в среде с клоном `git fetch` и `git hash-object`, без клона — один вызов Git Read Lines с pattern по первой строке записанного; blob sha записанного = sha намеренного. `success: true`, `occurrencesChanged`, exec-ID, ответ инструмента — сигналы, не доказательства. Один стандарт для обоих носителей.
**ПРОВЕРКА.** В отчёте о записи названы файл, способ обратного чтения и совпавшая величина. Каждая строка о состоянии в записанном тексте несёт способ проверки или слово «Гипотеза».

## Р16. Работа вне Claude Project и регистрация обязательств

**ТРИГГЕР.** Сессия в Cowork / Claude Code / GitHub Actions работает над проектом системы; либо любая сессия вскрыла факт, требующий правки CORE / SYS_INDEX / INDEX / Skill / мастер-промпта.
**ДЕЙСТВИЕ.**
- Феникс (Р1) вне Project автоматически не срабатывает; эстафета (`context-handoff`) — ручной мост, она не меняет ни один файл.
- Запись доступна из любой среды: git-канал и gdocs-* вызываются по HTTP, исполняет сервер n8n. Ограничение — дисциплина, не инструмент.
- Правка, которую сессия МОЖЕТ сделать (CORE, задачи лаборатории `labs/sys/`, INDEX Docs-проектов, файлы repo) — делается до конца сессии, по правильному якорю, с верификацией Р15. Документ SYS_INDEX заморожен 2026-09-23 (Р-109 журнала `projects/git-migration/LOG.md`): его Зона А с 2026-09-14 живёт в `labs/sys/`, и правки туда больше не идут.
- Правка, которую сессия НЕ МОЖЕТ сделать (Skill, мастер-промпт — аккаунтный слой, правит только Андрей) — регистрируется позицией в `registry/maintenance-queue.md` через Git Append File (запасной путь — Git Append; `second-brain-git` 8.3): № | что внести | куда | источник | дата смерти | статус. Позиция без даты смерти не существует. Номер берётся из свежего чтения непосредственно перед вызовом; однобуквенные префиксы A–Z в файле исчерпаны 2026-09-24, новые позиции берут двухбуквенный префикс. Текст позиции не должен содержать внутренних переводов строки: они разрывают строку таблицы, и колонки «Дата смерти» и «Статус» уезжают на другую физическую строку, из-за чего харвест видит позицию без даты смерти. Пересказ в чате и текст эстафеты регистрацией не являются. Очередь читает харвест (Р11).
- Харвест не сканирует внешние чаты: незарегистрированное обязательство для системы не существует.
**ПРОВЕРКА.** Позиция видна при обратном чтении очереди по `second-brain-git` 8.1 (без клона — Git Read Lines с pattern по номеру позиции); в ответе назван её номер.

## Р21. Чтение через посредника

**ТРИГГЕР.** Нужен ответ на вопрос, а не текст, и объект тяжёлый: ответ инструмента, справка Skill, архив, большой файл.

**ДЕЙСТВИЕ.** Выбор делается по одному признаку — можно ли сузить объект ДО попадания в контекст.
- Файл, любой — сужает сама сессия по правилу «чем читать» (second-brain-git 7.6; в среде с клоном grep и sed). Посредник на файле почти ничего не добавляет: замер Р-25 журнала `projects/kontext-reduktion/LOG.md` — посредники прочли 2 и 24 процента файлов, то есть сделали тот же срез, а выигрыш поверх среза съедается проверкой их ответа.
- Ответ инструмента, который приходит целиком и сужению не поддаётся — `get_workflow_details`, выдача грязного воркфлоу, длинная выдача внешнего API — отдаётся посреднику. Это его единственная ниша: замер Р-25 даёт 5,7 раза, и правилом 7.6 такой выигрыш недостижим.
- Правила, которые сессия исполняет САМА — контракт записи, контракт чтения, протокол, пункт Skill — посредником не читаются НИКОГДА. Исполнять можно только прочитанное; пересказ правила исполнением не является.

Заданием посреднику назначается вопрос, а не файл, и вменяется вернуть ответ, а не текст. Форма задания и ответа (Р-29 журнала `projects/kontext-reduktion/LOG.md`, правка 2026-10-09):
- При каждом факте ответа стоит адрес доказательства: для ответа инструмента — имя узла и путь в JSON или цитата до 80 знаков; для файла — путь и номер строки. Ничего не нашёл — пишет NOT_FOUND и перечисляет, где искал. Замер Р-29: лёгкая модель без адреса дала 7 верных из 8 и одно ложное «не найдено», с адресом — 8 из 8 при том же расходе.
- Вопросы одному посреднику задаются пакетом: основная цена посредника — его собственный старт, второй вопрос в том же задании обошёлся примерно в 10 процентов первого.
- Модель посредника по умолчанию — среднего класса. Самая лёгкая — только для буквального извлечения (имена, поля, ID, значения) и только с адресом доказательства. Имена моделей здесь не пишутся: они меняются чаще Skill.
Расход посредника замеру не подлежит: харнесс сообщает его не всегда (Р-25), а приборы наблюдения вокруг работы не наращиваются.

**ПРОВЕРКА.** Ответ посредника помечается ПРОЧИТАНО ПОСРЕДНИКОМ с именем объекта (Р15); факт без адреса доказательства и без NOT_FOUND считается не полученным. В таком виде он годится, чтобы направить следующий шаг сессии. В канон — файл repo, INDEX, реестр, позицию очереди, запись журнала — он не пишется, пока сессия не прочитала источник сама; тогда пометка становится ПРОЧИТАНО В ЭТОЙ СЕССИИ. Правило «кто читал источник, тот и прав» посредник не отменяет: прав тот, кто читал, а не тот, кто пересказал.
