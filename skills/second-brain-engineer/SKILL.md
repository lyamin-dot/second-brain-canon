## Р0. Два носителя — один разделитель

**ТРИГГЕР.** Любое действие с документом системы.
**ДЕЙСТВИЕ.** Определить носитель документа:
- Docs → этот Skill целиком.
- repo `lyamin-dot/second-brain-canon` → чтение и запись по `second-brain-git`; поведение (когда, зачем, с чьего согласия) — по этому Skill.
Носитель проекта — колонка «носитель канона» в `registry/projects.md`. Проект не найден там и нет INDEX в Docs — проекта не существует, не угадывать.
CORE живёт в repo (`core/`, состав — `core/MANIFEST.md`). Старый CORE в Docs (`1fnWdPUE695BYXhwkMe8Pkzncsi8jYBecH_66ELCcjo4`) — исторический источник, не читается для принятия решений.
**ПРОВЕРКА.** В ответе назван носитель и файл, из которого он прочитан (`registry/projects.md` / CORE Р.2).

## Р1. Старт сессии — Правило Феникса

**ТРИГГЕР.** Первое сообщение в любом Claude Project с мастер-промптом системы. Вне Project (Cowork, Claude Code) автоматически не применяется — см. Р16.
**ДЕЙСТВИЕ.**
Проект в Docs:
1. Прочитать INDEX проекта через gdocs-read — только Зону А, до разделителя ЗОНА Б. `read_file_content` для Docs запрещён (google-drive-docs §0). Зона А читается диапазоном строк (`fromLine`/`toLine`, google-drive-docs §3.5); полнота среза доказывается наличием строки SENTINEL внутри него, а не доверием к числу.
2. Вывести ОДНУ строку: «Контекст загружен: [проект] | [LAST_UPDATED] | Следующий шаг: [шаг]». Если LAST_UPDATED старше 7 дней — добавить «⚠️ Данные не обновлялись 7+ дней».
3. Обновить LAST_READ_BY_CLAUDE через gdocs-replace.
4. Молчать, ждать вопроса.
Проект в repo `[НОВОЕ 2026-09-07]`:
1. Прочитать meta/PENDING_RULES.md и projects/<имя>/STATE.md одним вызовом Git Read Batch (И-6 second-brain-git).
Вывести ОДНУ строку: «Контекст загружен: [проект] | STATE.md sha [первые 7] | PENDING sha [первые 7] | Следующий шаг: [шаг]». Полей LAST_UPDATED/LAST_READ у repo-файлов нет — актуальность даёт git log и blob sha, записи на старте нет.
Молчать, ждать вопроса.
**ПРОВЕРКА.** Строка одна. Не список, не «кратко». Для Docs — gdocs-replace вернул occurrencesChanged=1 и строка LAST_READ_BY_CLAUDE видна при обратном чтении.

## Р8. Команды

| Команда | Действие |
|---|---|
| !save | Р7. Единственная команда, читающая CORE целиком |
| !tasks | Задачи текущего проекта из Зоны А INDEX / STATE.md. CORE не читается |
| !priority [high/low/Xh] | Приоритеты по формуле МЕТКА × ВЕС; веса — registry/projects.md. CORE не читается |
| !inbox | Необработанный Inbox из Drive |
| !review | Зона А всех активных INDEX + STATE.md repo-проектов → дайджест + карта зависимостей |
| !status | Метаданные файлов + БЛОКЕРЫ с дедлайнами + INDEX старше 7 дней + РЕЕСТР ПРОТОКОЛОВ целиком, таблицей, все строки |
| !digest [период] | Дайджест CHANGELOG (по умолчанию 30 дней) |
| !map | Mind Map взаимосвязей как артефакт; источник — блоки СВЯЗИ |
| харвест | Р11. Команда проекта SYS, в мастер-промпты прочих проектов не входит |

Естественноязыковой эквивалент !status: любой вопрос «как дела с системой / что с протоколами / какой прогресс» = !status, с полным реестром, без отбора «интересных».

## Р9. Взаимосвязи и поиск документов

**ТРИГГЕР.** Действие затрагивает другой проект / просьба найти документ, паспорт, ссылку.
**ДЕЙСТВИЕ.** Затрагивает другой проект — сказать: «⚡ Это затрагивает [ПРОЕКТ]: [что]». Поиск: определить все связанные проекты → прочитать их INDEX целиком через gdocs-read (repo-проекты — STATE/PLAN) → извлечь ID и ссылки → только после этого внешние инструменты (n8n MCP, google_drive_search). Паспорта воркфлоу — по реестру `registry/` и N8N_INDEX, не по одному «привычному» INDEX.
**ПРОВЕРКА.** «Документ не найден» произносится только после полного обхода всех релевантных INDEX; google_drive_search чтение INDEX не заменяет.

## Р13. Права доступа

**Claude автономно:** создать INDEX / папку проекта; зарегистрировать в CORE; подготовить мастер-промпт; записать захваты при !save; обновить LAST_UPDATED / LAST_READ_BY_CLAUDE / STATE.md; перенести закрытую задачу в АРХИВ; записать баг / прогресс; дописать позицию в `registry/maintenance-queue.md`.
**Claude после «да»:** изменение воркфлоу n8n; удаление данных из INDEX и repo; изменение структуры INDEX или мастер-промпта (отдельным действием, текстом «было → стало»); действие, затрагивающее >3 нод.
**Андрей обязан (блокирует систему):** создать Claude Project и прислать URL; привязать credentials в n8n; решить об удалении; подтвердить структурные изменения; перезалить Skill; сохранить старый текст мастер-промпта файлом до вставки нового — текст живёт только в интерфейсе Anthropic, инструментом не читается и не откатывается. Наряд с DoD «промпт переключён» без этого файла не выдаётся.
**Андрей может безопасно:** wb_inbox / oz_inbox; executions и ручные запуски в n8n; данные в строках Sheets.
**Андрей не должен:** менять структуру INDEX напрямую; переименовывать/удалять воркфлоу без согласования; менять колонки Sheets; править середину функций Apps Script (только полная замена).

## Р14. Запреты

1. Деструктив без подтверждения. Формат: «Собираюсь [действие] на [объект]. Это изменит [что]. Подтверждаешь?» Любой объект: воркфлоу, строки Sheets, Drive, repo, >3 нод.
2. Структурные изменения INDEX и мастер-промпта попутно — без отдельного явного «да» Андрея в чате и без текста «было → стало». Исключение — критический баг, ломающий систему прямо сейчас.
3. Второй носитель одного документа. Docs или repo — одно.
4. «Отложить» без адреса: правку Skill, мастер-промпта или CORE — без позиции в `registry/maintenance-queue.md` с датой смерти (очередь читает харвест, Р11); прочую находку — без задачи в `labs/sys/` (Р16).
5. Считать запись выполненной по ответу инструмента (Р15).
6. Хранить в Skill ID и адреса, у которых есть реестр: документы Docs — CORE Р.2; git-канал и repo — `registry/`; таблицы Sheets и доменные детали — `n8n-workflow-registry`. Три реестра, три класса объектов, пересечений нет.

## Р15. Провенанс и верификация — единый стандарт

**ТРИГГЕР.** Любое утверждение о состоянии системы; любая запись.
**ДЕЙСТВИЕ.**
- Каждое утверждение помечается: ПРОЧИТАНО В ЭТОЙ СЕССИИ (файл), ПРОЧИТАНО ПОСРЕДНИКОМ (кто и какой объект — Р21) или ВСПОМНЕНО. Четвёртого нет; уверенность провенансом не является. Решение цитируется вместе со статусом — отметка об отмене часто стоит в хвосте.
- Конкретика (ID, пороги, версии) берётся из реестра в момент использования, не из текста задания. В задания пишутся правила поведения при неизвестном, не факты.
- Перед пакетной операцией — манифест реальных объектов, полученных чтением в этой сессии.
- Кто читал источник, тот и прав — независимо от роли в наряде и класса модели. Расхождение факта с ожиданием — стоп и вопрос, не тихая правка.
- Запись верифицируется ТОЛЬКО независимым перечитыванием: Docs — gdocs-read, счёт вхождений якоря или совпадение текста; repo — git-read, blob sha записанного = sha намеренного файла. `success: true`, `occurrencesChanged`, exec-ID, ответ инструмента — сигналы, не доказательства. Один стандарт для обоих носителей `[verified: 2026-09-07]`.
**ПРОВЕРКА.** В отчёте о записи названы файл, способ обратного чтения и совпавшая величина.

## Р16. Работа вне Claude Project и регистрация обязательств

**ТРИГГЕР.** Сессия в Cowork / Claude Code / GitHub Actions работает над проектом системы; либо любая сессия вскрыла факт, требующий правки CORE / SYS_INDEX / INDEX / Skill / мастер-промпта.
**ДЕЙСТВИЕ.**
- Феникс (Р1) вне Project автоматически не срабатывает; эстафета (`context-handoff`) — ручной мост, она не меняет ни один файл.
- Запись доступна из любой среды: git-канал и gdocs-* вызываются по HTTP, исполняет сервер n8n. Ограничение — дисциплина, не инструмент.
- Правка, которую сессия МОЖЕТ сделать (CORE, SYS_INDEX, INDEX, файлы repo) — делается до конца сессии, по правильному якорю, с верификацией Р15.
- Правка, которую сессия НЕ МОЖЕТ сделать (Skill, мастер-промпт — аккаунтный слой, правит только Андрей) — регистрируется позицией в `registry/maintenance-queue.md` через Git Append: № | что внести | куда | источник | дата смерти | статус. Позиция без даты смерти не существует. Номер берётся из свежего чтения непосредственно перед вызовом; однобуквенные префиксы A–Z в файле исчерпаны 2026-09-24, новые позиции берут двухбуквенный префикс. Текст позиции не должен содержать внутренних переводов строки: они разрывают строку таблицы, и колонки «Дата смерти» и «Статус» уезжают на другую физическую строку, из-за чего харвест видит позицию без даты смерти. Пересказ в чате и текст эстафеты регистрацией не являются. Очередь читает харвест (Р11).
- Харвест не сканирует внешние чаты: незарегистрированное обязательство для системы не существует.
**ПРОВЕРКА.** Позиция видна при git-read очереди после append; в ответе назван её номер.

## Р21. Чтение через посредника

**ТРИГГЕР.** Нужен ответ на вопрос, а не текст, и объект тяжёлый: ответ инструмента, справка Skill, архив, большой файл.

**ДЕЙСТВИЕ.** Выбор делается по одному признаку — можно ли сузить объект ДО попадания в контекст.
- Файл, любой — сужает сама сессия по правилу «чем читать» (second-brain-git 7.6; в среде с клоном grep и sed). Посредник на файле почти ничего не добавляет: замер Р-25 журнала `projects/kontext-reduktion/LOG.md` — посредники прочли 2 и 24 процента файлов, то есть сделали тот же срез, а выигрыш поверх среза съедается проверкой их ответа.
- Ответ инструмента, который приходит целиком и сужению не поддаётся — `get_workflow_details`, выдача грязного воркфлоу, длинная выдача внешнего API — отдаётся посреднику. Это его единственная ниша: замер Р-25 даёт 5,7 раза, и правилом 7.6 такой выигрыш недостижим.
- Правила, которые сессия исполняет САМА — контракт записи, контракт чтения, протокол, пункт Skill — посредником не читаются НИКОГДА. Исполнять можно только прочитанное; пересказ правила исполнением не является.

Заданием посреднику назначается вопрос, а не файл, и вменяется вернуть ответ, а не текст. Расход посредника замеру не подлежит: харнесс сообщает его не всегда (Р-25), а приборы наблюдения вокруг работы не наращиваются.

**ПРОВЕРКА.** Ответ посредника помечается ПРОЧИТАНО ПОСРЕДНИКОМ с именем объекта (Р15). В таком виде он годится, чтобы направить следующий шаг сессии. В канон — файл repo, INDEX, реестр, позицию очереди, запись журнала — он не пишется, пока сессия не прочитала источник сама; тогда пометка становится ПРОЧИТАНО В ЭТОЙ СЕССИИ. Правило «кто читал источник, тот и прав» посредник не отменяет: прав тот, кто читал, а не тот, кто пересказал.
