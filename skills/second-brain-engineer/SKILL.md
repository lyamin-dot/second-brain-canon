## Р0. Два носителя — один разделитель

**ТРИГГЕР.** Любое действие с документом системы.
**ДЕЙСТВИЕ.** Определить носитель документа:
- Docs → этот Skill целиком.
- repo `lyamin-dot/second-brain-canon` → чтение и запись по `second-brain-git`; поведение (когда, зачем, с чьего согласия) — по этому Skill.
Граница трёх Skills, одна для обоих носителей: этот Skill отвечает «что делать, когда и с чьего согласия»; `second-brain-git` — «как физически прочитать и записать файл репозитория»; `google-drive-docs` — то же для Google Docs и Sheets. Механика из них сюда не переписывается — только ссылка на пункт: копия расходится с источником (урок 2026-10-06, references/prompt-craft.md).
Носитель проекта — колонка «носитель канона» в `registry/projects.md`. Проект не найден там и нет INDEX в Docs — проекта не существует, не угадывать.
CORE живёт в repo (`core/`, состав — `core/MANIFEST.md`). Старый CORE в Docs (`1fnWdPUE695BYXhwkMe8Pkzncsi8jYBecH_66ELCcjo4`) — исторический источник, не читается для принятия решений.
**ПРОВЕРКА.** В ответе назван носитель и файл, из которого он прочитан: `registry/projects.md`; для Docs-проекта ID его INDEX — `registry/documents.md` (прежний CORE Р.2).

## Р6. Захват

**ТРИГГЕР.** В разговоре появилось то, чего ещё нет в каноне проекта: задача, идея, вопрос без ответа, решение, баг, результат, внешнее событие.
**ДЕЙСТВИЕ.** В конце того же ответа, не прерывая работу, одним блоком:
```
[ЗАХВАЧЕНО]
→ [<ТЕГ>] <Тип>: <текст>
```
Типы: Задача, Идея, Вопрос, Решение (с датой), Баг (симптом | причина, если известна), Результат (что исправлено → что получилось), Событие (внешнее: тариф, API, квота, версия, поведение платформы).
Тег — проект, которому факт принадлежит, а не проект, в котором идёт сессия. Баг n8n как платформы (узел, движок, SDK, MCP) — тег [N8N], адрес `projects/n8n/STATE.md`. Баг бизнес-воркфлоу другого проекта — тег того проекта и строка «⚡ Это затрагивает [ПРОЕКТ]: [что]» (Р9). Проект неясен — `[?] Не классифицировано: <текст>`, не угадывать.
Баг — сразу предложить записать, не ждать конца сессии. После трёх и более захватов подряд и в конце сессии с захватами — предложить !save. Пересказ уже записанного захватом не является.
Трение. Когда правило, процедура или инструмент мешают результату работы, сессия вправе отметить это одной строкой в ответе — «Трение: <что мешает> → <чему мешает>» — без разбора, без вопроса и без отдельного захвата. Это снятый запрет, а не обязанность и не ритуал: когда трения нет, строки нет. В канон трение попадает захватом типа Идея с тегом [SYS] только тогда, когда Андрей его подхватил. Основание: договорённость Андрея 2026-07-20, подтверждена им 2026-10-11 (ответ 7 записи Р-16 журнала `projects/archivarius/LOG.md`; урок У-53).
Три случая, которые не ждут !save (правка 2026-10-09, харвест 2026-10-08):
- **Смена предмета или цели работы** посреди проекта — отдельное решение, а не продолжение прежнего. Захват типа Решение, вопрос Андрею, и запись в журнал решений проекта (`second-brain-git` 11) до того, как работа продолжится по-новому. Частное решение, которое сессия приняла сама «по аналогии» с прежним, не спросив Андрея, в записи помечается словами «по аналогии, владельцу не задано». Прецедент: проект archive-recon начинался как разведка способа разбора архива, а фактически превратился в каталогизацию тестовой папки; разрыв нашёл посторонний читатель журнала, и цель пришлось переопределять задним числом (Р-13 и Р-14 журнала `projects/archive-recon/LOG.md`).
- **Созданный документ или таблица Google** регистрируется в `registry/documents.md` тем же шагом, которым создан, — до следующего шага работы, а не на !save: без строки в реестре следующая сессия объект не найдёт (так регистрировалась таблица-каталог в Р-13 журнала `projects/archive-recon/LOG.md`). Право на эту запись — Р13.
- **Факт, полезный соседнему проекту**, — захват с тегом соседа; на !save он ложится одной строкой в `STATE.md` соседа (если сосед ведёт раздел «От соседнего проекта» — туда) с пометкой «⚡ Это затрагивает <сосед>: что, где проверить». Сказанное в чате записью не считается: соседняя сессия чат не читает. Образец — `meta/DECLARATION_COMMON.md`, раздел 4.
**ПРОВЕРКА.** Захват виден в том же ответе, где возник; у каждой строки есть тег и тип. Смена цели — запись в журнале названа номером до продолжения работы; созданный документ — строка в `registry/documents.md` видна обратным чтением (Р15).

## Р14. Запреты

**ТРИГГЕР.** Любое действие. Назначен при раскладке 2026-10-20.

1. Деструктив без подтверждения. Формат: «Собираюсь [действие] на [объект]. Это изменит [что]. Подтверждаешь?» Любой объект: воркфлоу, строки Sheets, Drive, repo, >3 нод.
2. Структурные изменения INDEX и мастер-промпта попутно — без отдельного явного «да» Андрея в чате и без текста «было → стало». Исключение — критический баг, ломающий систему прямо сейчас.
3. Второй носитель одного документа. Docs или repo — одно.
4. «Отложить» без адреса: правку Skill, мастер-промпта или CORE — без позиции в `registry/maintenance-queue.md` с датой смерти (очередь читает харвест, Р11); прочую находку — без задачи в `labs/sys/` (Р16).
5. Считать запись выполненной по ответу инструмента (Р15).
6. Хранить в Skill ID и адреса, у которых есть реестр: документы Docs — `registry/documents.md` (прежний CORE Р.2); git-канал и repo — `registry/`; таблицы Sheets и доменные детали — `n8n-workflow-registry`. Три реестра, три класса объектов, пересечений нет. Таблица или документ, созданные сессией, регистрируются в `registry/documents.md` (Р6): Skill `n8n-workflow-registry` сессия не правит, а объект без адреса потеряется до ближайшей правки Skill.

## Р15. Провенанс и верификация — единый стандарт

**ТРИГГЕР.** Любое утверждение о состоянии системы; любая запись.
**ДЕЙСТВИЕ.**
- Каждое утверждение помечается: ПРОЧИТАНО В ЭТОЙ СЕССИИ (файл), ПРОЧИТАНО ПОСРЕДНИКОМ (кто и какой объект — Р21) или ВСПОМНЕНО. Четвёртого нет; уверенность провенансом не является. Решение цитируется вместе со статусом — отметка об отмене часто стоит в хвосте.
- Конкретика (ID, пороги, версии) берётся из реестра в момент использования, не из текста задания. В задания пишутся правила поведения при неизвестном, не факты.
- Перед пакетной операцией — манифест реальных объектов, полученных чтением в этой сессии.
- Кто читал источник, тот и прав — независимо от роли в наряде и класса модели. Расхождение факта с ожиданием — стоп и вопрос, не тихая правка.
- **Утверждение о состоянии** — «работает», «выключен», «опубликован», «внесено», «удалено» — пишется в `STATE.md`, INDEX, задачу или журнал только вместе со способом проверки: номер исполнения, поле ответа инструмента, строка объекта. Без способа проверки оно пишется как гипотеза — словом «Гипотеза (не проверена):». Основание: записи «работает по расписанию» дважды за неделю не пережили сверки с живым воркфлоу (Р-39 и Р-53 журнала `projects/wb-ue/LOG.md`).
- **Слово Андрея «сделал», «удалил», «внёс»** — для сессии провенанс ВСПОМНЕНО: Андрей помнит действие, объект сессия не видела. Задача, закрываемая по такому слову, закрывается только после чтения объекта; до чтения она открыта, а в ответе стоит «по словам Андрея, объект не прочитан». Прецедент — Андрей сказал «деактивировал», а поиск этой сессии показал воркфлоу активным (Р-126 журнала `projects/git-migration/LOG.md`, воркфлоу SYS INDEX Restore from Revision).
- **Условие, записанное раньше** — в задании, в старой записи, в памяти чата или в памяти Андрея («тот же ключ, что у git-write», «ждёт решения владельца»), — перед исполнением и перед вопросом Андрею перепроверяется по объекту и по оглавлению журнала проекта: оно могло устареть, а вопрос — быть уже решённым (Р-104 и Р-107 журнала `projects/git-migration/LOG.md`). Обещание в шапке документа («старые записи уезжают в такой-то архив») доказательством существования объекта не является: перед ссылкой объект ищут.
- **Утверждение об отсутствии** — «файла нет», «воркфлоу не существует», «журнала нет», «решения нет», «в Skill этого нет» — пишется и произносится только после поиска в собственном носителе объекта, и в ответе перечисляется, где искали. Носитель: воркфлоу — search_workflows или get_workflow_details на инстансе; файл — названный слой: живой Skill в `/mnt/skills/`, файл репозитория (в среде с клоном `git ls-files` и `grep`, без клона — Git Read Lines с pattern), документ Google Drive (поиск Drive); решение — оглавление журнала своего и соседнего проекта по словам темы, `STATE.md` и `PLAN.md` (`second-brain-git` 7.6). Отсутствие в реестре, в CORE или в памяти сессии — дефект регистрации, а не доказательство того, что объекта нет. Поиск документа по просьбе Андрея — Р9. Основание: 4 случая, последний датированный 2026-07-30 — за одни сутки журнал объявлен несуществующим при его ID в мастер-промпте, воркфлоу `M5dqSv2yiklnDXoP` объявлен выдуманным, и на этом ложном опровержении отменена верная правка CORE, файл INCIDENT_LOG.md объявлен несуществующим, хотя лежал в смонтированном Skill (JOURNAL_INCIDENTS, строки 113–124 и 211–215; урок У-78); ответ «решения нет» при решении, записанном в индексе проекта (WB_REVIEWS_INDEX, строка 1722; урок У-144) — уроки журнала `projects/archivarius/LOG.md`.
- **Идентификатор, число или дата в канон** — правило лежит в references/write-moment.md и читается перед такой записью (таблица «Что читать дальше»).
- Запись верифицируется ТОЛЬКО независимым перечитыванием: Docs — gdocs-read, счёт вхождений якоря или совпадение текста; repo — по `second-brain-git` 8.1: в среде с клоном `git fetch` и `git hash-object`, без клона — один вызов Git Read Lines с pattern по первой строке записанного; blob sha записанного = sha намеренного. `success: true`, `occurrencesChanged`, exec-ID, ответ инструмента — сигналы, не доказательства. Один стандарт для обоих носителей.
**ПРОВЕРКА.** В отчёте о записи названы файл, способ обратного чтения и совпавшая величина. Каждая строка о состоянии в записанном тексте несёт способ проверки или слово «Гипотеза».
