# SECOND BRAIN — ПОЛЕВОЙ РЕГЛАМЕНТ

Редакция 2026-10-20.

Формат каждого блока: **ТРИГГЕР** — когда применять. **ДЕЙСТВИЕ** — что делать, по порядку. **ПРОВЕРКА** — чем доказать, что сделано. Нет проверки — блок не закрыт.

**Один регламент для всех проектов.** Этот Skill — единственное место регламента Второго мозга для всех Claude Project: мастер-промпт проекта несёт только адрес проекта, триггер старта, слова-команды и особенности проекта (Р2), а старт, захват, !save и команды исполняются отсюда. Почему: копии регламента в нескольких мастер-промптах расходятся между собой за неделю. Основание: решение Андрея 2026-10-06, позиции AH-13 и AH-23 `registry/maintenance-queue.md`. Когда правка этого Skill начинает действовать — Р13 (references/permissions.md).

**Как устроен этот текст.** Каждое правило держит четыре вещи: что делать и когда; почему — механизм одной-двумя фразами; признак, если ситуация неочевидна; строку основания. Строка основания имеет вид «Основание: N случаев, последний <дата> — отчёт синтеза, правило <номер>»: адреса каждого случая лежат в таблице «правило → случаи» отчёта `meta/SYNTHESIS_second-brain-engineer_2026-10-20.md`, а не здесь. Решение или слово Андрея как основание пишется одной строкой с датой и местом записи, без отчёта. Рассказов случаев, номеров исполнений и истории правок в Skill нет: Skill читается целиком при каждом срабатывании, и каждая строка истории оплачивается в каждой сессии. Почему правило менялось — история коммитов зеркала `skills/second-brain-engineer/` и отчёты синтеза `meta/SYNTHESIS_*`. Правку этого Skill готовят по `meta/PROTOCOL_knowledge-synthesis.md`: кластер переписывается правилом, урок не дописывается. Основание: решения Андрея 2026-10-18 и 2026-10-20 (`labs/sys/t-knowledge-synthesis.md`, разделы «Решения Андрея 2026-10-18» и абзац «Решения Андрея 2026-10-20 по отчёту синтеза `second-brain-git`», пункт 5).

Пометка `[НОВОЕ 2026-09-07]` у правила значит: правило ждёт подтверждения Андрея. До подтверждения оно исполняется как написано; при возражении — спросить, не откатывать молча.

Номера пунктов общие для всех файлов Skill: ссылка «Р13» означает раздел Р13, в каком бы файле он ни лежал; таблица называет файл. Номера разделов прежние и при раскладке и синтезе не перенумеровываются: на них ссылаются другие файлы и другие Skills.

Правило раскладки по триггеру. Раздел, чья строка ТРИГГЕР называет конкретное событие или действие, лежит в references/ и назван в таблице ниже. В этом файле — разделы, чей ТРИГГЕР — «любое действие», «любое утверждение» или «любая запись», и два исключения: захват (Р6) — он срабатывает почти в каждом ответе; чтение через посредника (Р21) — решение о нём принимается до вызова инструмента, и из references/ его не открыли. Почему по триггеру: так постоянный слой, который модель читает при каждой загрузке Skill, не растёт от правил одного вида действия. Новое правило обязано назвать триггер, и триггер определяет файл; правило без триггера в Skill не входит. Основание: решение Андрея 2026-10-20 (`meta/PLAN_skill-layers_2026-10-20_v3.md`, раздел 2); исключение Р21 — 1 случай, последний 2026-10-20 — отчёт синтеза, правило «раскладка.Р21».

## Р0. Два носителя — один разделитель

**ТРИГГЕР.** Любое действие с документом системы.

**ДЕЙСТВИЕ.**
- Определить носитель документа. Docs → этот Skill целиком. Repo `lyamin-dot/second-brain-canon` → чтение и запись по `second-brain-git`; поведение (когда, зачем, с чьего согласия) — по этому Skill.
- Граница трёх Skills, одна для обоих носителей: этот Skill отвечает «что делать, когда и с чьего согласия»; `second-brain-git` — «как физически прочитать и записать файл репозитория»; `google-drive-docs` — то же для Google Docs и Sheets. Механика из них сюда не переписывается — только ссылка на пункт. Почему: копия механики расходится с источником, и сессия исполняет устаревшую. Основание: 1 случай, последний 2026-10-06 — отчёт синтеза, правило Р0.граница.
- Носитель проекта — колонка «носитель канона» в `registry/projects.md`. Проект не найден там и нет INDEX в Docs — проекта не существует, не угадывать.
- CORE живёт в repo (`core/`, состав — `core/MANIFEST.md`). Старый CORE в Docs (ID — `registry/documents.md`, строка CORE) — исторический источник, для принятия решений не читается.

**ПРОВЕРКА.** В ответе назван носитель и файл, из которого он прочитан: `registry/projects.md`; для Docs-проекта ID его INDEX — `registry/documents.md`.

## Р6. Захват

**ТРИГГЕР.** Любой ответ, в разговоре которого появилось то, чего ещё нет в каноне проекта: задача, идея, вопрос без ответа, решение, баг, результат, внешнее событие.

**ДЕЙСТВИЕ.** В конце того же ответа, не прерывая работу, одним блоком:
```
[ЗАХВАЧЕНО]
→ [<ТЕГ>] <Тип>: <текст>
```
- Типы: Задача, Идея, Вопрос, Решение (с датой), Баг (симптом | причина, если известна), Результат (что исправлено → что получилось), Событие (внешнее: тариф, API, квота, версия, поведение платформы).
- Тег — проект, которому факт принадлежит, а не проект, в котором идёт сессия. Баг n8n как платформы (узел, движок, SDK, MCP) — тег [N8N], адрес `projects/n8n/STATE.md`. Баг бизнес-воркфлоу другого проекта — тег того проекта и строка «⚡ Это затрагивает [ПРОЕКТ]: [что]» (Р9). Проект неясен — `[?] Не классифицировано: <текст>`, не угадывать.
- Баг — сразу предложить записать, не ждать конца сессии. После трёх и более захватов подряд и в конце сессии с захватами — предложить !save. Пересказ уже записанного захватом не является.
- Трение. Когда правило, процедура или инструмент мешают результату работы, сессия вправе отметить это одной строкой в ответе — «Трение: <что мешает> → <чему мешает>» — без разбора, без вопроса и без отдельного захвата. Это снятый запрет, а не обязанность и не ритуал: когда трения нет, строки нет. В канон трение попадает захватом типа Идея с тегом [SYS] только тогда, когда Андрей его подхватил. Основание: договорённость Андрея 2026-07-20, подтверждена им 2026-10-11 — ответ 7 записи Р-16 журнала `projects/archivarius/LOG.md`.

Три случая, которые не ждут !save: каждый записывается тем шагом, на котором возник. Почему: следующая сессия читает канон, а не чат, и факт, отложенный до !save, до неё может не дойти.
- **Смена предмета или цели работы** посреди проекта — отдельное решение, а не продолжение прежнего. Захват типа Решение, вопрос Андрею и запись в журнал решений проекта (`second-brain-git` 11) — до того, как работа продолжится по-новому. Частное решение, которое сессия приняла сама «по аналогии» с прежним, не спросив Андрея, в записи помечается словами «по аналогии, владельцу не задано». Признак: делается уже не то, что записано целью в `PLAN.md` или INDEX. Основание: 1 случай, последний 2026-09-27 — отчёт синтеза, правило Р6.цель.
- **Созданный документ или таблица Google** регистрируется в `registry/documents.md` тем же шагом, которым создан, — до следующего шага работы. Без строки в реестре следующая сессия объект не найдёт. Право на эту запись — Р13. Основание: 1 случай, последний 2026-09-27 — отчёт синтеза, правило Р6.документ.
- **Факт, полезный соседнему проекту**, — захват с тегом соседа; тем же шагом, на котором узнан, он ложится одной строкой в `STATE.md` соседа с пометкой «⚡ Это затрагивает <сосед>: что, где проверить» — адрес и форма строки: `second-brain-git` 10.6. Сказанное в чате записью не считается: соседняя сессия чат не читает. Образец — `meta/DECLARATION_COMMON.md`, раздел 4. Основание: решение харвеста 2026-10-08 — отчёт синтеза, правило Р6.сосед; момент записи — разбор 6 файла `meta/SKILLS_MAP_resolution_2026-10-19.md`.

**ПРОВЕРКА.** Захват виден в том же ответе, где возник; у каждой строки есть тег и тип. Смена цели — запись в журнале названа номером до продолжения работы; созданный документ — строка в `registry/documents.md` видна обратным чтением (Р15).

## Р14. Запреты

**ТРИГГЕР.** Любое действие.

1. Деструктив без подтверждения. Формат: «Собираюсь [действие] на [объект]. Это изменит [что]. Подтверждаешь?» Любой объект: воркфлоу, строки Sheets, Drive, repo, >3 нод. Почему: удалённое и перезаписанное сессия сама не вернёт.
2. Структурные изменения INDEX и мастер-промпта попутно — без отдельного явного «да» Андрея в чате и без текста «было → стало». Исключение — критический баг, ломающий систему прямо сейчас.
3. Второй носитель одного документа. Docs или repo — одно. Почему: два носителя расходятся, и неизвестно, какой прав.
4. «Отложить» без адреса: правку Skill, мастер-промпта или CORE — без позиции в `registry/maintenance-queue.md` с датой смерти (очередь читает харвест, Р11); прочую находку — без задачи в `labs/sys/` (Р16). Почему: отложенное без адреса не прочтёт ни одна следующая сессия.
5. Считать запись выполненной по ответу инструмента (Р15).
6. Хранить в Skill ID и адреса, у которых есть реестр: документы Docs — `registry/documents.md`; git-канал и repo — `registry/`; таблицы Sheets и доменные детали — `n8n-workflow-registry`. Три реестра, три класса объектов, пересечений нет. Таблица или документ, созданные сессией, регистрируются в `registry/documents.md` (Р6): Skill `n8n-workflow-registry` сессия не правит, а объект без адреса потеряется до ближайшей правки Skill.

**ПРОВЕРКА.** Перед действием из запретов 1 и 2 в чате видны вопрос в названном формате или текст «было → стало» и «да» Андрея; у отложенной правки или находки назван адрес — позиция Очереди или задача `labs/sys/`; запись считается выполненной только по обратному чтению (Р15).

## Р15. Провенанс и верификация — единый стандарт

**ТРИГГЕР.** Любое утверждение о состоянии системы; любая запись.

**ЗАКОН.** Утверждение верно только для того чтения объекта, из которого оно взято. Всё, чего сессия не прочитала в самом объекте, — память, пересказ или старая запись, и решение на этом не принимается: объект читается до решения, либо утверждение пишется словами «Гипотеза (не проверена):». Ответ посредника (Р21) годится, чтобы выбрать следующий шаг, но не для записи в канон, пока сессия не прочитала источник сама. Почему: записанное когда-то выглядит как факт, закрывает поиск и молча стареет — следующая сессия не ищет того, что «уже известно». Основание: решение Андрея 2026-10-18 — пилот принят целиком (`labs/sys/t-knowledge-synthesis.md`, «Решения Андрея 2026-10-18», пункт 3).

**ДЕЙСТВИЕ.**
1. Каждое утверждение несёт метку происхождения: ПРОЧИТАНО В ЭТОЙ СЕССИИ (файл), ПРОЧИТАНО ПОСРЕДНИКОМ (кто и какой объект — Р21) или ВСПОМНЕНО. Четвёртой метки нет; уверенность происхождением не является. Решение цитируется вместе со статусом: отметка об отмене часто стоит в хвосте записи. Кто читал источник, тот и прав — независимо от роли в наряде и класса модели. Расхождение факта с ожиданием — стоп и вопрос, не тихая правка.
2. **Слово Андрея** «сделал», «удалил», «внёс» — для сессии ВСПОМНЕНО: Андрей помнит действие, а объект сессия не видела. Задача, закрываемая по такому слову, закрывается только после чтения объекта; до того она открыта, а в ответе стоит «по словам Андрея, объект не прочитан». Основание: 1 случай, последний 2026-10-01 — отчёт синтеза, правило Р15.слово.
3. Что считается чтением объекта — по виду утверждения:

| Вид утверждения | Что прочитать до решения или до записи в канон | Что чтением не считается |
|---|---|---|
| **Утверждение о состоянии**: «работает», «выключен», «опубликован», «внесено», «удалено» — в `STATE.md`, INDEX, задачу, журнал | номер исполнения, поле ответа инструмента или строку объекта; способ проверки пишется рядом с утверждением, без него — «Гипотеза (не проверена):» | прежняя запись о состоянии |
| **Причинное объяснение**: «X случилось потому, что Y», «не работает из-за Y», «откатилось, потому что» — в канон и в текст правила | пробу на объекте: запись, запрос или прогон, где меняется только предполагаемая причина и результат меняется вместе с ней; до пробы — «Гипотеза (не проверена):» | совпадение по времени, правдоподобный механизм |
| **Описание объекта**: описание воркфлоу в n8n, паспорт, строка реестра, пометка в карте, строка Skill о воркфлоу или листе — перед решением выключить, считать тестовым, считать подключённым, считать, что у листа нет читателя | определение воркфлоу, сам лист, исполнение | само описание |
| **Условие, записанное раньше**: в задании, в старой записи, в памяти чата или в памяти Андрея («тот же ключ, что у git-write», «ждёт решения владельца»); обещание в шапке документа («старые записи уезжают в такой-то архив») — перед исполнением и перед вопросом Андрею | объект и оглавление журнала проекта: условие могло устареть, вопрос — быть уже решённым; перед ссылкой на объект его ищут | само условие |

| **Идентификатор, число или дата в канон** | правило — references/write-moment.md, читается перед такой записью (таблица «Что читать дальше») | — |

Носитель для поиска отсутствия: воркфлоу — search_workflows или get_workflow_details на инстансе (воркфлоу целиком, когда нужен только ответ, — через посредника, Р21); файл — названный слой: живой Skill в `/mnt/skills/`, файл репозитория (в среде с клоном `git ls-files` и `grep`, без клона — Git Read Lines с pattern), документ Google Drive (поиск Drive); решение — оглавление журнала своего и соседнего проекта по словам темы, `STATE.md` и `PLAN.md` (`second-brain-git` 7.6). Поиск документа по просьбе Андрея — Р9.

## Р21. Чтение через посредника

**ТРИГГЕР.** Перед вызовом инструмента, чей ответ нельзя сузить до попадания в контекст: `get_workflow_details` воркфлоу целиком, когда сумма узлов всех воркфлоу, которые задача требует прочитать целиком, больше 100 (порог — ниже); выдача исполнения грязного воркфлоу; длинная выдача внешнего API. Решение принимается до вызова, а не по пришедшему ответу: что ответ тяжёлый, сессия узнаёт только после вызова, когда он уже в контексте. То же — когда нужен ответ на вопрос, а не текст, от справки Skill, архива или большого файла. Основание: 1 случай, последний 2026-10-20 — отчёт синтеза, правило Р21.триггер.

**ДЕЙСТВИЕ.** Выбор делается по одному признаку — можно ли сузить объект ДО попадания в контекст.
- Файл, любой — сужает сама сессия по правилу «чем читать» (`second-brain-git` 7.6; в среде с клоном grep и sed). Посредник на файле почти ничего не добавляет: он делает тот же срез, а выигрыш поверх среза съедается проверкой его ответа. Основание: 1 замер, 2026-09-24 — отчёт синтеза, правило Р21.файл.
- Ответ инструмента, который приходит целиком и сужению не поддаётся, — отдаётся посреднику. Это его единственная ниша: выигрыш на таком ответе измерен около 5,7 раза, и правилом 7.6 он недостижим. Основание: тот же замер — отчёт синтеза, правило Р21.файл.
- Порог для воркфлоу. Описание воркфлоу целиком отдаётся посреднику, только если сумма узлов всех воркфлоу, которые задача требует прочитать целиком, больше 100; при сумме до 100 включительно сессия читает их сама. Число узлов каждого воркфлоу сессия узнаёт до чтения: поле `nodeCount` в ответе `get_workflow_details` с `detailLevel: "execution"` — ответ около тысячи токенов, без узлов и кода. Почему: посредник окупается, только когда то, что он не пустит в контекст сессии, дороже его собственного старта, а старт стоит 80–110 тысяч токенов (Skill `avtopilot`, абзац «Когда раздавать субагенту»); полное описание стоит примерно от 350 до 850 токенов на узел, и порог взят с запасом — тысяча токенов на узел. Признак ошибки: размер ответа сессия видит только после вызова, когда он уже в контексте, поэтому решение по размеру ответа опоздало бы; число узлов видно до вызова. Объём кода в узлах Code число узлов не различает — для этого и запас. Основание: замер 2026-10-20 на трёх воркфлоу в 5, 8 и 19 узлов и решение Андрея 2026-10-20 о пороге по числу узлов — `labs/sys/t-knowledge-synthesis.md`, абзац «Порог Р21 по числу узлов — замер и решение 2026-10-20».
- Правила, которые сессия исполняет САМА — контракт записи, контракт чтения, протокол, пункт Skill, — посредником не читаются НИКОГДА. Исполнять можно только прочитанное; пересказ правила исполнением не является.
- Исключение по тому же основанию: воркфлоу, правку которого Андрей поручил в этой задаче или которая стоит в записанном пакете разрешения Р10, сессия читает сама (Р10, references/permissions.md). Диагностика «почему не работает» исключением не является, пока правка не названа: она подчиняется порогу, как любое чтение воркфлоу, — выше порога сначала ответ посредника, затем чтение для правки. Почему: правка опирается на текст объекта, а не на ответ о нём, — объект, над которым сессия действует, она читает сама, как и правило, которое исполняет. Посредник — только когда о воркфлоу нужен ответ, а не его текст для правки.

Заданием посреднику назначается вопрос, а не файл, и вменяется вернуть ответ, а не текст. Форма задания и ответа:
- Вопрос не несёт ожидаемого ответа и ожидаемой роли объекта. Почему: посредник, которому назвали ответ, ищет доводы за него, и проверка становится подтверждением подсказки. Основание: 1 случай, последний разобран 2026-10-10, дата самого случая в корпусе неизвестна — отчёт синтеза, правило Р21.подсказка; решение Андрея 2026-10-13 — запись Р-39 журнала `projects/archivarius/LOG.md`.
- При каждом факте ответа стоит адрес доказательства: для ответа инструмента — имя узла и путь в JSON или цитата до 80 знаков; для файла — путь и номер строки. Ничего не нашёл — пишет NOT_FOUND и перечисляет, где искал. Почему: без адреса лёгкая модель даёт ложное «не найдено», и его нечем поймать; с адресом ошибка видна при сверке. Основание: 1 замер, 2026-09-25 — отчёт синтеза, правило Р21.адрес.
- Вопросы одному посреднику задаются пакетом. Почему: основная цена посредника — его собственный старт; второй вопрос в том же задании стоит примерно десятую часть первого. Основание: тот же замер — отчёт синтеза, правило Р21.адрес.
- Модель посредника по умолчанию — среднего класса. Самая лёгкая — только для буквального извлечения (имена, поля, ID, значения) и только с адресом доказательства. Имена моделей здесь не пишутся: они меняются чаще Skill.

Расход посредника замеру не подлежит: харнесс сообщает его не всегда, а приборы наблюдения вокруг работы не наращиваются. Основание: замер 2026-09-24 — отчёт синтеза, правило Р21.расход; предпочтение Андрея 2026-09-03 не наращивать контрольные механизмы.
Не путать: проверка ответа двумя посредниками разных моделей не обязательна — её отклонили 2026-10-09 по тому же предпочтению Андрея 2026-09-03 (отчёт синтеза, правило Р21.непутать).

**ПРОВЕРКА.** Ответ посредника помечается ПРОЧИТАНО ПОСРЕДНИКОМ с именем объекта (Р15); факт без адреса доказательства и без NOT_FOUND считается не полученным. В таком виде он годится, чтобы направить следующий шаг сессии. В канон — файл repo, INDEX, реестр, позицию очереди, запись журнала — он не пишется, пока сессия не прочитала источник сама; тогда пометка становится ПРОЧИТАНО В ЭТОЙ СЕССИИ. Прочитать источник сам — достаточно прочитать адрес доказательства, который назвал посредник (одну строку файла, одно поле ответа инструмента); весь объект заново читать не нужно. Правило «кто читал источник, тот и прав» посредник не отменяет: прав тот, кто читал, а не тот, кто пересказал. Основание примирения: разбор 9 файла `meta/SKILLS_MAP_resolution_2026-10-19.md`.
