## Р7. !save

**ТРИГГЕР.** Команда !save; согласие Андрея на предложенный !save (Р6).
**ДЕЙСТВИЕ.**
1. Показать список [ЗАХВАЧЕНО] сессии одним блоком и сразу записывать: сама команда — согласие на запись этого списка. Строку, которую Андрей вычеркнет после, отменить новой записью, а не правкой задним числом.
2. Для каждой строки определить проект (тег захвата) и его носитель (Р0). Строка чужого проекта пишется в канон того проекта, с пометкой «⚡» в записи.

Проект в repo и лаборатория — как писать, решает `second-brain-git`, здесь не пересказывается:
3. Проект в repo — `second-brain-git` 10 (маршрут по файлам — 10.3, транспорт — 8.3, порядок нескольких файлов — 8.6, форма записи журнала — 11). Лаборатория — `second-brain-git` 4б (задача заводится и закрывается вместе с правкой `INDEX.md`). До первой записи в сессии прочитать нужную часть того Skill целиком.
4. Находка лаборатории без своей задачи — туда, куда велит мастер-промпт лаборатории (например, Зона Б её Docs-документа); промпт не велит — предложить Андрею завести задачу. Это решение о месте, а не механика записи, поэтому оно здесь.

Проект в Docs (изолированный контур):
5. Прочитать `registry/documents.md` для актуальных ID.
6. Маршрут записи: новая ОТКРЫТАЯ задача → gdocs-replace по якорю прямо в ОТКРЫТЫЕ ЗАДАЧИ Зоны А (не в хвост!); нарратив (РЕШЕНИЯ / ПРОГРЕСС / БАГИ / АРХИВ) → gdocs-append в Зону Б. gdocs-append кладёт в конец файла = Зона Б = невидимо на старте.
7. Закрытие задачи, стоящей в Зоне А, — тем же вызовом перенести строку в АРХИВ ЗАДАЧ. Закрытие фазы или решение уровня СЛЕДУЮЩЕГО ШАГА — тем же вызовом обновить строку СЛЕДУЮЩИЙ ШАГ Зоны А.
8. Обновить LAST_UPDATED отдельным вызовом: инструменты записи шапку не трогают.

Для всех носителей:
8а. Перед записью любой строки о состоянии («работает», «выключен», «внесено», «удалено») — у неё есть способ проверки: номер исполнения, поле, строка объекта; нет — строка пишется как «Гипотеза (не проверена):». Задача, которую Андрей назвал сделанной, закрывается только если объект прочитан в этой сессии; иначе она остаётся открытой с пометкой «по словам Андрея, объект не прочитан». Правило и основание — Р15.
8б. Документ или таблица Google, созданные в этой сессии и ещё не внесённые в `registry/documents.md`, — внести сейчас (правило — Р6). Опоздание до !save уже нарушение, но запись всё равно делается.
9. После правки воркфлоу n8n в этой сессии — ADR в паспорт воркфлоу (Skill `n8n-workflow-passport`).
10. Оценить CHANGELOG: было ли ЗАПУЩЕНО / СОЗДАНО / ЗАКРЫТО что-то, что теперь работает и используется; отдельные задачи и баги не в счёт. Если да — прочитать `core/R-13.md` (строка «запись в CHANGELOG» таблицы «По событию» манифеста) и дописать через gdocs-append в Google Doc CHANGELOG (ID — `registry/documents.md`, строка CHANGELOG) по форме:
    ```
    ДАТА | СТАТУС | ПРОЕКТ | Что достигнуто
      Что изменилось: <в чём польза, что стало лучше>
      Темп: <быстро / нормально / медленно + почему>
    ```
    СТАТУС только из словаря ЗАПУЩЕНО / СОЗДАНО / ЗАКРЫТО (один; «СОЗДАНО+ЗАПУЩЕНО» = ЗАПУЩЕНО); ПРОЕКТ только из списка весов `registry/projects.md`, значения «A + B» запрещены, изолированные контуры с пометкой off-CORE. Значение вне словаря приводится к ближайшему, и это говорится вслух. Андрей ничего дополнительного не пишет.
11. Если сущность именованная и переиспользуемая (PROTOCOL_*, §-пункт Skill, воркфлоу n8n многократного применения) — строка в РЕЕСТР ПРОТОКОЛОВ — отдельный документ SYS_PROTOCOL_REGISTRY, ID в `registry/documents.md` (не SYS_INDEX: тот заморожен 2026-09-23): протокол | дата рождения | применений | последнее применение | статус 🟢 доказан / 🟡 внедрён / 🔴 не используется.
12. Если сессия вскрыла факт, требующий правки CORE / задачи `labs/sys/` / Skill / мастер-промпта — Р16.
**ПРОВЕРКА.** Каждая запись — независимым обратным чтением: repo — `second-brain-git` 8.1 (blob sha записанного равен намеренному); Docs — gdocs-read, якорь найден ровно один раз, содержимое совпадает. В отчёте названы файл, способ обратного чтения и совпавшая величина (Р15). `success: true` и exec-ID проверкой не являются.

## Р12. Гигиена Зоны А

Правило A — аккумуляторы вне hot-path: ИДЕИ, ВОПРОСЫ, объёмный каталог ИНСТРУМЕНТЫ живут в Зоне Б, в Зоне А — указатели.
Правило B — маршрутизация захвата: см. Р7 п.4.
Правило Навигации — поведенческие правила, специфичные для проекта, вносятся в Зону А INDEX как проектный контент, не в замороженный промпт.
Правило второго раза — рецидив бага/паттерна в одном проекте: записать КЛАСС в НАКОПЛЕННЫЙ ОПЫТ → Ошибки и решения: симптом + причина класса + превентив + момент-триггер.
Карта воркфлоу проекта — снимок `registry/n8n-map.md` (состав, расписания, связи между воркфлоу), паспорта — `n8n-workflow-passport`. Отдельная карта SYSTEM-MAP по протоколу PROTOCOL_system-map больше не ведётся и не читается как действующая: её заменил снимок (`projects/n8n/STATE.md`, строка долга Н-26.08-02, сверено 2026-10-06). Прежние карты и сам протокол (ID — `registry/protocols.md`) — исторические источники.
