# second-brain-engineer — !save и гигиена Зоны А

Часть Skill second-brain-engineer. Читать: перед командой !save в проекте любого носителя и перед записью в Зону А INDEX, целиком. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

Правка 2026-09-24, вторая (решение Р-111 журнала `projects/git-migration/LOG.md`, решения Р-3 и Р-5 журнала `projects/kontext-reduktion/LOG.md`). Блок !save: CORE читается по таблице «Список» Манифеста плюс строке таблицы «По событию», которая называет !save; `meta/header.md` не читается; сверка byteLength с текстом снята — воркфлоу считает byteLength из тех же байт, что и text, и сверка ничего не доказывала (second-brain-git 7.1).

## Р7. !save

**ТРИГГЕР.** Команда !save.
**ДЕЙСТВИЕ.**
1. Показать список [ЗАХВАЧЕНО] для подтверждения.
2. Для каждой записи определить проект и носитель (Р0). Проект в repo — дальше `second-brain-git`, раздел «save». Ниже — только Docs.
3. Прочитать CORE Р.2 (repo) для актуальных ID.
4. Маршрут записи: новая ОТКРЫТАЯ задача → gdocs-replace по якорю прямо в ОТКРЫТЫЕ ЗАДАЧИ Зоны А (не в хвост!); нарратив (РЕШЕНИЯ / ПРОГРЕСС / БАГИ / АРХИВ) → gdocs-append в Зону Б. gdocs-append кладёт в конец файла = Зона Б = невидимо на старте.
5. Закрытие задачи, стоящей в Зоне А, — тем же вызовом перенести строку в АРХИВ ЗАДАЧ.
6. Закрытие фазы или решение уровня СЛЕДУЮЩЕГО ШАГА — тем же вызовом обновить строку СЛЕДУЮЩИЙ ШАГ Зоны А.
7. Обновить LAST_UPDATED.
8. Оценить CHANGELOG: было ли ЗАПУЩЕНО / СОЗДАНО / ЗАКРЫТО что-то, что теперь работает. Если да — запись по контракту CORE §13: СТАТУС только из словаря ЗАПУЩЕНО / СОЗДАНО / ЗАКРЫТО (один; «СОЗДАНО+ЗАПУЩЕНО» = ЗАПУЩЕНО); ПРОЕКТ только из CORE Р.1, значения «A + B» запрещены, изолированные контуры с пометкой off-CORE. Значение вне словаря приводится к ближайшему и это говорится вслух.
9. Если сущность именованная и переиспользуемая (PROTOCOL_*, §-пункт Skill, воркфлоу n8n многократного применения) — тем же вызовом строка в РЕЕСТР ПРОТОКОЛОВ (SYS_INDEX): протокол | дата рождения | применений | последнее применение | статус 🟢 доказан / 🟡 внедрён / 🔴 не используется.
10. Если сессия вскрыла факт, требующий правки CORE / SYS_INDEX / Skill / мастер-промпта — Р16.
**ПРОВЕРКА.** Каждая запись — независимым обратным чтением через gdocs-read: якорь найден ровно один раз, содержимое совпадает. `success: true` и exec-ID проверкой не являются (см. Р15).

## Р12. Гигиена Зоны А

Правило A — аккумуляторы вне hot-path: ИДЕИ, ВОПРОСЫ, объёмный каталог ИНСТРУМЕНТЫ живут в Зоне Б, в Зоне А — указатели.
Правило B — маршрутизация захвата: см. Р7 п.4.
Правило Навигации — поведенческие правила, специфичные для проекта, вносятся в Зону А INDEX как проектный контент, не в замороженный промпт.
Правило второго раза — рецидив бага/паттерна в одном проекте: записать КЛАСС в НАКОПЛЕННЫЙ ОПЫТ → Ошибки и решения: симптом + причина класса + превентив + момент-триггер.
SYSTEM-MAP — для проектов с 3+ координирующимися воркфлоу; канон — PROTOCOL_system-map (CORE Р.2), паспорта — `n8n-workflow-passport`.
