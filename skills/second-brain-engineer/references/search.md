## Р9. Взаимосвязи и поиск документов

ЗАКОН РАЗДЕЛА. Ответ ищется сначала в каноне проектов, которые его держат, и только потом внешним поиском. Почему: ID и ссылки проекта записаны в его каноне; внешний поиск находит только совпавшее по имени, и его «не нашёл» ничего не доказывает (Р15, утверждение об отсутствии). Решённое в одном проекте лежит в его журнале, и сессия, не заглянувшая туда, изобретает то же заново.

**ТРИГГЕР.** Действие затрагивает другой проект / просьба найти документ, паспорт, ссылку / перед проектированием шага, который мог быть решён у соседа.
**ДЕЙСТВИЕ.**
- Затрагивает другой проект — сказать: «⚡ Это затрагивает [ПРОЕКТ]: [что]».
- Поиск: определить все связанные проекты → прочитать их INDEX целиком через gdocs-read (repo-проекты — STATE/PLAN) → извлечь ID и ссылки → только после этого внешние инструменты (n8n MCP, google_drive_search). Не по одному «привычному» INDEX.
- Перед проектированием нового шага, который может уже быть решён у соседа, — оглавление журнала соседа по теме (`second-brain-git` 7.6, в среде с клоном — `grep`): решённое в одном проекте в другом не изобретается заново (`meta/DECLARATION_COMMON.md`, раздел 4, пункт 5).
- Паспорта воркфлоу — по маршруту Skill `n8n-workflow-passport`, стадия 1 «Найти паспорт»: строка PASSPORT в description воркфлоу (искать без учёта регистра), затем имя документа в папке DOCS проекта; полный порядок путей — там. Живой состав воркфлоу и их связи — снимок `registry/n8n-map.md`.

Основание: правило общей декларации проектов — `meta/DECLARATION_COMMON.md`, раздел 4, пункт 5.
**ПРОВЕРКА.** «Документ не найден» произносится только после полного обхода всех релевантных INDEX, и в ответе перечислено, где искали; google_drive_search чтение INDEX не заменяет.
