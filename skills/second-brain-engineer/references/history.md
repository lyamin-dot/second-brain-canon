# second-brain-engineer — история правок

Часть Skill second-brain-engineer. Читать: по вопросу, почему правило этого Skill изменилось. Действующих правил здесь нет: каждое, о котором говорит история, стоит в своём пункте SKILL.md или references/. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

Правка 2026-09-16 (решения Р-89, Р-90, Р-91 журнала `projects/git-migration/LOG.md`): цикл обслуживания CORE Раздела 12 снят; Р11 «Обслуживание» заменён на Р11 «Харвест» с процедурой в `meta/PROTOCOL_harvest.md`; слово «обслуживание» как шлюз структурных правок заменено явным «да» Андрея с текстом «было → стало» (Р2, Р13, Р14); очередь правок и перепроверка правил (Р16, Р17) читает харвест; правило C в Р12 снято.

Правка 2026-09-24 (наряд Н-24.09-02, приёмка по объекту). Две правки, обе в блоке команд. Первая: «харвест» снят из эталонного списка команд Р2 и из чеклиста Р3. Основание — Р11 этого Skill и `meta/PROTOCOL_harvest.md` раздел «Кто читает и когда» ограничивают команду проектом SYS, а Р2 и Р3 требовали её от каждого мастер-промпта; чеклист с неверным пунктом производил ложные дефекты (прецедент 2026-09-24, позиция A-1 очереди правок, пункт 3). Охват команды в решениях Р-89…Р-91 не обсуждался — это пробел, унаследованный протоколом от снятого цикла Раздела 12, и сужение Р2/Р3 есть новое решение владельца, а не восстановление утраченного правила. Вторая: CORE читается при `!save`, а не при каждой команде — `!tasks` оплачивал десять файлов канона ради списка задач, который уже лежит в Зоне А, и ни одно правило CORE в его исполнении не участвует.

Правка 2026-09-26 (обход Skill после фазы Ф2 проекта n8n-map, сверка с репозиторием на эту дату). Ссылки «CORE Р.1», «CORE Р.2», «CORE Р.14» заменены прямыми адресами `registry/projects.md`, `registry/documents.md`, `registry/protocols.md`: разделы вынесены из core/ 2026-09-10 (Р-66 журнала `projects/git-migration/LOG.md`), и старая ссылка стоила лишнего чтения карты разделов. Реестр протоколов из !save и !status назван своим документом SYS_PROTOCOL_REGISTRY: прежний адрес «SYS_INDEX» неверен, а SYS_INDEX заморожен 2026-09-23. Правки, которые сессия делает сама, называют `labs/sys/` вместо SYS_INDEX. Мастер-промпт repo-проекта читает на старте meta/PENDING_RULES.md вместе со STATE.md — прежде эталон Р2 расходился со стартом Р1 и с инвариантом И-6 `second-brain-git`. В шаблон INDEX Р5 добавлена строка SENTINEL, без которой проверка старта Р1 неисполнима; форма снята с живого INDEX. Поиск паспорта в Р9 переведён на маршрут Skill `n8n-workflow-passport`. Проверка записи в repo (Р15, Р16) и чтение протокола харвеста (Р11) отданы правилам `second-brain-git` 8.1 и 7.6; регистрация в очереди — через Git Append File. В методе проектирования Р19 поиск прецедента переведён на оглавление журналов вместо указателя DECISIONS_MAP; убраны ссылки на несуществующий «ниже» текст и на позиции очереди, уже закрытые. Ссылка вводного абзаца на Р-13 журнала kontext-reduktion исправлена: Р-13 нарезки этого Skill не касается.

Правка 2026-09-27 (Р-113 журнала `projects/git-migration/LOG.md`, решение владельца). Снят пункт Р17 «Период полураспада правил» — метки `[verified: дата]` и перепроверка правил старше 90 суток. Во всех Skills стояли две такие метки, обе в определении самого механизма и одна в Р15; правило «без метки — подтверждено на дату введения политики» делало шаг харвеста всегда нулевым, а заводить метки ради счёта значило бы наращивать контрольный механизм без читателя. Вместо него харвест задаёт владельцу вопросы пересмотра Skill `naryad`. Метка в Р15 снята, ссылки на Р17 в Р11 и Р20 заменены.

Правка 2026-10-06 (решение владельца в чате пересмотра мастер-промптов WB_UE, OZON_UE, WB_LOGISTICS, WB_REVIEWS и N8N; позиции очереди AH-13 и AH-23). Регламент Второго мозга собран в одно место — этот Skill. Причина: за неделю регламент оказался переписан в пяти мастер-промптах и в Skill, и копии разошлись — четыре формата строки старта, `!map` в одних промптах и снятая в других, адрес CHANGELOG то в промпте, то в реестре, а Р6 отправлял баг n8n в замороженный N8N_INDEX. Изменения. Описание Skill перечисляет слова-триггеры старта, команд и захвата: прежнее описание их не называло, и команда могла не вызвать Skill. Р1 получил ветки для repo-проекта и лаборатории с единым форматом строки старта и правило добавок проекта; ветка Docs оставлена для изолированных контуров. Р6 получил единый формат захвата блоком, тег проекта-владельца факта и маршрут бага n8n в `projects/n8n/STATE.md` (AH-23). Р8 переписан под repo: команды исполняются даже без перечисления в промпте, CORE ни одна команда целиком не читает (прежняя строка «!save — единственная команда, читающая CORE целиком» расходилась со всеми repo-промптами), `!priority` выводит задачу без метки отдельной строкой, `!inbox` и `!digest` получили адреса, `!map` стала командой проекта N8N, как харвест — команда SYS (AH-13). Р10: формат запроса с именем воркфлоу, исключение для записанного пакета разрешения, ADR в паспорт после правки. Р7 (references/save.md) разделён по трём носителям, получил форму записи CHANGELOG и перестал ждать отдельного подтверждения списка захватов: сама команда !save — согласие. Р2 (references/onboarding.md) — вместо полного эталонного мастер-промпта эталонный блок Второго мозга на двух языках; Р3 проверяет отсутствие пересказа регламента в промпте.
