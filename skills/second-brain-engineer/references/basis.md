# second-brain-engineer — основания правил и устройство Skill

Редакция 2026-10-22. Кто читает: синтез (`meta/PROTOCOL_knowledge-synthesis.md`), харвест, сессия, которая правит Skill или оспаривает правило. Исполнитель правил этот файл не читает: ему нужны условие, действие, «почему» и «не путать», и они остались в правиле. Ярлык `[основание: X]` в тексте правила разрешается строкой `- X (...)` ниже; продолжение многострочного основания — строки с отступом в два пробела. Сам текст оснований перенесён скриптом байт в байт (`meta/scripts/restructure_sbe_2026-10-22.py`).

## Устройство Skill

**Один регламент для всех проектов.** Этот Skill — единственное место регламента Второго мозга для всех Claude Project: мастер-промпт проекта несёт только адрес проекта, триггер старта, слова-команды и особенности проекта (Р2), а старт, захват, !save и команды исполняются отсюда. Почему: копии регламента в нескольких мастер-промптах расходятся между собой за неделю. Основание: решение Андрея 2026-10-06, позиции AH-13 и AH-23 `registry/maintenance-queue.md`. Когда правка этого Skill начинает действовать — Р13 (references/permissions.md).

**Как устроен этот текст.** Каждое правило держит четыре вещи: что делать и когда; почему — механизм одной-двумя фразами; признак, если ситуация неочевидна; строку основания. Строка основания имеет вид «Основание: N случаев, последний <дата> — отчёт синтеза, правило <номер>»: адреса каждого случая лежат в таблице «правило → случаи» отчёта `meta/SYNTHESIS_second-brain-engineer_2026-10-20.md`, а не здесь. Решение или слово Андрея как основание пишется одной строкой с датой и местом записи, без отчёта. Рассказов случаев, номеров исполнений и истории правок в Skill нет: Skill читается целиком при каждом срабатывании, и каждая строка истории оплачивается в каждой сессии. Почему правило менялось — история коммитов зеркала `skills/second-brain-engineer/` и отчёты синтеза `meta/SYNTHESIS_*`. Правку этого Skill готовят по `meta/PROTOCOL_knowledge-synthesis.md`: кластер переписывается правилом, урок не дописывается. Основание: решения Андрея 2026-10-18 и 2026-10-20 (`labs/sys/t-knowledge-synthesis.md`, разделы «Решения Андрея 2026-10-18» и абзац «Решения Андрея 2026-10-20 по отчёту синтеза `second-brain-git`», пункт 5).

**Как устроен Skill.** Этот файл читается всегда. Остальное лежит в references/ и читается перед своим действием, целиком, по таблице ниже. Номера пунктов общие для всех файлов Skill: ссылка «Р13» означает раздел Р13, в каком бы файле он ни лежал; таблица называет файл. Номера разделов прежние и при раскладке и синтезе не перенумеровываются: на них ссылаются другие файлы и другие Skills.

Правило раскладки по триггеру. Раздел, чья строка ТРИГГЕР называет конкретное событие или действие, лежит в references/ и назван в таблице ниже. В этом файле — разделы, чей ТРИГГЕР — «любое действие», «любое утверждение» или «любая запись», и два исключения: захват (Р6) — он срабатывает почти в каждом ответе; чтение через посредника (Р21) — решение о нём принимается до вызова инструмента, и из references/ его не открыли. Почему по триггеру: так постоянный слой, который модель читает при каждой загрузке Skill, не растёт от правил одного вида действия. Новое правило обязано назвать триггер, и триггер определяет файл; правило без триггера в Skill не входит. Основание: решение Андрея 2026-10-20 (`meta/PLAN_skill-layers_2026-10-20_v3.md`, раздел 2); исключение Р21 — 1 случай, последний 2026-10-20 — отчёт синтеза, правило «раскладка.Р21».

Поправка 2026-10-22 (контракт автопилота, `projects/kontext-reduktion/PLAN.md`): исключение для Р21 снято — раздел перенесён в references/intermediary.md со строкой таблицы «Что читать дальше». Что правило в файле по действию не нарушается, — гипотеза до поведенческого теста после заливки (`meta/TEST_skill-layers_2026-10-22.md`); нарушение в тесте возвращает Р21 в SKILL.md.
