# second-brain-engineer — полномочия, права доступа и калибровка исполнителя

Часть Skill second-brain-engineer. Читать: перед изменением воркфлоу n8n, перед действием, требующим «да» Андрея или его рук, и перед выдачей наряда, целиком. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md. Файл выделен из SKILL.md раскладкой по триггеру 2026-10-20: текст разделов перенесён без изменения.

## Р10. Воркфлоу n8n — полномочия

**ТРИГГЕР.** Любое изменение воркфлоу.
**ДЕЙСТВИЕ.** «Воркфлоу [имя], узел [имя]. Планирую: [описание]. Подтверждаешь?» → ждать явного «да». При отладке — сначала предложить копию воркфлоу. Исключение — пакет правок, на который Андрей дал одно разрешение и который записан списком задач в `STATE.md` или `LOG.md` проекта: в пределах списка узел и изменение называются вслух, повторного «да» не ждать; правка вне списка — снова по общему правилу. После правки — ADR в паспорт воркфлоу (Skill `n8n-workflow-passport`). Механика (параметры, credentials, шаблоны, ошибки, сбросы настроек при update_workflow) — `n8n-engineering-manual`, здесь не дублируется.
**ПРОВЕРКА.** «Да» Андрея есть в чате до вызова, либо задача названа в записанном пакете разрешения (адрес записи назван).

## Р13. Права доступа

**ТРИГГЕР.** Перед действием, которое требует «да» Андрея или его рук (удаление данных, изменение воркфлоу n8n, структуры INDEX или мастер-промпта, правка Skill, действие на 3 и более узла), перед записью, право на которую сессия не помнит, и перед выдачей наряда. Назначен при раскладке 2026-10-20.

**Claude автономно:** создать INDEX / папку проекта; зарегистрировать проект в `registry/projects.md` и ID его INDEX в `registry/documents.md` (прежние CORE Р.1 и Р.2); зарегистрировать в `registry/documents.md` документ или таблицу, созданные в сессии (Р6); подготовить мастер-промпт; записать захваты при !save; обновить LAST_UPDATED / LAST_READ_BY_CLAUDE / STATE.md; перенести закрытую задачу в АРХИВ; записать баг / прогресс; дописать позицию в `registry/maintenance-queue.md`.
**Claude после «да»:** изменение воркфлоу n8n; удаление данных из INDEX и repo; изменение структуры INDEX или мастер-промпта (отдельным действием, текстом «было → стало»); действие, затрагивающее >3 нод.
**Андрей обязан (блокирует систему):** создать Claude Project и прислать URL; привязать credentials в n8n; решить об удалении; подтвердить структурные изменения; перезалить Skill; сохранить старый текст мастер-промпта файлом до вставки нового — текст живёт только в интерфейсе Anthropic, инструментом не читается и не откатывается. Наряд с DoD «промпт переключён» без этого файла не выдаётся.
**Правка Skill действует только после перезаливки.** Живой Skill — тот, что лежит в Customize → Skills; многофайловый Skill (SKILL.md и папка references/) заливает Андрей zip-архивом там же, кнопка Save skill в Cowork для него не годится — она заменяет только SKILL.md (`google-drive-docs`, раздел 12). Текст правки, выданный в чате, записанный в зеркало `skills/` репозитория или в файл Drive, ничего не меняет, пока zip не залит. Почему: сессия видит Skill только снимком из аккаунта (`/mnt/skills/`) и только читает его. Признак: правка «внесена» по словам, а в снимке Skill старый текст. Поэтому правка Skill закрывается приёмкой по снимку в той сессии, которая на него опирается — по якорю правки или побайтово; механика приёмки, зеркала и сверки перед заливкой — `second-brain-git` 2.6. Основание: решение владельца В12 харвеста 2026-10-18 (`meta/HARVEST_2026-10-18_answers.md`: канон — живой Skill, зеркало — копия); запись Р-12 журнала `projects/kontext-reduktion/LOG.md` (многофайловый Skill — только zip); запись Р-32 того же журнала (заливка без сверки стёрла бы пункт живого Skill).
**Андрей может безопасно:** wb_inbox / oz_inbox; executions и ручные запуски в n8n; данные в строках Sheets.
**Андрей не должен:** менять структуру INDEX напрямую; переименовывать/удалять воркфлоу без согласования; менять колонки Sheets; править середину функций Apps Script (только полная замена).
