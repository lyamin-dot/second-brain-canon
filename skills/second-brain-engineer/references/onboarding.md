# second-brain-engineer — онбординг нового проекта

Часть Skill second-brain-engineer. Читать: «Создай проект», «заведи INDEX», новый Claude Project; перед выдачей любого мастер-промпта или его блока Второго мозга Андрею. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

## Р2. Эталонный блок Второго мозга в мастер-промпте

Регламент Второго мозга живёт в этом Skill, а не в мастер-промптах. Мастер-промпт несёт только четыре вещи: адрес проекта, триггер старта, слова, которые обязаны вызвать этот Skill, и особенности проекта. Основание (правка 2026-10-06): к 2026-10-06 регламент стоял в шести местах — пять мастер-промптов и этот Skill — и копии разошлись: четыре формата строки старта, `!map` в одних промптах и снятая в других, адрес CHANGELOG то в промпте, то в реестре, Skill отправлял баг n8n в замороженный документ. Одно место — одна правка на все проекты.

Блок меняется только отдельным действием после явного «да» Андрея в чате, текстом «было → стало» (Р13). В блок не вписываются правила, которые уже есть в Skill: дубль — дефект (Р3).

Docs-проект (изолированный контур, Р4 п.0) получает тот же блок; в строке канона вместо папки — «Google Doc <ИМЯ>_INDEX, ID — registry/documents.md».

Особенность проекта — правило, которого нет в Skill или которое для этого проекта отличается: своя строка старта, своё значение команды, свой маршрут находки, своё правило записи. Тон, роль, предмет и правила домена проекта — не особенности блока, а остальная часть мастер-промпта.

## Р3. Валидация мастер-промпта

**ТРИГГЕР.** Перед выдачей любого мастер-промпта или его блока Второго мозга Андрею.
**ДЕЙСТВИЕ.** Прогнать все пункты. Один не выполнен — промпт не выдавать.
- Тег — как в весах `registry/projects.md`; носитель и папка совпадают со строкой проекта в реестре.
- Блок называет Skill second-brain-engineer и четыре триггера: старт (Р1), слова-команды (Р8, все девять слов), захват (Р6), изменение воркфлоу (Р10).
- Регламент Второго мозга в промпте не пересказан: нет формата строки старта, маршрута !save, таблицы команд, формата захвата, порядка записи. Пересказ — дефект: копия разойдётся со Skill.
- Особенности проекта — только то, чего в Skill нет или что для проекта отличается; каждая особенность — одна строка с причиной.
- Docs-ID CORE и ID замороженных документов как источников состояния в промпте отсутствуют.
- Тон и роль — в проектной части промпта: неформально, на «ты», с иронией.
**ПРОВЕРКА.** Чеклист показан Андрею вместе с промптом, каждый пункт отмечен.

## Р4. Онбординг нового проекта

**ТРИГГЕР.** «Создай проект», «заведи INDEX», новый Claude Project.
**ДЕЙСТВИЕ.**
0. Выбрать носитель `[НОВОЕ 2026-09-07]`: по умолчанию — repo (`second-brain-git`, раздел «Новый проект»). Docs-INDEX заводится только для изолированного контура, который по PLAN_git-migration в repo не мигрирует (Tutor, DOSSIER, Justus и аналоги), или по прямому слову Андрея. Выбор назвать вслух до создания чего-либо.
1. Имя: repo — нижний регистр через дефис (`wb-logistics`); Docs — ДОМЕН_ТИП (`WB_LOGISTICS`). Вес — из `registry/projects.md`, секция «Проекты с INDEX в Google Docs» (прежний CORE Р.1).
2. repo: дальше по `second-brain-git` «Новый проект», затем п.6–7 здесь.
3. Docs: создать INDEX в INDEX_FOLDER (`1UV-7hP0L2jiwPAtulPZ1gket-mdz0ktT`) по шаблону Р5; верифицировать {id, title, mimeType} и обратным чтением через gdocs-read.
4. Docs: зарегистрировать проект в registry/projects.md (секция «Проекты с INDEX в Google Docs» — вес и карточка) и идентификатор его INDEX в registry/documents.md по контракту записи second-brain-git. Перед записью прочитать секцию проектов в registry/projects.md целиком — проект может быть зарегистрирован под другим именем; поиск подстроки отсутствие не доказывает.
5. Docs: убедиться, что Зона А заканчивается строкой SENTINEL и разделителем ЗОНА Б по шаблону Р5 — без них старт Р1 не может доказать, что Зона А прочитана до конца.
6. Подготовить мастер-промпт по методу Р22 (references/prompt-craft.md) с блоком Второго мозга (Р2), прогнать Р3, выдать Андрею. Андрей создаёт Claude Project сам и присылает URL.
7. URL Claude Project — в карточку проекта в registry/projects.md по контракту записи repo.
**ПРОВЕРКА.** Каждый шаг закрыт независимым чтением (Docs: gdocs-read; repo: git-read с blob sha) до начала следующего. Ответ инструмента проверкой не является.

## Р5. Шаблон INDEX (Docs)

```
[ИМЯ_ПРОЕКТА]_INDEX
LAST_UPDATED: YYYY-MM-DD
LAST_READ_BY_CLAUDE: —

ПРОЕКТ: [описание]
СТАТУС: [Активен / Заморожен / Не начат]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

РЕШЕНИЯ (лог)         [дата] [решение] — [контекст]
ПРОГРЕСС              [дата] [что сделано] → [результат]
БАГИ / ИНЦИДЕНТЫ      [дата] [проблема] → [решение]
АРХИВ ЗАДАЧ           [дата] [задача] → [результат]; при закрытии [ ]→[x] переносить сюда с датой
ИДЕИ (полный список)
ВОПРОСЫ БЕЗ ОТВЕТА (полный список)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Инструменты и паттерны   [YYYY-MM-DD] [инструмент/паттерн] — описание

Устаревшее (кандидаты на удаление)  удаляется только после подтверждения Андрея
```
Поля ENTRIES_COUNT нет — не искать; в старых INDEX оно ещё стоит и ничего не значит. ЗОМБИ — метка статуса задачи в Зоне А, отдельного блока нет.
Строка SENTINEL — последняя строка Зоны А, прямо перед заголовком «ЗОНА Б»: по ней Р1 доказывает, что срез Зоны А дочитан до конца. Шесть случайных знаков делают строку уникальной в документе. Форма снята с живого INDEX (TRADING_INDEX, строка «--- SENTINEL ЗОНА А | TRADING | 2026-07-24 | uhhju6 ---»); INDEX без этой строки проверку Р1 не проходит.
