## Р21. Чтение через посредника

**ТРИГГЕР.** Перед вызовом инструмента, чей ответ нельзя сузить до попадания в контекст: `get_workflow_details` воркфлоу целиком, когда сумма узлов всех воркфлоу, которые задача требует прочитать целиком, больше 100 (порог — ниже); выдача исполнения грязного воркфлоу; длинная выдача внешнего API. Решение принимается до вызова, а не по пришедшему ответу: что ответ тяжёлый, сессия узнаёт только после вызова, когда он уже в контексте. То же — когда нужен ответ на вопрос, а не текст, от справки Skill, архива или большого файла. [основание: intermediary-01]

**ДЕЙСТВИЕ.** Выбор делается по одному признаку — можно ли сузить объект ДО попадания в контекст.
- Файл, любой — сужает сама сессия по правилу «чем читать» (`second-brain-git` 7.6; в среде с клоном grep и sed). Посредник на файле почти ничего не добавляет: он делает тот же срез, а выигрыш поверх среза съедается проверкой его ответа. [основание: intermediary-02]
- Ответ инструмента, который приходит целиком и сужению не поддаётся, — отдаётся посреднику. Это его единственная ниша: выигрыш на таком ответе измерен около 5,7 раза, и правилом 7.6 он недостижим. [основание: intermediary-03]
- Порог для воркфлоу. Описание воркфлоу целиком отдаётся посреднику, только если сумма узлов всех воркфлоу, которые задача требует прочитать целиком, больше 100; при сумме до 100 включительно сессия читает их сама. Число узлов каждого воркфлоу сессия узнаёт до чтения: поле `nodeCount` в ответе `get_workflow_details` с `detailLevel: "execution"` — ответ около тысячи токенов, без узлов и кода. Почему: посредник окупается, только когда то, что он не пустит в контекст сессии, дороже его собственного старта, а старт стоит 80–110 тысяч токенов (Skill `avtopilot`, абзац «Когда раздавать субагенту»); полное описание стоит примерно от 350 до 850 токенов на узел, и порог взят с запасом — тысяча токенов на узел. Признак ошибки: размер ответа сессия видит только после вызова, когда он уже в контексте, поэтому решение по размеру ответа опоздало бы; число узлов видно до вызова. Объём кода в узлах Code число узлов не различает — для этого и запас. [основание: intermediary-04]
- Правила, которые сессия исполняет САМА — контракт записи, контракт чтения, протокол, пункт Skill, — посредником не читаются НИКОГДА. Исполнять можно только прочитанное; пересказ правила исполнением не является.
- Исключение по тому же основанию: воркфлоу, правку которого Андрей поручил в этой задаче или которая стоит в записанном пакете разрешения Р10, сессия читает сама (Р10, references/permissions.md). Диагностика «почему не работает» исключением не является, пока правка не названа: она подчиняется порогу, как любое чтение воркфлоу, — выше порога сначала ответ посредника, затем чтение для правки. Почему: правка опирается на текст объекта, а не на ответ о нём, — объект, над которым сессия действует, она читает сама, как и правило, которое исполняет. Посредник — только когда о воркфлоу нужен ответ, а не его текст для правки.

Заданием посреднику назначается вопрос, а не файл, и вменяется вернуть ответ, а не текст. Форма задания и ответа:
- Вопрос не несёт ожидаемого ответа и ожидаемой роли объекта. Почему: посредник, которому назвали ответ, ищет доводы за него, и проверка становится подтверждением подсказки. [основание: intermediary-05]
- При каждом факте ответа стоит адрес доказательства: для ответа инструмента — имя узла и путь в JSON или цитата до 80 знаков; для файла — путь и номер строки. Ничего не нашёл — пишет NOT_FOUND и перечисляет, где искал. Почему: без адреса лёгкая модель даёт ложное «не найдено», и его нечем поймать; с адресом ошибка видна при сверке. [основание: intermediary-06]
- Вопросы одному посреднику задаются пакетом. Почему: основная цена посредника — его собственный старт; второй вопрос в том же задании стоит примерно десятую часть первого. [основание: intermediary-07]
- Модель посредника по умолчанию — среднего класса. Самая лёгкая — только для буквального извлечения (имена, поля, ID, значения) и только с адресом доказательства. Имена моделей здесь не пишутся: они меняются чаще Skill.

Расход посредника замеру не подлежит: харнесс сообщает его не всегда, а приборы наблюдения вокруг работы не наращиваются. [основание: intermediary-08]
Не путать: проверка ответа двумя посредниками разных моделей не обязательна — её отклонили 2026-10-09 по тому же предпочтению Андрея 2026-09-03 (отчёт синтеза, правило Р21.непутать).

**ПРОВЕРКА.** Ответ посредника помечается ПРОЧИТАНО ПОСРЕДНИКОМ с именем объекта (Р15); факт без адреса доказательства и без NOT_FOUND считается не полученным. В таком виде он годится, чтобы направить следующий шаг сессии. В канон — файл repo, INDEX, реестр, позицию очереди, запись журнала — он не пишется, пока сессия не прочитала источник сама; тогда пометка становится ПРОЧИТАНО В ЭТОЙ СЕССИИ. Прочитать источник сам — достаточно прочитать адрес доказательства, который назвал посредник (одну строку файла, одно поле ответа инструмента); весь объект заново читать не нужно. Правило «кто читал источник, тот и прав» посредник не отменяет: прав тот, кто читал, а не тот, кто пересказал. [основание: intermediary-09]
