# n8n-workflow-passport

Паспорт воркфлоу — документ Google Docs, который отвечает на один вопрос: как воркфлоу работает, с чем связан, почему устроен именно так и какие у него ловушки. Жизнь документа идёт стадиями: найти, читать, родить, дозаписать, закрыть. Ищи стадию, на которой стоишь.

## Стоп-правила

### Что паспорт знает
- Что о воркфлоу держат другие носители (таблица «Что читать»), в паспорт не копировать.
- SYSTEM-MAP не читать как носитель связей: он не ведётся; указание «сначала читать SYSTEM-MAP» в старых планах проектов не исполнять.
- Собственные ID и имя воркфлоу в паспорт не вносить.

### Поиск и чтение
- Ни правку, ни отладку, ни разбор, ни запуск воркфлоу не начинать, не поискав паспорт (стадия 1).
- Строку паспорта в `description` не искать с учётом регистра.
- Паспорт найден — `get_workflow_details`, чтобы понять воркфлоу или ответить на вопрос о нём, не вызывать.
- Паспорт не читать целиком, когда нужна одна зона.
- Паспорт доказательством не считать: когда по прочитанному последует действие или вердикт (правка, аудит, приёмка, разбор отказа, наряд о поведении воркфлоу) — читать живой код.
- При расхождении паспорта с живым кодом код по паспорту не править — правится паспорт по коду.
- Без паспорта молча не работать: не найден ни одним путём — сказать Андрею прямо и выполнить стадию 3.
- Перед действием с воркфлоу не действовать, не назвав, что прочитано и откуда: зону паспорта и дату его последнего изменения или «паспорта нет, читал `get_workflow_details`»; фиксированная фраза подтверждением не считается.

### Рождение и строка PASSPORT
- Строку `PASSPORT:` в `description` существующего воркфлоу (созданного не этой сессией) сессия через MCP не вписывает — вписывает Андрей руками в настройках воркфлоу. В `description` нового воркфлоу, созданного этой сессией, строку вписывает сама сессия (стадия 3, пункт 5).
- Слово «вписал» проверкой не считать — только выдача `search_workflows`.
- «Паспорт создан» не говорить до проверки; проверка упала — паспорт созданным не считать.
- Заготовку «результат после приёмки» в строке ПРИЁМКА созданного паспорта не оставлять.
- Утверждение о поведении платформы, не проверенное пробой, фактом не писать — только словами «Гипотеза (не проверена):».
- Временному зонду паспорт не заводить.
- Строку «Паспорт → ID» в секции ИНСТРУМЕНТЫ INDEX проекта не вести.
- Ключ папки не подписывать своими словами — только `DOCS_FOLDER:`.

### Закрытие фазы
- Фазу плана или наряд, который создаёт или меняет воркфлоу, не закрывать без трёх вещей стадии 3а.
- Дозапись паспорта после правки на потом не переносить; сессию не закрывать без выполненного шага 2 стадии 4 либо явного отказа Андрея с причиной.

### Запись зон
- ADR не записывать без сверки строк ЗОНЫ А (ТРИГГЕР, СВЯЗИ, CREDENTIALS) и ЗОНЫ Б (СХЕМА, ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ).
- Неуникальную строку зоны А или Б не править дроблением — дописать новый блок с датой внутри зоны.
- Старые ADR-блоки ЗОНЫ В не редактировать и не удалять — только дозапись.
- Простой `gdocs-append` для ADR не применять: он пишет после маркера `%%ЗОНА_В_КОНЕЦ%%`, блок выпадает из зоны.
- Запись в паспорт не принимать по ответу инструмента (`success: true`) — только перечитыванием документа.
- Поле ПРИЁМКА в ADR не пропускать; доказательство в нём — объект воздействия или номер исполнения, не ответ инструмента.
- `alwaysOutputData: true` по умолчанию не ставить и не ставить ради «чтобы не обрывалось»; он оправдан, только когда пустой случай обрабатывает отдельная ветвь с явной проверкой на пустоту.

### Ненужный воркфлоу
- Паспорт не удалять никогда.
- Архивацию по умолчанию не предлагать; архивировать без решения владельца — только устаревшую версию инструмента, вытесненную новой.
- Снятие не записывать без причины — и тогда, когда паспорта у воркфлоу нет.

### Долг
- Числа долга паспортов в этот Skill не писать.
- Недостающие паспорта пачкой заранее не создавать — при следующем касании воркфлоу.

## Как делать

### Что паспорт знает, а что нет
Вносится обязательно:
1. ID и имена того, что воркфлоу вызывает и куда пишет (блок СВЯЗИ); запрет «собственные ID не вносить» на них не распространяется.
2. Имя привязанного credential у каждого узла и почему у узла именно этот ключ: кабинет, юрлицо, право чтения или записи. Имя списывается из объекта: `get_workflow_details` отдаёт у узла поле `credentials` с id и именем ключа. Отсутствие поля доказательством отсутствия ключа не считается.
3. Имя в паспорте расходится с полем `credentials` узла — правится паспорт по объекту.

### Стадия 1. Найти паспорт — первое действие перед любой работой с воркфлоу
Три пути по порядку; первое найденное останавливает поиск.
1. Строка паспорта в `description` воркфлоу — видна в выдаче `search_workflows`, без учёта регистра (`PASSPORT:` и `Passport:`).
2. Имя документа в Drive по схеме `[ПРОЕКТ]_WF_[имя-воркфлоу]` (раздел «Где хранятся паспорта»).
3. Строка воркфлоу в `registry/tools.md` — только для воркфлоу Git-канала, у которых паспорт там назван.

Найден — открыть по ID через `gdocs-read` и читать только нужную зону по маркерам (стадия 2).

Живой код читается и при найденном паспорте, когда следующий шаг — изменить воркфлоу, вынести о нём вердикт или поручить работу, исходя из того, как он себя ведёт:
- правка: сверка до и после записи — по `get_workflow_details` (Skill `n8n-engineering-manual`, разделы «Перед записью» и «После записи»);
- аудит, приёмка, разбор отказа, наряд о поведении воркфлоу — Skill `naryad`, «Выдача (Руководитель)».

Расхождение паспорта с кодом — дрейф паспорта: правится паспорт по стадии 4.

Не найден ни одним путём — читать `get_workflow_details`, сказать Андрею, что документации нет, выполнить стадию 3.

Перед действием назвать, что прочитано и откуда: зону паспорта и дату последнего изменения, либо «паспорта нет, читал `get_workflow_details`».

### Стадия 2. Читать — только нужную зону
Паспорт состоит из трёх зон; каждая открыта и закрыта уникальным маркером.

| Ситуация | Читать |
|---|---|
| касание воркфлоу, понять что это | ЗОНА А |
| изменение или отладка | ЗОНА А и ЗОНА Б |
| вопрос «почему выбрали такой подход» | ЗОНА В |
| создание нового паспорта или полная миграция | все три |

Выбор зоны сужает то, над чем сессия рассуждает, а не то, что приходит в контекст (Skill `google-drive-docs`, «Пути чтения»).

### Стадия 3. Родить паспорт
1. Убедиться, что папка DOCS проекта существует: ID — строка `DOCS_FOLDER:` в каноне проекта (раздел «Где хранятся паспорта»); найти — поиск по ключу `DOCS_FOLDER` в папке проекта. Папки нет — создать воркфлоу Create Folder (Skill `google-drive-docs`, разделы «Create Folder», «ID воркфлоу инструмента»).
2. Создать файл: `create_file` с `title: "[ПРОЕКТ]_WF_[имя-воркфлоу]"`, `contentMimeType: "text/plain"`, `textContent` — по шаблону ниже, `parentId` — ID папки DOCS. Подчёркивания в имени обязательны.
3. `create_file` отказал — Skill `google-drive-docs`, раздел «create_file отказал, а чтение работает»: копия существующего документа через `copy_file`, затем наполнение через `gdocs-overwrite`.
4. Взять ID из ответа `create_file`.
5. Строка `PASSPORT: <ID Google Doc>` в конце `description` воркфлоу, в ВЕРХНЕМ регистре — главный адрес паспорта.
   - Существующий воркфлоу: сессия даёт Андрею готовую строку на вставку и название воркфлоу; вписывает Андрей руками в настройках воркфлоу в редакторе.
      - Воркфлоу создан в этой же сессии: описание держать коротким, чтобы вместе со строкой PASSPORT оно уложилось в 255 знаков. Паспорта при создании воркфлоу ещё нет, поэтому строку сессия вписывает сама после создания паспорта — операцией `setWorkflowMetadata` вызова `update_workflow` (предел 255 знаков — раздел «Адреса и ловушки»); отдельного «да» Андрея это не требует: воркфлоу новый и создан этой сессией.
   - Проверка: строка видна в выдаче `search_workflows` по имени воркфлоу.
6. Только после проверки сказать «паспорт создан». Проверка упала — ID остаётся в чате резервной копией, об ошибке сказать прямо.
7. Строку ПРИЁМКА шаблона заменить результатом приёмки тем же шагом, что и создание. Непроверенное пробой утверждение о поведении платформы (например «это расписание никогда не сработает») — словами «Гипотеза (не проверена):», пока проба его не подтвердит.

Временный зонд — воркфлоу только для чтения, созданный, чтобы один раз снять факты: паспорта нет, итог — запись в журнал проекта (что снято, номер исполнения, ID зонда). Зонд понадобился снова и стал инструментом — паспорт создаётся при первой его правке.

### Стадия 3а. Фаза не закрыта без документации
Фаза плана или наряд, который создаёт или меняет воркфлоу, закрыт, когда есть:
1. паспорт по стадии 3 или новый ADR по стадии 4;
2. строка PASSPORT в `description`, видимая в выдаче `search_workflows`;
3. инструкция для человека, если воркфлоу запускает человек (форма, ручной запуск); где она лежит — решает план проекта.

Временного зонда это не касается.

### Стадия 4. Дозаписать после каждой правки воркфлоу
Продолжение протокола правки Skill `n8n-engineering-manual`; в той же сессии, где была правка.
1. Назвать паспорт, которого касается правка.
2. Паспорта нет — создать по стадии 3 сейчас. Паспорт есть — все три действия:
   - вставить ADR-блок перед маркером `%%ЗОНА_В_КОНЕЦ%%` (по «Правилу записи зон»);
   - сверить строки ЗОНЫ А — ТРИГГЕР, СВЯЗИ, CREDENTIALS — и ЗОНЫ Б — СХЕМА, ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ; правка добавила или убрала узлы — СХЕМА переписывается;
   - проверить результат перечитыванием документа.
3. Сессия не закрывается без шага 2 либо явного отказа Андрея с указанной причиной.

Claude следит, чтобы шаги не были пропущены; Андрей отвечает за содержание ADR — контекст, альтернативы, последствия.

#### Правило записи зон
- ЗОНА А и ЗОНА Б — `gdocs-replace` короткими уникальными однострочными якорями (выбор якоря — Skill `google-drive-docs`, «Запись в Google Docs»). Строка не уникальна — новый блок с датой внутри зоны.
- ЗОНА В — только дозапись.
- Новый ADR вставляется ПЕРЕД маркером `%%ЗОНА_В_КОНЕЦ%%` в порядке «блок, перевод строки, маркер»; инструмент — по размеру блока:

| Размер ADR-блока | Чем вставлять |
|---|---|
| до примерно 2 КБ | `gdocs-replace`: якорь `%%ЗОНА_В_КОНЕЦ%%` заменяется на (ADR-блок + перевод строки + тот же маркер) |
| крупнее примерно 2 КБ | `gdocs-apply-from-file`, `mode: "replace"`, `search` = `%%ЗОНА_В_КОНЕЦ%%`; текст ADR вместе с маркером — файлом на Drive |

ADR с подробной СХЕМОЙ или списком альтернатив легко переходит за несколько килобайт.
- После вставки перечитать документ.

### Стадия 5. Воркфлоу больше не нужен
Снятие с публикации и его проверка — Skill `n8n-engineering-manual`, раздел «Снятие с публикации». Что воркфлоу снят и почему, записывается туда, где проект хранит невзятое и снятое (обычно `NOT_TAKEN.md` или журнал проекта); причина обязательна и без паспорта.

Часть паспорта: у воркфлоу есть паспорт — вставить перед `%%ЗОНА_В_КОНЕЦ%%` строку (по «Правилу записи зон»):

```
СТАТУС: СНЯТ С ПУБЛИКАЦИИ [дата] — [причина; чем вытеснен, если вытеснен] — КАК ВЕРНУТЬ: [publish_workflow; что проверить перед возвратом, если есть]
```

Воркфлоу архивирован — та же строка со словом `АРХИВИРОВАН`, в поле КАК ВЕРНУТЬ — «владелец возвращает из архива руками в редакторе, затем publish_workflow». Архивирует без решения владельца сессия только устаревшую версию инструмента, вытесненную новой; в остальных случаях решает владелец.

### Где хранятся паспорта
1. Папка DOCS — отдельно для каждого проекта. Её ID — строкой `DOCS_FOLDER: [ID папки Google Drive]` там, где проект держит свои инструменты: у проекта в репозитории — его `PLAN.md`, раздел ИНСТРУМЕНТЫ; у лаборатории — её `INDEX.md`; у проекта, чей INDEX ещё в Google Docs, — секция ИНСТРУМЕНТЫ этого INDEX.
2. Поиск `DOCS_FOLDER` в папке проекта пуст, а паспорта у проекта есть — найти папку поиском по Drive и записать строку с ключом.
3. Имя файла — `[ПРОЕКТ]_WF_[имя-воркфлоу]`: `N8N_WF_gdocs-append` (Second Brain), `WB_WF_finance-sync` (Wildberries), `OZON_WF_intake` (Ozon). Схема имени — единственное, что находит паспорт поиском по Drive без строки в `description` (стадия 1, путь 2).

### Долг паспортов
1. Сколько живых воркфлоу без строки паспорта, с пустым `description` и с разным регистром строки — выводится заново одним вызовом `search_workflows`, строка ищется без учёта регистра. Текущие числа — `projects/n8n/STATE.md`, раздел «Паспорта воркфлоу».
2. Долг — и паспорт, который есть, но не назван ни в `description`, ни в `registry/tools.md`: его находит только поиск по имени.
3. Недостающий паспорт создаётся при следующем касании воркфлоу (стадия 3).

## Адреса и ловушки
- Адреса документов (N8N_REGISTRY и другие) — в реестре `registry/documents.md`; состав воркфлоу — `registry/n8n-map.md`.
- Операция `setWorkflowMetadata` инструмента `update_workflow` заменяет `description` целиком, а не дописывает: без прежнего текста в вызове описание молча пропадает, ошибка переноса молча портит его — проверяй выдачей `search_workflows`.
- `setWorkflowMetadata` принимает в `description` не больше 255 знаков, `create_workflow_from_code` молча сокращает описание до 255 знаков — строка PASSPORT в конце отрезается первой (предел взят из описания инструментов MCP, вызовом не проверен) — проверяй выдачей `search_workflows`.
- Склейка строк при вставке ADR не видна в ответе `success: true` — проверяй перечитыванием (Skill `google-drive-docs`, «Проверка записи»).
- Список воркфлоу не несёт поля `description` — строку паспорта ищи через `search_workflows` (Skill `n8n-engineering-manual`, «Инструменты MCP и отчёты»).

## Куда писать результат
- Паспорт — Google Doc `[ПРОЕКТ]_WF_[имя-воркфлоу]` в папке DOCS проекта; адрес — строка `PASSPORT:` в конце `description` воркфлоу.
- ADR и строка о снятии — перед маркером `%%ЗОНА_В_КОНЕЦ%%` паспорта.
- Итог временного зонда — журнал проекта.
- Снятый воркфлоу и причина — `NOT_TAKEN.md` или журнал проекта.
- ID папки DOCS — строка `DOCS_FOLDER:` в каноне проекта.
