# АВТОПИЛОТ

Редакция 2026-10-21. Владелец — Андрей.

Этот Skill не повторяет чужую механику. Ревизия — `denken`. Чтение и запись репозитория — `second-brain-git`. Форма вопроса посреднику — `second-brain-engineer`, правило «Чтение через посредника». Здесь только то, чего нет нигде: кто держит работу, когда Андрея нет рядом, и где она обязана остановиться.

Как устроен этот текст. Каждое правило держит четыре вещи: что делать и когда; почему; признак, если ситуация неочевидна; основание. Строка «Основание: N случаев, последний <дата> — отчёт синтеза, правило <id>» значит: адреса каждого случая лежат в отчёте `meta/SYNTHESIS_avtopilot_2026-10-21.md` репозитория lyamin-dot/second-brain-canon, в таблице «правило → случаи». Решение Skill и отвергнутые варианты — `meta/CASES_avtopilot.md`. Как менялся текст — история коммитов зеркала `skills/avtopilot/`. Правка этого Skill готовится по `meta/PROTOCOL_knowledge-synthesis.md`: урок не дописывается, кластер переписывается правилом.

## Зачем

Каждое короткое «да» Андрея заставляет модель заново обработать весь разросшийся разговор. Когда Андрей только соглашается, его реплики ничего не добавляют, а стоят каждый раз дороже предыдущего. Автопилот переносит согласование в одну точку — контракт запуска — и убирает Андрея из роли курьера между исполнителями.

Что измерено: в пилоте между согласием и итоговым отчётом от Андрея не потребовалось ни одного сообщения. Чего не измерено: сколько стоила бы та же работа без автопилота — сравнения нет. Основание: 1 пилот, 2026-10-13 — отчёт синтеза, правило AVT.цена.

## Пять ворот

Работа проходит ворота по порядку. Ворота не пройдены — дальше не идти.

### Ворота 1. Разговор — Андрей здесь

Сессия добивается четырёх вещей, коротко и без лишнего контекста:

1. **Квитанция рамки.** Цели Андрея отдельно, его предположения о способе отдельно, по каждому предположению — «оставляю» или «предлагаю снять, потому что» (метод проектирования, пункт 1, `second-brain-engineer` references/design.md).
2. **Критерий приёмки — наблюдаемый объект.** Не «проверено», а, например, «по каждому из восьми пунктов вердикт с адресом доказательства». Критерий без объекта — ворота не пройдены.
3. **Все ручные действия Андрея — одним списком сразу.** Это действия, которые сессия сделать не может: создать Claude Project, привязать ключ доступа в n8n, перезалить Skill, вставить мастер-промпт, открыть папку сервисному аккаунту. Список собирается в начале, а не всплывает по ходу: действие, о котором Андрей узнал посреди прогона, останавливает работу, которая шла без него.
4. **Стоп-список** (раздел ниже) дополняется особыми стопами этой работы.

### Ворота 2. Ревизия

Skill `denken`, уровень 2, при необратимой или разрушительной операции — уровень 3. Ревизия идёт по написанному плану. Отдельный пункт ревизии для автопилота: какие шаги действительно независимы. Если все шаги строго последовательны, параллельности не будет — это говорится вслух до запуска, а не обнаруживается после: тогда экономия автопилота сводится к отсутствию промежуточных «да» Андрея. Основание: вердикт решаемости ревизии, создавшей этот Skill, 2026-10-13 — отчёт синтеза, правило AVT.решение.

### Ворота 3. Контракт запуска — одно «да»

Контракт — один текст, записанный в канон до исполнения:
- repo-проект — раздел «Контракт автопилота» в `PLAN.md` проекта;
- лаборатория — сам файл задачи `t-<имя>.md`;
- если записать нельзя — блоком в чате, и тогда запись контракта становится первым шагом исполнения.

Поля контракта: цель; критерий приёмки; пакеты работы (у каждого — объекты, вопрос, ожидаемый результат-объект, класс модели); разрешённые правки списком; особые стопы.

Список разрешённых правок и есть пакет разрешения из правила о полномочиях на воркфлоу n8n (`second-brain-engineer`, раздел Р10 «Воркфлоу n8n — полномочия», references/permissions.md): правка из списка исполняется без повторного «да», правка вне списка — снова по общему правилу.

Согласием считается ответ Андрея на контракт: «да», «действуй», «запускай». Молчание согласием не считается.

### Ворота 4. Исполнение — Андрея нет

**Шина — сессия-диспетчер, а не Андрей.** В автономном режиме правило Skill `naryad` «Андрей — шина, роли между собой не общаются» не действует: диспетчер сам раздаёт работу субагентам и сам принимает их ответы. Вне автономного режима `naryad` не меняется; обратная оговорка стоит в самом `naryad`, раздел «2. Роли». Наряды в формате `naryad` внутри автопилота не печатаются: пакет контракта — не наряд. Почему исключение, а не новый маршрут внутри `naryad`: основа `naryad` («Андрей — шина») противоречит автономному режиму, и прививка сделала бы его противоречивым. Цена исключения — пропадает взгляд Андрея между шагами; её компенсирует независимая приёмка (Ворота 5). Основание: решение Андрея 2026-10-13 — отчёт синтеза, правило AVT.решение.

**Когда раздавать субагенту.** Старт одного субагента стоит около 80–110 тысяч токенов, почти всё — его собственный стартовый контекст. Поэтому:
- субагенту отдаётся только тяжёлое чтение, которое нельзя сузить до попадания в контекст — полный граф воркфлоу, длинная выдача внешнего API, большая пачка файлов;
- лёгкий шаг (одно чтение файла, одно число, одна запись) диспетчер делает сам;
- объекты группируются так, чтобы один старт обслуживал два-три объекта;
- независимые пакеты запускаются одним сообщением — тогда они идут параллельно.
Основание числа: 1 замер, 2026-10-13 — отчёт синтеза, правило AVT.замер-старта; группировки: 1 пилот (девять объектов на четыре субагента), 2026-10-13 — правило AVT.цена.

**Что умеет субагент.** Есть: инструменты n8n, Канал чтения репозитория, память, Google Drive, командная строка. Нет: запуска своих субагентов — глубина одна, как в `naryad`. Поэтому работа, которой нужен второй уровень раздачи, раздаётся диспетчером, а не субагентом. Основание: 1 зонд, 2026-10-13 — отчёт синтеза, правило AVT.зонд-субагента.

**Задание субагенту** — вопрос, а не файл, по форме посредника (`second-brain-engineer`, Р21 «Чтение через посредника»: вопрос без ожидаемого ответа, адрес доказательства при каждом факте, NOT_FOUND со списком мест, вопросы пакетом). Сверх неё:
- по умолчанию только чтение, и это написано в задании словами «READ-ONLY, ничего не менять»;
- у вопроса закрытый набор вердиктов (например, ЖИВ / ИСПРАВЛЕН / ИЗМЕНЁН);
- задание пишется на английском и компактно — субагент его читает, Андрей нет.

**Пишет в канон только диспетчер.** Так нет гонки записи внутри прогона, и правила записи `second-brain-git` читает одна сессия, а не каждая. Правила, которые диспетчер исполняет сам, он читает сам, а не через посредника.

**Перед правкой воркфлоу n8n** диспетчер перечитывает время последнего изменения воркфлоу (updatedAt) и сверяет его с прочитанным в начале. Расхождение — стоп: воркфлоу правит параллельная сессия, а правка в n8n перезаписывает граф без проверки версии (`labs/sys/t-n8n-workflow-race.md`).

**Долгое ожидание** (прогон воркфлоу на десятки минут или работа, которую нужно продолжить на следующий день) — два носителя, оба проверены прогоном, второй — не во всём:
- отложенное сообщение самому себе — возврат в ту же сессию. Берётся, когда продолжать должна та же сессия, с её контекстом. Основание: 5 срабатываний, последнее до 2026-10-13 — отчёт синтеза, правило AVT.ожидание.
- запланированная задача со свежей сессией. Свежая сессия не помнит разговора диспетчера, поэтому её задание пишется самостоятельным текстом: какие объекты прочитать, что проверить, куда записать итог; всё остальное она берёт из канона, а не из чата. Режим одобрения задачи называет ответ на её создание; если там не auto, такую задачу носителем автопилота не делать: по описанию инструмента создания задачи прогон без auto останавливается на первом действии, которое требует одобрения, а одобрить некому (зондом не проверялось). Зонд не проверял правку воркфлоу n8n, запуск субагентов, отправку сообщения Андрею и запись во внешние системы (маркетплейсы) из такой сессии — для этих действий она гипотеза; итог прогона подтвердила сама сессия, без независимой приёмки. Основание: 1 зонд, 2026-10-18 — отчёт синтеза, правило AVT.задача.
Не путать: «запланированная задача со свежей сессией ни разу не создавалась, режим одобрения неизвестен — носителем только после отдельного зонда» — так было до 2026-10-18; зонд состоялся, и она стала вторым носителем.

**Массовая механическая работа** — скриптом, а не моделью (`second-brain-engineer`, references/design.md, пункт 17; для файлов репозитория — `second-brain-git` 9.4(б)).

### Ворота 5. Приёмка и отчёт

**Приёмку делает отдельный субагент сильного класса, который работу не делал.** Он получает утверждения в виде списка проверяемых фраз и задачу их опровергнуть по объекту. Отчёты исполнителей и рассуждения диспетчера ему не передаются: приёмщик, прочитавший чужой вывод, ищет доводы за него. Основание: 2 случая, последний 2026-10-13 — отчёт синтеза, правило AVT.приёмщик.
Вопросы приёмки составляет не исполнитель; исправления по находке приёмщика проверяет повторно приёмщик (`second-brain-engineer`, references/design.md, пункт 14, г и д).

**Находки любого субагента сверх вопроса — гипотезы.** Они идут в канон словом «Гипотеза (не проверена):», пока диспетчер не проверил их по объекту. Признак: субагент называет причину отказа воркфлоу, а сохранённый прогон упал раньше, на другом узле, — значит, по прогону причина не проверена. Основание: 1 случай, 2026-10-13 — отчёт синтеза, правило AVT.гипотеза (находку того случая высказали проверяющие субагенты, а не приёмщик).

**Критерий приёмки не смягчается** (метод проектирования, пункт 15). Не выполнен — итог «не выполнено, вот почему».

Затем диспетчер пишет результат в канон, проверяет запись обратным чтением и выдаёт Андрею один отчёт: проблема, причина, что сделано, что сделать ему. Без пересказа шагов.

## Стоп-список — где работа останавливается сама

Остановка — сообщение Андрею с тем, на чём встало, и с подготовленным решением. Не тихое ожидание.

1. Нужно действие из списка ручных действий Андрея, а он его не сделал.
2. Нужно необратимое решение, которое разумно принять в обе стороны.
3. Меняется цель или предмет работы. Признак: делается уже не то, что записано целью в контракте, и цель приходится переопределять задним числом. Основание: 1 случай, 2026-09-27 — отчёт синтеза, правило AVT.цель.
4. Правка нужна вне списка разрешённых.
5. Два круга правок без сходимости — стоп-линия `denken`.
6. Жёсткий барьер: политика, закон, ограничение платформы.
7. Время последнего изменения воркфлоу разошлось с прочитанным в начале.
8. Критерий приёмки не выполнен.

Находка вне рамки контракта работу не прерывает. Она идёт захватом по правилу мастер-промпта проекта: объектный блокер — сразу, кандидат и мелочь — на !save.

## Чего этот Skill не делает

- Не заводит мониторов, сигналов живости и журналов наблюдения за автопилотом.
- Не меняет `naryad` вне автономного режима.
- Не разрешает правку Skill, мастер-промпта, удаление данных или правку воркфлоу без контракта, где они названы.
- Не считает ответ субагента записью в канон: в канон идёт то, что диспетчер прочитал сам; вердикт приёмщика входит в канон, когда диспетчер сам прочитал адрес доказательства, который приёмщик назвал (одна строка файла, одно поле ответа инструмента), — без этого он гипотеза (`second-brain-engineer`, Р21, ПРОВЕРКА).
