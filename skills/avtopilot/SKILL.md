# АВТОПИЛОТ

Версия 1.0. Создан 2026-10-13 сессией SYS (Аргус) по просьбе Андрея; пилот того же дня — задача `labs/sys/t-audit-0723-unverified.md`. Решение и отвергнутые варианты — `labs/sys/t-avtopilot-skill.md`. Владелец — Андрей.

Этот Skill не повторяет чужую механику. Ревизия — `denken`. Чтение и запись репозитория — `second-brain-git`. Форма вопроса посреднику — `second-brain-engineer`, правило «Чтение через посредника». Здесь только то, чего нет нигде: кто держит работу, когда Андрея нет рядом, и где она обязана остановиться.

## Зачем

Каждое короткое «да» Андрея заставляет модель заново обработать весь разросшийся разговор. Когда Андрей только соглашается, его реплики ничего не добавляют, а стоят каждый раз дороже предыдущего. Автопилот переносит согласование в одну точку — контракт запуска — и убирает Андрея из роли курьера между исполнителями.

## Пять ворот

Работа проходит ворота по порядку. Ворота не пройдены — дальше не идти.

### Ворота 1. Разговор — Андрей здесь

Сессия добивается четырёх вещей, коротко и без лишнего контекста:

1. **Квитанция рамки.** Цели Андрея отдельно, его предположения о способе отдельно, по каждому предположению — «оставляю» или «предлагаю снять, потому что» (метод проектирования, пункт 1, `second-brain-engineer` references/design.md).
2. **Критерий приёмки — наблюдаемый объект.** Не «проверено», а «по каждому из восьми пунктов вердикт с адресом доказательства». Критерий без объекта — ворота не пройдены.
3. **Все ручные действия Андрея — одним списком сразу.** Это действия, которые сессия сделать не может: создать Claude Project, привязать ключ доступа в n8n, перезалить Skill, вставить мастер-промпт, открыть папку сервисному аккаунту. Список собирается в начале, а не всплывает по ходу.
4. **Стоп-список** (раздел ниже) дополняется особыми стопами этой работы.

### Ворота 2. Ревизия

Skill `denken`, уровень 2, при необратимой или разрушительной операции — уровень 3. Ревизия идёт по написанному плану. Отдельный пункт ревизии для автопилота: какие шаги действительно независимы. Если все шаги строго последовательны, параллельности не будет — это говорится вслух до запуска, а не обнаруживается после.

### Ворота 3. Контракт запуска — одно «да»

Контракт — один текст, записанный в канон до исполнения:
- repo-проект — раздел «Контракт автопилота» в `PLAN.md` проекта;
- лаборатория — сам файл задачи `t-<имя>.md`;
- если записать нельзя — блоком в чате, и тогда запись контракта становится первым шагом исполнения.

Поля контракта: цель; критерий приёмки; пакеты работы (у каждого — объекты, вопрос, ожидаемый результат-объект, класс модели); разрешённые правки списком; особые стопы.

Список разрешённых правок и есть пакет разрешения из правила о полномочиях на воркфлоу n8n (`second-brain-engineer`, «Воркфлоу n8n — полномочия»): правка из списка исполняется без повторного «да», правка вне списка — снова по общему правилу.

Согласием считается ответ Андрея на контракт: «да», «действуй», «запускай». Молчание согласием не считается.

### Ворота 4. Исполнение — Андрея нет

**Шина — сессия-диспетчер, а не Андрей.** В автономном режиме правило Skill `naryad` «Андрей — шина, роли между собой не общаются» не действует: диспетчер сам раздаёт работу субагентам и сам принимает их ответы. Вне автономного режима `naryad` не меняется. Наряды в формате `naryad` внутри автопилота не печатаются: пакет контракта — не наряд.

**Когда раздавать субагенту.** Замер 2026-10-13: старт одного субагента — около 80–110 тысяч токенов, почти всё — его собственный стартовый контекст. Поэтому:
- субагенту отдаётся только тяжёлое чтение, которое нельзя сузить до попадания в контекст — полный граф воркфлоу, длинная выдача внешнего API, большая пачка файлов;
- лёгкий шаг (одно чтение файла, одно число, одна запись) диспетчер делает сам;
- объекты группируются по субагентам так, чтобы один старт обслуживал два-три объекта: пилот проверил девять воркфлоу четырьмя субагентами;
- независимые пакеты запускаются одним сообщением — тогда они идут параллельно.

**Что умеет субагент** (зонд 2026-10-13, исполнение n8n 79581). Есть: инструменты n8n, Канал чтения репозитория, память, Google Drive, командная строка. Нет: запуска своих субагентов — глубина одна, как в `naryad`.

**Задание субагенту** — вопрос, а не файл, по форме посредника (`second-brain-engineer`, «Чтение через посредника»):
- у каждого факта адрес доказательства — имя узла и путь в JSON, или цитата до 80 знаков, или путь и номер строки; не нашёл — NOT_FOUND со списком, где искал;
- по умолчанию только чтение, и это написано в задании словами «READ-ONLY, ничего не менять»;
- у вопроса закрытый набор вердиктов (например, ЖИВ / ИСПРАВЛЕН / ИЗМЕНЁН);
- задание пишется на английском и компактно — субагент его читает, Андрей нет.

**Пишет в канон только диспетчер.** Так нет гонки записи внутри прогона, и правила записи `second-brain-git` читает одна сессия, а не каждая. Правила, которые диспетчер исполняет сам, он читает сам, а не через посредника.

**Перед правкой воркфлоу n8n** диспетчер перечитывает время последнего изменения воркфлоу (updatedAt) и сверяет его с прочитанным в начале. Расхождение — стоп: воркфлоу правит параллельная сессия, а правка в n8n перезаписывает граф без проверки версии (`labs/sys/t-n8n-workflow-race.md`).

**Долгое ожидание** (прогон воркфлоу на десятки минут) — возврат в ту же сессию через отложенное сообщение самому себе. Это проверено пятью срабатываниями до 2026-10-13. Запланированная задача со свежей сессией на этом аккаунте не создавалась ни разу, режим одобрения у неё неизвестен до создания. Поэтому как носитель автопилота она используется только после отдельного зонда, записанного в `t-avtopilot-skill.md`.

**Массовая механическая работа** — скриптом, а не моделью (`second-brain-git`, references/delivery.md, пункт 9.4).

### Ворота 5. Приёмка и отчёт

**Приёмку делает отдельный субагент сильного класса, который работу не делал.** Он получает утверждения в виде списка проверяемых фраз и задачу их опровергнуть по объекту. Отчёты исполнителей и рассуждения диспетчера ему не передаются. Прецедент: так принимался поиск archive-recon — `projects/archive-recon/STATE.md`, «независимую проверку делает агент с моделью opus, запускаемый из сессии».

**Находки приёмщика сверх вопроса — гипотезы.** Они идут в канон словом «Гипотеза (не проверена):», пока диспетчер не проверил их по объекту. Пилот: приёмщик объявил, что незакрытый комментарий в коде узла роняет каждый прогон воркфлоу; единственный сохранённый прогон упал раньше — на ключе доступа Google в первом узле. Значит, по прогону гипотеза не проверена.

**Критерий приёмки не смягчается** (метод проектирования, пункт 15). Не выполнен — итог «не выполнено, вот почему».

Затем диспетчер пишет результат в канон, проверяет запись обратным чтением и выдаёт Андрею один отчёт: проблема, причина, что сделано, что сделать ему. Без пересказа шагов.

## Стоп-список — где работа останавливается сама

Остановка — сообщение Андрею с тем, на чём встало, и с подготовленным решением. Не тихое ожидание.

1. Нужно действие из списка ручных действий Андрея, а он его не сделал.
2. Нужно необратимое решение, которое разумно принять в обе стороны.
3. Меняется цель или предмет работы. Прецедент — archive-recon начинался как разведка, а превратился в каталогизацию, и цель переопределяли задним числом (записи Р-13 и Р-14 журнала `projects/archive-recon/LOG.md`).
4. Правка нужна вне списка разрешённых.
5. Два круга правок без сходимости — стоп-линия `denken`.
6. Жёсткий барьер: политика, закон, ограничение платформы.
7. Время последнего изменения воркфлоу разошлось с прочитанным в начале.
8. Критерий приёмки не выполнен.

Находка вне рамки контракта работу не прерывает. Она идёт захватом по правилу мастер-промпта проекта: объектный блокер — сразу, кандидат и мелочь — на !save.

## Чего этот Skill не делает

- Не заводит мониторов, сигналов живости и журналов наблюдения за автопилотом.
- Не меняет `naryad` вне автономного режима.
- Не разрешает правку Skill, мастер-промпта, удаление данных или правку воркфлоу без контракта, где они названы.
- Не считает ответ субагента записью в канон: в канон идёт то, что диспетчер прочитал сам или принял у приёмщика по объекту.
