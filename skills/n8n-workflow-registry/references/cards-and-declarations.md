# Карточки товаров и декларации — Wildberries и Ozon

Спутник раздела 3 файла SKILL.md этого Skill. Читается перед любой записью в карточку товара Wildberries или Ozon и перед работой с декларациями соответствия через API. Здесь только факты внешних API, установленные исполнениями; порядок работы с карточками Wildberries целиком — meta/PROTOCOL_wb-card-write.md репозитория second-brain-canon, он здесь не пересказывается.

Каждый факт несёт адрес, где его можно перечитать. Внесено 2026-10-09 по харвесту 2026-10-08 (находки А4, А33, Б2, Б8; позиции очереди AH-25 и AH-29).

---

## 1. Wildberries — запись карточки

**Ответ 200 ничего не доказывает.** POST `/content/v2/cards/update` отвечает 200 и меняет `updatedAt` карточки, но документ в карточке может остаться прежним: так шесть карточек отказали поштучно 2026-10-05, хотя журнал ошибок был пуст (projects/deklaration-ozon/LOG.md, Т-7). Итог записи проверяется двумя способами, оба обязательны:
- перечитать карточку через POST `/content/v2/get/cards/list` и сравнить поле за полем;
- прочитать журнал ошибок асинхронной записи — POST `/content/v2/cards/error/list`, тело `{cursor:{limit:100}, order:{ascending:false}}`. Метод GET на этот адрес отвечает 405. Записи журнала сгруппированы по пакетам и `vendorCode`, поля `nmID` в них нет (projects/deklaration-wb/PLAN.md, абзац «Факты записи»).

**Одна ошибочная карточка отклоняет всю склейку.** Склейка — группа карточек с общим `imtID`. Если в ней есть карточка с ошибкой, Wildberries не применяет запись ни к одной карточке склейки (projects/deklaration-ozon/LOG.md, Р-30).

**Запись заменяет карточку целиком.** Характеристика, не переданная в запросе, стирается. Поэтому запись идёт только по схеме «прочитал свежую карточку в том же прогоне → поправил нужные поля → отправил целиком»; узел перед отправкой сравнивает отправляемое с прочитанным (projects/deklaration-wb/PLAN.md, абзац «Ловушка записи»). Поле `kizMarked`, не переданное в запросе, принимается равным false — передавать текущее значение из чтения (projects/deklaration-ozon/LOG.md, Р-44).

**Применение с задержкой в часы (кабинет ИП).** В кабинете второго юрлица Wildberries применяет правки карточек с задержкой в часы. Ответ 200 значит «принято в обработку»; чтение через 45 секунд и через 4 минуты показывает старую карточку — это не отказ. Проверять на следующий день, после ночного робота листа карточек (projects/deklaration-wb/LOG.md, Р-11 пункт 5).
ИСТОРИЯ ДИАГНОЗА: записи Р-9 и Р-10 того же журнала считали, что Wildberries молча отбрасывает запись в карточки кабинета ИП; опровергнуто чтением 2026-10-09 15:12 UTC — записи применились, просто позже.

**Случайные отказы пачки.** Ответ 400 или 500 «Internal server error» на пачку карточек бывает случайно; повтор той же пачки проходит (projects/deklaration-wb/LOG.md, Р-12 пункт 6).

**Форма значений.** Значения характеристик передаются массивом строк: `["3403990000"]`, `["01.06.2026"]` (meta/PROTOCOL_wb-card-write.md, раздел 5).

**Описание карточки.** Предел поля — 2 000 символов; переносы строк — обычный перевод строки (у Ozon — тег `<br/>`, раздел 4) (projects/card-content-sync/LOG.md, Р-5).

## 2. Wildberries — документ и маркировка в карточке

**Где лежит декларация.** Характеристики 15001135 «Номер декларации соответствия», 15001136 «Номер сертификата соответствия», 15001137 «Дата регистрации», 15001138 «Дата окончания действия». Характеристики для ссылки на запись реестра нет. Кроме характеристик, у карточки есть блок `documents`: `items[{type, number, startDate, endDate, verdict{verified, status, reason}}]` и `overallVerdict` — это собственная сверка Wildberries документа с реестром (projects/deklaration-ozon/LOG.md, Р-21). При каждой записи декларации Wildberries создаёт документ заново, с новым id; промежуточный вердикт вроде `supplier_not_registered` через несколько часов может смениться на `ok` (meta/PROTOCOL_wb-card-write.md, раздел 5). Даты документа Wildberries сверяет с реестром — расхождение даёт `document_dates_mismatch` (projects/deklaration-wb/PLAN.md).

**Форматы дат в карточках.** Встречаются разные, и разбирать их надо явно, по всем встреченным формам; неузнанная дата — ошибка с сигналом, а не пустое значение:
- ММ-ДД-ГГ: `01-27-27` значит 27.01.2027 (meta/PRODUCT_DATA_HIERARCHY.md, раздел 4). Воркфлоу «LM_DECL — WB Sync ИП» эту форму не понимал, пока разбор не исправили (projects/deklaration-wb/STATE.md);
- ДД.ММ.ГГГГ — в характеристиках 15001137 и 15001138 у карточек, снятых зондом 2026-10-02 (projects/deklaration-ozon/LOG.md, Р-21);
- в блоке `documents` даты приходят в виде ГГГГ-ММ-ДД с временем (код узла `03_Build_Rows` воркфлоу `fGHfVrI58Ws1wfTw`).
Основной «LM_DECL — WB Sync» разбирает три формата (projects/deklaration-wb/STATE.md).

**ОКПД 2 — характеристика 15004292.** ОКПД 2, введённый руками в личном кабинете, API не показывает, поэтому полная перезапись карточки (раздел 1) его стирает. Для предметов «Автохимия» и «Смазки автомобильные» вместе с ним Wildberries снимает `needKiz` и `kizMarked`, и повторная запись `kizMarked=true` без ОКПД 2 не принимается: так 2026-10-07 потеряли отметку маркировки 29 карточек основного кабинета (projects/deklaration-ozon/LOG.md, Р-44 и Т-9). ОКПД 2, записанный через API, API показывает, и он переживает следующую запись (projects/deklaration-wb/LOG.md, Р-7 и Р-11).

**Нужна ли маркировка (КИЗ).** Wildberries решает по паре «предмет + ТН ВЭД»: справочник `/content/v2/directory/tnved`, поле `isKiz`. Для части предметов («Автохимия», «Смазки автомобильные») маркировка нужна только при ОКПД 2 из перечня постановления Правительства № 1683 от 30.11.2024 (projects/deklaration-ozon/LOG.md, Р-44 пункт 2). Справочник ОКПД 2 — `/api/content/v2/directory/okpd` (взято из позиции очереди AH-25; вызовом в журналах не подтверждено).

**Два поля маркировки.**
- `needKiz` («Нужна маркировка КИЗ») — только чтение: Wildberries выводит его сам из предмета, ТН ВЭД и ОКПД 2. Через API без ОКПД 2 признак не включается; ручная галка сотрудника в личном кабинете включает.
- `kizMarked` («Подтверждаю, что на товар нанесена маркировка») — записывается, но это юридическое заявление продавца по закону о маркировке (289-ФЗ). Ставить только по прямому слову владельца на названные им карточки (projects/deklaration-wb/LOG.md, Р-7 «отвергнуто»; meta/PROTOCOL_wb-card-write.md, раздел 1).
Блокировку карточки «подлежит обязательной маркировке» снимает не запись в карточку, а регистрация продавца в «Честном знаке» по этой товарной группе (projects/deklaration-wb/LOG.md, Р-7 пункт 3).

## 3. Ozon — декларации

- Загрузка: POST `/v2/product/certificate/create` одним вызовом, товары передаются списком `skus` и привязываются сразу. Метод `/v1/product/certificate/create` отключён Ozon 2026-08-31, вызов даёт 404 (projects/deklaration-ozon/PLAN.md, абзац «Факты API Ozon»).
- Для типа DECLARATION стандарт — только `NATIONAL` или `EAEU`. Что значение прошло проверку Ozon, не значит, что оно верное: `EAEU` для декларации РОСС Ozon принял (projects/deklaration-ozon/LOG.md, Т-5, Р-16) — стандарт выводится из номера документа.
- Сертифицируемые типы товаров: POST `/v2/product/certification/list {page, page_size}`; версия 1 отвечает 400 «obsolete method cannot be used».
- `page_size` у `/v1/product/certificate/list` — не больше 100. У `/v1/product/certificate/products/list` поле `limit` от 1 до 1000, `page_size` не годится; по товару он отдаёт только `product_id`, `sku`, `product_status_code`, причину отказа не отдаёт (projects/deklaration-ozon/LOG.md, Т-4).
- Метода `/v2/product/info/list` нет, есть `/v3/product/info/list`.
- Статус документа `approved` не значит, что товары одобрены: Ozon проверяет каждый товар отдельно, порядка 10 дней; итог перечитывается отдельным режимом «статус» (projects/deklaration-ozon/LOG.md, Р-36). Вкладки кабинета «На проверке», «Отклонены», «Одобрены» фильтруют статус документа, а не товаров: документ с зависшими товарами стоит в «Одобрены», зависание видно только по колонке «Одобрено товаров» (projects/deklaration-ozon/PLAN.md).
- Факты этого раздела сняты с полного swagger.json, прочитанного в браузере 2026-10-01, и проверены вызовами; из сессии документацию Ozon прочитать нельзя (SKILL.md, «Внешние источники»).

## 4. Ozon — описание карточки

Описание читается пакетно атрибутом 4191 «Аннотация» через `/v4/product/info/attributes`; поштучный `/v1/product/info/description` не нужен. Переносы строк у Ozon — только тег `<br/>`; при сравнении с текстом Wildberries теги заменяются переводом строки (projects/card-content-sync/LOG.md, Р-5).
