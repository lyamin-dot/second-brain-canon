# naryad — пересмотр Skill

Часть Skill naryad. Читать: при ревизии текста этого Skill — сигналы накопились за серию нарядов, харвест, прямое слово Андрея. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

Пересмотр Условия, при которых текст этого Skill пересматривается. История введения пунктов здесь не хранится — она в строке Supersedes и в журнале git-migration.

Если за 10 нарядов ни один не отбит по причине (б) — проверить оба объяснения: среды универсальны и поле ТРЕБУЕТ лишнее, либо Исполнители не отказывают. Не выбирать заранее.

Если за 10 нарядов с широким мандатом ноль отказов по мандату — поле не работает: либо оно не читается, либо мандат выдаётся формально.

Если за 10 нарядов с полем ЗАМЫСЕЛ (§3.8) ни один не отбит по причине (е), ни один текст наряда не изменился по итогу заполнения поля и ни одна задача не ушла на ревизию — поле заполняется формально, задним числом под уже написанный наряд. Признак того же: строка «слабое звено» из наряда в наряд называет одно и то же общее место (сроки, объём, «может не хватить контекста») вместо конкретного места этого наряда.

Если после нескольких нарядов ОСНОВАНИЕ ГДЕ стабильно указывает на «3» вне зависимости от реальной потребности в контексте проекта — вопрос 3 требует повторного пересмотра, а не дерево целиком. Признак вопроса 3 — контекст, не диалог: диалог по ходу выполнения доступен и в Cowork (§3.2).

Если наряд с ТРЕБУЕТ «git push» отбит по §6(б) в Claude Code дважды подряд — среда перестала быть средой с push, и вопрос 1 пересматривается на приёме, не в тексте.

Если паттерн дрейфа §3.6 повторяется (пометка о дрейфе не появляется там, где Андрей её ожидал бы) — проверка не работает как текст среди прочего текста наряда и требует более жёсткого места, например обязательного поля в самом блоке НАРЯД. Если правило БЛОКЕРа обходится систематической регистрацией мнимых БЛОКЕРов в реестр — вопрос не в тексте Skill, а в том, кто утверждает записи в CORE Р.5.

Если наряд снова превышает прогноз паспорта ×2 без STOP-LOSS-строки в журнале хода — не ужесточать формулировки, а искать, какой слой Skill (Drive / Customize / сессия) фактически действовал в той сессии (класс П-05, дрейф трёх слоёв).
