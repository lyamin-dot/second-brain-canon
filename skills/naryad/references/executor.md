# naryad — роль Исполнителя

Часть Skill naryad. Читать: перед приёмом наряда, целиком, один раз за сессию. Номера пунктов — прежние, общие со SKILL.md; ссылки на пункты других частей разрешаются по таблице «Что читать дальше» в SKILL.md.

6. Контракт Исполнителя Отказ приёма. Работа не начинается, если:

(а) пусты DoD, ИСПОЛНИТЕЛЬ, МОДЕЛЬ, ГДЕ, ТРЕБУЕТ или МАНДАТ НА ОТКАЗ, либо МОДЕЛЬ стоит без номера вопроса §3.1а, либо ОСНОВАНИЕ ГДЕ стоит голым номером без ответов «нет» по §3.1; (б) в текущей среде отсутствует инструмент из списка ТРЕБУЕТ — для «git push» наличие проверяется не именем среды, а командой git push --dry-run в этой самой сессии (second-brain-git 9.1), и отказ прокси есть отсутствие инструмента; (в) поле ОСНОВАНИЕ ГДЕ пусто или не соответствует §3.1; (г) отсутствует ID либо ID не соответствует формату §3.3; (д) наряд содержит деструктивные правки, а ПАСПОРТ пуст, стоит прочерком или превышает потолок §3.7 — ответ: <ID> НЕ ПРИНЯТ. ПАСПОРТ: <что не так>. (е) наряд содержит деструктивные правки, а ЗАМЫСЕЛ пуст, стоит прочерком, обоснован ссылкой на обычай («обычно так», «best practice», «надёжнее») либо строка «чем опровергается» не называет наблюдаемого объекта — ответ: <ID> НЕ ПРИНЯТ. ЗАМЫСЕЛ: <что не так>. Это отказ по форме поля, а не спор о содержании замысла: спор о содержании ведётся мандатом на отказ (§3.4) уже после приёма.

Ответ одной строкой, до всякой работы:

<ID> НЕ ПРИНЯТ. Пустые поля: <перечень>. <ID> НЕ ПРИНЯТ. В этой среде нет: <инструмент>. <ID> НЕ ПРИНЯТ. ОСНОВАНИЕ ГДЕ не сходится: <что не так>. НЕ ПРИНЯТ. Отсутствует ID. Куда переадресовать наряд — решает Андрей. Исполнитель среду не выбирает и наряд не переписывает.

Подтверждение приёма — первой строкой, до начала работы:

<ID> Принял. DoD своими словами: <пересказ>. Вне рамки: <что не делаю>. Пересказ обязателен именно своими словами. Дословное повторение формулировки из наряда подтверждением не считается — оно доказывает копирование, не чтение.

Закрытие — ID артефакта или сам результат. «Сделано» закрытием не является.

Находка вне рамки — то, что замечено по ходу работы, но РАМКОЙ не охвачено, — не исправляется и не бросается: она кладётся в раздел «Находки вне рамки» того же результата, по одной строке на находку, с адресом объекта. Если находок нет, раздел содержит слова «находок вне рамки нет». Рассказ о находке в ходе работы, вне результата, её доставкой не является: результат читает Руководитель, переписку Исполнителя — нет; зарегистрировать находку — дело Руководителя при приёмке (references/issuer.md, проверка перед выдачей). Основание: 1 случай, не позже 2026-08-31 — пять захватов Исполнителя остались под риском потери, потому что канала записи у него не было (SYS_JOURNAL_2026, строка 5891; урок Ф2-4 журнала projects/archivarius/LOG.md, запись Р-6).

Пустое чтение — стоп, а не повод продолжить. Если инструмент вернул пустоту без ошибки, работа останавливается и об этом сообщается. Ответ по памяти вместо прочитанного — корень конфабуляции, зафиксированный дважды за один день 2026-08-04.

Шаг, для которого инструмент не дал данных — нужного поля нет в ответе, у инструмента нет такой операции, объект недоступен в этой среде, — в отчёте стоит словами «шаг <номер> не выполнен: данных нет», с названием инструмента и того, чего в его ответе нет. Вывод из косвенных признаков вместо отсутствующих данных исполнением шага не является: рапорт по такому шагу выглядит как исполнение и проходит приёмку молча. Исполнитель вправе назвать другой наблюдаемый канал — например, Андрей сверяет в интерфейсе по выданному списку узлов, — но переназначить или снять шаг решает Руководитель, как и среду (выше). Основание: 1 случай, 2026-07-31 — шаг «выписать привязанные ключи через get_workflow_details» был неисполним (поле credentials тогда в ответе не приходило; с 2026-10-08 приходит), сверку отдали Андрею списком из трёх узлов (JOURNAL_INCIDENTS, строки 493–497; урок У-90 журнала projects/archivarius/LOG.md).

ЖУРНАЛ ХОДА (обязателен при трёх и более деструктивных правках). Счёт не поручается вниманию — он встроен в артефакт, который сессия обязана производить: номер следующей строки арифметически следует из предыдущей, держать в уме нечего. После КАЖДОЙ правки, до перехода к следующей, одна строка в ответе:

[k/N] <файл> <§/корень> | тактов: +t (норма +3) | всего: m/B | exec: <ID записи>, <ID read-back>

где k — номер правки (номер предыдущей строки +1), N и B — из ПАСПОРТА, t — фактические такты этой правки (норма 3: чтение ДО + запись + read-back; каждый повтор из-за промаха якоря или пустого чтения = +1 с причиной в строке), m — сумма предыдущей строки + t.

STOP-LOSS — проверяется в момент записи строки, по двум числам из неё же: если m ≥ B/2 при k < N/2 — следующей строкой пишется «STOP-LOSS: k из N, m из B, причина перерасхода», работа останавливается, продолжение только по слову владельца наряда. Правка, начатая до стопа, довершается: запись без read-back не бросается никогда. Мера времени — такты и вызовы, не минуты: минут у сессии нет, счётчик вызовов объективен.

Журнал не защищает от намеренной лжи в строке — от неё защищает приёмка по объекту (§8) с резолвируемыми exec-ID: ложь в строке с проверяемым execution-ID оставляет улику. Журнал закрывает незаметный перерасход, дрейф «ещё одна попытка» и невидимость статуса снаружи: текущее состояние работы читается по последней строке журнала в любой момент. Наряд с деструктивными правками без журнала хода приёмке не подлежит.
