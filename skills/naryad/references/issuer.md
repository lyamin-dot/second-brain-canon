3.6 Проверка релевантности Главной цели Перед печатью блока НАРЯД Руководитель отвечает себе на два вопроса — не Андрею, про себя, до выдачи:

(а) Известна ли Главная цель текущей сессии или проекта в явном виде? Если нет — наряд не о ней, а о её выяснении, и это нужно писать в ЗАДАЧЕ прямо («выяснить Главную цель», не маскировать под что-то другое). (б) Продвигает ли этот наряд к Главной цели, или выбран за лёгкость исполнения, а не за важность?

Признак дрейфа (зафиксирован 2026-08-13): несколько нарядов подряд бьют по мелким установочным деталям вместо БЛОКЕРА/РЫЧАГА текущего проекта (CORE Р.5), а на прямой вопрос Андрея «это важно?» ответ — «нет». Так подменяется работа над Главной задачей серией удобных мелочей.

Если ответ на (б) — «нет» или неочевиден, дальнейшее зависит не от суждения Руководителя в моменте, а от того, есть ли под находкой объект (правка 13.08.2026, по TRIZ-проверке: без этого разделения находка просто начинает называть себя БЛОКЕРОМ, и дрейф возвращается под новой этикеткой):

БЛОКЕР — уже зафиксированный объект: существующая строка в CORE Р.5 или в разделе БЛОКЕРы активного INDEX. Наряд выдаётся; одной строкой перед блоком НАРЯД называется, какой именно объект-БЛОКЕР он закрывает — ссылка на строку, не пересказ своими словами.

Кандидат в БЛОКЕРы — похоже на риск потери данных или повреждения структуры, но нигде ещё не зарегистрировано как объект. Наряд НЕ выдаётся. Находка фиксируется как [ЗАХВАЧЕНО → НОВЫЙ БЛОКЕР?: ...], решение о статусе — на ближайшем обслуживании или следующем прямом контакте с Андреем. Исключение: потеря данных наблюдается прямо сейчас, в моменте — тогда сообщить немедленно, регистрация задним числом.

Не БЛОКЕР — мелочь, «давно не трогали», второстепенное. Наряд НЕ печатается. Находка фиксируется как [ЗАХВАЧЕНО → ...], решается на обслуживании.

Самопровозглашение находки БЛОКЕРОМ без объекта в реестре, чтобы обойти это правило, — тот же дрейф, который правило призвано остановить. При сомнении, БЛОКЕР это или нет, — находка идёт по ветке «кандидат», не по ветке «БЛОКЕР».

Три и более наряда подряд с меткой БЛОКЕР без ссылок на разные объекты реестра — сигнал возможной перегрузки классификации; остановиться и спросить Андрея прямо, не мелочь ли это, наряженная в БЛОКЕР.

3.9 Маршрут шага. Введён 2026-09-10 (Н-10.09-10). Сессия применяет к каждому шагу собственного плана — после ревизии denken, если была, и до первого действия по шагу. Маршруты: А — продолжать проектирование; Б — исполнить самой; В — выдать наряд. Перед первым действием печатается строка:

МАРШРУТ: <А|Б|В> — <№ вопроса>: <наблюдённый факт>

Шаг без строки не начат — как наряд без ОСНОВАНИЯ ГДЕ. Вопросы по порядку, первое «да» даёт маршрут. Входы — только наблюдаемые: инструмент в среде, вход в контексте, происхождение входа, число вызовов. «Сложность», «важность», «ощущение контекста» входами не являются.

У шага нет DoD-объекта (§3), либо поле наряда (ГДЕ, якорь, ID, номер записи, посылка) пришлось бы заполнить по памяти, а не по прочитанному в этой сессии? ДА → А. Первое действие А — чтение недостающего входа (самой, если инструмент есть; иначе наряд на чтение по §3.5), затем шаг маршрутизируется заново.
Шаг исполним только в другой момент (дата, автозапуск, чужой результат), либо в ТРЕБУЕТ шага есть инструмент, которого нет в этой среде? ДА → В; ГДЕ — по §3.1.
Вход шага — продукт этой сессии (её решение, замер, текст), так что поля наряда содержали бы сам записываемый текст? ДА → Б. Наряд провёз бы тот же текст дважды и состарил вход на время шины.
Результат шага — вход следующего шага этого же плана? ДА → Б. Иначе по §3.5 результат обязан лечь в файл и вернуться через шину.
Стоимость шага B = N×3 + R (§3.7) не больше накладных наряда O = S + 3, где S — число Skill, которые Исполнитель обязан прочитать по ТРЕБУЕТ и §6 (naryad считается), 3 — текст наряда, приём с пересказом, отчёт через шину? ДА → Б. НЕТ → В.

Маршрут Б снимает для этого шага запрет §4 на вызов инструментов, но не §6–§8: паспорт, журнал хода и приёмка по объекту действуют. Следующий шаг маршрутизируется заново; сессия Исполнителем не становится и наряды по-прежнему выдаёт.

Пересмотр: если из 10 шагов с маршрутом Б по вопросу 5 хотя бы один по журналу хода дал m > 2·O — прокси «вызовы» не отражает цену, и вопрос 5 переводится на байты по бюджетам second-brain-git 4.5.

4. Контракт Руководителя Сессия заканчивается блоком НАРЯД. Если наряда нет — сессия не закончена. Инструменты вызывает только на шаге с напечатанной строкой МАРШРУТ: Б (§3.9). Нужны данные, а инструмента в среде нет — выдаёт наряд на чтение. Не обязан знать оснастку сред. Задаёт целевой текст правки, но не якорь. Якорь — место в объекте, куда ложится правка, — Исполнитель берёт из собственного свежего чтения объекта. Якорь, продиктованный в наряде, взят из памяти Руководителя, а тот объект в этой сессии не читал. Если такого якоря в объекте дословно нет, Исполнитель не подбирает похожий, а называет расхождение в отчёте (прецедент — Р-14 журнала PROJECT_LOG_SYS). Заполняет ТРЕБУЕТ по задаче, ГДЕ — по §3.1, ОСНОВАНИЕ ГДЕ — номером сработавшего вопроса. Присваивает ID по §3.3 в момент выдачи. Один замысел — минимум нарядов, а не максимум. Наблюдаемый признак соблюдения роли: перед каждым вызовом инструмента стоит строка МАРШРУТ: Б, перед каждым блоком НАРЯД — строка МАРШРУТ: В; сессия заканчивается нарядом или строкой МАРШРУТ: Б с результатом по объекту. Вызов без строки — нарушение роли, видное в интерфейсе без заявлений.

Проверка перед выдачей (пять дефектов, зафиксированных 2026-08-05, все — расхождение текста с замыслом):

DoD не уже ЗАДАЧИ — иначе часть работы выпадет молча. ТРЕБУЕТ не содержит метода — это поле про доступ, не про способ. Отмена и новое поручение по отменённому объекту не идут одним сообщением. Если назначена очерёдность нарядов — назначен и способ её проконтролировать. МАНДАТ НА ОТКАЗ заполнен осознанно, а не скопирован из прошлого наряда. ПАСПОРТ посчитан формулой §3.7, потолок (N ≤ 5, файлов ≤ 1) соблюдён либо наряд отдан Прорабу на разбиение — совокупный размер считается заново при КАЖДОМ доливе задач в наряд, аддитивный рост без пересчёта и есть механизм прецедента Н-20.08-04. Проверка §3.6 пройдена — наряд либо явно продвигает Главную цель, либо закрывает объектный БЛОКЕР со ссылкой на строку реестра. ЗАМЫСЕЛ заполнен по §3.8: механизм назван, опровергающий факт объектен, слабое звено названо и не является несущим. МОДЕЛЬ выведена по §3.1а номером вопроса; ОСНОВАНИЕ ГДЕ содержит ответы «нет» с фактами, не только номер; перед блоком НАРЯД напечатана строка МАРШРУТ: В по §3.9 — наряд на шаг с маршрутом А или Б не выдаётся.
