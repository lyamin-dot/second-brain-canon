## Что это за машина

Clasp — программа командной строки от Google. Она выгружает код Apps Script книги в обычные файлы на компьютере Андрея и загружает обратно. Между выгрузкой и загрузкой код правится как любой файл, а git хранит историю каждой правки. Работает она от имени самого Андрея, с его входом в Google, поэтому доступ к личным скриптам у неё есть, а у сервисного аккаунта n8n его нет.

## Как заводить смену

1. Перейди в папку нужной книги и выполни `git status`. Папка должна быть чистой. Если в ней есть несохранённые правки, это твои незавершённые изменения прошлой смены: зафиксируй их коммитом или спроси Андрея, если они не твои. Причина: `clasp pull` затирает локальные файлы версией из облака.
2. Выполни `clasp pull`, затем снова `git status`. Если файлы изменились, значит, Андрей правил код в браузерном редакторе. Зафиксируй это отдельным коммитом «Правка в редакторе Apps Script, подобрана перед работой» и прочитай, что изменилось. Живой текст скрипта — это то, что пришло с `pull`, а не твоя копия из прошлой смены.
3. Правь файлы. Правила содержимого — в Skill apps-script-sheets.
4. Выполни `git diff` и прочитай сам, что изменилось, прежде чем загружать.
5. Выполни `clasp push` без параметра `--force`. Push перезаписывает весь проект целиком: правка, сделанная в редакторе после последнего `pull`, пропадёт без предупреждения. Если Андрей говорил, что правил в редакторе, снова начни с шага 1.
6. Зафиксируй загруженное коммитом: что изменено и зачем.
7. Запускает функцию Андрей: из редактора Apps Script или из меню книги. Результат читай сам, через gsheets-read и служебный лист `_log` в книге; отчёту скрипта верить как гипотезе.

## Кто что делает

Сессия: `clasp pull`, правка файлов, `git diff`, `clasp push`, коммит. Андрей: запуск функций, вход в аккаунт (`clasp login`), решение о подключении новых книг.

Граница проведена по необратимости. Загрузка кода обратима: прежнюю версию можно вернуть из git и загрузить снова. Запуск функции меняет данные книги, и откатить его можно только историей версий Google, всей книги целиком. Поэтому запускает человек.

Сессия не делает без прямой просьбы: `clasp deploy`, `clasp create`, `clasp push --force`, удаление файлов проекта, любые действия с файлом .clasprc.json.

## Граница слоёв

Apps Script отвечает за логику: пересчёты, сигналы, оформление, меню. Данные (выгрузки с маркетплейсов, запись строк) остаются за n8n. Если смешать, в один лист будут писать двое, и при расхождении будет непонятно, кто прав.

## Как этот Skill встроен в систему

Механизм работает, только если каждая сессия, которая собирается трогать код скрипта, узнаёт о нём до первого действия. Для этого есть четыре крючка.

1. **Инструкция Claude-проекта по Apps Script.** В ней названо имя этого Skill с указанием читать его перед любой работой с кодом книги. Это главный крючок: сессия проекта открывается именно там.
2. **Skill apps-script-sheets.** Откуда сессия берёт живой текст скрипта и как вносится правка, решает его раздел 1 «Порядок работы»: основной путь — мост gas-bridge, clasp — только аварийный ручной путь Андрея при недоступном n8n (запись Р-4 журнала `projects/gas-bridge/LOG.md`). Правила содержимого кода остаются там и здесь не повторяются.
3. **Данные читает не этот Skill.** Результат прогона читается через gsheets-read (Skill google-drive-docs); здесь описана только доставка кода.
4. **Репозиторий second-brain-canon.** Код книг в него не кладётся: репозиторий публичный, запись в него необратима. В канон попадают только решения и уроки по самому механизму.

Открытый вопрос: копии кода вне компьютера Андрея нет. Если диск выйдет из строя, останется только история версий внутри самой книги Google. Если понадобится удалённая копия, она может быть только в закрытом репозитории, не в публичном.

## Что отвергнуто и почему

- **Запуск функций через `clasp run`.** Требует привязать скрипт к проекту Google Cloud и развернуть его как исполняемый интерфейс: много настройки ради одной кнопки, запуск и так делает Андрей. Возвращаться, только если понадобится запуск без Андрея.
- **Мост через n8n** (воркфлоу с методами projects.getContent и projects.updateContent). Метод записи тоже заменяет проект целиком, без сравнения изменений и истории, код проходит через контекст модели и тратит токены. Воркфлоу gscript-read уже не заработал из-за ограничений сервисного аккаунта. Не отвергнут навсегда: может понадобиться для мелких правок с телефона, когда базовая схема отработает.
