ПРАВИЛО ПОТОКОВОГО ВЫТЕСНЕНИЯ ≤2 КБ (НОВОЕ, решение 4)
Основание: SYS_JOURNAL_2026_02, записи 2026-08-05 (в SYS_INDEX такой секции нет — вынесена в корпус хирургией Н-15.08-05 от 15.08; уточнено нарядами Н-30.08-20/22). В самом источнике формулировка мягче: «вставка текста крупнее ~2 КБ в Doc» названа одной из трёх подтверждённых ручных операций, а числа «практический потолок ~1-2 КБ» как категорического утверждения в источнике нет — оно появилось при переносе в CORE. Основание отпало 2026-08-26 с появлением gdocs-apply-from-file (source читается из Drive-файла и через тело вызова не проходит): заявлено 1 500 000 символов одним batchUpdate (паспорт Н-26.08-03, независимо не перепроверено), независимо подтверждена запись 174 326 Б, отказ Docs API зафиксирован на 1 900 000 — фактическая граница между 1,5М и 1,9М не измерена. Прежний список инструментов (gdocs-append/replace/overwrite v2, MCP create_file) верно описывал состояние на 14.08 и не описывает состояние с 26.08. Массовое удаление у gdocs-replace/overwrite v2 тем же путём по-прежнему не работает (Guard K1, google-drive-docs §15.7 — держится, не опровергнуто), дробить его на серию однострочных replace запрещено; mode=overwrite у gdocs-apply-from-file выполняет полное удаление и перезапись машинно, другим инструментом.
Правило для вытеснения (перенос закрытых/устаревших строк Зоны А → Зона Б или журнал/архив) при исполнении бюджета M1 (ШАГ 0.7):
  — вытеснение выполняется порциями ≤2 КБ за один write-вызов (gdocs-replace для точечного удаления строки с однозначным якорем, см. протокол деструктивного replace google-drive-docs §3.2);
    — для gdocs-append v2 и gdocs-replace v2 числовой потолок операции НЕ ИЗМЕРЕН: объекта с зафиксированным числом не найдено нигде (наряд Н-30.08-20) — это «не зарегистрировано», а не «проверено и подтверждено»; для gdocs-overwrite v2 известна только нижняя граница отказа (порча байт на ~29 КБ, инцидент 31.07), верхняя граница успеха не зафиксирована; как общее утверждение «любая операция» — опровергнуто gdocs-apply-from-file, где полная операция многократно превышает 2 КБ на каждом шаге и работает штатно;
  — вытеснение объёмом больше ~2 КБ выполняется через gdocs-apply-from-file (mode=overwrite, source из Drive-файла, наряд Н-26.08-03): заявленный потолок 1 500 000 символов независимо не перепроверен, независимо подтверждена запись 174 326 Б, отказ на 1 900 000. Машинный путь для текста крупнее тела вызова существует с 2026-08-26; ручной путь §15.6 остаётся резервным для объёмов выше подтверждённого и на случай отказа инструмента;
  — каждая порция подтверждается независимым read-back до перехода к следующей (не пакетно) — иначе теряется провенанс, какая именно порция ушла успешно, а какая нет.
Общего машинного потолка ~2 КБ как факта не существует (наряд Н-30.08-20): цифра относится только к gdocs-append/replace/overwrite v2 и точным числом не измерена ни для одного из трёх; у gdocs-apply-from-file предел иного порядка. Дробление ≤2 КБ сохраняется для gdocs-append/replace/overwrite v2 как КОНСЕРВАТИВНЫЙ ДЕФОЛТ БЕЗ ЗАМЕРА и как дисциплина порционного read-back, а не как отражение измеренного предела. Условие пересмотра: появление объекта с измеренным числом хотя бы для одного из трёх инструментов.
Очерёдность при превышении бюджета: первыми вытесняются записи с низшим итоговым приоритетом по формуле Р.5 (метка × вес проекта).
