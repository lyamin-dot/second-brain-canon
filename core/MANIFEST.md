# Состав CORE в репозитории — из чего складывается канон и что значит «прочитан целиком»

Заведён 2026-09-06. Причина — Т-25 журнала `projects/git-migration/LOG.md`: сессия, читающая CORE через git, не может узнать, из чего CORE состоит. Канал чтения (воркфлоу `git-read`) отдаёт файл по имени, а на каталог отвечает отказом; списка имён в репозитории не было ни одного.

## Кто это читает

Мастер-промпт проекта: шаг «прочитать CORE» = прочитать этот файл, затем все файлы его списка. Пока такая строка в мастер-промпт не внесена, у этого файла читателя нет — и это сказано здесь прямо, потому что файл, объявляющий себе триггер собственной строкой, читателя не приобретает (Т-24).

## Что значит «CORE прочитан целиком»

Прочитаны `meta/header.md` и все 27 файлов списка ниже. Признак для отчёта сессии — назвать число прочитанных файлов и последнее имя списка.

Хвостовой пароль-канарейка признаком полного чтения в git-форме НЕ является. Канарейка работала, пока канон был одним документом: пароль стоял в последних байтах, и назвать его мог только тот, кто дочитал до конца. Двадцать семь файлов концом не обладают, а отдельный файл с паролем доказывает ровно одно — что прочитан этот отдельный файл. Файл `meta/canary.txt` в репозитории есть, но частью CORE не является и проверкой не служит; его собственный маркер переноса называет пароль `HEMD`, а тело файла — `FORM`, то есть как пароль он к тому же недостоверен.

Контрольных сумм и байтовых пломб этот файл не хранит намеренно: запрет Б-1 — контрольная сумма и число байт не доказывают ни целостности, ни потери. Размеры ниже даны для оценки стоимости чтения, не для проверки.
