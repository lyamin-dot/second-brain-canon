# Состав CORE в репозитории — что читать на старте и что читать по событию

Канал чтения отдаёт файл по имени, а на каталог отвечает отказом, поэтому состав CORE задан этим файлом (Т-25 журнала `projects/git-migration/LOG.md`). Файл держит правило и списки, а не летопись своих редакций: как менялся состав — решения Р-66, Р-89…Р-94, Р-110, Р-111 того же журнала и журнал проекта `projects/kontext-reduktion/LOG.md`; где текст разделов, убранных из `core/`, — `meta/MAP_core-sections.md`.

## Критерий состава

В таблицу «Список» входит только то, что нужно любой сессии любого проекта в момент чтения CORE — правило, которое управляет каждым чтением и каждой записью. Материал, нужный в один определённый момент (запись в CHANGELOG, запись в журнальный корпус), стоит в таблице «По событию» и читается в этот момент. Реестр, из которого берут одну строку, и материал с единственным читателем не входят ни в одну таблицу: они в `registry/`, в Skill или в истории.

## Кто это читает

Мастер-промпты проектов: шаг «прочитать CORE» = этот файл, затем все файлы таблицы «Список»; таблица «По событию» в пакет старта не включается. `meta/header.md` на старте не читается: оба его поля помечены недействующими, файл хранит только провенанс блока T-001. Состав CORE меняется правкой одного этого файла, без правки мастер-промптов.

## Что значит «CORE прочитан целиком»

Прочитаны все 4 файла таблицы «Список».

Признак для отчёта сессии — три величины сразу:

1. число прочитанных файлов таблицы «Список»;
2. путь последнего файла таблицы;
3. blob sha этого файла — из ответа Канала, а не отсюда.

Blob sha здесь намеренно не записан и записываться не должен: величина, доказывающая чтение, обязана лежать вне текста, который сессия и так держит в руках. Он доказывает, что вызов чтения по этому пути состоялся, а не что файл цел, поэтому запрету Б-1 не противоречит. Контрольных сумм, байтовых пломб и размеров файлов этот файл не хранит: размер приходит в ответе Канала на каждый файл (поле byteLength), а записанный здесь размер расходится с файлом при первой же правке.

## По событию — в пакет старта не входит

| событие | прочитать перед ним | что там |
|---|---|---|
| запись в INDEX-документ проекта, в журнальный корпус или в INBOX, в том числе по команде !save; закрытие задачи | core/R-06-marshrut.md, core/R-06b.md, core/R-06d.md, core/R-08.md, core/R-11.md | адресация записи — тип и приёмник (ШАГ 0.5, маршрутная таблица 0.5.3), Зона Б для проектов без журнала (п.0.5.4), предикат входа в Зону А (ШАГ 0.6), поле-симптом журнальной записи, шапка метаданных и формат INBOX, обновление LAST_UPDATED и перенос закрытой задачи в архив |
| запись в CHANGELOG | core/R-13.md | формат записи, закрытые словари статусов и проектов |
| запись в Google Docs текста крупнее примерно 2 КБ | core/R-06c.md | потолки инструментов записи Docs и путь через gdocs-apply-from-file. Временная строка: убирается вместе с файлом, когда этот текст внесён в Skill google-drive-docs (позиция Q-4 очереди, решение Р-111) |

Правило чтения по событию: файл строки читается одним вызовом `git-read` в той сессии, где событие наступило, до первой записи этого вида. Сессия, записавшая без такого чтения, нарушает контракт записи так же, как сессия, не прочитавшая CORE.

## Ведение

Таблицы и число «4 файла» выше правятся тем же коммитом, которым файл добавляется в `core/`, убирается или переходит из таблицы в таблицу. Таблица, разошедшаяся с каталогом, хуже отсутствия таблицы: она даёт ложную уверенность, что прочитано всё.
